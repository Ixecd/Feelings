# 从数据流到无限状态机——一个字节的三层读法

> 作者：qc
> 日期：2026-08-16
> 性质：硬件随想，紧接 iCE40 UART 2b 结案
> 结论先行：一个字节从键盘到屏幕，物理上是一段 3.3V 电信号的往返；工具链上是从 Verilog 到位流的四段流水线；哲学上是 FSM 与无限状态的分界。三层读法合起来一句话——**信号是电不是数据，综合器是编译器会编译错，可证明性只属于有限状态机。**

---

## 零、先定前提

```
① 物理层   信号是电。键盘敲的不是字符，是 USB 差分线上的电平跳变；
            FPGA 引脚上只有 0 和 3.3V，没有"数据"这个实体。
② 工具链   综合器是编译器。yosys 不是"把 Verilog 变 FPGA"的翻译器，
           而是带优化 pass 的编译器——编译器会编译错，优化会反向优化。
③ 状态论   可证明性只属于 FSM。无限状态的东西只能被相信，不能被证明；
           被证明的只能是有限的东西。这是 Feelings 架构分层的逻辑必然。
```

---

## 一、数据流：一个字节的往返

```
键盘 → Mac 终端 → USB → CP2102 → TXD 引脚 →(跳线)→ FPGA RX (ball 2)
    → RX 机 → FIFO → TX 机 → FPGA TX (ball 6) →(跳线)→ CP2102 RXD 引脚
    → USB → Mac → 屏幕显示
```

三个容易踩空的细节：

```
① 交叉命名    CP2102 的 TXD 接 FPGA 的 RX，CP2102 的 RXD 接 FPGA 的 TX。
              命名是从器件自己的视角出发的——它发叫 TXD，它收叫 RXD。
② 两盏灯的语义 TXD 灯闪 = 数据出去了；RXD 灯 = 数据回来了。
              板级失败的每一轮诊断里，这两盏灯其实早就把答案说了：
              TXD 闪而 RXD 常量，说明数据到了 FPGA、回显没回来——
              只是我们一路追到综合器才真正看懂。
③ 中文的真相  一个汉字 = 3 字节 UTF-8，IME 一口气连发，字节间隔远小于 1ms。
              旧架构丢一个字节 → 解码边界错位 → 随机掉进别的码位 → 看着像繁体。
              乱码从来不是波特率问题，是丢字节问题。
```

第一条的前提（信号是电）在调试里被反复验证：0.32V 的虚接读数、GND 无参考电平时"全乱码"、绿灯心跳的消失——没有一次问题的本质是"数据"错了，全都是电错了。硬件工程师的全部工作，就是在电的层面上把数据重新认出来。

---

## 二、工具链：综合器是编译器

四段流水线：

```
top.v     Verilog 源码（人写的意图）
   ↓  yosys（综合器：语法分析 → 优化 → FSM 提取 → 映射到 iCE40 单元）
top.json  逻辑网表：SB_LUT4/SB_DFF/SB_CARRY 单元 + 连接关系，无物理位置
   ↓  nextpnr-ice40（布局布线）+ top.pcf（引脚约束）
top.asc   物理网表：每个 LUT 落在哪个格子、每根线怎么绕
   ↓  icepack（打包）
top.bin   位流：所有 LUT 真值表、FF 配置、布线开关的配置位
   ↓  拖进 iCELink
FPGA 芯片完成配置
```

用编译器的语言说：

```
yosys      ≈ 编译器前端 + 中端（含各优化 pass）
top.json   ≈ 目标汇编（已映射到 iCE40 的"指令集"）
nextpnr    ≈ 链接器（分配物理地址、解析跳转）
icepack    ≈ 打包成可执行二进制
```

就像 gnu 编译器的 O0/O1/O2 有时会"反向优化"，yosys 的 FSM 提取 pass 也有自己的 O2 时刻——它看见 `case(rstate)` 加状态寄存器，就认定"这是状态机"，自作主张重编码成 one-hot（rstate 从 [2:0] 变成 [4:0]）。源码合法、语义正确、仿真通过——产物错。两天的两个主凶都住在这个 pass 里：

```
default 当状态用     FSM 提取把 default 当"其余所有编码"，
                    真状态的逻辑被绑到包括非法编码在内的一整片区域
if/else 套 case     外层 if 与内层 case 合并重编码时被抽坏
```

由此立下的铁律：**门级仿真验证的不是代码，是综合器理解之后的东西。** RTL 仿真验证意图，门级仿真验证理解，两层都过才配烧板。这不是防御性编程洁癖，是两天板级失败换来的生存事实。

## 三、状态机论：FSM 与无限状态

```
Pivot 部署链 = FSM   资源对象的状态集合有界，reconcile 循环可枚举——
                     这正是它能被证明收敛的原因。

Feelings = 混合系统  生理量是连续的（HRV/皮电/相位是实数，不是状态）；
                     人的内部态是无限的（记忆、关系、心境不可枚举）；
                     当量账本是无限计数器（理论里最小的无限状态机）。
```

Feelings 不是无限状态机，是"无限 + 连续 + 离散"的混合系统——无限的部分是人，连续的部分是生理，离散的 FSM 岛是安全层。

这个分类的价值不在名词，在**可验证性的边界**：

```
FSM 才能被证明       状态可枚举 → 门级仿真逐拍验证 → 安全性可证明
无限状态只能被相信   人的部分没法"证明"，只能"防护"

所以 Feelings 的架构天然长成这样：
  硬件层（FPGA 熔断/帧使能/比较器）  = FSM 岛，可证明，写死
  账本层（90+ 当量累计）             = 无界计数器，可审计
  判断层（教练 AI + qc）             = 无限状态的那一侧，只能相信
```

这不是审美的分层，是逻辑必然：凡是安全攸关的，必须裁成 FSM；凡是需要适应和学习的，必须是无限的。今天的调试恰好示范了这条边界——我们能在门级把 FSM 的每个拍证明干净，正是因为它是有限的；而"qc 批准 90+"永远不可能被同样地证明，所以它才需要签名、审计、人。

顺带，这也是 Pivot 与 Feelings 的深层分野：Pivot 的野心是"把世界裁成 FSM"——所有资源可枚举、收敛可证明；Feelings 的诚实是"承认人裁不成 FSM"——于是把证明留给硬件岛，把相信留给设计。一个追求完全可验证，一个知道验证的边界在哪。两种都成立，但 Feelings 必须知道自己是后者。

---

## 四、三种读法，一条链

```
数据流的读法   告诉我们信号怎么走——电的层面上，没有数据只有电平。
工具链的读法   告诉我们综合器怎么理解你——你写的和它造的可能是两个东西。
状态机的读法   告诉我们验证的边界在哪——FSM 岛内可证明，岛外只能相信。
```

三者连起来是 Feelings 硬件哲学的一整条：**在电的层面认真，在编译的层面怀疑，在状态的层面分层。** 今天的板级胜利是这条链的第一次闭环，但链本身比胜利重要——下一个模块、下一个芯片、下一个原型，都还要从这条链上走一遍。

---

*一个字节走完全程，人在两头。硬件证明得了中间，证明不了两端——中间是 FSM，两端是无限。*
