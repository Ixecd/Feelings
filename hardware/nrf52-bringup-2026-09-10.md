## 二、踩的坑（关键）

### 1. Adafruit bootloader 不肯跳 app
按常规流程烧了 `feather_nrf52832_bootloader-0.9.1_s132_6.1.1.hex`（SoftDevice+bootloader）+ app，
结果复位后 **PC 停在 bootloader 区（0x74xxx）**——因为 SWD 直烧不会写 **bootloader settings**（app 校验信息），
bootloader 认为 app 无效 → 停在 DFU。自带的 `adafruit-nrfutil` 是精简版，没有 `settings generate` 命令。

### 2. 解法：绕开 bootloader/SoftDevice，app 直接跑 0x0
- 确认 core 里对 SoftDevice 的依赖极弱（只有 `wiring.c` 一处 `sd_softdevice_is_enabled`→没有则 `__WFE`）
- 自定义链接脚本 `nrf52832_nosd.ld`：`FLASH ORIGIN=0x0 LENGTH=0x80000`，`RAM ORIGIN=0x20000000 LENGTH=0x10000`
- 编译：`--build-property build.ldscript=nrf52832_nosd.ld`
- 烧录：`nrf5 mass_erase` 后 `program ...` 到 0x0
- 复位后 **PC 落在 app 区间** → 裸跑成功

### 3. SWD 突然连不上
`init mode failed`——最后原因是**杜邦线松了**。重新插紧即恢复。
（教训：nRF SWD 的 VCC/SWD/SCK/GND 四线接稳，探测时别碰松、别短接相邻针。）

## 三、Makefile 用法

```bash
cd hardware/nrf52
make detect                 # 探测芯片（验证 ST-Link 接线）
make compile SKETCH=blink   # 编译到 build-nosd/
make flash   SKETCH=blink   # 整片擦除 + 烧到 0x0
```

链接脚本 `nrf52832_nosd.ld` 需放到 core 的 `cores/nRF5/linker/` 下（仓库内留了副本）。

## 四、当前卡点：模块引脚未知

- 模块是"青风电子"的 nRF52832 成品板，**PCB 上无任何型号丝印**
- 引脚是纯数字 **0~31**（32 个），右下角另有 4 针 `VCC / SWD / SCK / GND`（SWD 编程口）
- 0~31 的具体含义未知（≠ 芯片脚号，也未必 = P0.xx 名字）
- 4 个 LED：LED1/LED3 常亮蓝，LED2/LED4 灭
- 烧了 `findpin`（P0.06 输出慢方波）用万用表定位，但**反复碰触有短路风险**，暂停

**待做**：
- ⬜ 确定模块 0~31 与 P0.xx 的映射（或至少找 2 个 GPIO + GND）
- ⬜ 接上 iCE40 的 UART（帧）到 nRF52832，跑 HR/HRV
- ⬜ 或者：直接问买家/找模块资料

> 注：Arduino core 可把 UART 放到**任意 GPIO**，所以不必非找 P0.06/P0.08，任意 2 个 GPIO + GND 即可。
