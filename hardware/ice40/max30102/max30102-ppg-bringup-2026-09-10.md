## 二、硬件接线（★ 最容易白调的地方）

iCESugar 的扩展口是**弯排针**，左右/前后在视觉上刚好镜像。**务必认丝印数字、别凭手感**：

| MAX30102 | iCESugar | FPGA ball |
|---|---|---|
| SCL | **P46** | ball46 |
| SDA | **P44** | ball44 |
| VIN | 3V3 | — |
| GND | GND | — |

- PMOD2（官方 io.pcf）：`P2_1=46 P2_2=44 P2_3=42 P2_4=37 / P2_9=36 P2_10=38 P2_11=43 P2_12=45`
- 板上丝印直接是 ball 号（`P46`/`P44`），但**弯排针物理孔位极易看反**——本次就曾把线插到 `P45`/`P43` 上，白调了半天。
- UART：`tx=ball6`（P6），9600 8N1，接外接 CP2102 的 RXD。
- LED：`ball39` 心跳（低电平亮）。

> **经验：接线后先用万用表确认——程序把某脚设成固定低电平时，对应孔应量到 0V。**

## 三、RTL 设计

代码在 `hardware/ice40-max30102/`。

### 3.1 `i2c_master.v` —— 可复用的事务级 I2C master

一次 `start` 完成一笔事务，支持两种操作：

- **写**：`START → dev+W → reg → data → STOP`
- **读**：`START → dev+W → reg → RESTART → dev+R → 读 N 字节(前 N-1 ACK, 末 NACK) → STOP`

命令接口：置好 `rw/dev/reg_addr/wr_data/rd_len` → 拉高 `start`（保持到 `busy`）→ 等 `done`。
读模式每读到一个字节 `rd_valid` 拉高一拍、`rd_data` 有效。

- SCL/HFOSC：`DIV4 = CLK_HZ/(SCL_HZ*4)`，四相位（低-高-高-低）
- START/STOP 严格分离相位（见坑四）
- 仿真验证：`sim/tb_i2c.v` + `sim/i2c_slave_model.v`

### 3.2 `uart_tx.v` —— 8N1 发送

`sh <= {1'b1, data, 1'b0}`（停止位+数据+起始位），`DIV=CLK_HZ/BAUD`。

### 3.3 `max30102_ppg.v` —— 顶层

**状态机**：`S_PWR → 9 个配置写 → (读 WR_PTR → 写 RD_PTR → 读 FIFO → UART 发) 循环`

配置表：

| reg | 值 | 含义 |
|---|---|---|
| 0x09 | 0x40 | MODE: RESET |
| 0x04/0x05/0x06 | 0x00 | FIFO_WR_PTR / OVF / RD_PTR 清零 |
| 0x08 | 0x10 | FIFO_CONFIG: 无平均 + rollover |
| 0x09 | 0x03 | MODE: SpO2（RED+IR） |
| 0x0A | 0x27 | SPO2: 4096nA / 100sps / 411us(18bit) |
| 0x0C/0x0D | 0x24 | LED1/LED2 电流 ≈7.2mA |

**关键：FIFO 读指针对齐**（见坑九）——每轮先读 `FIFO_WR_PTR`，再写 `FIFO_RD_PTR = WR-1`，
保证每次读到的是**最新的完整样本**，避免溢出/漂移导致字节错位。

**18 位重组**（见坑八）：MAX30102 的 FIFO 每通道 3 字节，标准重组要屏蔽首字节高 6 位：
```
RED = ((b0 & 0x03) << 16) | (b1 << 8) | b2
IR  = ((b3 & 0x03) << 16) | (b4 << 8) | b5
```

**UART 帧**：`FE E1` 同步头 + 6 字节（两通道首字节已屏蔽到 2 位）。

## 五、踩坑全记录

### 坑一（★）iCESugar 弯排针丝印看反 → 线接错孔
把 SCL/SDA 接到 `P45`/`P43` 而以为是 `P46`/`P44`，白调很久。
**教训**：接线后逐孔量电压确认；弯排针别凭手感。

### 坑二 MAX30102 PART_ID 在 0xFF，0xFE 是 REVISION_ID
读 `0xFE` 得到 `0x03` 一度以为错——其实那正是 REVISION_ID，说明 I2C 已通。
`0xFF` = PART_ID = `0x15`。

### 坑三 iCESugar 拖拽烧录不会自动重配 FPGA
拖 `.bin` 只写 SPI flash，FPGA 仍在跑旧 SRAM 配置，**必须拔插 USB**。
判断"程序有没有换"要给 LED 一个不可能误认的标记（常亮/特异闪烁）。

### 坑四 软 I2C 的 START 时序
`SCL<=0; SDA<=0;` 写在同一拍不构成合法 START。必须分相位：SCL 高时 SDA 先 1→0，SCL 后降。

### 坑五 仿真里分频寄存器未复位
`divc` 无复位，仿真初值 x → `tick=x` → 卡死。加 `if (rst) divc<=0`（硬件上电为 0 所以没暴露）。

### 坑六 `buf` 是 Verilog 关键字
`reg [7:0] buf [0:5];` 报语法错，改名 `rxbuf`。

### 坑七 48MHz 时序不收敛
nextpnr 报 `Max frequency 33.9MHz (FAIL at 48MHz)`。降到 **24MHz**（`CLKHF_DIV="0b01"`）后 PASS。

### 坑八 FIFO 首字节高 6 位
早期按 `(b0<<16)|(b1<<8)|b2` 直接当 18 位，手指一按首字节就冒出 `0x11`/`0x15`（>0x03）。
查 SparkFun 官方驱动：它做 `& 0x3FFFF` **屏蔽首字节高 6 位**。按此屏蔽后数值平滑合理。

### 坑九 FIFO 读指针漂移/溢出
只按固定节奏读 6 字节，跑一会儿字节相位就漂了（首字节乱）。
解法：**每轮读 `FIFO_WR_PTR`，写 `FIFO_RD_PTR = WR-1`**，永远对齐到最新完整样本。

### 坑十（分析）用移动平均去 DC 把心跳滤掉了
脉搏 ~1Hz，而 1 秒移动平均在整数 Hz 处有零点 → 正好把脉搏抹掉，FFT 只剩 0.5Hz。
改用 **FFT 频域带通 0.6~3.5Hz** + Hann 窗，脉搏立刻清楚。

## 六、PC 端分析

`tools/ppg_capture.py`（纯 numpy，无需 pyserial/matplotlib）：
读串口 → 切 `FE E1` 帧 → 18 位重组 → 存 `ppg_capture.csv` → 带通 + FFT 找主频 → ASCII 波形。

```
stty -f /dev/cu.usbserial-0001 9600 raw
python3 tools/ppg_capture.py /dev/cu.usbserial-0001 40
```

**实测（手指按稳 40s，28.8 帧/s）**：
```
RED DC≈115952  ACpp≈2413(2.1%)  → 主频 1.12Hz = 68 BPM
IR  DC≈133323  ACpp≈1951(1.5%)  → 主频 1.12Hz = 68 BPM
```
两通道独立指向同一频率 → 确认为脉搏，静息心率 68 BPM，正常。
