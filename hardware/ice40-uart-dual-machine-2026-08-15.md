## 一、第一轮：三个 RTL 层真 bug（08-15）

### 1. 多驱动冲突

`push_pend`/`pop_pend` 被两个 always 块同时写——yosys 报 "multiple conflicting drivers"，综合出垃圾逻辑。

```
修法：单驱动纪律
    事件脉冲（rx_good/tx_req）由源块独占写、每拍自清零
    pending 标志只在结算块里写
    跨块信号全是寄存器
```

### 2. 索引写时序

`rx_data[rbit] <= rx` 的 8 路写使能解复用器 + 全局 CE 分布，拖垮 48MHz 时序。

```
修法：移位寄存器装载
    rx_data <= {rx_sync[1], rx_data[7:1]}   // 新位进 [7]，8 拍后 b0 落 [0]
    TX 同步改移位发出 tx_data[0] + {1'b0, tx_data[7:1]}
```

### 3. nwords 竞争

RX 入队和 TX 出队同拍相遇时，两个 `nwords <=` 非阻塞覆盖，计数漂移。

```
修法：统一结算点（块 3 独占写 FIFO，先消费 pending 再锁存新事件）
```

## 二、第二轮：板级侦查（08-16）——两天症状的全部线索

症状全集：上电一个乱码字符、之后打字不回显、绿灯心跳消失、TXD 按一下闪一下、RXD 常量蓝灯。

### 侦查 1：把 LED 当逻辑分析仪

D3 是 RGB 灯：ball 39 绿、40 红、41 蓝。把 `err` 输出接到 ball 40 当探针，换固件镜像不同内部信号：

```
err = tx           → D3 呈黄色（绿+红混合）= TX 线空闲高 → TX 机健康
err = rx_sync[1]   → 红色熄灭 = FPGA 眼中的 RX 线恒低 → 指向物理层
绿灯心跳消失        → rx_led 被连续翻转 = RX 在持续收到"有效"垃圾帧
```

"绿灯心跳消失"是决定性线索：它不是收不到，是**被垃圾流淹没**。同时否掉了"RX 线虚接"的方向——真虚接只会安静，不会翻 rx_led。

### 侦查 2：电压量测

CP2102 TXD = 3.49V（健康空闲高）；FPGA 端 P1_11 一度读到 3.49V/0.32V 跳动——换新线仍无改善。**教训：量到 FPGA 端才算数，中间接头的读数会撒谎。**

### 侦查 3：控制实验（决定性）

烧 2a：同线材、同引脚、回显正常 → 硬件无罪 → 问题在 2b 的设计与工具链之间。RTL 仿真三轮全绿而板级全败，中间只隔一层：综合。

### 结论

仿真对、板子错、硬件无罪 → 嫌疑落在综合网表。RTL 仿真验证的是"我写的意思"，板子跑的是"yosys 理解的意思"——这一层从未验证过。补上。

## 三、门级网表仿真方法论（可复用资产，已入 sim/ 目录）

### 工作流（Makefile 已内置）

```bash
make sim      # 第一层：RTL 压测（32 字节背靠背连发）
make gatesim  # 第二层：综合后网表仿真（真实参数 48MHz/104170ns 一位）
```

```
sim/top_sim2.v      RTL 仿真版：外部 clk 输入，CYCLES=48（=1000ns/位，等比缩放）
sim/tb_stream.v     压测台：无停止位间隔连发，逼出推弹同拍
sim/tb_gate.v       门级台：探针 + 采样器 + TX 波形逐位解码器
sim/cells_official.v 单元模型：yosys 官方 ice40 cells_sim（换掉 SB_HFOSC 为自振荡版）
```

### 五个坑（全部实踩）

```
① 网表 FF 上电值    手写模型漏了 initial Q=0 → x 锁死整条链
                    （x 经过 if 恒假，永远赋不上值）
② SB_DFFESR 语义    官方模型 E 罩 R：E=0 时 R 被忽略；
                    我手写成了 R 优先 → 门级仿真与真硅片行为分歧
                    （症状：tx_data[7] 在起始位被误清零，0xA5 变 0x25）
                    最终方案：直接用官方 cells_sim.v，只换 HFOSC
③ 探针读旧值        push_byte 与 rx_good 在网表里是不同 FF，
                    探针触发瞬间读到的还是上一拍 → 探针里加 #1
④ one-hot 编码      FSM 提取后 rstate 是 [4:0] 不是 [2:0]——正常，
                    但 default 分支的行为在重编码后彻底走样
⑤ 时间单位          $time 实为 ps、格式串写 ns 的旧坑继续有效
```

### 门级仿真抓到的证据链

```
RX 机时序完美但 rx_good 每 104μs 空触发一次   → default 之毒（bug 7）
tstate 上电即冲 3，nwords=0 也"弹出"          → 嵌套 case 之毒（bug 8）
TXDATA=0x25（0xA5 只清了 bit7）              → 模型语义坑（非设计 bug）
换官方模型后：TXDATA=0xa5→0x52→0x29→…→0x01→0x00 逐位正确
```

## 四、两个网表级主凶（板级两天不通的全部原因）

### bug 7：case 的真状态写成了 default

```verilog
// 错误写法——RTL 仿真里 default 与 4: 行为等价（5-7 不可达），看不出问题
case (rstate)
0: ... 1: ... 2: ... 3: ...
default: begin   // ← 这里其实是状态 4！
    ...停止位采样逻辑...
end
endcase
```

yosys 的 FSM 提取把 `default` 当"其余所有编码"处理，停止位逻辑被绑定到包括非法编码在内的一整片区域 → 机器在任何不匹配的编码下都执行停止位逻辑 → rx_good 每 5000 周期空触发一次 → 板级乱码与持续发送的全部来源。

```verilog
// 正确写法——真状态显式编号，default 只做防御
4: begin ...停止位采样逻辑... end
default: rstate <= 3'd0;   // 非法状态防御：绝不承载真逻辑
```

### bug 8：状态机 if/else 嵌套 case

```verilog
// 错误写法——外层 if 与内层 case 合并重编码时被抽坏
if (tstate == 0) begin ... end
else begin ... case (tstate) 3: ... 4,5,...: ... 12: ... endcase ... end
```

网表表现：上电 tstate 直冲 3——空 FIFO 也发送——RXD 常量蓝灯的来源。

```verilog
// 正确写法——单层完整 case
case (tstate)
0: begin ... end
3: begin ... end
4,5,6,7,8,9,10,11: begin ... end
12: begin ... end
default: tstate <= 0;   // 纯防御
endcase
```

## 五、完整 bug 清单（按发现顺序）

| # | Bug | 层 | 症状/证据 |
|---|---|---|---|
| 1 | push_pend/pop_pend 多驱动 | RTL | yosys 直接报错 |
| 2 | rx_data[rbit] 索引写 | RTL | 时序不过 |
| 3 | nwords 同拍竞争 | RTL | 计数漂移 |
| 4 | 移位方向位反转 | RTL | 0xA5 是位回文所以 RTL 验证被蒙混；ASCII 位反转后多为非打印字符=打字"无回显" |
| 5 | 上电幻影帧 | RTL | rx_sync 上电 00，!rx_sync[1] 恒真；五态机根治（先等空闲高再等起始边） |
| 6 | FIFO 推弹同拍 rptr 错进 | RTL | wptr==rptr 时同槽被回填，rptr 不前移 |
| 7 | 状态 4 写成 default | **网表级** | rx_good 每 104μs 空触发——板级乱码主凶 |
| 8 | TX 机嵌套 case | **网表级** | 上电空 FIFO 就发送——RXD 常量主凶 |

bug 4/5/6 的修法细节：

```verilog
// bug 4：新位进 [7]，8 拍后 b0 落 [0]；TX 侧 tx_data[0] 先出
rx_data <= {rx_sync[1], rx_data[7:1]};

// bug 5：五态机，中途不可能被字节内的 0 骗走
0: if (rx_sync[1]) rstate <= 1;          // 等空闲高（防上电幻影帧）
1: if (!rx_sync[1]) begin rstate <= 2; rcnt <= 13'd0; end   // 起始边
2: 半位等待  3: 8 数据位采样  4: 停止位采样（帧错误静默丢弃）

// bug 6：推弹同拍时同槽被回填，rptr 不前移
if (push_pend && pop_pend) begin
    fifo_mem[wptr] <= push_byte;
    wptr <= wptr + 4'd1;
    if (wptr != rptr) rptr <= rptr + 4'd1;
    ...
end
```

## 六、FSM 两条铁律（已进 FORGET）

```
① case 的真状态必须显式编号，default 只做非法状态防御，绝不承载真实逻辑
② 状态机用单层 case，不要 if/else 套 case
```

RTL 仿真无法区分"合法但危险"的写法——这两条违例都是语义正确、仿真通过、综合即坏。
