### iCE40 时钟源
**永远用内部 SB_HFOSC，别碰外部 STM32 MCO。**
内部振荡器 48MHz，稳定可靠——外部 MCO 烧录后可能不跑、可能频率不对。
CLKHF_DIV("0b00") = 不分频 = 48MHz。

### 引脚映射（PMOD1 → FPGA ball）
```
PMOD 物理孔 → FPGA ball（已验证）
  RX:  pin 2（对应 PMOD 上排第二个孔） → FPGA ball 2（= P1_11）
  TX:  pin 6（对应 PMOD 下排某个孔）   → FPGA ball 6（= P1_2）
  GND: 任一 GND 孔
```
**不要假设丝印 P4/P6 = FPGA ball 4/6。** 丝印 Px 是 PMOD 序号——不是 FPGA ball。

### MAX30102/30105 接线（PMOD2，2026-09-10 血泪）
```
SCL → P46（ball46）   SDA → P44（ball44）   VIN → 3V3   GND → GND
UART: tx → ball6（P6），接外接 CP2102 的 RXD
```
**PMOD2 丝印就是 ball 号**（P46=ball46, P44=ball44）。但**弯排针左右/前后镜像，极易看反**——
曾把 SCL/SDA 接到 P45/P43 上，白调半天。**接线后务必逐孔量电压确认**
（程序把某脚设成低电平时，对应孔应量到 0V）。

### PPG 实测踩坑（2026-09-11，指纹 8 小时的教训）
- ★ **板载 LED 会漏光进传感器**：iCESugar 的大绿灯/指示灯的光被 MAX30102 收进去，
  形成伪周期（自相关 r 掉到 0，HR 乱跳）。**把板子翻面 / 灯遮住**，r 立刻回到 0.8。
  **测 PPG 时环境光 + 板载灯都要挡。**
- **I2C 线接反（SCL↔SDA）**：传感器完全不响应、固件一字不发。
  用"固定发帧无 I2C"的固件（`uart_ping`）隔离——能发=UART/线好，问题在 I2C；不发=UART/线。
- **DC 是接触指标**：10~15 万=耦合好；<8 万=太松；≈26 万=饱和（压太狠或 LED 电流大）。看 DC 调接触。
- **压力**：按太狠→压闭血管（幅度掉）；太松→滑（运动伪迹）。**轻贴 + 胶带固定**最佳。
- **LED 电流**：7.2mA(0x24) 配轻贴正好；3.6mA 太弱（DC 缩一半）。
- **UART 波特率**：这块 CP2102 克隆 **9600 通、115200 不通**（现象：恒 `FE`/无数据）→ 统一 9600。
- **数样本时基**：IBI = 两拍间样本数 ÷ 采样率。HR 用**中位数/自相关**稳；
  **RMSSD 对峰位精度极敏感**（指尖 PPG 峰是宽平顶+重搏波 → 峰位 ±100ms 抖 → RMSSD 虚高）；
  改**长窗 SDNN**看趋势。

### UART 设计
**起步写法：单 always 块——单周期脉冲握手会漏。**
双机并行版（2b）已板级验证，可行——但必须守三条纪律：
```
① 事件脉冲由源块独占写（rx_good/tx_req），结算块独占写 FIFO 状态
② case 的真状态必须显式编号，default 只做非法状态防御，绝不承载真逻辑
③ 状态机用单层 case，不要 if/else 套 case
```
②③ 是 yosys FSM 提取的坑：RTL 仿真行为正确，综合后变成坏机器（2b 板级两天不通的全部原因）。
状态机：0 空闲 → 1 半起始位 → 2 数据位 ×8 → 3-12 发送位 → 0。
波特率：48MHz / 5000 = 9600。

### 烧板前两道关
**RTL 仿真验证意图，门级仿真验证综合——两层都过再烧。**
```
make sim       # RTL 压测（32 字节连发）
make gatesim   # 综合网表仿真（官方 cells_sim + 自振荡 SB_HFOSC）
```
门级仿真的坑：官方 cells_sim 的 SB_HFOSC 是白盒不振荡（要换自振荡版）；
FF 模型 E 罩 R（E=0 时 R 被忽略）——手写模型别搞错优先级。

### 布线
**CP2102 GND 必须接 FPGA GND。不接地 = 信号无参考电平 = 全乱码。**
千万不要把电源脚（3V3/5V）短路到 GND——烧 CP2102 或烧 FPGA。

### 电源隔离
iCESugar 和 CP2102 **各自独立 USB 供电**——不要共用一根 USB 线——CP2102 对供电质量敏感。

### 微小电流控制 + 人体内阻测量（tVNS 刺激侧，2026-09-14 记）
> 关联：`hardware/ecp5-i5/tvns-stim-circuit-v0-2026-09-13.md`（刺激电路）、`docs/feelings-science/tolerance-is-not-safety.md`（耐受≠安全）、`docs/architecture/frame-protocol.md` §5.7（0x26）

**A. mA 级微小电流怎么控**
```
① 用【线性】恒流源（op-amp VCCS / LM334 / LT3092）
   ❌ 别用给 LED/几百mA 设计的开关恒流模块——mA 级不准(offset/最小电流/纹波)
② 精度: 开环 = 基准电阻容差 + 源容差 + 温漂
        闭环 = 采样电阻测实际电流 + ADC 反馈 → 抵消漂移   ← 要准就走闭环
③ 电流源 ≠ 电压源: 电流源会自动【抬压】补偿负载 → 电流不变
   → 组件多不直接降压; 但【每个串联元件都吃 compliance】
④ ★ compliance 才是真约束: 皮肤阻抗 1–10kΩ+
   1mA × 5kΩ = 5V + L293D(~1.8V) + 源开销(~1V) ≈ 7.5V
   → 5V 电源根本推不动 → 电流掉下来(不是"组件多", 是"总阻超了源供电能力")
⑤ 解法: compliance 刚够(9–12V) + 独立硬限流(不经 MCU) + 测电流闭环
   ★ 抬压 = 抬风险(CC 失效 → 高压×低阻 = 大电流) → 硬限流必须独立
⑥ 决定"招不招深部纤维"的是【每相电荷 = 幅度 × 脉宽】, 不是"前沿陡度"
   → 卡【每脉冲电荷上限 + 脉宽上限 + 软启动】, 不是限斜率
```

**A·2. 恒流源与 H 桥的拓扑（2026-09-24 实测，重要）**
```
★ 恒流源必须【浮空串在 VCC2/VM 前面】：
    供应 → [恒流源] → VCC2 → H桥 → 负载 → GND
    VM 保持高，恒流源只"限制电流"。
❌ 不能【用恒流源替代 VM 供电】（低压侧采样 VCCS 会为限流把 VM 拖低）：
    · L293D(VCC2)：VCC2 被限流 → 达林顿高边基极被饿 → 高边压降 2.6V、不饱和 → 电流失控
    · DRV8833(VM)：VM 被拖到 <2.7V → 芯片直接不工作
→ 换 MOSFET 桥(DRV8833) 可"电流馈 VM"（不靠基极电流），5V 下闭环成立但精度 ~15%(余量窄)
正解：浮空恒流源(LM334/LT3092 / op-amp+三极管) + 9~12V 供电
```

**A·3. OVP 稳压管阈值怎么选（2026-09-24 记）**
```
· OVP 跨在电极两端，阈值要：略高于"正常工作电压"、远低于"损伤电压"
· 选低了 → 会【误钳日常工作电压】→ 把有效刺激削掉
· 选高了 → 永不导通 = 没保护
· 5V bench（电极 ≤3.5V）→ 用 5.1/6.2V 够高、当前不导通（正常）
· 9-10V 运行（电极可能到 ~9V）→ 换 ~12V（如 1N4742A）
· 两只【反向串】才能挡双相（单向管只挡一个方向）
```

**B. 人体内阻怎么测**
```
① 测电极对两端 V + 回流串采样电阻测 I → Z = V/I   (2 电极够)
   2 电极 = 总阻抗(接触+组织); 4 电极(Kelvin)才【分离】接触/组织 → MVP 不用
② 电极只是导体, 不"测"; 测量点就是【电极对】, 电子(差分+ADC)做测量
③ ★ 采样电阻在刺激侧回路里 → 测量必须【跨隔离屏障以数字形式】过
   (隔离放大器 AMC1300  或  岛侧 ADC + 数字隔离器 ISO1540)
   绝不能让刺激回路地连到采集地 → 隔离失效 + 危险
④ 做小 → 避【模拟隔离】(隔离放大器+隔离电源 B0505S 体积大、易漂)
   走: 隔离 ΔΣ(AMC1306, ~5×4mm) 或 岛侧ADC+数字隔离器 或 浮地不隔离
⑤ GND: 电池浮地时"GND 在设备内"成立(回路自包含, 无大地路径)
   → 但(1)刺激回流走专用路径 + 星地(防地弹污染 PPG/accel)
        (2)一旦插 USB/充电 → 隔离又要回来(防市电泄漏)
```

**C. 安全（和 A/B 一样重要）**
```
· 安全层用【比较器 + 锁存】(纯硬件), 不依赖 MCU/软件 —— 软件会挂, 比较器不会
· 耐受 ≠ 安全: 皮肤适应(不疼) ≠ 深部反射阈值提高 → 安全绝不依赖用户痛觉反馈
· 实测 I/Z 异常 → 0x3X 安全帧 → 硬件熔断
```

**D. 落地**
```
· 协议: 0x26 TVNS_EVENT 加 i_actual(u8) + z_load(u16) —— 命令 vs 事实(剂量验证)
· 架构: MCU 为主(脑: 采集/控制/闭环/通信) + FPGA 为辅(硬实时/多通道同步)
        + 独立硬件安全(比较器锁存, 不经软件)
```

### 烙铁教训：2232HL 报废——排针连锡 + 550°C + 锡太深（2026-09）
```
- CJMCU-2232HL 有两种：A 焊好排针成品（插接用）/ B 只有洞（要自己焊排针）
  我的 = B 版：2.54mm 过孔，要自己焊排针（不是密脚，不难）
- 真实死因（三个叠加，不是芯片坏）：
  ① 排针全短接（连锡短路）——锡堆成片，相邻针全连
  ② 550°C 烙铁温度太高——助焊剂瞬间烧焦失效，锡乱流
  ③ 锡焊太深太厚——吸锡带/松香都除不掉（热量不够/锡太多）
- 焊坏症状：插上 USB 灯都不亮 = 供电断（连锡短路拉垮）
- 排查顺序：①换 USB 线试 ②放大镜检查连锡 ③闻糊味/摸芯片烫不烫
- 教训：
  成品模块能插接就不焊；要焊先确认温度（含铅 340-360°C，不是 550）
  助焊剂必须有；锡少量；焊一个量一个；连锡趁热用吸锡带
- 替代：ST-Link V2 刷 CMSIS-DAP 固件可先顶上（见上）
```

### 焊 2.54mm 排针正确方法（防连锡）
```
1. 排针从板背面穿过洞，对角先焊两个孔固定（防歪）
2. 助焊剂/松香：所有孔涂一点（关键！让锡成球不连）
3. 每个孔烙铁沾一点锡点到孔上，锡自己流进去——够润湿就停，别堆
4. 连锡用吸锡带压走
5. 焊完万用表通断档量相邻孔 → 不通 = 没连锡，才上电
铁律：助焊剂必须有 + 锡少量 + 焊一个量一个 + 温度 340-360°C
上次失败原因：550°C 太高（助焊剂烧焦）+ 没助焊剂 + 锡一大坨 → 连成片
```

### SOIC-8 贴片焊接——温度/时间失控会把芯片焊伤（ISO7721，2026-09-23 踩）
```
现象：ISO7721 焊在 SOIC→DIP 转接板上。
      冷态：8 脚全开路（好的）；一通电发热 → pin 之间才短路（如 pin3↔pin4）。
      换脚、重焊都反复出现。
可能根因（两个，都要排）：
① ★ 芯片被【焊接热】打伤——冷态好、热了才短 = 硅片内部热缺陷
② ★ 【助焊剂残留漏电】——免洗/松香/助焊膏常温绝缘，但温度一高离子活性增强、
   绝缘电阻骤降 → 引脚间漏电，表现和"芯片内部热短路"一模一样（冷态好、热了漏）
   · 助焊膏(flux paste) 尤其易残留/吸潮，比免洗助焊剂更爱漏
   · 处理：无水酒精(IPA)+硬毛刷 把引脚间残渣刷净、晾干，再冷态+热态各测一次
     ——清完不漏 = 芯片其实没坏
叠加：之前还焊出过 pin6↔pin7 连锡（两输出互打，也会伤芯片）。

SOIC 正确焊法：
  · 温度 300–320°C（不是 350+，更不是 550——塑料封装扛不住）
  · 每脚 ≤2 秒，点一下就起，别反复拖/回焊
  · 助焊剂必上（成球、不连、导热匀）
  · 先焊对角两脚定位 → 再逐脚点
  · 烙铁接地、手先摸接地金属（防 ESD）
  · 焊完逐对量相邻脚（1↔2 … 7↔8）全 0L，且【掰一掰也不变】才算过

排查口诀：
  冷态就短           → 外部连锡，清（吸锡带+助焊剂）
  冷态开路 + 热态短路 → 先【清助焊剂残渣】再冷/热测；
                       清完还漏 → 芯片焊伤，换

省事替代：热风枪焊 SOIC 比烙铁好得多；或先拿废 SOIC 练手。
```

### 傻鸟设计吐槽（FG202 + CJMCU-2232HL）
```
- 板子全是洞、没标引脚——对丝印反推引脚跟猜谜一样
- MODE0/1 引脚做 10K 分压搞出 0.96V 中间态——既不高也不低，纯恶心人
- 外部 W25Q32 烧了配置根本不参与启动（从内置 Flash autoboot）——白烧
- 官方例程 cst 约束的 cell 名（R13C1_OBUF_A）和实际设计名（l1_OBUF_O）对不上——openFPGALoader 直接跳过约束
- CJMCU-2232HL 电源灯红但不枚举——D+/D- 不通，Micro-USB 座虚焊/线只供电
- openFPGALoader 的 Gowin 烧 Flash 报 "CRC FAIL" 但数据其实写进去了——误导排查方向
- SRAM 配置 Done Final 置位但 IO 全高阻——配置"成功"了个寂寞
```


### 双板 UART 帧协议
```
10 字节帧：8 字节数据 + 1 字节帧序号 (0-255 循环) + 1 字节 CRC-8-CCITT
GW1N 接收：先打两拍同步（跨时钟域） → 验证 CRC → 入 FIFO
5ms 看门狗超时 → 异步硬路径熔断 → 切安全锚点帧
```

### 过采样时钟
GW1N 板载 24MHz → rPLL 硬核 → 精准 7.3728MHz（16×460800 波特）。
不能强行分频——误差累积超 4.5% = 高位字节乱码。

### 不要跨时钟域发单周期脉冲
单周期脉冲从快时钟域到慢时钟域——概率极低被捕获。
要么拉长脉冲——要么用持续信号+握手——要么同域。
iCE40 内部用单 always 块避开了这个问题。

### 运动抑制 / ANC 的边界（2026-09-12 实测）
"用加速度对消 PPG 运动伪迹"（`tools/motion_anc.py`，NLMS）**只在轻度运动可能有用，别指望它救严重运动**。实测三档：

```
合成(纯正弦伪迹, 与 accel 完美线性相关) → 伪迹带降 97%、HR/SDNN 回理想  ← 假象
真实静止会话                            → 无脑跑 ANC 反而搞坏(SDNN 51→89、拍 125→92)
真实"猛动"会话(accel 0.84–1.37g)        → ANC 无效(SDNN 60→89、拍 87→113、伪迹带几乎没降)
```

四个根因（记住，别再走弯路）：
1. **运动太猛** → PPG 被运动主导，脉搏已不是主要成分，ANC 救不回；
2. **accel 只有 10Hz** → 参考带宽 <5Hz，真伪迹（手抖 8–12Hz）参考不到；
3. 真伪迹与 accel 的耦合是**非线性、时变**的，LMS 假设线性时不变；
4. ★ **参考与脉搏相关**（运动调制 PPG 的 DC/基线）→ ANC 把脉搏也消掉一块（经典 ANC 陷阱）。

另一条独立的坑：**静止时参考≈0 → NLMS 归一化分母趋零 → 权重发散 → 连脉搏一起消**。
→ 所以必须加"**运动门**"：无显著运动(<5%样本)整体跳过；逐样本只在"在动"时更新权重。

结论：**严重运动 → 质量门拦掉（正确做法），别硬救**；ANC 标注为"仅轻度运动、实验性"。
要真提升运动抑制，先把 **accel 提到 ≥50Hz**（像当初 PPG 提采样率），再谈算法。

### 调试技巧
- 先短路 CP2102 TXD-RXD 确认模块本身能回显——隔离"是 FPGA 的问题还是 CP2102 的问题"
- LED=rx 直接观察信号有没有到 FPGA
- 所有 PMOD 引脚用 GND 触碰——找到能控制 LED 的孔——那就是连到 FPGA 的脚
- 二分法调波特率分频——先找到"偶尔能打对几个字"的值——再微调

### 快速打字乱码
2b 版已有 FIFO16 吸收连发（32 字节连发仿真通过）——连发丢帧不再是单缓冲限制。
正常打字 100-200ms 间隔足够。若仍有乱码，先查 FSM 铁律与门级仿真。
