# MPU6050 接入 —— 与 MAX30102 共 I2C 总线（2026-09-12）

> 目标：给流固件加第二路传感器（加速度），为运动伪迹抑制打底。
> 关联：`max30102_stream.v`、`tools/hrv_monitor.py`、`FORGET.md`（PPG 踩坑）、`s0-collection-protocol.md`

---

## 一、接线（与 MAX30102 共用一条 I2C）

```
MPU6050  →  iCESugar
  VCC → 3V3
  GND → GND
  SCL → P46 (ball46)     ← 与 MAX30102 同一根
  SDA → P44 (ball44)     ← 同一根
  AD0 → GND              → 从机地址 0x68
  INT → 不接（本版轮询，不用中断）
```

要点：

- **两块模块都带 I2C 上拉**，并联后约 2.4kΩ，100kHz 没问题。
- 弯排针易镜像 → **接线后逐孔量电压**（同 FORGET 的 P44/P46 教训）。
- 地址：MAX30102=0x57、MPU6050=0x68，**不冲突**。

## 二、固件改了什么（`max30102_stream.v` v2）

```
1. I2C master 的 dev 从写死 7'h57 改成寄存器 i2c_dev（一主多从）
2. 配置表扩到 12 项：MAX 8 项 + MPU 4 项
     PWR_MGMT_1(0x6B)=0x00  唤醒
     SMPLRT_DIV(0x19)=0x09  → 100Hz
     CONFIG(0x1A)=0x03      DLPF 44Hz
     ACCEL_CONFIG(0x1C)=0x00 ±2g
   唤醒后等 50ms（MPU 上电时序）
3. 上电读 WHO_AM_I(0x75) → 发一帧，作接线自检
4. 主循环：每 10 个 PPG 样本读一次 ACCEL_XOUT_H(0x3B) 6 字节 → 发一帧（≈10Hz）
```

### 帧格式（PC 靠第 2 字节区分）

```
FE E1 + RED(3B)        100sps  PPG 样本（原有）
FE E2 + AX,AY,AZ(各2B) 大端 i16，±2g，16384 LSB/g，≈10Hz
FE E3 + WHO_AM_I(1B)   上电一次，期望 0x68
```

> 大端：`AX_H` 在前。UART 仍 9600；加 accel 后总带宽 ~580B/s（占 9600 的 60%）。

## 三、仿真验证（`sim/tb_stream.v`）

双从机模型（0x57 + 0x68，共总线）——从机模型加了 `selected` 门控，**未寻址的从机绝不驱动 SDA**（否则共总线会争用出 X）。

```
[FRAME] E3 WHO = 68  OK(0x68)
[FRAME] E1 RED = 01 21 31 ...
[FRAME] E2 ACC = AX=0102 AY=0304 AZ=0506   ← 与预置值一致
```

综合通过：`make TOP=max30102_stream` → `max30102_stream.bin`。

## 四、PC 侧（`tools/hrv_monitor.py`）

```
· 解析 FE E2：大端 i16 还原 AX/AY/AZ；|a| 偏离 1g > 0.1g 计为"运动"
· 解析 FE E3：打印 WHO_AM_I（0x68=OK，否则提示查接线/AD0）
· 实时行追加 ACC=(ax,ay,az)
· sidecar meta.quality.motion_pct = 运动样本占比
```

> ⚠️ 踩坑记录：DUT 发大端，PC 一开始按小端读 → 加速度全错（静止姿态 motion_pct=100%）。
> 已修（`(buf[2]<<8)|buf[3]`）。**固件/PC 的字节序必须对齐**。
