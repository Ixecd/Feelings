# 弱周期保护机制

> 作者：qc
> 日期：2026-04-22
> 核心：人变弱的时候，系统不施压、不刺激、只兜底——等待是最好的干预

---

## 一、为什么需要这份文档

```
人会变弱。这是生理事实，不是失败。

但很多人不敢承认变弱
    害怕被系统记录「我今天状态很差」
    害怕弱的时候还要被推送「你应该提升」
    害怕「低谷」被标记成某种需要修复的问题

Feelings 的立场
    弱周期不是需要修复的错误
    是需要被保护的状态
    系统在这个时候的任务
        不是推你振作
        不是给你「提升状态」的感受包
        是陪着你，什么都不做，等你自己回来
```

---

## 二、弱周期的识别

### 2.1 触发条件（满足任意一条）

```
综合能量指数（CEI）
    CEI < 35 持续超过 4 小时

睡眠连续异常
    深睡比例 < 10%，连续 3 天
    或总睡眠时间 < 5 小时，连续 2 天

HRV 持续压低
    HRV 低于个人基线 30%+，持续超过 8 小时
    非运动引起

生理信号综合异常
    以下三项同时出现：
        心率偏高（+15% 基线，非运动）
        皮电基线异常低（低于基线 20%）
        呼吸浅而不规则
    这个组合通常对应「麻木」或「情绪耗尽」状态
```

### 2.2 不触发弱周期的情况

```
以下情况不触发弱周期保护
    运动后的正常疲劳（信号会在 2 小时内恢复）
    单次睡眠不足（不是连续）
    可识别的高压事件中（比如重要截止日）
        系统识别上下文
        高压事件中的 CEI 低是「正常代价」
        不是「需要保护」的弱周期

识别逻辑
    弱周期 = 没有明确原因的持续低能量
    不是「有原因的暂时低谷」
```

## 三、弱周期中系统做什么

### 3.1 停止所有「提升」类推送

```
立即停止
    「你今天状态不如昨天，建议...」
    「基于你的数据，推荐这个感受包来改善...」
    「你已经 X 天没有达到基线，建议关注...」
    任何形式的「你应该做什么来变好」

为什么
    弱周期中的人最不需要的是被提醒「我很弱」
    「提升建议」在弱周期中会被感知为施压
    施压会加重疲惫感，延长弱周期
```

### 3.2 感受包推荐策略变更

```
弱周期中允许的感受包
    强度上限降低到 40（正常上限的 40%）
    类型限制：只推送「接纳」「平静」「存在感」类
    时长限制：单次不超过 20 分钟

不允许推送
    高唤醒类（即使用户主动要求）
    情绪释放类（可能加重不稳定）
    高强度刺激类

用户主动要求高强度时
    「你当前的状态建议不超过强度 40，
     坚持继续吗？（系统会全力保护，但效果可能和平时不同）」
    给一次确认机会，然后尊重用户的选择
    但把强度上限提高到 60，不是直接解锁
```

### 3.3 AI 教练切换到「陪伴模式」

```
普通模式的 AI 教练
    主动提问
    分析感受
    给出建议
    帮用户认识自己

弱周期的陪伴模式
    不主动发起对话
    用户开口，才回应
    回应风格
        不分析（「你现在可能是因为 X 导致了 Y」）
        不建议（「你应该去做 Z」）
        只是陪着（「嗯，你说的我听到了」）
        偶尔确认（「需要我做什么吗？」）
    
    不问「你今天感觉怎么样？」
    因为弱的人有时候不想回答这个问题
```

### 3.4 数据记录但不呈现

```
弱周期中的所有数据继续记录
    用于个人的长期趋势分析
    用于预测下一次弱周期的可能时间

但不呈现给用户
    弱周期中不显示「你的 CEI 今天是 XX」
    不显示「你今天的睡眠质量是 X 分」
    不显示与基线的比较数据
    
    只显示
        「你现在在休整期」（不说「弱周期」）
        「系统已经切换到轻量模式」
    
    为什么
        数字可能强化「我很差」的感知
        弱周期不需要量化，只需要陪伴
```

## 四、弱周期中的边界保护

### 4.1 防止「逼自己」

```
有些用户在弱周期中会强迫自己
    要求高强度感受包
    要求 AI 教练给「振作」建议
    忽略系统提示继续高强度工作

系统的应对
    允许用户覆盖建议（用户主权）
    但在覆盖前给一次明确的信息
        「当前状态建议轻量，
         强制高强度可能延长恢复时间。
         你确定要继续吗？」
    用户确认后，执行，不再重复提醒
    记录用户的选择（供长期分析）

不做的
    不反复提醒（一次确认就够）
    不评判「你为什么要这样对自己」
    不记录成「违规行为」
```

### 4.2 外部关系保护

```
伴侣模式中的弱周期处理
    进入弱周期时
    自动降低向对方传递的信号强度
    不是隐藏状态，而是「过滤」：
        传递：「对方现在需要安静」
        不传递：具体的生理低谷数据

用户可以选择
    完全暂停伴侣模式的感受共享（默认选项）
    维持共享但过滤低谷数据
    完全维持共享（用户主动选择）
```

## 五、弱周期结束的识别

```
退出弱周期的条件（满足全部）
    CEI > 45 持续超过 6 小时
    睡眠质量回到正常范围（深睡 > 12%）
    HRV 回到基线 ±15% 范围

退出时的系统行为
    不主动宣布「你的弱周期结束了！」
    静默切换回正常模式
    等用户自己发现状态变好了
    
    如果用户问「我现在状态怎么样」
    才告知「你的状态在过去 X 小时里持续回升」

为什么不主动宣布
    「弱周期结束」的通知本身会带来压力
    （「我终于好了，我之前一直很差」）
    低调退出，让状态的改善成为自然的感受，不是系统的结论
```

## 六、长期弱周期的处理

```
定义
    弱周期持续超过 14 天
    或同一个月内出现超过 3 次弱周期

系统行为
    继续执行所有弱周期保护机制
    不升级干预（不推送「你应该寻求帮助」）
    
    一次性、非强制的提示
        「过去 X 天你的状态一直处于休整期。
         如果你愿意，可以考虑和医生或心理咨询师聊聊。
         这只是一个提示，你随时可以关闭它。」
    
    只出现一次，不重复
    用户关闭后，不再出现
    不记录为「需要干预的问题」

为什么不强制
    长期低谷可能有很多原因（身体、生活、选择）
    Feelings 不是医疗干预系统
    把「建议看医生」做成非强制的一次性提示
    是尊重，不是漠视
```

---

*弱的时候，最好的保护是被允许弱。Feelings 不催促，不评判，只是在那里，等你自己回来。*
