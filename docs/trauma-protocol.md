# 创伤协议：Feelings 与心理创伤的边界

> 作者：qc
> 日期：2026-04-05
> 核心：Feelings 接收有心理创伤的用户，互补而非竞争，先试探后增强

---

## 一、基本立场

**Feelings 接收有心理创伤的用户。**

拒绝他们才是真正的风险——他们往往是「感受空白」最严重的群体，也是 Feelings 使命最直接的服务对象。但接收他们需要一套专门的协议，不能让他们走标准的解锁路径。

---

## 二、Feelings 与心理治疗的关系

**互补，不是竞争。**

```
心理治疗        话疗为主
                帮助用户建立对感受的认知框架
                理解创伤的来源和机制
                但停留在认知层面，缺少身体层面的锚点

Feelings        给认知框架一个神经层面的现实载体
                「治疗师说的那种「平静」，我现在知道它在我身体里是什么感觉了」
                从认知到体验的桥梁，不是替代
```

Feelings 不做诊断，不做治疗，不替代专业心理医生。

它做的事情是：在治疗师建立的认知框架之上，提供感受层面的验证和练习空间。

### 与治疗师的协作可能性

长期方向：允许持证心理治疗师创建「临床账号」，为特定患者定制感受路径。治疗师的访问权限和普通用户不同，可以在安全监测的前提下，为患者解锁更高强度的区间。

这条路需要严格的资质验证和滥用防护机制，是长期目标，不是初期功能。

---

## 三、创伤用户的识别

系统不做心理诊断，但需要识别高风险用户，触发创伤协议。

### 主动申报

注册时，用户可以选择申报：

```
「我目前正在接受心理治疗」
「我有创伤经历，希望系统给我更多保护」
「我不确定自己的状态」
```

申报是可选的，不申报不代表没有风险。但申报的用户直接进入创伤协议，无需系统识别。

### 被动识别

系统根据以下信号判断是否触发创伤协议：

```
使用行为信号
    反复体验高强度负面感受包（失去/恐惧/心碎）
    凌晨时段异常高频使用
    体验结束后的自省报告显示高度痛苦

生理信号
    多次触发安全体系的级别二及以上响应
    生理数据显示持续的高应激状态

音乐档案信号
    长期偏好极度低落情绪的音乐
    近期音乐行为突变（从正常到高度低落）
```

任意两个信号同时出现，系统轻提示：

```
「我们注意到你最近的状态有些不同。
 如果你愿意的话，可以告诉我们你现在的情况，
 我们会相应地调整陪伴你的方式。」
```

不诊断，不标签，只调整。

## 四、创伤协议的核心机制：先试探，后增强

创伤用户不走标准的渐进式解锁路径，走创伤协议专用路径。

### 第一阶段：锚定安全

```
强度上限        固定在 15 分（低于标准新用户的 30 分）
感受类型        只开放「平静」「归属」「被理解」三类
               全部是正向、稳定、低冲击的感受维度
会话时长        最长 10 分钟（标准用户无上限）
生理监测        最保守阈值，轻微偏离即提示
自省引导        强制开启，不可跳过
```

这个阶段的目标不是体验新感受，是建立「安全感受是存在的」这个基础认知。

### 第二阶段：边界探测

系统在锚定安全阶段积累足够数据（至少20次会话，基准稳定）后，开始边界探测：

```
方式
    在安全感受包的结尾，附加一个极短的（10秒）轻微压力刺激
    然后立即回到安全感受
    观察生理数据的反应和恢复速度

判断
    反应幅度在基准预期内，恢复快 → 可以进入第三阶段
    反应异常，或恢复缓慢 → 继续留在第二阶段
    触发级别三安全响应 → 退回第一阶段，记录
```

边界探测是无感的——用户不知道这10秒是「测试」，系统不告知。这不是欺骗，是避免期待效应干扰判断。

### 第三阶段：谨慎扩展

```
强度上限        缓慢提升，每次只提升5-10分，观察2周再提升
感受类型        逐步开放相邻维度（从「平静」到「释然」，而不是直接跳到「失去」）
生理监测        持续最保守阈值
异常响应        一次级别三响应 → 强度上限回退10分，维持4周
```

扩展的节奏远比标准用户慢，没有固定时间表，完全由数据决定。

## 五、异常时的援助机制

创伤用户体验过程中，触发级别三及以上安全响应时：

```
立即执行
    切换平静保底包
    终止所有非安全信号
    5分钟强制冷静期

冷静期结束后
    系统询问：「你现在还好吗？」
    提供三个选项：
        「我还好，想继续」
        「我需要休息」
        「我需要帮助」

选择「我需要帮助」
    系统提示预设的支持资源：
        用户自己设定的紧急联系人
        当地心理援助热线（根据地理位置自动提供）
        用户当前的治疗师联系方式（如果有记录）
    系统不拨打，不发送，只提示——最终动作由用户完成
    记录本次事件，标记为「需要关注」
```

### 紧急联系人设置

所有创伤协议用户，注册时强烈建议（不强制）设置紧急联系人：

```
紧急联系人可以是
    家人、亲密朋友、治疗师
    任何用户信任的人

紧急联系人的角色
    Feelings 不会主动联系他们
    只有在用户选择「我需要帮助」时，系统提示用户联系他们
    紧急联系人不会收到任何用户的感受数据
```

## 六、创伤协议的诚实边界

Feelings 能做到：

```
在安全环境里，让有创伤史的用户接触正向感受
为心理治疗提供感受层面的现实锚点
在异常出现时立即停止并提供援助资源
比标准用户更保守、更慢、更细致地陪伴
```

Feelings 不能做到：

```
诊断任何心理状况
替代专业心理治疗
保证不会触发任何创伤反应
在没有用户同意的情况下联系任何人
```

这两个清单都需要在创伤协议用户的初始设置中明确告知。

---

## 七、与心理治疗师的信息共享（用户授权）

如果用户同意，Feelings 可以生成一份给治疗师的简要报告：

```
报告内容
    用户在 Feelings 上体验的感受维度分布
    触发安全响应的频率和类型（无具体生理数据）
    自省报告中反复出现的关键词（脱敏处理）
    整体进展方向（扩展/停滞/退步）

不包含
    任何原始生理数据
    具体的感受包名称（保护用户隐私）
    任何不经用户授权的内容
```

这份报告是工具，帮助治疗师了解用户在感受体验层面的情况，配合话疗的方向调整。

---

*创伤协议是 Feelings 安全体系的延伸，也是 Feelings 使命最深处的体现：那些感受最空白的人，也应该有安全接触感受的权利。*
