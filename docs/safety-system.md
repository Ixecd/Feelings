# 安全体系设计

> 作者：qc
> 日期：2026-04-05
> 核心原则：平台尽到告知和保护义务，最终选择权归用户

---

## 一、安全哲学

Feelings处理的是人类神经系统的直接干预，安全不是功能之一，是整个系统的地基。

但安全不等于家长式的永久拦截。

Feelings的安全哲学建立在两个并行的承诺上：

```
对用户的承诺一    平台会尽一切可能保护你
对用户的承诺二    最终选择权是你的，不是平台的
```

这两个承诺不矛盾。平台的责任是确保用户在充分知情、真实感受过风险之后做出选择，然后在用户做出选择之后继续保护他。

**签了协议，安全措施不会松手。用户承担后果，不代表系统放弃保护。**

---

## 二、实时安全监测

所有体验过程中，设备持续采集生理数据，安全监测全程在线。

### 监测指标

```
心率            基线偏离幅度、骤升骤降、持续异常
皮肤电导        应激反应强度、持续时间
呼吸频率        过度换气、屏气
体温变化        外周血管收缩信号
运动传感器      设备是否脱落、用户是否失去意识
```

### 响应层级

```
级别一    轻微异常
          生理指标偏离基线但在可控范围
          系统记录，不干预，持续观察

级别二    中度异常
          多项指标同时偏离，或单项持续异常
          系统自动降低感受强度1-2档
          界面出现「是否需要暂停」的轻提示

级别三    严重异常
          生理指标触发安全阈值
          系统立即切换至「平静保底包」
          感受体验终止，进入冷静引导模式
          记录本次事件，影响后续解锁评估

级别四    极端异常
          设备检测到用户可能失去意识或无响应
          立即终止所有信号输出
          触发紧急联系人通知（用户预设）
```

### 保底包机制

任何时候触发级别三及以上，系统切换至「平静保底包」：

```
平静保底包
    强度固定在 5-10 分
    感受类型固定为「平静/安全感」
    持续时间 3-5 分钟
    音乐切换为低能量、低密度的稳定音乐
    不可被用户手动跳过
```

保底包不是惩罚，是系统在检测到危险时给神经系统一个安全的落地点。

## 三、渐进式强度解锁

强度不是付费解锁的，是耐受历史解锁的。新用户默认访问1-30区间，更高区间需要逐步解锁。

```
1-30      默认开放，所有用户
30-60     使用历史积累自动解锁
60-80     需要主动申请 + 生理评估通过
80-90     需要专项评估 + 知情确认
90+       不对普通用户开放
```

解锁不是单向的。如果用户在某个区间持续触发安全事件，系统会下调可访问上限，并给出原因。

## 四、犟种协议——给坚持的人

有一类用户，系统给出建议，他们选择对抗。

这不是坏事，这是人的自主性。Feelings的胸怀足够宽，不会因为用户不听话就永久拒绝他。但平台必须先尽到责任，再把选择权还给他。

### 完整流程

```
用户申请超出当前解锁范围的强度
    ↓
第一次拒绝
    告知原因（使用历史不足/生理评估未通过）
    给出建议路径（如何达到解锁条件）
    语气：平等，不说教
    ↓
第二次申请
    强制体验60秒预览包
        该强度区间的真实感受，不渐进，直接落地
        生理数据实时监测，触发级别三立即终止
    60秒后询问：「你确认继续吗？」
    此时的选择基于真实感受，不是对未知的对抗冲动
    ↓
第三次申请
    系统明确列出风险清单
    强制冷静期：24小时后才能再次申请
    冷静期内可以查看风险清单，不可提交申请
    ↓
第四次申请
    弹出「犟种协议」
```

### 犟种协议内容

```
在继续之前，请逐条确认：

□ 我已经了解此强度区间（X-Y分）的潜在风险
□ 我已经体验过该区间的60秒预览，知道接下来是什么
□ 我确认我当前的身体和精神状态是清醒且适合体验的
□ 我理解体验过程中设备会持续监测我的生理数据
□ 我理解系统在检测到危险信号时有权自动降档或终止体验
□ 我理解平台已经尽到了告知义务
□ 我自愿承担此次体验的后果

以上七条，需要逐条手动勾选，不支持「全部同意」一键勾选。
最后需要输入：「我已阅读并理解以上内容」

签署后解锁本次体验。
下次申请同一区间，流程重新开始。
```

### 关键约束

**协议签署不会降低任何安全措施的级别。**

用户签字，系统安全机制不松手：

```
实时监测    继续
保底包      继续待命
自动降档    继续执行
紧急联系    继续有效
```

协议解决的是告知责任的归属，不是安全机制的开关。平台在继续保护的前提下，尊重了用户的选择。

## 五、特殊用户群体的额外保护

### 新用户保护期

注册后30天内，强度上限固定在30分，不可申请解锁。

系统需要足够的数据才能评估个体耐受模式。30天是建立基础数据的最短时间。这不是惩罚，是系统在盲目开放之前先了解你。

### 高风险状态识别

系统根据使用行为识别高风险状态，并在此状态下降低可访问强度上限：

```
高风险信号
    凌晨时段的异常使用频率
    近期频繁触发级别二及以上安全事件
    音乐数据显示近期情绪状态异常低落
    连续多天体验高强度负面感受包

触发后
    系统轻提示：「我们注意到你最近的状态，今天先从低强度开始？」
    临时降低可访问上限
    不强制，用户可以选择忽略
    但忽略的行为会被记录，影响后续的安全评估
```

### 未成年人

设备激活时强制进行年龄验证。未成年用户：

```
强度上限固定在 20 分
不可申请解锁
不可使用犟种协议
监护人可设置额外限制
```

## 六、紧急停止机制

任何时候，用户可以通过以下方式立即终止体验：

```
物理方式    摘下设备（传感器检测到设备脱落，立即停止信号输出）
手势方式    设备预设的紧急手势（双击后颈设备三次）
语音方式    预设的停止词（用户自定义，默认「停止」）
App方式     界面紧急停止按钮，始终可见，不可被其他UI遮挡
```

紧急停止后：

```
所有信号立即停止
自动切换平静保底包（音乐继续，感受信号停止）
系统询问：「你现在还好吗？」
记录本次事件
```

用户可以选择继续（重新开始体验）、休息（保底包继续）、或完全退出。

## 七、数据记录与透明

所有安全相关事件完整记录，用户可以随时查看自己的安全历史：

```
查看内容
    每次体验的生理数据曲线
    触发过的安全事件记录
    历次强度申请和拒绝记录
    签署过的协议记录

用途
    帮助用户了解自己的耐受模式
    作为解锁申请的参考依据
    平台内部用于优化安全阈值

不用于
    任何形式的对外分享（即使脱敏）
    商业目的
    未经用户同意的任何其他用途
```

## 八、安全体系的诚实边界

Feelings的安全体系能做到什么，不能做到什么，需要对用户诚实：

```
能做到
    实时监测常见的生理异常信号
    在检测到危险时自动干预
    确保用户在充分知情后做出选择
    记录和分析安全事件

不能做到
    100%预测个体的神经系统反应
    完全防止所有不良体验
    替代专业心理或医疗评估
    在用户完全关闭生理监测时保护用户
```

极端故障场景（设备硬件故障、etcd脑裂类的系统级问题）需要人工介入，这一点我们诚实地写在这里，不用免责声明掩盖。
