## 已经讨论过的关键点（来自 2026-04-24 上午对话）

### 写法的三种可能

```
写法 A：Feelings 在中国语境下如何和当局相处
    处理具体国家的政府部门
    公安、市容、法院、检察院
    谈合规、备案、许可

写法 B：Feelings 和任何国家执法系统的通用原则
    适用于任何司法管辖区
    定义 Feelings 对所有政府的姿态

写法 C：Feelings 在面对极端情况时的边界
    搜查、传票、强制配合
    技术上做什么、不做什么

倾向：B + C 写进公开文档
A 不写进公开文档（属于各地区运营实体的内部合规）
```

### 几个未决的核心问题

```
问题 1
    某国法律要求交出神经数据
    Feelings 退出该国市场
    qc 接受这个代价吗

问题 2
    中国大区面临"中国法律 vs GOVERNANCE"冲突时
    选 A（配合）还是 B（拒绝并退出中国市场）

问题 3
    Feelings 配合法律请求的最大边界是什么
    哪些可以配合
    哪些必须拒绝
```

### 已经达成的共识

```
来自 GOVERNANCE 的相关红线
    数据不向任何机构报告任何用户的感受数据或行为模式
    包括但不限于
        执法机构
        监管机构
        政府部门
        私营企业
        保险公司
        医疗机构
        教育机构
        雇主

    强制神经刺激禁止
    不主动报警
    分布式治理（各地区独立运营实体）
```

### 已经明确的工程层面

```
搜查令/传票到来时
    Feelings 能交出
        法律程序要求的元数据
        链上可查的公开信息
    Feelings 无法交出
        原始神经信号（物理上不在服务器）
        原始感受数据（加密在用户设备 TEE 里）
        即使有法院命令也无法解密

关于"无法交出"的设计哲学
    不是"拒绝交出"
    是"技术上不持有"
```
