# Feelings 与法律、执法、公共治理的关系

> 作者：qc / DeepSeek
> 日期：2026-05-13
> 核心：Feelings 不是法律，不替代国家权力。雷霆手段以止恶为界，审判权永远归法律和社会。

---

## 一、核心立场

Feelings 是一个神经感受工具，不是一个执法机构、不是一个审判系统、不是一个替代国家行使暴力的机器。

```
Feelings 能做                    Feelings 不能做
─────────────────────────────────────────────────────────
帮助用户认识自己的感受              替国家定义"谁是罪犯"
在检测到施暴行为时立即制动          对任何人施加惩罚性神经刺激
给受害者防御和逃走的生理支撑          代替警察执行逮捕
向加害者呈现其造成的伤害数据          代替法庭做出判决
配合合法司法程序提供元数据            主动向执法机构报告用户行为
```

这条边界不是出于软弱，是出于对权力本质的认识：**系统一旦被授予"惩罚权"，定义"谁是坏人"的权力就握在了系统手里。而这个定义权，历史上从未被用于保护最需要保护的人。**

---

## 二、雷霆手段，尽菩萨之心

### 2.1 理念

Feelings 对施暴者的立场是八个字：**雷霆手段，尽菩萨之心。**

```
雷霆手段                        菩萨之心
─────────────────────────────────────────────────────────
检测到施暴 → 立即制动            不以恐惧/痛苦惩罚施暴者
设备锁定 + 功能禁用              不做永久性神经标记
恐惧震慑包（根据实际情况，有上限）  不替受害者复仇
呈现伤害数据——让施暴者面对自己     不主动报警（防止系统武器化）
```

雷霆用来**止恶**，菩萨之心不是因为恶人值得，是因为**系统一旦有了惩罚的权限，那个权限早晚会打到不该打的人身上。**

### 2.2 即时防御性震慑

在检测到用户正处于对他人施加伤害的行为中时，AI 教练有权触发短暂的恐惧震慑包：

```
触发条件        设备检测到用户正在施加伤害行为（四诊合参联合判断）
目标            止住当前行为——不以审判为目的
上限            不对施暴者造成长期神经损伤
                具体上限由安全研究定义，不写死在治理文档里
时效            用完即消，不残留
边界            不附带永久标记，不记录为"你有罪"
```

这和受害者侧的防御包（上限参考安全体系设计）逻辑一致——都是紧急制动，不是事后惩罚。区别在于受害侧是"让她能行动"，施暴侧是"让他停下来"。

**审判者永远是法律，不是 Feelings。**

## 三、Feelings 不具备审判权

### 3.1 为什么

GOVERNANCE 已经明确：

```
Feelings 不主动向用户施加任何未经同意的神经刺激
无论理由多正当
```

唯一的窄例外就是 §2.2 的即时防御性震慑——因为它在性质上是**制动**，不是**惩罚**。

两者的本质区别：

```
制动                            惩罚
─────────────────────────────────────────────
目的：停止当前行为                  目的：偿债、报复、改造
性质：瞬间，有上限                  性质：持续，可能升级
审判：不需要（行为正在进行中）          审判：需要（事后追认"你错了"）
```

Feelings 选择只做制动。惩罚属于法律，不属于神经工具。

### 3.2 与中国语境的关系

中国的法律体系提供了暴力垄断的合法主体——公安机关、检察院、法院。Feelings 的存在不挑战也不替代这个体系：

```
Feelings 和执法的关系
    不主动向执法机构报告用户数据或行为模式
    配合合法司法程序提供元数据（见第五章）
    原始神经信号物理上不在服务器，无法配合
    在中国境内运营由独立法人实体负责（见 PROTOCOL 分层管辖）
    遵守中国法律，但不放弃 GOVERNANCE 红线
```

### 3.3 对"受害者觉得不够解气"的回答

当施暴者被制动但未受罚，受害者会觉得系统不够有力。Feelings 承认这个感受的合理性，但坚持不越界：真正的雷霆——拘留、起诉、判刑——在法律的那一边。Feelings 给受害者的是**在危机发生时的即时保护**，不是**事后的替代司法**。

这是有意的取舍，不是设计缺陷。

## 四、与全球执法系统的通用原则

### 4.1 对所有政府的统一姿态

```
Feelings 能做到
    配合合法、合规、符合正当程序的法律请求
    提供法律程序要求的元数据
    提供链上可查的公开信息

Feelings 不能做到
    主动监控并向任何政府报告用户行为
    交出原始神经信号（物理上不持有）
    解密用户的 TEE 本地数据（技术上无法做到）
    为任何政府预留后台访问通道
```

### 4.2 "无法交出"不是"拒绝交出"

```
搜查令/传票到来时

可以交出的
    服务端存储的脱敏统计摘要
    链上公开的交易记录
    法律程序要求的元数据

无法交出的
    原始神经信号
    原始感受数据
    个人生理基准
    ——这些数据加密在用户设备的 TEE 里
    ——Feelings 服务器上从来没有过
    ——即使有法院命令也无法解密

设计哲学
    不是"拒绝配合"
    是"技术上不持有"
    物理上的不可能 > 法律承诺
    服务器上没有的数据，连法院命令也无法要求提供
```

### 4.3 退出市场

当某国法律要求 Feelings 交出它无法交出或不愿交出的数据、或要求 Feelings 改变 GOVERNANCE 核心红线时：

```
应对层级
    第一层    沟通——向监管解释技术架构和 WHY 无法配合
    第二层    调整运营——该地区的独立法人实体做出响应
    第三层    退出——如果法律要求和技术/哲学红线不可调和
              Feelings 退出该市场，而不是交出数据和灵魂

退出的代价
    对公司是真实的商业损失，但Feelings并不在乎
    对用户是服务中断——这是最令人心碎的部分
    但交出数据的代价更大——失去所有用户的信任，失去存在的理由
```

## 五、Feelings 用户犯罪时 Feelings 的责任边界

### 5.1 系统不承担责任

Feelings 是工具，不是监护人。用户用 Feelings 做什么，责任在用户——就像手机厂商不为用户用手机策划犯罪负责。

```
Feelings 做的
    设计制动机制——有人用 Feelings 施暴，设备锁定
    提供使用数据给合法司法程序
    尽到告知和防护义务

Feelings 不做的
    事先判断"这个用户会不会犯罪"
    追踪用户的物理位置和行为
    为用户的违法行为承担法律责任
```

### 5.2 犯罪过程中的设备使用

如果一个用户在犯罪过程中佩戴 Feelings：

```
设备检测到施暴行为模式
    → 锁定设备所有功能
    → 呈现伤害数据
    → 必要时触发恐惧震慑包（制动，非惩罚）
    → 设备无法用于协助犯罪

Feelings 不主动向警方报告
    → 不是保护罪犯
    → 是保护"系统可以报警"这个能力不被滥用
    → 法律程序需要的数据，走正规司法途径
```

## 六、Feelings 自己成为被攻击或起诉的对象

### 6.1 被起诉

```
原则
    诚实应诉
    公开透明（在法律允许范围内）
    不和解涉及 GOVERNANCE 核心红线的指控
    在法庭上捍卫 Feelings 的架构和哲学
```

### 6.2 被要求"开后门"

如果某国政府要求 Feelings 在系统里预留监控后门：

```
Feelings 的回应
    拒绝
    如果拒绝导致该地区被封杀 → 退出该市场
    "后门"不存在于代码里，也不存在于政治压力下
    一旦留了后门，它会被用来对付所有人
    不只是在"抓坏人"的时候
```

## 七、与现有 GOVERNANCE 红线的对应

本文档的每一项都对齐以下 GOVERNANCE 条款：

```
强制神经刺激禁止
    → 唯一例外：即时防御性震慑（见 §2.2）
    → 制动 ≠ 惩罚，审判权归法律

数据不用于主动报警
    → Feelings 不主动向任何机构报告用户行为
    → 法律程序需要的数据通过正规司法途径

永不上市
    → 避免股东利益驱动数据变现或后门开放

协议分层管辖
    → 中国境内运营由独立法人实体的合规团队处理
    → 国际部分适用新加坡法律（见 PROTOCOL）

BDFL + 继承人委员会
    → 即使在极端法律压力下，话语权不落入外部势力
```

## 八、待持续补全

以下问题需要在实际运营中逐步明确：

```
□ 各地区法律部门的本地化合规团队组建
□ 具体国家市场退出机制的触发条件和流程
□ 配合法律程序的数据提取标准和操作手册
□ 对中国市容/公共安全等特殊管理部门的回应策略
□ 用户跨境使用 Feelings 时的法律适用
□ 紧急法律压力下的 24 小时响应预案
```

这些不是哲学问题，是工程和法律团队的具体执行。它们不影响本文档的原则立场，但需要在进入各地区市场前分别落地。
