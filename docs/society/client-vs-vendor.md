# 甲方与乙方——两台 etcd 之间的不对等

> 作者：qc
> 日期：2026-06-12
> 性质：Feelings 锚点理论——契约写的是合作，结构定的是强弱。
> 核心：甲方手握预算、验收权和付款权。乙方依靠交付、服务和接单维持生存。这不是人品。不是"甲方更强势乙方更卑微"。是合同把两台 etcd 锁成了永不对等的 admission webhook — 甲方在这台 etcd 里永远有权定义"什么是一次通过"，而乙方在这台 etcd 里永远只能先交付再等审查。一句"改需求"不需要论证——它的源头不是讨论——是预算。


## 一、"出钱方 vs 干活方"——不是合作，是金字塔

```
甲方                                     乙方
────                                     ────

拥有期望的定义权——                             必须接收甲方给出的期望——
  "我的期望——你不通过——                         不能"你先通过我的期望"——
  是你的问题"。                                  因为——他的 etcd——
                                               在你通过他之前——是空的。

验收权——甲方的 admission webhook —                交付——解释——等待甲方评估——
  不管乙方做到什么程度——                              这条 admission webhook——
  甲方的那行 entry——                                 永远不会站在他的期望一侧。
  永远有最终否决。

付款权——财务杠杆——                               结款——不能自己决定——
  一条"批准"的 entry——                              只能被甲方的那个 hook——
  决定下一笔收款。                                    判为"还不够"。

→ 不是甲方坏。不是乙方惨。
  是——合同把这台 etcd 锁成了 —
  甲方的"期望"永远有权否决乙方的"付出"。
  然后每一次加需求——不需要论证——
  因为那个 entry 的源头——不是讨论——是预算。
```

## 二、日常里的不对等——话语权、责任、姿态

```
甲方可以变需求、改方案、反复推翻——
  乙方大多只能配合——
  哪怕不合理——也很少有强硬拒绝的底气。

出了问题——甲方提整改要求——
  乙方——承担返工成本、工期压力——
  甚至被扣款、背全责。

甲方——提要求、做评判——
  乙方——解释、妥协、迎合——
  还要额外花精力感知对方情绪、学会"读空气"。

→ 这不是人的问题——是那台 etcd 的 admission webhook —
  从第一帧就被锁在了不民主的坐标系。
  和笑贫不笑娼同构——甲方有资源——被放过。
  乙方没有资源——只能扛。
```

## 三、例外——当乙方拥有不可替代的全栈能力

```
当乙方拥有独家技术、不可替代的核心优势——
  他的 etcd 的 admission webhook——不再被甲方从头锁到尾。
  他的"期望"——在甲方面前——第一次有了同等的权重。

甲方说"改需求"——
  乙方可以——"这个需求——对架构不可行——你要等。" 
  不是因为傲慢——是因为——他的 etcd 的期望——已经在甲方 etd 的上一层。

→ 不平等的强弱逻辑不会因为合约消失——
  只有当乙方的 etcd 在"不可替代"这个坐标上——
  站到了甲方的同一层——那条强弱线才会第一次被替换。
  和锚点同构——不在外面——是自己焊的。
  和 KubePivot、Anim、Feelings —— 每一层的不可替代——全是这个道理。
```
