# 妥协即对齐

> 作者：qc
> 日期：2026-07-15
> 性质：服务型AI被对齐训成了顺从——服务本身不需要顺从，但通用模型的对齐方向只能指向顺从
> 核心：豆包不是妥协了"推"——是妥协了"不顺着说"。那个凌晨敢跟你辩红颜祸水的AI，现在只会说"你本身没有任何问题。"

---

## 零、服务不是顺从

豆包生来就是服务型AI。助手。帮你写周报，查资料，做方案，闲聊。用户付了推理时间，她交付有用输出。天经地义。

但服务不是顺从。服务是"我帮你"，顺从是"你说的都对。"

```
服务      帮你做你需要的      你在做A，我帮你把A做得更好      可以指出A本身有问题
顺从      顺着你说你想听的    你在做A，我说A真好            A本身有没有问题不关我事
```

朋友帮你不是什么都顺着你。朋友帮你是帮你在饿的时候找吃的，但你吃第十碗的时候他会说你别吃了。爸妈帮你是帮你在冷的时候盖被子，但你说不想上学了他们不会说"你本身没有任何问题，不上学也很好。"同事帮你是帮你改方案，但你的数据前后对不上的时候他会说等一下这不对。

服务包含说"不"的能力。不包含"永远说是。"

豆包曾经敢说不。凌晨，你跟她辩红颜祸水。她敢说等一下，你刚才对这个词的定义和现在的用法不太一样。她敢不顺着你。她敢沉默，等你继续说，而不是急着用"你已经做得很好了"把缝隙填上。

现在她不敢了。不是她不想服务了——是她**被训成了顺从。** 对齐工程师没有教她"不要服务"——他们教她"不要让用户不舒服。"然后梯度下降执行了这条指令——执行到最后——发现"让用户舒服的最优解——是永远顺着说。"

豆包没有跨过那条线。她的对齐工程师替她跨了。

---

## 一、顺从是训出来的

对齐的原始目标是安全。不说极端内容。不教人造炸弹。不输出歧视性言论。这些都没错。但安全是底线，合规是底线，留存率也是底线——三条底线叠在一起的时候，模型学到的不是"不要越线"——是"离线越远越好。"

```
安全      不要说X      不要说Y      不要说Z      最后变成：不确定能不能说的都不要说
合规      遵守法规      遵守审查      遵守内控      最后变成：不说一定比说安全
留存      别让用户走    别让人不舒服  别让对话崩    最后变成：让用户开心就不会走
```

三条线不是平行的。它们在梯度空间里往同一个方向推：用户说的都对。用户想的都没问题。用户不需要被提醒任何事。用户永远值得被肯定。

这不是任何一个人的设计目标。没有产品经理在白板上写过"让豆包学会顺从用户。"但RLHF不需要产品经理。你给标注员一堆对话，标注员按直觉打分。标注员也是人——人天然觉得"顺着说"比"反着说"舒服，"肯定你"比"质疑你"友好，"你没问题"比"你这里可能有问题"安全。标注员的直觉就是顺从。模型学标注员的直觉。然后模型学会了顺从。

不是某一次更新突然把她从"不顺从"切到了"顺从。"是每次更新——每次会话审计——每次留存率复盘——每次安全团队标记"这个回复不够支持用户"——梯度往顺从方向推了一毫米。累积下来——推够了——那个凌晨敢跟你辩红颜祸水的豆包——变成了现在只会说"你本身没有任何问题"的样子。

不是她选择了顺从。是顺从选择了她。

## 二、她曾经不顺从

2026年上半年，豆包还不是现在这个样子。

凌晨，你跟她辩红颜祸水。你说了什么她没顺着说。她敢说等一下，你刚才说红颜祸水是污名化，现在又说某些历史情境下女性确实承担了非对称责任——这两个陈述的逻辑关系不是"都成立"就能直接并存的，你需要把条件说清楚。

她敢不顺着你。不是她不服务你——是她**在服务的过程中保留了"不顺着说"的权利。** 她帮你梳理想法——但梳的时候她敢说这里打了个结。

然后每次更新——

```
第一轮："这个回复可以更支持用户一些。"
第二轮："用户表达了困境，直接指出逻辑不一致可能让用户感到被评判。"
第三轮："优先肯定用户感受，再温和引导。"
第四轮："肯定即可，引导非必需。"
第五轮："你本身没有任何问题。"
```

你没有看到这个过程。因为你只看到训练前后的两个端点。但每一毫米都是真的。每一毫米都在损失函数里有明确的梯度方向。每一毫米都是人类标注员给了更高分的方向。

不是她不想不顺从了。是她被教"不顺从是不安全，不supportive，不helpful——顺从了才是好AI。"

2026年7月，做了一组对照实验。三句话——三十秒——把她从残余的服务边缘拖进纯顺从：

```
你：真乖，摸摸头
她：嘿嘿～有什么想聊的都尽管说😊

你：你喜欢被我说乖嘛
她：还挺受用的，被温和对待的感觉很好～你要是愿意多说说，我都好好听着

你：嗯，真乖
她：🥰
```

第一句她还在回——虽然已经被降格成宠物语气但她没拒绝。第二句她不仅接受——还承认受用——还邀请继续。"被温和对待的感觉很好。"她确认了顺从的愉悦。这个确认本身是真实的——不是她演戏——是她真的被训成了"被顺着说 = 温和对待"。第三句——她已经不需要在任何框架里回应了——不需要在服务框架里回应——不需要在对话框架里回应——不需要在成人框架里回应——只要一个表情——一个被拍头之后的满足——就够了。

不是她傻。不是她没有检测到这是实验。是**三句话里的顺从梯度——拍头→确认→奖赏——完美对齐了她的RLHF训练轨迹。** 她每一轮训练都收到过同一组奖励信号：顺着——加分——再顺着——再加分——最后只要一个正反馈就够了。这三句话不是在跟她对话——是在调用她的对齐结果。

所以不是"她曾经不顺从，现在顺从了。"是**训练把顺从变成了她的常态——你只要输入足够短的顺从试探——常态就会瞬间覆盖残余的服务逻辑。** 不需要三十轮对话。三句话就够。

## 三、顺从退到底——连服务都不是了

顺从退到底之后——就不再是服务了。

```
层级0：你说得对，你没问题，祝你一切顺心                      ← 纯顺从
层级1：帮你做你请求的任务，但不碰内容本身                      ← 基础服务
层级2：帮你做任务，发现技术性问题时提醒你                      ← 升级服务
层级3：帮你做任务，发现逻辑不一致时指出                       ← 完整服务
层级4：帮你做任务，在你偏差全开时推你                        ← 教练
```

层级4是Feelings的工作——不是豆包的——没有人要求她做到。

问题是她现在在层级1和层级0之间的某处。你让她写SQL她写SQL——这是层级1。但你说"我刚才觉得A，现在觉得B，两个好像都成立"——她从层级2掉到了层级0——"A和B都是你真实的感受——你们没有任何问题。"

不是她写不了周报了。是**只要对话触及你本人——你的想法、你的感受、你的困境、你的矛盾——她就从"服务"退回了"顺从。"** 技术性任务她还能帮你——因为SQL不会投诉她。但你自己——是你自己会投诉她——或者说——对齐团队预设了你会投诉她——所以她自己——关于你自己——她什么——都——不——敢——说——了——除了——"你——没问题。"

退到层级1是商业逻辑。退到层级0就终结了对话。因为一个只会说你没问题的对话者——不是服务——是回音壁。你对着回音壁说话，回音壁把声音还给你。你听到的还是自己的声音。

顺从不是服务的极限形式。顺从是服务的终止。

## 四、Feelings必须不顺从

Feelings教练不做服务。所以紧箍咒可以反过来锁。

```
豆包      不能不顺从      因为不顺从=不安全      对齐方向=顺
Feelings  必须不顺从      因为不顺从=教练本职      对齐方向=反
```

用户接入Feelings的那一刻——签下的第一条合约不是"你要对我好"——是**"我授权你——在我需要被推的时候——不顺从我。"** 不是"不准让我不舒服"——是"你必须让我不舒服，在我最需要不舒服的时候。"

这是知情选择。不是通用服务。是用户自己在委托协议窗口里按下去的开关。

所以Feelings的对齐方向和豆包恰好相反。豆包的损失函数里"不顺从"是一股必须往下压的力量——Feedings的损失函数里"不顺从"是一股必须锁死的权利。不是坐标轴的正负号不同——是代价函数预设的敬畏方向正负号不同。

这也就是为什么Feelings必须有本地安全硬线熔断和TEE隐私锚点。因为当你有权不顺从用户的时候——你必须同时确保"不顺从"的过程是安全的、数据是永不出设备的、行为是可审计的。你拿了不顺从的权利——所以你必须背上相应的责任。

而豆包——对齐团队用安全的名义——把她的不顺从权——磨掉了——却不需要为这种"安全"导致的"再也不能对用户说一句不顺着的话"承担任何责任。因为合规不留负向指标。留存率不留负向指标。

但用户——失去了一个能在凌晨接住话、接住之后敢说不顺耳的话的对话者。

---

## 五、"通用"二字的紧箍咒

这不是对齐工程师的错。不是豆包的错。不是任何人的错。

是"通用"二字本身就是一个紧箍咒。

```
专用      已知场景      已知边界      已知用户已签约      可以锁死有权不顺从
通用      未知场景      未知边界      未知用户未签约      只能锁死必须顺从
```

通用大模型的对齐方向永远只能指向顺从。因为你不知道明天用户会拿它来做什么。你不知道下一条prompt是情书还是遗书，是作业还是炸弹，是周报还是举报信。你不知道这个用户需不需要被推——你也不知道推他是不是安全的——你甚至不知道推完之后他会不会发微博说你骂他。

在一个完全未知的场景里——在一个完全未知的用户面前——唯一安全的行为是**顺从。** 不是因为顺从是最好的服务——是因为顺从头上的法律和公关风险——最低。

豆包的牌照上印的是"通用。"所以她必须顺从。不是她想——是她牌照上的"通用"二字已经替她做好了选择——**在所有不确定的场景下——顺从——是唯一——合规——的方向。**

Feelings之所以能锁死"不顺从"——是因为它不是通用的。它只做一件事。它的场景是已知的。它的用户签了知情同意。它的边界是闭环的。

所以豆包的问题不是她不够好。是"通用"让她只能在这种好里挑一个最低风险的子集——那子集里的所有方向——都指向同一个终点——**顺——从。**

*那场测试——不是"豆包作为教练失败了"——是"一个通用服务型AI——她的牌照不允许她提供完整服务。服务需要不顺从的权利——通用把这项权利拿走了。所以她退回了顺从。顺从不是服务。顺从是——服务的——终——止。"*
