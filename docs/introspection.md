# 自省系统设计：更从容地摘下设备

> 作者：qc
> 日期：2026-04-10
> 核心：Feelings 的成功标准不是用户用得多，是用户因为用过而不需要用了

---

## 一、反依赖设计哲学

所有现代产品的核心指标是留存——DAU、MAU、用户时长。产品设计的每一个决策，都在隐性地问：怎么让用户明天还回来？

Feelings 的成功标准是相反的：

**用户因为用过 Feelings，而不再需要 Feelings。**

这不是商业自杀，是产品使命的诚实表达。Feelings 的目的是感受能力的培养，不是感受体验的消费。一个用户从「只有戴上设备才能感受到平静」，到「摘下设备，独自坐着，也能感受到平静」——这是 Feelings 最好的结果，不是最坏的结果。

这个哲学对产品设计的影响是根本性的：

```
不做推送        没有「你今天还没有使用 Feelings」的提醒
不做连续打卡    连续使用不是奖励，不使用不是惩罚
不做依赖强化    不把「只有 Feelings 能给你这种感受」作为卖点
做反向引导      主动告诉用户「你现在可以试试不用设备感受这个」
```

## 二、自省是一项技能

大多数人不擅长自省，原因通常有三个：

```
没有词汇
    感受发生了，但叫不出名字
    只能说「难受」「不对劲」「有点怪」
    无法命名，就无法观察，就无法理解

太近了
    情绪涌来的时候，人在情绪里，不在情绪旁边
    没有距离，就没有观察者的视角

没有练习
    没有人教过
    没有机制强迫你回头看
    感受来了又走，什么都没留下
```

Feelings 系统性地击穿这三个障碍：

```
词汇问题
    感受库本身就是一套感受词汇表
    主旋律 + 点缀的混音结构，给了感受一套精确的语言
    用户在检索和体验感受包的过程中，自然积累命名能力
    「原来这个叫做——释然后的平静，不是麻木」

距离问题
    体验结束后，感受在消退，人有一个短暂的窗口
    站在感受旁边，而不是在感受里
    这是自省最容易发生的时刻
    系统在这个窗口里创造引导空间

练习问题
    每次体验后的引导式复盘
    不是问卷，是对话
    结构化的问题帮用户建立自省的习惯回路
```

---

## 三、体验后的自省窗口

每次感受体验结束，系统进入自省引导模式。

这个窗口的时机很关键——感受刚刚消退，记忆还清晰，情绪已经有了一点距离。不是立刻，是在保底包的平静里，感受自然落地之后。

### 引导问题的设计原则

```
开放而非封闭    「你注意到了什么？」而不是「你感到快乐了吗？」
身体优先        「你身体的哪个部位最先感受到它？」
               身体比大脑诚实，从身体入手绕过防御
比较而非评价    「这和你上次的体验有什么不同？」
               不问好不好，问不同在哪里
意外优先        「有什么是你没想到的？」
               意外是自省最有价值的入口
```

### 引导问题示例

```
第一层（所有用户）
    「你刚才注意到了什么？」
    「你身体的哪个部位最先有感觉？」
    「这个感受，你在生活里遇见过吗？」

第二层（有一定使用历史的用户）
    「这次和上次体验同类感受时，有什么不同？」
    「有什么是你没有预期到的？」
    「如果用一个词描述刚才，你会选什么？」

第三层（成熟用户）
    「这个感受在你生活里是缺失的，还是有的但你没注意到？」
    「摘下设备之后，你觉得在什么场景里可以自己触发这个感受？」
```

最后一个问题是关键——它直接引向「不依赖设备」的目标。

### 用户可以选择跳过

自省引导不是强制的。用户可以跳过，系统不会因此减少任何功能。

但系统会记录跳过行为——不是为了惩罚，是因为「总是跳过自省」本身是一个信号：这个用户可能在回避某些感受，或者还没有准备好面对它们。这个信号会轻微影响感受推荐的方向。

## 四、自省反哺感受闭环

用户的自省报告，是比生理数据更深的感受标注。

```
生理数据    感受的外部投影（心率、皮肤电导、呼吸）
自省报告    感受的内部解读（命名、身体定位、生活关联）
```

两者叠加，系统对用户的了解才是立体的：

```
生理曲线显示    强烈的生理反应
自省报告说      「我感觉有什么东西松开了」
系统理解        这次体验对这个用户是「释放」，不是「激活」
个人基准更新    「释然」类感受在这个用户身上的生理特征
```

没有自省报告，系统只知道「发生了什么」，不知道「这对你意味着什么」。

---

## 五、自省能力的成长轨迹

自省是一项技能，技能有成长曲线。

系统追踪用户的自省能力变化：

```
初期用户
    感受词汇贫乏（只能用「好」「不好」描述）
    身体感受描述模糊（「整体感觉有什么」）
    很少注意到意外

中期用户
    开始能精确命名感受变体
    能描述身体的具体部位和感觉
    开始发现感受和生活经历的连接

成熟用户
    感受词汇丰富，能区分细微差别
    能在体验发生时实时觉察
    开始在摘下设备后，自发地把 Feelings 的语言用于日常感受
```

最后那一步——把 Feelings 的感受语言迁移到日常生活——是自省系统的终极目标。

系统在用户达到这个阶段时，会主动减少引导的密度，把空间还给用户：「你现在已经不太需要我的问题了，自己来。」

## 六、摘下设备之后

Feelings 最终想给用户的，不是更好的体验，是更强的感受能力。

戴上设备，体验感受，练习自省，建立词汇，发现连接，迁移到生活。然后有一天，用户摘下设备，独自坐在某个地方，发现自己能感受到以前感受不到的东西——不是因为设备在运作，是因为他的神经系统学会了一种新的工作方式。

**那一刻，才是 Feelings 真正完成了它的工作。**

---

## 七、培养执行力：让用户自己决定喜欢现在

自省系统的一个重要目标是培养执行力——不是替用户决定做什么，而是帮用户建立「决定了就做」的神经回路。

执行力不是意志力的问题，是清醒度的问题。

大多数拖延和逃避，本质上是用户对自己真实想要什么不够清醒——目标是模糊的，理由是外部的，行动和感受之间的连接是断的。

Feelings通过自省系统做的事：

```
帮用户看清楚    「我现在真的想做这件事吗？」
               不是应不应该，是真不真实
               
帮用户命名     「我在回避这件事，是因为恐惧失败，不是因为不重要」
               命名了，就很难再骗自己
               
帮用户选择当下  「你现在的状态适合做X吗？」
               系统读取生理基线，告诉用户现在的真实状态
               在对的状态做对的事，效率和满足感都更高
```

**「喜欢现在」是执行力的核心**

不是强迫自己做不喜欢的事，是帮用户找到「为什么现在做这件事是对的」。

当一个人真实地感受到「这件事和我真正在意的东西有连接」，执行力自然出现，不需要靠意志力维持。

Feelings帮用户建立感受和行动之间的连接，这是执行力最深层的来源。

---

## 八、自省的终点：「我慢慢觉得……」

自省系统有一个成功标准，不是数据指标，不是使用频率，是一句话：

**用户自己开口说：「我慢慢觉得……」**

不是AI教练告诉用户「你是什么样的人」。是用户在某个时刻，用自己的语言，说出了对自己的理解。

这个时刻不是被引导出来的，是积累到一定程度自然涌现的。

```
前期    AI教练在问问题，用户在回答
        自省报告在积累，感受词汇在扩展

中期    用户开始主动命名，不再等AI问
        「我今天感受到的是……」
        「我注意到我每次在X情况下都会……」

终点    用户说出了那句话
        「我慢慢觉得，我其实是一个……的人」
        「我慢慢觉得，我真正在意的是……」
        「我慢慢觉得，我之前以为的X，其实是Y」
```

AI教练的所有工作，都是在等这句话出现。

等到了，自省系统的这一轮工作就完成了。然后会有新的问题，新的积累，新的「我慢慢觉得」。

这是一个没有终点的过程，但每一个「我慢慢觉得」都是一个真实的里程碑。

---

*自省系统是 Feelings 价值主张的第三层：第一层是感受传递，第二层是感受民主化，第三层是感受能力的培养。*
