# 采集帧协议——从字节流边界到神经闭环的通信契约

> 作者：qc
> 日期：2026-09-10
> 性质：Feelings 设备间通信协议设计，不可降级
> 核心：iCE40↔ECP5 的帧协议——定长 TV 格式、设备分帧类型、持续/偶发分离、安全独立通道

---

## 零、先定前提

Feelings 的采集端（iCE40）和执行端（ECP5）之间，是一根串行链路（当前 UART，远期 SPI）。串行链路和 TCP 一样，本质是**字节流**——它不保留"消息边界"。

这意味着两个经典问题必然出现：

```
粘包    多帧的数据在接收端粘在一起，分不清哪到哪是一帧
半包    一帧被拆成两段到达，接收端收到半截
```

TCP 用序号/确认/重传/重组解决它，代价是 20–60 字节的头 + 握手 + 拥塞控制 + 状态机。Feelings 不需要交这份重税——链路短距可控、丢包率低，用**同步头 + 定长 + CRC** 这套轻量组合就够。

所以协议的目标不是"通用可靠传输"，是：**在一条可控的字节流上，用最小开销定出帧边界 + 校验完整性。**

---

## 一、为什么是定长 TV，不是 TLV、不是 TCP

### 1.1 粘包问题的四种解法

```
① 定长      每条消息固定 N 字节 → 数到 N 切一帧
② 分隔符    特殊字节/序列标记边界（如 '\n'、0x7E）
③ 长度前缀  消息头带长度字段 → 先读长度再收
④ 自描述    TLV / Protobuf / JSON（每段自带 Length）
```

### 1.2 Feelings 的选择：① + ② + 校验

```
[0xFE][0xE1]   ← 分隔符法（帧起点标记）
定长 N 字节     ← 定长法（读帧类型查长度表 → 数够切帧）
CRC-8          ← 校验（防误同步/污染）
```

### 1.3 为什么不用 TLV（带 Length）

```
TLV = Tag + Length + Value
  Length 存在的唯一理由 = Value 变长
Feelings 的 Value 定长（宽度由信号取值范围决定）+ 每帧类型段数固定
  → Length 冗余（Tag 已唯一决定该段多长）
  → 砍掉 Length → 只剩 Tag + Value（TV 格式）
```

TLV 是"变长消息"的粘包解法；Feelings 选定长，不需要它。TLV 的代价（每段多 1 字节 + 变长帧的状态机/鲁棒/重同步问题）在这里全部省掉。

### 1.4 为什么不用 TCP

```
TCP 的可靠是"重税"：20–60B 头 + 三次握手 + ACK/重传 + 拥塞控制 + 连接状态机 + 延迟
Feelings 的链路：短距、可控、丢包极低
  → 不需要 TCP 的完整机制
  → 安全靠看门狗 + 硬件熔断（比 TCP 重传更"硬"）
→ 轻量帧（CRC）换可控链路上的够用可靠
```

## 二、帧骨架

```
[0xFE][0xE1][帧类型][序号][Tag][Value]×N [标志位][CRC-8]
   ↑      ↑      ↑      ↑   └── N 段，每段 Tag(1B)+Value(变宽) ──┘  ↑      ↑
  2字节头  1字节类型 1字节序号(仅数据帧)                          标志位  全帧校验
```

```
字段          宽度        说明
同步头        2 字节      0xFE 0xE1，纯定界（解决粘包/半包）
帧类型        1 字节      分级编码，决定"用哪张 Tag 表 + 该帧长度"
序号          1 字节      仅数据帧；0–255 循环，丢帧诊断用
段（×N）      N×(1+W)     每段 = Tag(1字节) + Value(该信号宽度)
标志位        1 字节      仅数据帧；STIM/ARTIFACT/窗口/安全（见 5.6）
CRC-8         1 字节      多项式 0x07 / init 0x00；范围=从"帧类型"字节到 CRC 前一字节（同步头 0xFE 0xE1 不参与）
```

**每帧类型定长**：同一帧类型的所有帧长度固定；不同帧类型长度可不同（接收端按帧类型查长度表）。

---

## 三、同步头

```
0xFE      固定同步字
0xE1      第二同步字节（与 0xFE 组成 2 字节同步码）
```

**彩蛋**：`0xFE 0xE1` 读作 "FE/E1"——E1 的 `1` 形似 `L`，凑成 **FEEL**。
（原想写 `0xFE 0xEL` 直接拼 FEEL，但 `L` 不是合法十六进制字符——代码只能写 `0xE1`）

- 两字节都是**纯同步**，不承载任何元数据（不表示设备/长度/类型）
- 接收端在字节流里找 `0xFE 0xE1` 定位帧起点
- 误同步（载荷里正好出现 0xFE 0xE1）：靠 CRC 兜底——误同步位置收满一帧后 CRC 大概率不过 → 丢弃 → 重新找同步
- 半包：状态机收满该帧类型固定长度才校验；不完整则等待下一段
- **同步丢失恢复**：连续 N 帧（建议 3）CRC 校验失败 → 重置同步状态机、重新搜索同步头（防止链路噪声导致永久失步）

## 四、帧类型（1 字节，分级编码）

```
0x1X  数据帧
  0x10  耳后持续数据帧     N=4  (HR/HRV/温度/accel)
  0x11  腕部数据帧         N=2  (EDA/PPG)
  0x12  后颈数据帧         N=3  (EMG/运动/体温)
  0x13  颞部数据帧         N=?  (EEG)
  0x1E  偶发运动事件帧     (跌落/脱落检测)
  0x1F  SpO2 偶发帧        (可选)

0x2X  控制帧（中枢↔感官的协调）
  0x20  握手/注册
  0x21  session 启停
  0x22  配置下发
  0x23  ACK/NAK
  0x24  心跳/保活
  0x25  流控/背压
  0x26  TVNS_EVENT（刺激事件帧，见 5.7）

0x3X  安全帧（最高优先级）
  0x30  异常告警
  0x31  紧急停止
  0x32  熔断通知
  0x33  安全状态同步
```

**帧类型的三重作用**：
1. 区分帧的用途（数据/控制/安全）
2. 区分设备来源（0x10 耳后 / 0x11 腕部…）
3. 作为长度表的 key（读帧类型 → 查该类型固定长度 → 切帧）

## 五、Tag 与 Value

### 5.1 格式：TV（Tag-Value）

```
每段 = Tag(1 字节) + Value(该信号定宽)
Tag 不决定长度——长度由"帧类型 + 段位"确定（定长）
Tag 标明"这段是什么信号"
```

Tag 一个字节 = 256 种，够用。

### 5.2 Value 宽度由信号取值范围倒推

```
位宽 = ⌈log2(取值范围 / 精度)⌉
不拍脑袋给 8/16 位，从"这个量能到多少、要精确到多少"算
```

### 5.3 耳后持续帧 0x10 的段（范例，N=4）

```
Tag    信号    Value 组成                  宽度   范围 / 精度
0x01   HR      u8                          1B     30–220 bpm (1)
0x02   HRV     RMSSD(u16) + LF/HF(u16)     4B     RMSSD 0–6553.5ms(0.1)
                                                    LF/HF ×100 (0.01)
0x03   温度     u8                          1B     30–42.0°C (0.1)
0x04   accel   X(i16)+Y(i16)+Z(i16)         6B     按量程
──────────────────────────────────────────────────────────
载荷 = (1+1) + (1+4) + (1+1) + (1+6) = 16 字节
帧长 = 2(头) + 1(类型) + 1(序号) + 16 + 1(标志位) + 1(CRC) = 22 字节固定
```

**设计要点**：
- HRV 的 RMSSD 与 LF/HF **同源同周期、永远成对** → 合成一个 Tag 一段（不拆两个 Tag）
- accel 一个 Tag 打包三轴（不拆 X/Y/Z 三个 Tag）
- 持续信号 = 每帧必带，占固定段

### 5.4 编码公式（带偏移量，两端必须一致）

带偏移编码 = 用 1 字节覆盖窄范围（省空间），但公式必须写死：

```
信号            公式                      单位
HR            实际值 = 30 + Raw           bpm     (Raw 0–190 → 30–220)
温度           实际值 = 30.0 + Raw × 0.1   ℃       (Raw 0–120 → 30.0–42.0)
HRV-RMSSD     实际值 = Raw × 0.1          ms      (Raw 0–65535 → 0–6553.5)
HRV-LF/HF     实际值 = Raw / 100          无量纲   (Raw 0–65535 → 0–655.35)
accel X/Y/Z   i16 有符号原始值             g       (±2g/±16g 量程需另定标度)
```

⚠️ 不写公式 = 两端各自实现 → 偏移/标度对不上 → 解出错误的数。

### 5.5 帧序号（数据帧）

```
数据帧带 1 字节序号（0–255 自然循环），仅用于"丢帧诊断"
接收端：间隔 = (new - old) mod 256
  间隔 = 1  → 连续正常
  间隔 > 1  → 中间丢了 (间隔-1) 帧 → 记录丢帧率（不重传、不补齐）
  间隔 = 0  → 重帧/异常
不特殊处理循环跳变（255→0 是正常的，靠 mod 运算自然过渡）
```

### 5.6 标志位（数据帧，CRC 前）

```
标志位 1 字节，编码"帧状态 + 事件锚点"（定性标记）：

bit0  STIM      刺激锚点——本帧打 tVNS（ERP 锁时锚点）
bit1  ARTIFACT  数据质量无效（tVNS 伪迹等）——本帧 HR/HRV（及 EEG）不参与闭环计算，仅记录
bit2  PRE_BASE  预刺激基线窗口
bit3  POST_REC  刺激后恢复窗口
bit4  SAFETY    安全帧
bit5-7          保留
```

**三段窗口（tVNS + Ear-EEG）**：
```
刺激窗口    → STIM=1 + ARTIFACT=1（强电伪迹覆盖，数据不参与闭环，仅记录）
预刺激基线  → PRE_BASE=1（刺激前安静段，采集个体基线）
刺激后恢复  → POST_REC=1（电伪迹衰减后，采集 ERP / 频段响应 α/β/θ）
关心的是刺激后的诱发响应，不是脉冲瞬间的脑电
```

**锁时机制（不依赖绝对时间戳）**：
```
标志位给"锚点"（哪帧是刺激）
帧序号给"相对时间"（第几帧）
→ 刺激后 X ms = 刺激帧 + X 帧（帧周期固定）
→ ERP/频段分析：找 STIM 帧 → 按序号差值取 pre/post 窗口 → 跳过 ARTIFACT
→ 本地锁时不需要独立时间戳字段
（若将来需跨会话/云端绝对对齐，再另加时间戳字段）
```

### 5.7 TVNS_EVENT 事件帧（0x26）

tVNS 刺激事件独立成帧——它是 ERP 切片的**唯一时间锚点**（持续帧的 seq 不做 ERP 时间计算）。

```
payload = [absolute_tick(4B), stimulus_param(2B), multimode_mask(1B)] = 7B
帧长 = 2(头) + 1(类型) + 7 + 1(CRC) = 11B

absolute_tick   uint32   FPGA 本地 1ms 时基；刺激上升沿对齐该 tick
                         = ERP epoch 零点；4B → 49.7 天 @1ms（无回绕）
stimulus_param  uint16   高8位=电流编码 | 低8位=脉宽编码
multimode_mask  uint8    多模态参与位掩码
```

**stimulus_param 编码：**
```
高8位 电流：真实电流(mA) = code × 0.01   （内部用厘毫安整数，设备侧零浮点）
低8位 脉宽：真实脉宽(μs) = code × 1
  例：0x0F80 → 0x0F=15 → 0.15mA；0x80=128 → 128μs
0x0000 → 本次无电刺激（仅有其他模态）
注意：8位脉宽 ≤255μs；耳 tVNS 常用 50–200μs，够用（>255μs 需扩展版本位）
```

**电流三层（安全分层）：**
```
编码上限  2.55mA   8bit × 0.01，协议层可表（宽松）
硬熔断    1.8mA    出厂默认；支持个体化校准偏移，绝对上限 ≤2.0mA（防校准失误）
治疗上限  1.5mA    软配置（可调）
→ 协议宽松 + 硬件硬限 + 软配置；协议可下发大值，FPGA 硬熔断截断
```

**multimode_mask 位定义：**
```
bit0  TVNS_ELEC      tVNS 电刺激
bit1  TACTILE_PRESS  触觉压力
bit2  THERMAL        温度(冷/热)
bit3  BONE_CONDUCT   骨传导声学
bit4-7  保留（写 0）
例：仅电=0x01；四模态全开=0x0F；无电(温度+骨传导)=0x0C
```

**语义约束：**
```
① mask.bit0=0 → 即使 stimulus_param 非零，电刺激硬件不输出（忽略）
② absolute_tick = 刺激上升沿时刻 = ERP epoch 零点
③ 上层切片 [T0−200ms, T0+500ms]；持续帧用 seq 只做丢包校验，不做时间
④ 脉宽 >200μs 属高危 → 漏桶剂量状态机提升积分权重
⑤ HRV 走 uint16 rr_ms（RR 间期），脱离帧序号/tick 体系
```

**ERP 切片前提（实现要点）：**
```
接收端维护 ≥200ms 的持续帧环形缓冲（事件到达时 T0 前的数据已在）
且持续帧采样节拍与 absolute_tick 同源时钟（否则切片漂移）
```

## 六、持续帧 vs 偶发帧

Feelings 的信号按"时间特性"分两类，对应两种帧：

```
持续信号（每帧都带）  HR / HRV / 温度 / accel
  → 进持续帧的固定段（0x10，N=4）

偶发信号（偶尔/按需）  SpO2 / 跌落-脱落事件
  → 单开"偶发帧"类型，不占持续帧的固定段
```

**为什么偶发信号不塞进持续帧的空槽**：
```
塞进空槽 → 持续帧的段语义不再固定（某槽时而是 accel 时而是 SpO2）
         → 若宽度不同还会破坏定长
单开帧类型 → 持续帧纯净、定长；偶发信号各走各的帧
```

**这一模式可推广**：将来所有"偶尔测"的信号（校准、自检、事件）都走独立偶发帧类型。

## 七、控制帧——中枢↔感官

**先分清"控制"的两层**：
```
应用层控制（架构决策，设计时定）：
  中枢 = ECP5（跑 ESIR/漏桶/安全状态机）
  采集端 = iCE40（纯采集，附庸）
  输出节奏 = ECP5 自己的 ESIR 帧时钟（1ms）
  → 写进设计文档，不用运行时帧表达

协议层控制帧（运行时协调）：
  中枢把控制意图传达给采集端 → 这才是控制帧的活
```

**控制帧职责**：
```
下行（ECP5 → iCE40）：
  0x22 配置下发     采样率 / 分辨率 / 参数
  0x21 session      启停（start/pause/stop）
  0x25 流控/背压    处理不过来 → 让采集端慢点发
双向：
  0x23 ACK/NAK      收帧确认 / 错误码
  0x24 心跳          保活，判断对方活着
  0x20 握手/注册     设备注册 + 能力上报 + 协议版本协商
```

**ACK 规则**：
```
仅【控制帧】需要 ACK/应答
数据帧、安全帧 → 不做 ACK、不重传
  （与第十一节"不重传"原则呼应——避免实现时给数据流画蛇添足加确认，反而引入延迟）
```

## 八、安全帧——不走拥堵路径

**核心原则：安全信号绝不和数据帧挤同一条拥堵队列。**

```
默认：独立硬件引脚 + 脉冲宽度编码
  用不同脉宽表示不同安全状态（例：10%=正常 / 50%=警戒 / 90%=熔断）
  → 独立通道，硬件级，不经过数据流

引脚受限时（兜底）：
  总线硬件抢占式高优先级队列
  → 安全帧可抢占数据帧

真正的安全动作（熔断）：
  漏桶超限 + 看门狗 → 纯组合逻辑或门 → 直连输出引脚（~50ns）
  → 不经 CPU、不经 UART、不经帧
  安全帧只是"软件层的协同/通知/记录"（安全动作已由硬件做了）
```

安全帧类型（0x3X）：异常告警 / 急停 / 熔断通知 / 安全状态同步。

## 九、时间——硬实时在本地

```
刺激打点  完全在耳后设备本地执行（1ms 本地闭环）
  → 不跨设备 → 不需要跨设备高精度时间同步
  → 精确性落在耳后单设备内部

跨设备采集输入（EDA 等慢信号）
  → BLE 传输 ~7.5ms 延迟可接受（EDA <1Hz）
  → 帧带粗时间戳即可（用于关联/趋势，不要求 ms 级对齐）

边界：将来若出现"多设备协同刺激"或"跨设备实时闭环"
  → 才需要 device-architecture 里的 <1ms 精密同步方案
  → 当前不需要
```

## 十、设备信号集归属（一设备一套）

```
耳后设备   HR / HRV / 温度 / accel（N=4）+ 偶发(SpO2)
腕部设备   EDA / PPG
后颈设备   EMG / 运动 / 体温
颞部设备   EEG
皮肤阻抗   独立模块（AD5933）
呼吸       藏在 HRV-HF（RSA），不用另加传感器
```

**呼吸不需要独立传感器**：呼吸 → 心跳间期调制 → HRV 高频分量(HF, 0.15–0.4Hz)，耳后 N=4 的 HRV 已含呼吸信息，从 HRV-HF 提取即可。

## 十一、设计原则（汇总）

```
① 定长    每种帧类型固定长度（不取全局最大 N）
② TV 格式  无 Length——Value 定长 + 段数固定，Length 冗余
③ 持续/偶发分离  持续信号进固定段；偶发信号单开帧类型
④ 一设备一信号集  耳后 N=4、腕部 EDA…，不堆砌
⑤ 安全独立通道  独立引脚 PWM 编码；受限时总线抢占队列
⑥ 硬实时在本地  刺激打点在耳后本地，无跨设备精密同步
⑦ 位宽由范围定  位宽 = ⌈log2(范围/精度)⌉，不拍脑袋
⑧ 粘包三件套    同步头 + 定长 + CRC
⑨ 不重传        采集帧丢失无意义重传——下一帧很快到来，
                实时流里重传反而累积延迟；安全不靠帧重传，
                靠硬件熔断 + 看门狗
⑩ 仅控制帧 ACK  控制帧要应答；数据帧/安全帧不 ACK、不重传
```

### 12.2 决策与待定

```
已定：
· PPG 芯片：优先【单绿光 PPG】
  理由：HRV 对 PPG 波形质量极度敏感，绿光信噪比/抗运动伪迹最好
  （放弃红+红外双 LED 的 SpO2 能力——Feelings 不重视 SpO2）

待定：
· 各帧类型的确切长度表（0x11/0x12/0x13… 逐类算，遇到时填）
· SPI 远期切换（UART 当前够用）
```
