# 自有工厂：供应链主权与链上薪酬

> 作者：qc
> 日期：2026-04-20
> 核心：神经接入设备的供应链是安全问题，不是成本问题

---

## 一、为什么必须自己掌控供应链

Feelings 的硬件不是普通消费电子产品。

```
普通消费电子
    外包给代工厂（富士康/和硕等）
    成本低，效率高
    设计泄露了大不了重新设计
    这是可以接受的风险

Feelings 的硬件
    直接接触用户的神经系统
    硬件被植入后门 = 感受数据被窃取
    固件被篡改 = 用户安全红线失效
    供应链泄露 = 竞争对手复制核心传感器设计
    这些不是商业风险，是安全风险
```

**外包意味着把 GOVERNANCE 红线的物理执行交给了别人。**

代工厂不受 GOVERNANCE 约束，不理解 Feelings 的哲学，也没有动机保护用户的神经数据安全。

这条路从一开始就不通。

## 二、自有供应链的三个阶段

不是第一天就建完整的工厂。是按收入和需求，逐阶段建。

### 阶段一：手工组装（MVP 阶段）

```
规模        小批量，百台级别
人员        核心工程团队自己来
场地        实验室/工作室，不需要厂房
质控        每台手工验证，逐台测试

优点
    零固定成本
    直接积累生产工艺知识
    发现问题立刻修改设计
    每台都知道出自谁手

限制
    无法规模化
    产能天花板低
    这是验证阶段，不是量产阶段
```

### 阶段二：小规模自有生产线（初期市场阶段）

```
规模        千台级别
场地        租用厂房，购置关键设备
人员        招聘核心技术工人（传感器调试/质检）
            弹性用工负责辅助工序

关键工艺自控
    传感器校准
    神经信号采集模块组装
    固件烧录和验证
    整机安全测试

非关键工序可外协
    外壳加工
    包装
    但这些供应商不接触核心模块

薪酬
    核心技术岗位：月结，链上可查
    弹性岗位：日结或周结，链上可查
    所有工资从存储池划出，透明可验证
```

### 阶段三：完整自有供应链（规模化阶段）

```
规模        万台级别及以上
场地        自有工厂
人员        完整的生产团队
供应链      关键零部件供应商白名单
            供应商需要签署安全协议
            不得转包核心零件生产

这个阶段的触发条件
    收入稳定覆盖固定成本
    小规模生产线验证了工艺
    市场需求证明规模化有意义
    不是融资来了就建，是收入支撑了再建
```

## 三、薪酬体系：从存储池发工资

**这是 Feelings 薪酬设计最核心的一条。**

```
传统公司的工资
    公司账户里的钱
    老板/财务决定发多少
    员工不知道公司实际收入
    「公司最近不太好」是黑盒

Feelings 的工资
    从存储池划出
    存储池的进出全部链上可查
    员工知道钱从哪里来
    不存在「公司说了算」的黑盒
```

### 存储池是什么

```
Feelings 的收入来源
    硬件销售
    平台运营费
    感受包分成（平台运营费部分）
    存储服务利息收益

这些收入进入存储池
    存储池的余额和流水链上透明
    任何人可以验证

工资从存储池流出
    每次发薪都是链上的一笔转账
    有据可查，不可篡改
```

### 分层薪酬设计

**没有股权。Feelings 永不上市，股权对员工没有流动性，不用这套。**

```
核心技术岗位（月结）
    传感器工程师
    硬件安全工程师
    固件工程师
    质检负责人
    → 月薪，链上定期结算
    → 稳定性优先，这些岗位离职成本最高

弹性岗位（日结或周结）
    生产线组装工
    包装/测试辅助
    临时性项目支持
    → 完工即结，链上实时到账
    → 自由度优先，员工不被锁定

外部贡献者（按贡献结算）
    感受包创作者
    社区开发者
    文档贡献者
    → 按贡献链上分成
    → 没有雇佣关系，只有合作关系
```

### 为什么没有股权

```
传统公司用股权
    「你现在少拿钱，等上市了发财」
    这是用未来不确定性换现在的低成本

Feelings 为什么不这么做
    GOVERNANCE：永不上市
    股权没有流动性 = 给了也是废纸
    期权留人是画饼，Feelings 不画饼

Feelings 留人靠什么
    当期的、真实的、链上可查的报酬
    工作本身的意义（认同 Feelings 在做的事）
    高自由度（不用期权换，用自主权换）
    公平的分配（没有股东从中抽成）
```

## 四、员工自由度：具体是什么

「员工自由度较高」不是口号，是具体的设计。

### 工厂工人

```
排班弹性
    不强制固定班次
    工人可以选择工作时段（在产线运转范围内）
    日结制度本身就是最大的自由度——做多少拿多少，随时可以停

不强制长期绑定
    不签「不得离职」的竞业协议
    关键技术不掌握在单个人手里（知识必须文档化）
    任何人离开，工厂能继续运转

工作环境
    不设不必要的监控
    信任工人的基本判断
    质量问题追溯到流程，不是追责到人
```

### 工程师

```
远程/混合办公
    不强制每天到场
    结果导向，不是时间导向

副业自由
    工程师可以同时做其他开源项目
    只要不涉及 Feelings 核心机密
    Feelings 不买断工程师的全部时间

自主技术选型
    在边界内（Go/安全规范/文档先行）
    工程师自己决定技术方案
    不是「老板让用什么就用什么」

知识共享义务
    自由的对等条件
    你有自由，但你必须把知识文档化
    不允许「只有我知道这个系统怎么工作」
```

## 五、薪酬透明度与最大倍数

### 5.1 透明的粒度：岗位范围公开，不公开个人

```
链上记录的是
    每个岗位类型对应的薪酬范围
    结算规则（日结/月结/按贡献）
    总体薪酬支出（脱敏统计）

链上不记录的
    张三具体拿了多少
    李四今天的日结金额

每个人自己的薪酬记录
    自己可以完整查看
    他人只能看到岗位范围，看不到个人金额
```

**为什么这样设计：**

```
完全个人公开
    → 妒忌、猜测、人际内耗
    → 伤害的不是差距本身，而是「凭什么」说不清楚

完全不透明
    → 老板说了算，员工不信任
    → 违反 Feelings 的链上透明哲学

岗位范围公开
    → 每个人知道「这个岗位值多少」
    → 知道自己的上升路径和对应回报
    → 不会因为猜测而内耗
```

### 5.2 最大薪酬倍数：100 倍上限

**Feelings 内部，最高薪酬不超过最低薪酬的 100 倍。**

这个数字需要解释清楚——为什么是 100 倍，而不是 10 倍或无上限。

**为什么不是 10 倍：**

```
10 倍听起来"公平"，但它是虚伪的公平

顶级工程师的市场价格是真实的
    设计神经解码算法的人
    在市场上可以拿到很高的薪酬
    Feelings 如果付不起，他去别处
    Feelings 失去关键技术能力
    最终受损的是用户

10 倍上限 = Feelings 无法竞争顶级人才
    不是在保护基层工人
    是在让整个体系失去竞争力
```

**为什么不是无上限：**

```
无上限 = 差距可以无限扩大

在一个链上透明的体系里
    CEO 拿基层的 1000 倍
    这件事会被所有人看见
    组织内部会解体
    基层工人会感到被剥削，而不是被尊重

无上限不是竞争，是剥削
    Feelings 拒绝这条路
    GOVERNANCE 里的「恶的边界」同样适用于内部
```

**为什么是 100 倍：**

```
100 倍是一个诚实的中间位

它承认
    价值差异是真实的
    一个设计了核心算法的工程师
    和一条流水线上的装配工
    他们的市场价值本来就不同
    假装差距不存在，是虚伪

它拒绝
    差距无限扩大
    100 倍是上限，不是目标
    绝大多数时候实际差距远小于 100 倍

它鼓励
    体系内的良好竞争
    基层工人有明确的上升路径
    努力提升自己，差距是可以被跨越的
    100 倍的空间让「拼命提升自己」有真实的价值回报
    如果上限只有 3 倍，努力的动力就消失了

它保护
    组织不因为内部差距过大而解体
    100 倍以内的差距，在链上透明的环境下还能被接受
    超过 100 倍，则无论理由多充分，都会破坏内部信任
```

### 5.3 良好竞争是什么

100 倍的上限是为了鼓励竞争，但竞争必须是「良好的」。

```
良好竞争
    通过提升自己来获得更高回报
        学技能，从装配工升到质检工升到工程师
        做出真实贡献，贡献链上可查可验证
        让自己变得更有价值

    路径是透明的
        每个岗位的薪酬范围公开
        晋升标准明确
        不靠猜测，不靠关系

不是良好竞争的
    靠关系升职（链上贡献记录让这更难）
    靠打压别人获得优势（GOVERNANCE：没有受害者的恶系统不干预，但有受害者的恶，系统拒绝协助）
    靠信息不对称套利（薪酬范围公开，信息不对称减少）
```

### 5.4 让每一层的贡献都被看见

**控制薪酬比例只是一半。另一半是：不让贡献的「可见度」产生阶层差异。**

```
常见的错误
    工程师的代码被 changelog 记录
    算法突破被 README 表彰
    产品发布会上提到的全是技术团队

    工厂工人的贡献
    从未被提及
    「感谢所有员工」是空话

Feelings 的做法
    每台设备的生产记录链上存证
    经过了哪些工序，哪些人参与
    不是具体的「张三组装了这台」
    而是「这台设备经过了 N 道工序，N 个人参与了生产」

    不是表彰，是记录
    不是口号，是事实
```

## 六、工厂的治理原则

```
链上透明
    工资从存储池发
    任何员工都可以验证自己的薪酬和公司收入的关系
    不存在「公司亏损但老板发奖金」的可能

安全第一
    工厂里任何接触核心模块的岗位
    必须签署保密协议
    违反安全协议 = 立即终止合作

质量是底线
    不以产能压质量
    宁可慢，不能出不安全的设备
    质检不通过的设备，整批停产，不计产量

没有股东压力
    工厂不需要向季度报表负责
    产能扩张由收入驱动，不由融资驱动
    做多少，卖多少，收多少，发多少
```

## 七、和 GOVERNANCE 的关系

```
「关于开源」
    硬件协议全部公开
    工厂的生产工艺不一定全部公开（竞争壁垒）
    但硬件安全相关的部分必须开放审计

「关于资本结构」
    工厂投入从收入来，不从股权融资来
    不因为「需要建工厂」就接受有条件的投资

「关于数据」
    工厂工人不接触用户数据
    生产环节和用户数据环节物理隔离
    组装硬件的人不知道硬件最终被谁使用
```

## 八、一个长期愿景

```
Feelings 的工厂
    不是富士康的复制品
    不是「员工是机器」的流水线

是一个能让工人说「我知道我在做什么」的地方
    组装这个设备的人
    知道它会帮助用户感受世界
    知道自己的工作有意义
    这不是口号
    是「做对的事」的具体形式

最终
    这里的工人日结工资从链上到账
    知道自己的工资来自哪里
    可以随时选择离开
    但选择留下来，是因为认同这件事

这和感受民主化的哲学是一样的
    用户有感受的主权
    工人有劳动的主权
    没有人被锁定，没有人被剥削
    只有自愿的参与
```
