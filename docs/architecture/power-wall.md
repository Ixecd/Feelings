## 零、物理不站队

物理没有立场。它给所有计算设了同一道墙——热。

不管你是演化出来的脑，还是设计出来的芯片，每做一次运算，就产生一点热量。热量散不掉，运算就得停下来。这不分碳基硅基。这是宇宙规则。

```
演化    脑子 20W — 2% 体重 — 吃掉 20% 能量 — 不是不能再大，是散热跟不上了
工业    芯片 700W — 液冷系统 — 功耗墙 — 不是不能再快，是热量散不掉了
```

同一个公式。两种答卷。

---

## 一、脑子选了效率

大脑是人类已知最高效的计算机。二十瓦。一盏节能灯泡的功耗。但这二十瓦驱动了千亿神经元、百万亿突触，每秒处理十亿比特的感官输入。

```
大脑的效率来自两件事

    并行预处理    视觉、听觉、触觉、内脏——全部在皮层下同时跑
                意识只收到压缩后的那一滴——10 bit/s
                99.9999% 的运算不进入意识层——意识太慢了

    离子梯度不是晶体管    神经元用 ATP 泵维持钠钾梯度
                        一个动作电位 = 钠离子涌入 + 钾离子流出
                        没有焦耳热——热量来自 ATP 合成，不是电子的电阻
```

二十瓦的代价是 10 bit/s 的瓶颈。演化不是不会造高速意识——是有限热量预算下，把带宽全给了底层预处理。意识只需要知道结论。不需要知道推导过程。这是物理掩码的演化版本——不是有人在设计。是几十亿年的热力学约束雕刻出来的。

---

## 二、硅基选了性能

晶体管翻转产生焦耳热。每一次 0→1 或 1→0 的翻转，电子流过沟道→碰到晶格→释放声子→热。不可避免。这是物理。

```
从 5MHz 到 5GHz 的一千年

    1971    Intel 4004    740 KHz      ≈ 1W
    2000s   奔腾 4        3.8 GHz      ≈ 100W — 功耗墙第一次被撞上
    2010s   多核代        频率不涨了    热量散不掉，只能增加并行度
    2020s   GPU 集群      700W/卡      液冷成为标配
```

功耗墙不是一句口号。是一条物理曲线。频率每翻一倍，热密度翻超过一倍。散热技术跟不上。芯片可以设计成 10GHz——物理上能做。但运行几分钟就会烧毁。掩码就是掩码。不以任何人的意志为转移。

---

## 三、同一个墙，两种应对

脑选了降频。芯片选了加并行。最后殊途同归——脑停在 20W 不再涨了。芯片停在 ~5GHz 不再涨了。两条进化路线在物理掩码前碰了头。

```
脑                      芯片
──                      ──
选效率                   选性能
20W                     700W
千亿神经元并行            几千个 CUDA 核并行
10 bit/s 出口             每核宽度相同，无瓶颈
能自我散热（血液循环）      需要液冷（水比空气能带走更多热）
上限已被墙固定             上限正在被墙逼近

殊途同归。
都跑到了物理掩码允许的边界。
```

脑没有选择在更多热量下跑到更高速——因为它被卡在 20W 的墙上，被迫把带宽全给了预处理。芯片选择在更多热量下加更多核——因为它不关心 10 bit/s 瓶颈，它在一个不同的计算范式里。但热对谁都公平。

## 四、Feelings 停在刚好够

### 4.1 不是妥协——是巧合

FPGA 的 BRAM 零外部总线延迟，也零外部热量。安域 <100μs 不是靠把时钟拉到最高频——是靠中断直接触发，不经过调度器。后台预交织只在 Idle 时跑——前台感受域绝不被热量竞争挤占。

穿戴式设备不能烫皮肤。芯片的极限性能对 Feelings 没用。神经只需要 1ms 帧级。热量最低的那一层恰好是延迟最关键的那一层。这是物理掩码给你的唯一宽容——如果刚好够，就不用撞墙。

```
                内存延迟    中断→引脚   典型功耗   可穿戴？
x86 + Linux      ~50ns      ~10μs      15W+       ❌ 烫，不贴皮
ARM MCU (M4)     ~5ns       ~1μs       100mW      △ 温，紧张
FPGA BRAM+组合   ~5ns       ~50ns      15mW       ✅ 凉，零开销
```

热量最低的那一层 = 延迟最低的那一层。这不是权衡——是物理掩码在这个 1ms 窗口里给的对齐点。不需要在"为了低延迟而忍高热量"和"为了低热量而忍高延迟"之间选——小 FPGA 两个都拿走了。

### 4.2 安域的物理路径——不是软件看门狗

安全熔断跑在纯硬件路径上。GW1N 内部漏桶超限信号 + 5ms 看门狗超时信号 → 纯组合逻辑或门直连输出引脚 → 异步硬路径。没有中断向量表，没有优先级仲裁，没有时钟同步排队。

就是一根线。

```
NeuroEnergyTracker 漏桶超限 ──┐
                               ├── 或门 ──→ 输出引脚 (安全电平)
5ms 看门狗超时 ───────────────┘

不经过 CPU。不经过中断控制器。不经过任何可以被调度器抢占的路径。
```

软件看门狗能做的事，物理掩码说"不够快"——Linux 的 `panic_timeout` 从发现异常到实际断电可能隔了几十个 jiffy。硬件或门的 50ns 够让压电驱动器在下一个神经脉冲到达之前就已经被拉到安全电平了。

### 4.3 墙的另一面——撞上去会怎样

墙不是惩罚。是保护。它拦住的是"用更大芯片做更多功能"的本能冲动。

```
GW1N-4 (4.6K LUT)    ~15mW     皮肤无感，连续佩戴 12h 无热感
GW2A-18 (20K LUT)     ~50mW     微温，可接受，但已经开始有存在感
XC7A35T (33K LUT)     ~500mW    明显发热——皮肤接触面 >41°C，医疗红线
```

更大芯片 → 更多功能 → 更热 → 更不能戴 → 然后呢？失去了可穿戴性，再多 LUT 都是白费。墙逼你停在刚好够的地方——不是退而求其次，是在正确的位置停下来。

1ms 帧级 + 四维漏桶 + ESIR 预交织——HX1K 的 1280 LUT 和 GW1N-4 的 4608 LUT 够了。如果你需要比这更多的算力，大概率不是在为 Feelings 写代码——是在为"安全感"写代码。

### 4.4 后台预交织——占满 Idle，不碰前台

1ms 帧循环是硬实时：读传感器 → FSIR 转换 → 推 UART → 等下一帧。中间的空隙是 CPU 的 idle 窗口。

在这个窗口里跑的东西——AOT 仿真器预推下一帧 ESIR、分支预测器更新跃迁概率、阻尼矩阵 EMA 更新——全部属于后台。它们可以在 1ms 用不完，但不能在帧边界到来时还没结束。

```
─────────────────────────────────────────────────
│ 前台 (硬实时)  │ 后台预交织 (idle 填充)  │ 前台 │
│ 读传感器 200μs │ AOT 仿真 300μs          │ ...  │
│ FSIR 50μs      │ 分支预测 100μs          │      │
│ UART push 50μs │ 阻尼更新 100μs          │      │
│──────── 300μs ─│────── 500μs ────────────│      │
│                │←── 剩 200μs 余量 ──→    │      │
─────────────────────────────────────────────────
             1ms 帧边界                       1ms
```

AOT 仿真跑不完怎么办？不跑完。下一个帧边界到来时，预交织直接丢半成品——前台的中断优先级比后台的"优化效果"高一个数量级。

这不是 CPU 的时间片轮转。这是硬实时调度的第一原则：前台感受域绝不被热量竞争挤占——cpu 算力是热量的代名词，idle 是散热窗口，不是性能浪费。

## 五、最后

物理掩码不是阴谋。不是阻力。是规则。热就是热。不管你是什么做的——1 焦耳的热量比 0 焦耳的热量更接近系统的上限。接近不等于撞上。刚好够是最优位置。不需要更快。只需要刚好快过神经，刚好冷过皮肤。
