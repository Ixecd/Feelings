## 一、两路输入——同一个 PBM

```
生理数据通路                              对话数据通路
───────────                              ──────────

五设备传感器                               AI 教练对话记录
→ 耳后：PPG + 温度 + 加速度                   → 用户在对话中的语言模式
→ 腕部：EDA + 温度 + PPG                       → 词汇选择、句式变化
→ 后颈：EMG + 加速度 + 低频振动反馈              → 响应延迟、话题回避模式
→ 颞部：EEG（4-8 通道干电极）                    → 情绪标注一致性（自报告 vs 语言推断）
→ 飞行陪伴体：摄像头 + 麦克风                      → 场景上下文、面部表情、语音韵律

原始信号                                       原始文本/音频
↓                                              ↓
ADC + PLL 时钟同步                               NLP 特征提取
↓                                              ↓
片上预处理（滤波/去伪影）                          心理状态推断（焦虑/防御/开放/回避）
↓                                              ↓
特征提取（HRV/EDAtonic/EEG band）                置信度标注
↓                                              ↓
设备加权融合                                    独立通道——权重低于生理数据
↓                                              ↓
                    └────────┬────────┘
                         四诊合参融合层
                         （矛盾检测 → 生理优先）
                              ↓
                         一帧 PBM 输入向量
```

两路输入在 PBM 入口之前是**完全独立**的。它们各自有自己的采集频率、预处理逻辑、置信度。融合只发生在最后一步——而且四诊合参的铁律是：**生理数据和对话数据不一致时，生理数据权重更高。**

## 二、生理数据通路——从传感器到特征向量

### 2.1 五设备采集矩阵

```
设备          传感器              采集信号          采样率     分辨率     数据量/帧(1ms)
────          ────                ────────          ────       ────       ─────────
耳后(主)      PPG(红外+绿光)       心率/血氧/HRV      250 Hz     16 bit      0.5 B
              接触式温度           皮肤温度           10 Hz      12 bit      ~0.01 B
              3轴加速度            头部运动           100 Hz     12 bit      0.4 B

腕部          EDA(干电极)          皮肤电导           100 Hz     16 bit      0.2 B
              PPG                  心率(辅助)         100 Hz     16 bit      0.2 B
              接触式温度           远端体温            1 Hz       12 bit      ~0.001 B

后颈          表面EMG              斜方肌张力          500 Hz     12 bit      0.75 B
              3轴加速度            体态/头部倾斜        100 Hz     12 bit      0.4 B
              低频振动执行器(输出)  本体感受刺激          
              
颞部          EEG(4-8通道干电极)   Fp1/Fp2/F7/F8     250 Hz     24 bit      2-4 B
              接触式温度           颞部皮肤温度         10 Hz      12 bit      ~0.01 B

飞行陪伴体    摄像头(30fps)         面部表情/场景        —          —          压缩后 ~5-15 KB/帧
              麦克风(16kHz)        语音/环境音          —          —          压缩后 ~2 KB/帧
              ToF距离传感器         用户距离            30 Hz      12 bit      ~0.04 B
```

**每帧（1ms）生理数据总量（不含飞行陪伴体）：约 4-7 字节。** 飞行陪伴体的视频/音频不在硬实时路径上——它们走独立的压缩和异步上传通道，只在四诊合参融合时取最后一帧的推理结果（"用户在微笑"、"环境嘈杂"），而不是原始像素。

### 2.2 时钟同步——PLL 主时钟

```
Feelings-OS timerd (PLL 锁相环)
    主时钟脉冲：1ms 周期
    ↓
busd 广播 Epoch 序号 + 硬标签
    ↓
每个设备在收到 Epoch N 的脉冲时——
    锁存当前传感器读数
    打上 Epoch N 的硬标签
    放入本设备帧缓冲区
    ↓
busd 在 Epoch N+1 轮询所有设备——
    收集所有标有 Epoch N 的帧
    校验硬标签（拒收延迟帧）
    ↓
    交给融合引擎
```

时钟偏差容忍：±50μs。超过此偏差的设备帧——busd 拒收。该设备在那一帧被视为"缺失"，融合引擎用上一帧的该设备数据做插值——标注为"降级"。

### 2.3 片上预处理——在设备端完成

原始 ADC 数据不离开设备。每个设备在本地做：

```
PPG 预处理
    带通滤波 0.5-5 Hz（去除呼吸漂移和运动伪影）
    峰值检测 → RR 间期序列
    HRV 时域特征：SDNN / RMSSD（滑动窗口 30s）
    频域特征（可选，计算量大）：LF/HF 比值

EDA 预处理
    低通滤波 1 Hz
    分解为 tonic（皮肤电导基础水平，缓慢变化）和 phasic（快速波动，事件相关）
    tonic：滑动窗口 10s 的中位值
    phasic：当前值 - tonic

EEG 预处理
    带通滤波 1-40 Hz
    陷波滤波 50/60 Hz（工频干扰）
    伪影检测：眼动/肌电/电极位移 → 标记为不可用
    频带分解：δ(1-4), θ(4-8), α(8-12), β(12-30), γ(30-40) Hz
    输出：各频带相对功率 + 额叶 α/θ 比值

EMG 预处理
    带通滤波 20-200 Hz
    均方根包络 → 肌肉张力指数
```

**预处理后的数据才离开设备。** 原始 ADC 流永远不离开设备。GOVERNANCE 红线——"原始神经信号和生理数据永远不离开用户设备"——这一层就已经执行了。

### 2.4 特征向量——PBM 可接收的格式

每一帧（1ms），融合引擎收到的生理数据特征向量：

```
Frame {
    epoch: u64,                    // PLL 时钟序号
    
    // 心血管（耳后 PPG）
    hr: u8,                        // 瞬时心率 bpm
    hrv_rmssd: f16,                // HRV 副交感指标
    hrv_lf_hf: f16,                // 交感/副交感平衡
    
    // 皮肤电（腕部 EDA）
    eda_tonic: f16,                // 基础水平
    eda_phasic: f16,               // 事件相关响应
    
    // 额叶 EEG（颞部）
    eeg_alpha_power: f16,          // 放松/闭眼
    eeg_theta_power: f16,          // 专注/记忆
    eeg_alpha_theta_ratio: f16,    // 认知负荷指标
    eeg_artifact_flag: bool,       // 伪影——此帧 EEG 不可用
    
    // 肌肉（后颈 EMG）
    emg_tension: f16,              // 斜方肌张力（压力指标）
    
    // 运动（加速度融合）
    head_motion: f16,              // 头部运动强度
    posture_angle: f16,            // 头部前倾角度
    
    // 温度
    ear_temp: f16,                 // 核心温度近似
    wrist_temp: f16,               // 远端温度（外周循环指标）
    
    // 元数据
    device_mask: u8,               // 哪些设备在这一帧在线（bitmap）
    degraded: bool,                // 是否有设备缺失/插值
}
```

## 三、对话数据通路——从 AI 教练对话到心理状态推断

### 3.1 为什么对话数据也是生理数据的一种

用户和 AI 教练的对话——不是"聊天记录"。是**行为采样。** 每一次对话都是用户在特定心理状态下产生的语言行为样本。同一个问题在不同心率下回答——语言模式完全不同。

```
对话特征                                    对应生理相关
───────                                    ──────────
词汇多样性下降 + 句式变短                      交感神经过度激活（前额叶被抑制）
回避特定话题 + 话题频繁切换                     杏仁核激活——威胁检测跑满
自报告情绪 vs 语言推断情绪不一致                  岛叶/前额叶连接弱——自我感知准确性低
回应延迟增加 + 自我修正增多                      前额叶在前一帧被情绪劫持后恢复中
语气从陈述句变为疑问句（"是吧？""可能吧"）           不确定性——当前评分函数里多个选项权重接近
```

对话数据不能替代生理数据。但它能给出生理数据**给不出的东西**——用户在哪个话题上紧张、在哪个词上犹豫、在哪种场景下语言模式开始漂移。生理数据说"你紧张了"。对话数据说"你在说到你妈妈的时候紧张了"。

### 3.2 对话特征提取——不是 NLP。是行为分析。

```
输入：用户在当前 Session 中的对话文本 + 语音韵律（如果有飞行陪伴体）

特征提取（本地——文本不离开设备）：
    词汇层
        词汇多样性（TTR，type-token ratio）
        情感词密度（正/负/中性比例）
        第一人称 vs 第三人称代词比例
        模糊性修饰词占比（"可能""也许""不太确定"）
        
    句式层
        平均句长变化
        疑问句 vs 陈述句比例
        自我修正标记（"不是……我是说……"）
        重复模式（同一个词/短语在短时间内的重复）
        
    韵律层（需飞行陪伴体麦克风）
        基频变化范围
        语速变化
        停顿位置和时长
        呼吸模式（从语音间隙推断）
        
    交互层
        回应延迟
        话题切换频率
        问题回应的完整性（回答了 vs 回避了 vs 反问）
```

### 3.3 心理状态推断——置信度标注

```
从对话特征 → 心理状态标签 —— 不是断言。是带置信度的推断。

推断                    特征模式                                     置信度来源
────                    ──────                                       ────
焦虑状态                 词汇多样性↓ + 疑问句↑ + 回应延迟↓ + 自修正↑      高（模式明确）
防御状态                 回避话题↑ + 反问↑ + 情感词密度↓                   中（与生理确认——EDA↑=确认）
开放状态                 词汇多样性↑ + 自我修正↑ + 第一人称↑                 高（模式明确）
认知负荷高               句长↓ + 停顿↑ + 模糊词↑ + EEG α/θ 比值↑           高（对话+生理双重确认）
情绪标签不一致            自报告："我还好" vs 语言推断：负面词密度高           中——需生理确认（HRV↓+EDA↑=确认不一致）
```

**对话推断永远只是"建议"。最终确认——永远是生理数据。**

## 四、融合——两路数据怎么变成一帧 PBM 输入

### 4.1 融合时刻——在每一帧

```
Frame N 的融合输入：

生理数据向量（4-7 字节）                        对话推断向量（从最近 N 秒的对话窗口提取）
    hr: 72                                     anxiety_inferred: 0.3
    hrv_rmssd: 45.2                            defense_inferred: 0.1
    eda_phasic: 0.8 ↑（事件响应）                  openness_inferred: 0.7
    eeg_alpha_theta: 1.2                        emotional_self_report_match: 0.9
    emg_tension: 0.3                            topic_avoidance: [ ]
    ...
                                               
↓                                              ↓
    矛盾检测：
    EDA phasic ↑ = 生理层面有情绪事件。
    对话推断 anxiety_inferred 只有 0.3。
    → 不矛盾。EDA phasic 可能在回应一个非负面的刺激（兴奋、兴趣）。
    
    如果对话推断是 anxiety_inferred 0.9，但 HRV 正常、EDA 平稳——
    → 矛盾。用户可能在语言上表达了焦虑但身体没有。
    → 四诊合参铁律：生理优先。
    → 输出标签："用户报告焦虑——生理未确认。可能为认知层面的担忧而非自主神经激活。"
    
↓
融合输出——一帧 PBM 输入向量：

PBMInput {
    epoch: N,
    
    // 自主神经状态（生理）
    ans_sympathetic: 0.4,        // 交感激活度（HRV LF/HF + EDA + HR 加权）
    ans_parasympathetic: 0.6,    // 副交感激活度（HRV RMSSD + 呼吸推断）
    
    // 认知状态（生理 + 对话）
    cognitive_load: 0.3,         // EEG α/θ + 句式复杂度 + 回应延迟
    emotional_arousal: 0.5,      // EDA phasic + EMG + 情感词密度
    emotional_valence: +0.2,     // 正面/负面（语言情感分析 + HRV 模式）
    
    // 行为状态（对话）
    openness: 0.7,
    defensiveness: 0.1,
    topic_stability: 0.8,        // 话题一致性（是否在回避）
    
    // 元数据
    data_quality: 0.95,          // 本帧数据可信度（所有设备在线、无伪影）
    conversation_window_secs: 30, // 对话推断所用的时间窗口
}
```

### 4.2 四诊合参之"切"——不是四个并列通道。是两个。

```
传统四诊                                   Feelings 四诊
───────                                   ────────────
望  看——面色、舌苔、体态                      飞行陪伴体摄像头——面部表情、体态、场景
闻  听——声音、呼吸                            麦克风——语音韵律、呼吸模式
问  询问——自报告                               AI 教练对话——语言模式、话题、情感自报告
切  触——脉诊                                  五设备生理传感器——HRV/EDA/EEG/EMG/温度

但在 Feelings 里，这四个不是四个并列的数据源。是两个：

"切" = 生理数据通路（不依赖用户表达——用户无法伪装 HRV）
"望 + 闻 + 问" = 对话数据通路（依赖用户表达——但提供"切"不能给的上下文）

→ 四诊合参的本质 = 独立验证。
  "切"说：紧张了。
  "问"说：我不紧张。
  → 信"切"。但不否定"问"——"问"的矛盾本身就是一条信息。
     这个人在否认自己的紧张。岛叶-前额叶连接可能弱。
     下次 Session 可以试一下"你上次在这里紧张了——你有没有感觉到。"
```

```
输入：AI 教练对话文本
    不需要任何硬件。

    → 但可以做"用户的情绪标注一致性"追踪——

      我们再聊一次——这次试着不去想'还好'。"
```

### 5.2 第二阶段：腕部单设备

```
输入：腕部 EDA + PPG + 温度

    可以验证：
        EDA phasic 峰值与对话中"情绪话题"的时域相关性

        四诊合参的矛盾检测——对话说"我很好"，EDA 说"不太好"

### 5.3 第三阶段：耳后 + 腕部双设备

```
输入：耳后 PPG（HRV 金标准）+ 腕部 EDA
    PLL 时钟同步的第一次实战——两台设备在同一帧锁存数据。
    可以验证：
        多设备融合的时钟偏差和拒收逻辑
        交感/副交感平衡的实时追踪
        Session 中感受到安全放松时的 HRV 提升——第一个可测量的"Feelings 起效了"信号
```

### 5.4 第四阶段：全设备

```
五设备全部在线。
    EEG——认知负荷、专注/放松的实时追踪。
    EMG——压力在肌肉上的物理表现。
    飞行陪伴体——场景感知。"你在会议室里的紧张——和在卧室里的紧张——是两种不同的紧张。"
```

## 六、多源矛盾——当单点传感器给出不可信的答案

Feelings 的数据采集设计从第一天就假设：**单点传感器永远不可信。** 这不是传感器厂商的错。是物理和商业逻辑的双重约束——每个传感器都有自己测不准的场景，每家厂商都有自己的算法黑盒。下面是三个来自真实体验的例子——每一个都指向同一条架构铁律。

### 6.1 腕部 PPG 在水里——信噪比被水吞掉，算法选择了沉默

```
场景：自由泳结束。你明显感到心率 145+。
      看手表——心率 125，稳定得像贴在墙上。
      不是"你感觉错了"。是腕部 PPG 在水里——确实测不到。

物理原因：
    绿光 LED 照射皮肤 → 反射光变化 → 计算心率
    水 → 光散射 → 信噪比暴跌
    手臂划水 → 肌肉收缩 → 血管被挤压 → PPG 波形扭曲
    腕部和水膜之间的光学界面——不稳定

算法选择：
    当信噪比低于安全阈值时——
    传感器算法选择了"锁死在上一个可信值"——
    而不是"报告噪声"。
    → 125 不是测量值。125 是"我不知道真实值——
       所以我维持上一个看起来还靠谱的数字"。
    → 这是合理的工程权衡——但用户不知道。
       用户看到 125——信了。

→ 不是手表不好。是腕部 PPG 在水里的物理极限。
   Apple Watch 也好、华为 GT 5 也好——
   同样的绿光、同样的水、同样的信噪比天花板。
   差异只在"算法什么时候决定沉默"——
   不在"算法能不能穿透水"。
```

同样的问题在出水后依然存在——采样频率跟不上生理变化的真实速度：

```
游完看手表 → 心率从 145+ 往下跌 →
  不到一分钟跌到 100 以下。
  
  但手表可能只在这 60 秒里采了 6-12 个点。
  因为续航约束——PPG 是间歇开的——
  5-10 秒一次采样，中间全是空白。
  
  → 那段陡降曲线——
    "从极限运动到静息的自主神经切换"——
    手表根本没看到。
    它不是"记录不准"。是"采样太稀——
    漏掉了最关键的一帧"。
```

### 6.2 固态电池——能量密度是 250Hz 持续采样的物理前提

```
续航和精度——在同一块电池上——是零和博弈。

锂离子 ~250 Wh/kg → Apple Watch 一天一充
    → PPG 持续亮 → 每秒多次 → 数据密集
    → 但电量撑不住。必须每天充电。

锂离子 ~250 Wh/kg → 华为 GT 5 一周一充
    → PPG 间歇采样 → 5-10 秒一次 → 数据稀疏
    → 续航够了。但漏掉了关键帧。

→ 这不是"哪个更好的"选择。
  是"同一块电池——你只能在精度和续航之间——
  选一个"。

固态电池 ~500-700 Wh/kg →
  → 同等体积——2-3 倍容量。
  → 250Hz PPG 持续采样 + 一周续航——第一次同时成立。
  → 不是"电池变了"。是"能量预算变了——
    然后所有之前被砍掉的采样频率——
    可以被恢复"。

功耗墙有两面（见 power-wall.md）：
  面一：计算热——脑 20W vs 芯片 700W。FPGA 刚好够。
  面二：能量密度——锂离子 vs 固态电池。
        250Hz 持续采样不是传感器做不出来——
        是当前电池预算不允许。
        固态电池把预算从"紧紧巴巴"推到了"从容冗余"。
```

### 6.3 体脂秤——BIA 不准不是传感器不行。是每台机器用自己的黑盒模型在猜。

```
同一个你，同一周，五台不同的体脂秤——五个完全不同的数字。
不是"有一台是准的、其他不准"。
是它们在测的根本不是同一个东西。

BIA（生物电阻抗）怎么工作：
    脚底电极 → 通 50kHz 微弱电流 →
    电流走最短路径——
    一条腿上去 → 骨盆 → 另一条腿下来 →
    测到的电阻 ≈ 你两条腿的电阻。
    然后——

    体脂 = 算法(电阻, 身高, 体重, 年龄, 性别)
                      ↑
                   黑盒。每家不同。

为什么数字天差地别：
    算法训练人群      日本年轻女性 vs 欧美健身男性 →
                     同一个电阻——算出完全不同的体脂。
                     不是"谁更准"。
                     是"谁的模型更像你"。

    电极数量          4 点（只测腿）→ 上半身脂肪完全不知道。
                     8 点（加手臂）→ 稍好。但仍不是真实的体脂——
                     是"从四肢电阻推算全身"。
                     没有一种 BIA 体脂秤能测你的内脏脂肪——
                     电流根本到不了那里。

    水分              刚喝完 500ml 水 → 电阻低 →
                     算出来体脂低 3-5%。
                     脱水 → 体脂高 3-5%。
                     不是你胖了。是你的腿更湿了。

    时间              早上脱水 vs 晚上水肿 →
                     同一个人、同一台秤——
                     两天差出 5%。

→ 没有一台 BIA 体脂秤是"准的"。
  每一台都用不同的模型——在不同的条件下——
  做了一次推算。

  你能做的不是"找到最准的那台"——
  是"固定一台——固定时间——固定条件——
  只看三个月的趋势。绝不相信任何绝对值"。

更诚实的做法：如果机器显示原始阻抗值（Ω），
那个数字比算出来的体脂%更值得看——
因为阻抗是测出来的。体脂是猜出来的。
```

### 6.4 架构回答——不用任何单点黑盒算法

```

                          →  即使正常场景——采样频率被电池卡死。

                          →  换一台机器 = 换一套算法 = 数字重新洗牌。
