# 音乐系统设计

> 作者：qc
> 日期：2026-04-05
> 来源：音乐作为感受传递的第二通路，与神经接口信号协同工作

---

## 一、为什么音乐是核心，不是装饰

音乐是人类目前最接近「感受直接传输」的媒介。

在神经接口出现之前，音乐已经在做Feelings想做的事——它绕过语言，直接作用于情绪系统。好的电影配乐从来不是独立存在的，观众感受到的情绪高潮，有一半是配乐推上去的，但观众不会意识到，因为配乐消失在了体验里。

Feelings的音乐系统要做的是同样的事：

**不是「体验感受时有音乐」，而是「音乐和感受是同一件事的两个面」。**

高潮的时候，也是音乐最高潮的时候。消退的时候，音乐也在消退。那个峰值之后的短暂空洞，音乐也在。

---

## 二、三层架构

音乐系统分三层，用户可选，层层递进。

### 表层：音乐作为体验的伴随

音乐在体验进行时播放，提供氛围和情绪环境。

这是最基础的层次。音乐是体验的背景，不干预神经接口的信号传输，不影响感受包的核心机制。关掉这层，没有任何损失，只是体验更安静。

**用户可随时开关，无代价。**

---

### 中层：音乐作为感受结构的索引语言

音乐的结构映射感受的结构：

```
音乐主旋律      ←→    感受的主旋律
和声层          ←→    点缀感受的配比
节奏            ←→    感受的时间形状（急促/绵延）
调性            ←→    感受的情绪方向（明亮/沉郁）
音乐密度        ←→    感受的强度
```

用户在检索感受库时（见 feeling-taxonomy.md），可以通过音乐语言描述自己想要的感受结构——「我想要那种主旋律很清晰但和声层很复杂的感觉」，系统翻译成结构性参数，匹配对应的感受包。

音乐成为感受的描述语言，对没有神经科学背景的普通用户尤其友好。

**关掉这层，感受包的描述语言切换到纯文字和结构性参数，功能完整但少了一种直觉性的入口。**

---

### 深层：音乐作为信号的第二通路

这是音乐系统最核心的层次。

神经接口负责强度和方向的传递，音乐负责质地和氛围的传递。两个通路分工，在Layer 2层做混合，合力完成一个完整的感受体验。

```
神经接口通路    强度、方向、主旋律感受的激活
音乐通路        质地、氛围、点缀感受的细腻传递
                ↓
Layer 2 混合    两个通路的信号在这里融合
                ↓
完整的感受体验
```

为什么质地需要第二通路？

主旋律信号可以精确设计，但感受的「湿度」——那种完成一件事之后的快乐为什么有时候是轻盈的，有时候是沉的，有时候带着一点眼眶发热——这些细节用神经接口单独传很难做到精确。音乐在这里填补了精度的缺口。

**关掉这层有代价**：体验的完整度下降，质地传递精度降低。系统会诚实告知，但不强迫开启。类比色盲模式——你可以用，但「部分感受细节在这个模式下不可见」。

---

## 三、AI实时生成：跟着感受走

深层音乐不是预先生成然后播放，而是**实时生成、实时演进**。

输入不是静态的感受包参数，而是实时的感受曲线：

```
感受强度曲线        →    音乐能量曲线
感受上升速度        →    音乐张力积累速度
峰值时刻            →    音乐高潮时刻（精确对齐）
点缀感受比例变化    →    和声层的动态变化
消退斜率            →    音乐收尾方式（急收还是慢淡）
感受的「质地」      →    音色选择、混响深度、频率分布
```

两条曲线实时咬合：

```
感受上升 → 音乐张力积累
感受到达峰值 → 音乐同步高潮
峰值之后的空洞 → 音乐短暂的留白
感受消退 → 音乐渐渐收尾
体验结束 → 音乐自然落地，不硬切
```

**结果**：同一个感受包，每次体验的音乐都不完全相同。每次感受曲线都有细微差异，音乐实时跟随，每次都是独一份的。

你的每次体验都是独一无二的，连音乐都不会重复。

## 四、本地音乐：用户自己的情感锚点

用户可以使用自己本地存储的音乐，替换表层和中层的系统音乐。

**本地音乐不进入信号层。**

原因有两个：

```
安全边界    平台无法对任意音乐做神经激活模式分析
            贸然混入Layer 2信号有不可控的安全风险

隐私原则    音频数据永远不离开设备
            和神经数据的隐私原则保持一致
```

用户在耳机里听自己的音乐，神经接口走AI生成的信号通路，两者并行不干扰。本地音乐替换掉你听到的，但替换不掉神经接口在传的。

### 感受时长适配

感受包的时长不确定，本地音乐需要一个适配层避免硬切出戏：

```
系统实时估算当前感受阶段
    ↓
上升期    选用户本地库中能量上升的曲目
峰值期    匹配当前强度，维持音乐密度
消退期    自动淡出或切换到平缓曲目
结束      音乐同步收尾
```

实现方式：系统对用户本地音乐库做一次轻量分析，提取节奏、能量密度、情绪方向等结构性特征，建立本地索引。

```
分析内容    节奏型、能量密度、情绪方向、时长
不分析      歌词内容、版权信息、任何识别性信息
存储位置    本地设备，不上传
用户授权    一次授权，随时可撤销
```

版权问题从根上绕开——平台不持有任何音乐内容，不经过任何内容审查层，用户使用自己拥有的音乐，平台只读取结构性特征做适配。

## 五、三种音乐来源的分工总结

```
来源              层次          进入信号层    版权风险
─────────────────────────────────────────────────────
AI实时生成        深层          是            无
本地音乐          表层/中层     否            无（本地）
系统音乐库        表层/中层     否            平台持有版权
```

默认使用AI实时生成，覆盖三层。用户可以用本地音乐替换表层和中层的听觉体验，深层始终走AI生成。

## 六、与感受混音结构的关系

感受是主旋律+点缀的混音结构（见 feeling-taxonomy.md 第一节）。

音乐系统在这里的作用是把这个抽象的混音结构变得可感知：

```
主旋律感受（60%）    →    音乐主旋律，最突出，最清晰
点缀感受A（20%）     →    和声层，在主旋律下面托着
点缀感受B（10%）     →    音色质感，是整体的「湿度」
点缀感受C（10%）     →    节奏的微小起伏，几乎不被意识到
```

用户不需要理解这个结构，但他们会感受到——为什么「完成一件事的快乐」和「久别重逢的快乐」，在音乐上听起来完全不同，即使强度相近。因为点缀的配比不同，和声层不同，音乐的质地就不同。

**音乐让感受的质地变得可感知，而不只是可量化。**

## 七、未解决的问题

**AI实时生成的延迟**

感受曲线实时变化，音乐需要实时跟随。生成延迟如果超过人的感知阈值（约20ms），同步感会被破坏。这是Layer 2和音乐生成引擎之间的实时性挑战，需要在原型阶段重点验证。

**音乐高潮的预判**

感受曲线是实时的，但音乐的张力积累需要提前量——不能等到峰值时刻才开始推音乐，否则高潮会迟到。系统需要对感受曲线做短时预测，提前几秒开始音乐的张力积累。预测模型的准确度直接影响高潮的同步精度。

**不想要任何音乐的用户**

三层全部关闭，体验依然完整——神经接口单通道工作，只是质地传递精度下降。这是被设计支持的选择，不是边缘情况。

---

*音乐系统是Feelings感受传递体系的第二通路，与神经接口协同工作，将随Layer 2技术成熟持续演进。*
