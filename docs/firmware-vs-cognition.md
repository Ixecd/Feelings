# 固件与认知——用户体验优化应该在哪一层

> 作者：qc
> 日期：2026-06-04
> 性质：Feelings 工程哲学
> 核心：不是所有优化都应该下放到固件。画一条精确的线——信号闭环在固件，认知闭环在应用层。放错层级和没做优化一样危险。

---

## 零、iPhone 的 120Hz 和 Android 的 120Hz 不是同一件事

规格表上写的是同一个数字。但你手指滑下去的那一下，感受到的是六层叠加的差异：

```
iPhone 触控管线
    触摸传感器 → 触控协处理器（独享总线，不走主 CPU）
    → iOS touch event → Core Animation commit → Render Server
    → GPU → 显示
    端到端触控延迟：20-40ms
    
Android 触控管线
    触摸传感器 → 驱动 → Linux input 子系统 → InputReader
    → InputDispatcher → CFS 调度器（跟后台 GC、网络 IO 平等竞争）
    → WindowManager → Choreographer → SurfaceFlinger → 显示
    端到端触控延迟：40-80ms
```

差距不在帧率数字。在**触控事件的架构优先级**。iPhone 的触控协处理器是独享总线、硬件级中断。Android 的触控事件走标准 Linux input 子系统，在 CFS 调度器里跟所有用户态进程争 CPU。

**同样 120Hz。一条直连总线。一条排队等号。**

## 一、Mac 触控板——更极端的例子

```
普通笔记本触控板
    触控传感器 → MCU → USB HID 报告 → OS HID 栈 → 手势识别 → 屏幕光标
    端到端：15-30ms

Mac 触控板
    触控传感器 → 嵌入式 MCU（跑 Apple 自己的固件）
    → SPI 直连 T2/M 系列芯片的触控协处理器
    → 不走 USB 栈，不走 HID 报告协议
    → 手势分类在固件层完成（Kalman 滤波 + 分类）
    → macOS 只收"这是三指 swipe"
    → 端到端：< 8ms
```

关键在那一步——**手势分类在固件层，不在 OS 层。** 通用触控板把原始坐标点扔给 OS，OS 的 gesture recognizer 攒够几个点才知道这是 scroll 还是 pinch——攒点的过程就是延迟。Mac 的固件自己做了滤波和分类，SPI 直传结果。

**好的系统都在做同一件事：把判断推到离信号源最近的地方，用最短的路径抵达执行端。**

## 二、Feelings 的同构设计

Feelings-OS 的 busd + FPGA 层和这套逻辑完全一致：

```
Mac 触控板固件               Feelings 设备固件
──────────────             ──────────────
Kalman 滤波                 四诊合参信号滤波
手势分类（scroll/pinch）      OiSmoothing 衰减状态机
SPI 直传结果                 FPGA BRAM 端口 B 一拍替换端口 A
延迟 < 8ms                  延迟 < 100μs
```

以及往上追溯——整个 Feelings 全栈都遵循同一套分层哲学：

```
iPhone 触控协处理器           Feelings-OS busd + FPGA
─────────────────────        ─────────────────────
独享总线，不争带宽            主设备 PLL 主时钟广播，从设备锁定
硬件级中断，不经过调度器        P0 安域 < 100μs，不经过调度器
Render Server 独立进程        六个守护进程各自只做一件事
触摸 → 显示 3 帧内闭环        安全域中断 → BRAM 端口 B 一拍替换端口 A
```

**三条产品线。同一种架构直觉：不要在物理极限允许的延迟之外再多加哪怕一层。**

## 三、画线——什么必须在固件层，什么必须在应用层

放错层级和没做优化一样危险。把认知推到固件会烧死迭代速度。把信号响应留在应用层会烧死实时性。

### 固件层——判决器，不是认知器

```
共同特征：
    1. 输入是原始传感器数据，输出是分类/处理后的结果
    2. 必须在物理时间窗口内完成——超时就失效
    3. 不需要理解"用户意图"——只需要识别"信号模式"
    4. 错一次 = 用户体验差一个节拍，不是差一个结论
```

在 Feelings 里的对应：

```
固件层（层 5，C）
    OiSmoothing 衰减状态机        ← 这是"Mac 触控板固件"的 Feelings 等价物
    四诊合参信号滤波               ← Kalman 滤波的 Feelings 等价物
    安全域中断（< 100μs）          ← 硬件级中断，不经过调度器
    ESIR 帧级安全插桩             ← 门级逻辑，微秒级响应
    PLL 主时钟广播               ← SPI 直连的 Feelings 等价物

    共同点：信号层面的硬实时判决。确定性状态机。一次写入，长期运行。
           错 = 信号不干净。物理级安全底线。
```

### 应用层——认知器，不是判决器

```
不该下放到固件              应该在哪儿              为什么
───────────               ────────              ────
PBM 基线偏移               Pass 6 Personalize    需要跨 session 历史数据
创伤协议分支选择            Pass 3 + AI 教练      需要多源信息融合
感受包推荐                  AI 教练                需要理解用户叙事
SPL 财务结算               Feelings-Server        需要 GPG 多签 + 审计
PBM 长期收敛追踪            Pass 6 + 云端          需要几万维向量的累积
Anim 宏展开                 Pass 0 交织期          需要在完整 AST 上计算组合风险
```

这些不能进固件——不是因为固件不够快。是因为固件的 ROM 和认知的迭代速度不在同一个时间尺度上。认知需要跨 session 记忆、需要多源数据融合、需要理解用户叙事。固件没有这些东西——它只有寄存器、SRAM 和一个确定的时钟。

```
应用层（层 7+）
    Anim 交织管线（Pass 0-5）      ← 概率推理
    AI 教练                       ← 理解→适应→成长
    PBM 个性化 + 收敛追踪          ← 持续迭代
    感受包推荐                     ← 软实时（ms-s）

    共同点：认知级方向选择。错 = 建议不准。需要跨 session 记忆和持续迭代。
```

## 四、画线原则

```
固件层                        应用层
──────                       ──────
传感器原始信号 → 滤波 → 分类   分类结果 → PBM 偏移 → 个性化 → 推荐
硬实时（μs-ms）               软实时（ms-s）
确定性状态机                   概率推理
一次写入，长期运行              持续迭代
错 = 信号不干净                错 = 建议不准
物理级安全底线                  认知级方向选择

分界线：
    这层的输出是接物理设备还是接人的判断。
    → 接物理设备（SAR 寄存器、DAC 输出、衰减状态机）→ 固件层。不经过任何调度器。
    → 接人的判断（推荐感受包、调整强度、创伤协议分支）→ 应用层 + AI 教练。
```

```
12+     应用服务 + AI      应用层           AI 教练、感受包推荐、SPL 账本
```

## 六、和 iPhone/Mac 的最后一层对齐——预期链

iPhone 120Hz "丝滑"的神经学本质不在帧率数字——在**触控-视觉闭环的预期链不断裂**：

```
iPhone
    触控延迟 ~25ms → 视觉反馈在 3 帧内到达
    → 小脑预期链：手指移动 ↦ 视觉偏移在同一个感知窗口内
    → "我正在拖拽这个东西"——预期链不断。

Android（非旗舰）
    触控延迟 ~60ms → 视觉反馈在 7-8 帧后到达
    → 小脑预期链：手指移动了 ↦ 视觉还没跟上 ↦ 脱节
    → 帧率一直是 120。是预期链断了。不是帧率低。是反馈慢。
```

这和 Feelings 里岛叶的预期链是同一件事——**not about signal strength, about whether the next frame arrives before the prediction window closes.** "丝滑"不是帧率做出来的——是预期链在每帧都被准时接住。

---

*用户体验里那部分"物理信号 → 即时响应"的优化，推到固件层。用户体验里那部分"理解 → 适应 → 成长"的优化，留在认知层。两条线各走各的总线。*
