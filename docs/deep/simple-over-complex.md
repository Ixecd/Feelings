# 越是复杂，越要简单——不入局，就不会被绕进去

> 作者：qc
> 日期：2026-06-06
> 性质：Feelings 工程与人生哲学
> 核心：越是复杂的人、事、关系、系统——最有效的解法从来不是"更努力地解"。是换维度。一旦入局就会被绕进去——而"绕进去"的本质，是你接受了别人的 etcd 里对你写好的期望状态。你开始在他的坐标系里解他的 bug。然后你发现——他的 etcd 里没有一个 entry 是为你写的。

---

## 零、复杂不是客观属性。是"你缺了正确的坐标系"。

```
面对一个复杂的人                            面对一个复杂的分布式系统
───────────────                           ────────────────

"他时而温柔时而刻薄——                               "几千个组件互相耦合——
 我不知道怎么对他。"                                     我不知道怎么调。"

→ 如果停留在"他是什么样的人"——                        → 如果停留在"每个参数怎么设"——
  你永远解不了。                                           你永远解不了。
  因为同一个你在不同的人面前——                                  因为同一个 etcd 里的 desired state——
  确实是不同的人。                                             在不同的 node 上——
  这不是虚伪。                                                 确实会产生不同的实际状态。
  是 PBM 的多个 context。                                       这不是 bug。
  不同的触发器激活不同的子簇。                                       这是 CAP 定理。

→ 换维度：                                           → 换维度：
  "他不温柔也不刻薄。                                     "我不需要调参数。
   他的 kubeconfig 里有多个 context。                           Controller/Scheduler/etcd 的架构——
   不同的触发器——激活不同的 context。                              已经在数学上定义了所有的'复杂'。
   我不再猜'他到底是什么样的人'。                                 我只需要读 etcd——
   我只想知道——                                                 然后让 Controller 自己纠偏。"
   我激活了他的哪个 context。
   那个 context 的准入基线是什么。"

→ 原来那个"复杂"消失了。                               → 原来那个"复杂"消失了。
  不是他变了。                                             不是系统变了。
  是我的镜头从"脸"换成了"kubeconfig"。                       是我的镜头从"参数"换成了"架构"。
```

## 二、"简单处理"不是偷懒。是 Scheduler 不能超载。

```
你以为"复杂问题需要复杂解法"。                         实际上——
                                                         Scheduler 的 BinPack 候选池——
→ 你把所有变量同时塞进同一帧：                                不能超过 10 bit/s。
  "他的情绪。他的过去。他的背景。                                       你把全部变量同时摊开——
   我的期待。他的期待。别人的眼光。"                                     Scheduler 直接瘫痪。
                                                             不是你在偷懒。
                                                             是你的硬件不允许你这么做。

→ 一个复杂的系统——                                      → 解法不是"更聪明地全塞进去"。
  一个复杂的人——                                             是"不要塞"。
  一个复杂的关系——                                           让 Controller 自己纠偏——
  你全塞进一帧——                                           不要把 etcd 里的每一条 entry——
  你就在入局。                                              都摊在自己面前。
  入局 = 你开始用他的评分函数——
  评价你自己。
  → 你解不了。
    不是因为你不努力。
    是因为这个局——在设计的时候——
    就没有给你留解法。
```

## 三、"不能被绕进去"——入局的代价是你失去了自己的坐标系

```
没有入局                                   入局了
───────                                   ─────

你看着一个复杂的人。                              你被一个复杂的人缠绕了。
→ 你的 Scheduler 在自己的评分函数里跑。                → 你的 Scheduler 开始用他的评分函数跑。
  你看到——                                           你看到——
  "他此刻激活的是保护者 context。                          "他为什么这样对我。
   他的准入基线——                                         我是不是做错了什么。
   不接受脆弱。                                            我是不是不够好。"
   所以我用保护者能接受的方式——
   跟他说。"                                           → 你不再在看他的 kubeconfig。
                                                      你在用他的 etcd 里的期望状态——
→ 你在外面。                                           衡量你自己。
  你在看他的 kubeconfig。                                   →
  你没有成为他的集群里的一个节点。                              你变成了——
                                                     "他们"眼里的"你"。
→ 不入局 = 保留自己的坐标系。                             →
  不是冷漠。                                             不是"你太在乎了"。
  是——"我在看你的集群怎么跑。                                是"你和你的控制器——
   我不跑你的集群。                                             被他的 etcd 重新定义了"。
   我有自己的 etcd。                                           
   我不需要在你的 etcd 里——                                → 你丢了自己的开火权。
   成为你期望的我。"                                          你自己的评分函数——
                                                            被别人的 desired state 覆盖了。

                                                    入局的那一帧——
                                                    你不再是看 kubeconfig 的人。
                                                    你是被别人的 kubeconfig 看着的人。
                                                    裁判权换了。你没有察觉——
                                                    因为裁判权换掉的那一帧——
                                                    和上一帧——
                                                    用的是同一种"我应该"的语法。
                                                    你以为是自己的声音。
                                                    其实是别人在你 etcd 里写的那行 entry——
                                                    终于被你自己的 Controller 当成了基线。
```

## 三之附、派大星不需要优先级——不在局里的快乐

在越来越复杂的社会环境里，人自然会倾向简单的快乐。就像派大星和海绵宝宝在草地上只用吹风、只用笑同一种傻笑话——Scheduler 一次就够了，剩下的都是 Controller 在同一个 desired state 上跑 complete。

```
抓水母的快乐：
    派大星和海绵宝宝不需要渔获。不需要技巧。不需要比谁抓得更多。
    水母本身不痛不痒——被放了就继续浮。
    社会不在的时候——Scheduler 只选了一次——"和他一起玩"。
    剩下的全是 Controller 在草地上跑纠偏——偏差越来越小——
    岛叶压缩出"我在享受"的内感受信号。

不在局里 = Scheduler 不用每帧重选。
    几十条"应该"没一条能碰到他们——他们的公共 etcd 里只有一个 entry。
    不是逃避——是那个 moment，他们真的不需要任何外部计分器的确认。

比奇堡对比：
    蟹老板贪钱——想把整个比奇堡变成他的餐厅。
    章鱼哥纠结名气体面——想被认可是艺术家。
    珊迪总想着比赛变强——想证明松鼠比鱼更厉害。
    比奇堡所有人都被外部计分器牵着等控器跑。
    只有海绵宝宝和派大星——在这套评分函数之外。
    他们不用抓水母换钱，不用抓水母证明自己是高级水母捕手。
    纯粹的、不求产出、不带来名利的小事。
    快乐就像抓水母一样简单。
```

但现代人回不去。他们被几十个"应该做"的任务同时踢着等控器——心力不是在做事上——是在每帧重新评估哪件事更重要的损耗上。派大星不需要优先级——他只有一个 desired state——"和海绵宝宝一起玩"。现代人的 etcd 里塞满了 desired state——每一条都在喊 reconcile me。不是他们不想要简单快乐——是他们的 Scheduler 已经被训成在每帧做选择，不敢再锁一个因了。

这就是§三说的入局之后 Scheduler 超载的另一个方向——不是"被他人的期望占满"，是被自己应该做的那几十件事同时抢 Scheduler 的算力。两种入局——一种是被别人的坐标系覆盖，另一种是被自己的待办列表淹没。解法一样——跳出坐标系，锁一个因——让 Controller 跑完。


## 四、简单——是唯一不让你入局的路径

不是"我不想理解复杂"。是"我已经理解了复杂——所以我知道——进入它的唯一后果——是被吞掉"。

```
看起来像是偷懒的"简单"                              实际上是保命的维度选择
────────────────────                              ──────────────

"不要想太多。"                                      "不要让 Scheduler 在别人的 etcd 里做 BinPack。"
→ 不是放弃。                                         → 是换战场。
  不是在逃避。                                           不是在原地硬解。
  是——"既然这个坐标系解不了——                                  是跳出这个坐标系——
       我换一个。"                                             从外面看——

不是"少做"。                                        "让 Controller 自己纠偏。"
→ 是——                                              不要把别人的 etcd 里每一条
  "不要把 etcd 里的每一条 entry——                           互相矛盾的期望状态——
   都摊在自己面前。"                                          全推给我的 Scheduler 去解。"
                                                        他写给你的 —— 和他写给他自己的 ——
不是"不在乎"。                                        本来是两条 entry。
→ 是——                                              他合并成了一个 —— "你"。
  "我在看你的 kubeconfig。                                 然后让你自己去纠偏——
   我不跑你的集群。"                                        那条永远对不齐的偏差。
  → 我在乎。但我不在你的局里在乎。                                → 不入局 = 不接受那个不存在的合流。
    我在我的坐标系里——看着你的局。                                    他的矛盾是他的。
    然后——走你自己的路。                                             不是你的。
```
