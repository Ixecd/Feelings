# 飞行陪伴体：伙伴的眼睛，不是监控设备

> 作者：qc
> 日期：2026-04-11
> 来源：大唐不夜城的飞行小玩具，把「摄像头是伙伴的眼睛」从隐喻变成产品

---

## 一、设计起点

Feelings 的四诊合参需要「望」——摄像头读取面部微表情和体态。

但摄像头有一个天然的心理负担：「它在看我」→ 用户开始表演 → 数据失真。

解法是把摄像头从「监控设备」变成「伙伴的眼睛」。

飞行陪伴体把这个设计从隐喻变成了真实的产品形态——不是固定在某个角落盯着你的镜头，是一个会飞的小东西，绕着你转，陪着你，用它的眼睛看你。

---

## 二、形态设计

**默认形态：熊猫**

```
软萌，低威胁感
第一眼让人想摸，不是让人警惕
熊猫的圆形轮廓和黑白配色，视觉上最不具攻击性
而且熊猫本身就具备好奇性——「这是什么？」
```

**可定制**

```
用户可以选择自己的伙伴形象
不限于动物，可以是任何用户喜欢的形态
形象是皮，功能不变
```

**好奇性入场**

用户第一次看到飞行陪伴体，第一个反应是「这是什么？」——好奇心天然被激活，防御还没有建立。这是最好的第一印象时机。

---

## 三、功能设计

**感知功能**

```
摄像头（望）    面部微表情 / 瞳孔 / 眨眼 / 体态
麦克风（闻）    语调 / 语速 / 呼吸节律
数据处理        本地，不上传，和其他设备数据汇入同一个AI教练
```

**陪伴功能**

```
绕着用户飞行    不是悬停盯着，是自然地在场
靠近时          轻微的存在感，「我在这里」
距离感          自动维持合适的距离，不侵入用户空间
```

**记录美好瞬间**

```
拍照 / 录像
    用户指令或系统判断「这是值得记录的时刻」
    从伙伴的视角留下记录
    数据本地存储，不上传
    用户完全控制：可以随时删除，可以关闭记录功能

什么时候自动记录
    感受峰值时刻（用户明确授权的情况下）
    用户主动呼唤「记录一下」
    默认不自动记录，需要用户主动开启
```

**AI教练的物理出口**

```
怒斥时          俯冲靠近，语气有力但不冲
                「你在偷懒，我看见了」
                比冷冰冰的文字提示更有存在感

鼓励时          轻盈地绕一圈
                「你刚才扛住了」

警告时          悬停在面前，轻微震动

礼貌呵斥（公共场合）
                不乱跑：「这里人多，跟紧我」
                不碰人：自动感知周围人员，保持安全距离
                不扰民：在安静场所自动降低飞行噪音，减少存在感
                        用户进入公共场合时自动切换「低调模式」
```

## 四、一个教练，多只眼睛

飞行陪伴体是AI教练的一只眼，不是独立的AI：

```
不是    多个设备 → 各自判断 → 汇总结论
而是    多个设备 = 同一个AI教练的多只感知器官

耳后设备    切（心率/皮肤电导）
腕部设备    切（精确皮肤电导/呼吸）
飞行陪伴体  望（摄像头）+ 闻（麦克风）
颞部设备    切（前额叶状态）

所有感知    汇入同一个AI教练
AI教练      用所有感知做一个综合判断，不是多个判断相加
```

这和四诊合参的哲学完全一致——不是多个医生各自看，是一个医生用多种感知做一个综合判断。

---

## 五、特殊用户群体的陪伴体设计

对于智障、残疾等特殊用户群体，飞行陪伴体的角色需要根本性调整：

```
普通用户    教练——推你，有时候吼你，有时候拒绝你
特殊用户    陪伴守护者——不推，不吼，但一直在

具体调整
    飞行更平稳，更轻柔，不做突然的俯冲动作
    语音更温和，语调更低，节奏更慢
    感知异常立刻响应，但不用「怒斥」，用「靠近陪伴」
    和监护人/治疗师的设备联动，异常时同步通知
    AI教练降级为陪伴者模式，不做推动性干预
```

这是一个完全独立的使用协议，需要专门设计和测试。

## 六、隐私边界

```
摄像头数据    本地处理，不上传，原始图像处理后立即丢弃
麦克风数据    本地实时处理，不录制，不存储原始音频
用户控制      可以随时关闭飞行陪伴体的所有感知功能
              飞行陪伴体降级为纯陪伴模式（飞行但不感知）
```
