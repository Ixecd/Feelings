# 感受分类体系与存储设计

> 作者：qc
> 日期：2026-04-05
> 来源：对「平静」「失去」等笼统感受词的拆解，以及感受库架构的系统性思考

---

## 一、感受词的粒度问题

现有的感受分类太笼统。「平静」「失去」「归属」这些词是语言的懒惰，不是感受的真实边界。

以「平静」为例：

```
冥想后的平静    主动清空，内部安静，有意为之
疲惫后的平静    被动耗尽，身体沉重，无力而非宁静
释然后的平静    有具体的重量消失了，是放下之后的状态
孤独中的平静    没有他者，但不是难受，是一种完整
自然里的平静    外部触发，和内部状态无关，是被环境接管
```

以「失去」为例：

```
死亡的失去      永久性，没有可能性，边界是绝对的
关系终结的失去  对方还在，但那个关系的形态消失了
机会错过的失去  本可以但没有，反事实的重量
身份失去        你以为自己是什么，突然不是了
时间失去        回不去的阶段感，是对过去的哀悼
```

这些变体的神经底层很可能是完全不同的激活模式。把它们压缩成同一个词，意味着系统在最重要的地方失去了精度。

**感受库的存储单元不是「感受词」，是「感受词 + 叙事 + 结构性参数」的三元组。**

---

## 二、存储单元设计：感受 + 叙事

### 为什么叙事是必须的

没有上下文的神经信号参数是孤立的数据点。叙事是感受的土壤——它提供了感受发生的场景、触发条件、和感受者的关系背景。

用户在检索感受库时，搜索的不是「平静强度6」，而是「那种在医院走廊等待手术结果时的平静」。叙事让感受变得可检索、可辨别、可共鸣。

### 存储结构

```
feeling_package {
    id              UUID
    name            TEXT           // 感受词（粗粒度标签）
    narrative       TEXT           // 上传者的叙事描述
    structural_tags JSONB          // 结构性参数（见第三节）
    signal_config   JSONB          // 下发给 Layer 2 的神经信号参数
    core_score      FLOAT          // AI 判断的内核置信度（0-1）
    intensity_nominal INT          // 标称强度 1-100（评分引擎输出的单点值）
    intensity_version INT          // 评分版本号（score_v1/v2/v3...随重打分迭代）
    created_by      UUID           // 上传者
    created_at      TIMESTAMPTZ
}
```

强度存储为单点标称值而非区间，原因：评分引擎（见 scoring-engine.md）对每个感受包输出一个具体分数，随数据积累版本迭代。区间描述（如「适合30-60分用户」）是推荐层的计算结果，不是感受包本身的属性。

### 叙事的双重角色

叙事不只是元数据，它本身可以是体验的一部分。

下载者在接收神经信号之前先读到那段文字，文字已经在做一部分工作了——它在帮助下载者的神经系统找到接收的方向。这和「期待污染」的问题有张力（见 contrast-protocol.md），但也可能是一个刻意设计的体验前置层。

这个边界目前悬而未决，记录在此，等待第一批真实用户数据再做决定。

## 三、感受的结构性分类体系

最终的分类维度按感受的结构性特征来，而不是按情绪类型或触发场景。

结构性特征是正交的——每个维度独立，可以任意组合，覆盖大多数感受变体。

```
维度              取值
────────────────────────────────────────
持续时长          瞬时 / 短暂（分钟级）/ 绵延（小时级）/ 慢性
方向性            向内收缩 / 向外延展 / 无方向
主动/被动         主动触发 / 被动接受 / 混合
有无具体对象      有对象（人/事/物）/ 无对象（弥散性）
身体参与度        纯心理 / 轻微躯体感 / 强烈躯体感
时态锚点          过去导向 / 当下导向 / 未来导向
社会性            个体感受 / 需要他者在场 / 集体性
```

这些维度正交组合，可以精确描述大多数感受变体。

比如「冥想后的平静」：

```
持续时长    绵延
方向性      向内收缩
主动/被动   主动触发
有无对象    无对象
身体参与度  轻微躯体感
时态锚点    当下导向
社会性      个体感受
```

比如「接力赛赢了的集体荣誉感」：

```
持续时长    短暂
方向性      向外延展
主动/被动   混合
有无对象    有对象（队友）
身体参与度  强烈躯体感
时态锚点    当下导向
社会性      集体性
```

## 四、两种检索入口

感受库的检索支持两种入口，服务不同的用户状态。

### 入口 A：叙事搜索（知道自己想要什么场景）

```
用户输入：「那种在深夜独自完成一件事之后的感觉」
         ↓
系统语义匹配感受库里最接近的叙事
         ↓
返回候选感受包列表（附内核置信度）
         ↓
用户选择，结合强度设定，进入体验
```

### 入口 B：结构性参数过滤（想被带到某种结构性体验里）

```
用户选择：持续时长=绵延 / 方向性=向外延展 / 社会性=个体感受
         ↓
系统过滤符合参数的感受包
         ↓
结合盲选协议（contrast-protocol.md）决定具体内容
         ↓
用户不知道具体是什么感受，只知道结构性方向
```

### 入口 C：叙述生成（AI从用户描述直接生成感受包）

```
用户叙述：「那种刚刚解决了一个卡了很久的问题，
           脑子里有什么东西松开了，但又有点空」
         ↓
AI提取感受结构
    主旋律    解除阻塞后的释放感
    点缀A     疲惫的释然（卡了很久）
    点缀B     轻微的空洞感（问题消失了，占据你的东西没了）
    点缀C     对自己的微小确信
         ↓
生成对应感受包参数
         ↓
用户确认或微调，进入体验
```

入口 C 不需要用户懂感受分类体系，只需要用自己的语言描述——系统把语言翻译成感受结构。

这也是梦境叙述仿真还原的底层机制（见 `docs/dream-journal.md`）。

## 五、AI 判断内核置信度

### 问题

上传者自述「这是我在某个极限状态下的神经信号」，无法核实。有人可能通过药物、刻意制造的生理状态，或单纯的认知偏差，上传了一个「外壳」——神经信号存在，但和叙事描述的感受状态不对应。

### 判断路径

叙事文字里藏着信号强度的线索。真实的极限体验和伪造的叙事，在语言结构上存在可训练的模式差异：

```
真实叙事的倾向：
  细节的密度高（具体时间、地点、感官描述意外出现）
  情绪词反而被轻描淡写
  时态混乱（在描述过去时突然切换到现在时）
  有具体的身体感觉描述

伪造叙事的倾向：
  概念化、抽象化
  情绪词密度高，但缺乏感官锚点
  叙事结构过于工整
  缺乏「不必要的细节」
```

AI 给出的不是「真/假」的二元判断，而是一个内核置信度分数（0-1），附在每个感受包上。

```
core_score > 0.8    高可信度，叙事和信号高度一致
core_score 0.5-0.8  中等可信度，供下载者参考
core_score < 0.5    低可信度，系统标注，下载者自行判断
```

这个分数对下载者可见，不对上传者可见（避免针对性的叙事优化）。

### 局限性的诚实

AI 置信度不是真实性保证，是参考层。平台不承诺「你体验的是真实的感受」，承诺的是「你看到了我们对这个感受包的诚实评估」。来源透明优先于真实性保证。

## 六、感受库的开放性

感受库持续支持新感受加入，没有封闭的感受类型列表。

任何用户都可以上传感受包，经过 AI 内核评估和基本安全审核后进入库。这意味着感受库会随着用户群体的扩大，自然覆盖越来越多的文化背景、生活场景、和人类经历的边缘地带。

感受类型不是平台定义的，是人类集体上传的。

平台只做两件事：评估置信度，和保证安全边界（见 Feelings-HARD-PROBLEMS.md 第二节）。

## 七、悬而未决的问题

**叙事是否应该在体验前对下载者可见？**

叙事可见 → 帮助神经系统找到接收方向，但引入期待污染
叙事不可见 → 信号更纯，但下载者完全不知道自己在接收什么

这和盲选协议（contrast-protocol.md）的核心张力一致，目前没有定论。可能的解法是让用户在账号设置里自己选择「叙事前置」还是「纯盲选」模式。

**结构性参数的标注由谁来做？**

上传者自标注 → 成本低，但准确性依赖上传者的自我认知
AI 辅助标注 → 更一致，但需要足够的训练数据
下载者反馈迭代 → 最准确，但冷启动问题严重

三种方式可能需要组合使用，具体比例等第一批数据再决定。

## 八、痛苦的分类

痛苦和快乐一样，是一个被过度压缩的词。

不同性质的痛苦，神经底层完全不同，处理方式也完全不同。混为一谈，是无法真正面对它的原因之一。

**身体疼痛**

```
物理伤害触发的痛觉信号
神经科学最清晰的痛苦类型
有明确的来源，有明确的消退路径
```

**心理痛苦**

```
失去、背叛、羞耻、孤独
没有物理来源，但神经激活模式和身体疼痛有重叠
大脑对社交痛苦的处理，调用了和身体疼痛相同的脑区
这是「心碎」在身体上真实存在的原因
```

**存在性痛苦**

```
对意义的追问没有答案
对死亡的恐惧
对自由的重量的无力感
这类痛苦没有具体来源，是对存在本身的质疑
```

**见证性痛苦**

```
目睹他人的痛苦
战争、灾难、疾病
镜像神经元让人真实感受到他者的痛
这是共情的代价，也是人类联结的基础
```

**化学性痛苦**

```
物质戒断、神经递质失衡
不是经历触发，是生化状态本身
Feelings不介入纯化学性痛苦，这是医疗范畴
```

**Feelings 在痛苦分类里的工作**

不是消除痛苦，是帮用户精确命名正在经历的是哪种痛苦，然后用对应的方式处理。

```
身体疼痛      → 感知它，接受它，知道它会过去
心理痛苦      → 命名它，拆解混音结构，在自省中处理
存在性痛苦    → 在更大的坐标系里找到位置（见 on-right-and-wrong.md）
见证性痛苦    → 共情有边界，进入但不消融（见 docs/empathy.md）
```

命名准确，才能对症。把所有痛苦都叫「难受」，是无法处理任何一种的。
