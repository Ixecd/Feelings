# FEEL 代币：Feelings 生态的唯一功能通证

> 作者：qc
> 日期：2026-04-22
> 核心：FEEL 是纯功能型代币，只负责流转、结算、计费、燃烧，不承载任何治理权力

---

## 一、定位一句话

**FEEL 是 Feelings 生态内唯一功能通证（Utility Token），不是治理代币，不承诺收益，不由持仓决定任何决策权。**

---

## 二、为什么是纯 Utility，不做治理代币

### 2.1 治理代币和 GOVERNANCE 直接冲突

```
GOVERNANCE 的核心设计
    BDFL 否决权：qc 对哲学红线有不可撤销的最终否决权
    技术可共治，哲学必独裁
    社区可以 fork，绝不允许政变

治理代币的逻辑
    持仓量 → 投票权
    多数投票 → 可以改变协议方向
    资本可以通过大量买入代币获得话语权

两者的冲突
    治理代币 = 用金钱买决策权
    这和 BDFL 原则直接对立
    资本买入足够多的 FEEL 就能投票推翻 GOVERNANCE？
    这是 Feelings 绝对不允许的事
```

**治理代币违背 Feelings 的核心设计原则，从第一天就排除。**

### 2.2 Utility 场景已经足够强

```
不需要靠「治理」讲故事
真实使用场景已经闭环

感受包支付        用户购买感受包，用 FEEL 支付
创作者分成结算    平台向创作者支付分成，用 FEEL 结算
存储服务计费      设备数据的云端备份服务，FEEL 计费
计算服务计费      四诊合参的云端辅助计算，FEEL 计费
链上手续费        生态内交易的 gas 消耗
生态唯一计价单位  所有服务的价格以 FEEL 标价
```

全是高频、闭环、真实的使用场景——不需要治理叙事支撑，代币本身就有价值支撑。

### 2.3 合规层面最友好

```
Utility Token 的监管特征
    不承诺分红
    不承诺收益
    不由持仓量决定决策权
    持有者权益仅限于使用生态服务

全球监管压力最小
    完美避开证券定性风险（Howey Test）
    不需要在大多数司法管辖区注册为证券
    监管路径最清晰

治理代币的合规风险
    如果投票决策影响代币价值
    监管机构可能认定为证券
    这是 Feelings 不需要的麻烦
```

## 三、FEEL 的使用场景

### 3.1 消费端（用户花 FEEL）

```
感受包购买
    用户用 FEEL 购买创作者发布的感受包
    一次性买断或订阅制，价格由创作者定
    平台收取运营费（FEEL），剩余转给创作者

存储服务
    用户的感受地图、体验历史的云端备份
    按存储量 + 时间计费，FEEL 支付

计算服务
    需要云端辅助的高级四诊合参功能
    按调用次数/算力消耗计费

硬件激活
    新设备激活时消耗少量 FEEL（防止刷号）
    见 docs/device-identity.md
```

### 3.2 创作端（创作者收 FEEL）

```
感受包销售分成
    用户购买感受包 → 平台扣运营费 → 剩余转创作者
    全程 FEEL 结算，链上透明

官方感受包奖励
    Feelings-Patterns 的官方贡献者
    按贡献质量和使用量获得 FEEL 奖励

社区贡献奖励
    文档贡献、翻译、社区建设
    按贡献量获得 FEEL 奖励
```

### 3.3 B 端（企业用 FEEL）

```
Engine API 调用
    企业接入 Feelings Engine API
    按调用量消耗 FEEL（或直接法币结算后系统内转换）

硬件设备激活
    企业批量激活设备
    每台设备消耗 FEEL 完成链上注册

数据服务
    脱敏统计数据的访问权限
    企业按查询量消耗 FEEL
```

## 四、FEEL 的燃烧机制

燃烧让 FEEL 有通缩压力，长期供需平衡。

```
燃烧触发场景
    设备激活          消耗 X FEEL（一次性燃烧）
    感受包平台运营费  平台收取的运营费，50% 燃烧，50% 进存储池
    存储服务费        按比例燃烧
    API 调用手续费    按比例燃烧

燃烧的逻辑
    生态越活跃 → 燃烧越多 → 流通量减少
    不是人为操控，是使用量驱动的自然通缩
    燃烧比例由治理（qc）决定，不由代币投票决定
```

## 五、FEEL 和存储池的关系

```
法币收入（硬件销售/企业订阅）
    → 进入存储池（银行托管，见 storage-pool-governance.md）
    → 存储池按需兑换 FEEL 用于生态内支付

FEEL 收入（感受包平台费/API 手续费）
    → 部分燃烧
    → 部分进入存储池（折算法币）
    → 存储池统一管理

关键原则
    存储池不直接持有大量 FEEL
    FEEL 不是 Feelings 的储备资产
    法币 + 银行托管才是 Feelings 的真实储备
    FEEL 是生态内的流通媒介，不是价值储备
```

## 八、FEEL 不是什么

```
❌ 不是治理代币（不承载任何投票权）
❌ 不是证券（不承诺收益/分红）
❌ 不是 Feelings 的储备资产（法币才是）
❌ 不是投机工具（没有人为价格支撑机制）
❌ 不是 Feelings 的核心商业模式（ToB 法币收入才是基本盘）
```

**FEEL 是生态内流通的工具。工具就该像工具，不该承担它不该承担的重量。**
