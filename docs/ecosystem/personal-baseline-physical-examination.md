# 个人基线建档体检——佩戴前的体检

> 作者：qc
> 日期：2026-08-12
> 性质：生态设计——入职有入职体检，佩戴 Feelings 前也有体检——个人基线建档
> 核心：冷启动从"零数据探索"升级为"有先验校准"——DXA/血液/病史单作为原始数据接入——安全阈值第一天个体化——医院合作三方共赢（医院获客/Feelings 获黄金数据/用户获筛查）——静态金标准初始化，动态 PBM 追踪趋势——互补不替代。

---

## 一、入职体检的类比——佩戴前体检

入职有入职体检。佩戴 Feelings 前，也有体检——个人基线建档体检。

```
入职体检：雇主在录用前：建立员工的身体档案
          评估风险：决定岗位适配
          入职后：日常绩效追踪

佩戴前体检：Feelings 在激活前：建立用户的身体档案
           评估风险：决定安全阈值
           佩戴后：PBM 日常趋势追踪

同一个结构：先建档：后使用
    建档 = 先验数据（你是谁：出厂状态）
    使用 = 动态数据（你现在怎么样：趋势）
    先验初始化：动态追踪
    没有先验：冷启动是零数据探索
    有先验：冷启动是校准
```

## 二、冷启动的升级——从探索到校准

```
之前（零数据探索）
    Session Zero：广谱采集：推荐系统同构
    基线靠"猜"：安全阈值用通用默认
    探索期长：个体化来得慢

现在（有先验校准）
    佩戴前体检：原始数据直接接入
    DXA（体成分金标准：测量成本可控）
    血液检测（激素/代谢/炎症状态）
    病史单（重大疾病/神经病史/家族遗传/过敏）
    冷启动第一天就有
        体成分基线（DXA 金标准）
        生化状态（血液）
        已知风险（病史：漏桶参数/安全阈值的个体化起点）
    ：基线建立从"探索"变"校准"
    ：安全阈值从第一天就个体化
    ：冷启动期缩短：模型从先验开始
    ：不假装估算不是估算：但估算有真值锚
```

## 三、体检内容——黄金数据的构成

```
DXA 双能 X 射线（体成分金标准）
    脂肪/瘦组织/骨骼：三成分
    误差 2-4%：比 BIA 高一个量级
    校准阻抗模型（AD5933 的阻抗→体成分公式
    用真值修正：通用估算变个体校准）

血液检测
    激素（皮质醇/甲状腺/性激素：内分泌基线）
    代谢（血糖/血脂：能量基线）
    炎症（CRP：慢性炎症状态）
    校准 PBM 的健康参数

病史单（必填：正式化）
    重大基础疾病（心血管/神经/代谢）
    神经类病史（癫痫/精神类用药）
    家族遗传病（UserProfile 健康字段）
    过敏史（影响可能的刺激类型）
    目的：安全阈值个体化 + 责任边界清晰
    （隐瞒病史导致的意外：Feelings 不担责
     诚实申报：安全参数才准）

基础检查：血压/心率/身高体重：常规项
    充实 UserProfile 的作息+身体字段
```

## 四、性别字段——先验、周期、定义权

性别是必填的基础字段，但它的职责比"统计标签"重得多——三条：

```
① 先验启动
   性别差异是生理事实：静息交感/迷走张力、HRV、皮温节律、
   完成态的形态（贤者时刻两性都有，刚性不应期男性专属——
   静默的判据因此不同）、陪等/可共振的分界、交感储备的预期水平
   → 处方模板的初始猜测，缩短冷启动，让先验第一天就上岗

② 周期建模（硬需求）
   月经周期是结构化的月度节律：黄体期体温升、HRV 变、唤醒基线漂
   → 如果 PBM 不知道周期相位，会把用户自己的周期读成"偏差"——
     基线中毒最隐蔽的一种：被用户自己的生理节律污染
   → 区间需要周期感知的归一化：慢路径里除了漂移之外的第二根轴
   → 90+ 当量账本也要周期修正：自主神经反应性、痛阈随相位变，
     同样的当量在不同相位不是同一笔账

③ 定义权在用户
   日常数据（HRV/皮温/作息/行为）确实能收敛出答案，
   但系统不推断——推断有敏感性：misgender、
   跨性别用户的生理与身份标签分离（PBM 跟踪的是生理，不是身份）
   → 体检问一次，标签由用户给，数据只当后验
   → 这和"不说教"是同一条线：系统可以知道，但不能替用户宣布
```

收口：**性别是先验，数据是后验。** 体检问一次，日常数据慢慢修正；而 PBM 的换基本身不依赖标签——它直接学用户的生理。标签的职责是给先验一个起点、给周期一根轴、给处方模板一个初值——仅此而已。

## 五、医院合作——三方共赢

```
医院（获客）：体检套餐导流：健康筛查业务
Feelings（获黄金数据）：金标准数据接入
    校准模型的真值：漏桶参数/安全阈值/PBM 初始化的
    个体化输入
用户（获筛查）：一次体检：查病 + 拿数据基础
    体检不白做：数据两用
"从上往下"的咬合
    医院合作 = 专业层合作（不是大众市场）
    医院背书 = 权威背书的起点（识货者验证
    医疗数据生态的位置：专业机构
    从上往下的第一站）
```

## 六、边界——静态金标准与动态 PBM

```
体检数据（静态金标准：一次测量）
    初始化：安全阈值/漏桶参数/模型起点
    不是日常数据：是"出生档案"
    "你出厂是什么样"

PBM 数据（动态信号：日常采集）
    趋势：感受地图：基线的日常漂移
    "你现在怎么样"

互补不替代
    体检初始化起点：PBM 追踪变化
    体检数据不能替代 PBM（静态不是动态）
    PBM 也不能替代体检（趋势不是真值）
    日常估算（随时：趋势）+
    定期金标准（每几个月：校准锚）
    估算不越跑越偏（定期被金标准拉回）
    像 GPS 差分校正：像传感器定期标定
```

## 七、分级模式——三条路径与核心取舍

理想工程流程和大众真实行为之间有落差：就算全套体检不算巨款，心理门槛、时间成本、麻烦程度会拦住绝大多数普通用户——很多人不会专门为一台穿戴设备跑医院做基线建档。不搞"必须做 DXA + 血检才允许开机"的一刀切强制——拆成三条现实路径，分层处理。

```
路径 1：理想完整模式（医疗级：医院合作版本）
    面向高风险使用场景、医疗临床人群
    强制完成基线建档体检（DXA/血检/病史表单）
    才解锁全部强度刺激能力
    完整安全方案：走医院渠道
    面向愿意付出时间金钱的用户

路径 2：消费开放模式（面向普通大众：妥协方案）
    不强制去医院做全套体检
    病史问卷必填（软件层面：零成本）
    癫痫/严重心脏病/颅内损伤/特殊精神用药等高危选项
    线上勾选申报
    命中高危条目：硬件底层直接锁死大功率刺激
    只保留微弱采集功能：强刺激不可启用
    零成本：底层安全依旧焊死
    没有 DXA/血检金标准真值：用通用保守默认参数
    Core 内核用保守偏低的默认刺激上限
    不用激进个体定制参数
    Profile 冷启动不靠医院快照
    靠设备自身长时间日常采集（PPG/HRV/皮肤阻抗）
    慢慢迭代出个人基线
    相当于把"医院一次性真值快照"替换成
    "设备长时间自采样"：慢一点：但能用
    代价：早期模型对身体认知模糊：策略保守
    效果上限打折扣：几周到数月 profile 才收敛贴合

路径 3：可选增值项
    APP 内提供对接合作机构入口
    用户自愿自费去做完整基线建档体检：上传报告
    金标准数据直接灌入 Profile
    立刻获得个体化阈值：缩短冷启动周期
    可选：不是强制
```

核心工程取舍：

```
医疗临床分支    强制全套体检：安全拉满
消费民用分支    必填病史问卷做最低安全闸门
               金标准体检改为可选增值服务

安全底线不分级：所有路径同一套
    最大电流/最长刺激时长的硬件硬上限
    永远焊死：不会因为没有医院体检数据而放开
    分级的是"个性化程度"（第一天个体化 /
    几周收敛 / 随时升级）
    安全永远是最高档：个性化可以降级

两条冷启动路径并存
    有先验（路径 1/3：第一天个体化）
    无先验（路径 2：几周收敛：原始冷启动
    推荐系统同构：设备自采样迭代）
    先验可随时补（路径 3：上传即升级）

承认缝隙
    逻辑可以写得完美闭环：但活生生碳基普通人的
    时间、钱包、惰性是不能忽略的缝隙
    不能拿理想流程强行要求全部人
    分级模式适配现实世界
    不搞一刀切强制：也不搞一刀切放水
    分级的边界：个性化可以降级：安全不能降级
```
