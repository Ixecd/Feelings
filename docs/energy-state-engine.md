# 能量状态与行为克制引擎

> 作者：qc
> 日期：2026-04-22
> 核心：识别你的能量状态，在巅峰时帮你保持强势，在耗尽前帮你守住底线

---

## 一、为什么需要这个引擎

```
常见的问题
    状态最好的时候不知道，没有充分利用
    开始耗尽的时候没有察觉，继续消耗
    等到真的垮掉了，才意识到应该早点停

Feelings 的角色
    持续监测能量状态
    在巅峰时告诉你「现在是你最强的时候」
    在下滑前告诉你「你还有多少」
    不替你做决定，只给你数据和建议
```

## 二、能量状态的量化模型

### 2.1 五个核心维度

```
生理储备（Physical Reserve）        0-100
    基于：HRV、睡眠恢复指数、运动疲劳、体温
    含义：身体还有多少可调用的能量

神经激活度（Neural Activation）     0-100
    基于：皮电基线、心率、呼吸频率、HRV
    含义：当前神经系统的激活水平（注意力、反应速度）

情绪稳定度（Emotional Stability）   0-100
    基于：HRV 变异性、皮电波动频率、睡眠 REM
    含义：情绪调节能力的储备

压力负荷（Stress Load）             0-100
    基于：皮质醇代理指标、HRV 压低程度、呼吸模式
    含义：当前承受的压力总量（越低越好）

恢复速率（Recovery Rate）           0-100
    基于：睡眠质量趋势、运动恢复速度
    含义：当前恢复能力的效率
```

### 2.2 综合能量指数（CEI）

```
CEI = 生理储备 × 0.30
    + 神经激活度 × 0.25
    + 情绪稳定度 × 0.20
    - 压力负荷 × 0.15（压力越高，CEI 越低）
    + 恢复速率 × 0.10

CEI 范围    0-100
```

### 2.3 状态分级

```
强势区（CEI 75-100）
    生理储备充足
    神经激活度高
    压力负荷低
    → 最适合：高强度体验、重要决策、创作、训练
    → 系统建议：充分利用，不要浪费在低价值事务上

高效区（CEI 55-74）
    状态良好但不是巅峰
    → 最适合：常规工作、中等强度体验、社交
    → 系统建议：正常推进，注意监测是否下滑

维持区（CEI 35-54）
    能量开始消耗
    神经激活度或生理储备开始下降
    → 最适合：轻度任务、维护性工作
    → 系统建议：减少高消耗活动，准备恢复

保护区（CEI 15-34）
    明显耗尽
    → 见弱周期保护机制文档
    → 系统建议：强制轻量化，不推送高强度感受包

临界区（CEI 0-14）
    接近崩溃
    → 只做兜底保护
    → 系统进入最小干预模式
```

## 三、强势状态维持引擎

当用户处于强势区（CEI 75+）时，系统进入强势维持模式。

### 3.1 不放松交感神经

```
强势状态的生理特征
    交感神经适度激活
    HRV 在中等偏高水平（不是最高，最高反而是过于放松）
    皮电基线稳定但有适度张力
    神经激活度在 70-85 区间

系统行为
    不主动推送「放松」类感受包
    不推送「入睡辅助」或「副交感激活」内容
    感受包推荐偏向「专注增强」「状态锁定」类型

为什么
    过度放松会打散当前的高激活状态
    损失可能需要几个小时才能恢复
    强势时候的副交感放松 = 主动丢失状态
```

### 3.2 状态锁定机制

```
用户进入强势区后
    系统标记「状态锁定窗口」
    预测这个状态能维持多久（基于历史数据）
    在窗口内：感受包推荐全部偏向「维持强势」

状态锁定期间的感受包策略
    允许：专注增强、能量循环、轻度神经激活
    不允许：深度放松、情绪释放、高度感官刺激（会打散注意力）
    不允许：高强度情绪体验（会消耗神经资源）

窗口结束提醒
    「你的强势窗口还有约 X 小时」
    不是催促，是信息
```

### 3.3 消耗预警

```
强势区内的消耗监测
    每 30 分钟计算一次 CEI 变化趋势
    如果连续 2 次 CEI 下降超过 5 点
    → 触发「消耗预警」

预警内容
    「当前状态开始消耗，建议减少高强度输出」
    不强制，不说你「应该」怎样
    只提供数据
```

## 四、行为克制引擎

### 4.1 什么是行为克制引擎

```
不是道德约束
    Feelings 不评判用户的行为选择

是能量层面的提醒
    「这件事会消耗你 X 点能量」
    「基于当前状态，这个选择的代价是...」
    「你还剩 Y 点储备，这件事会用掉 Z」
```

### 4.2 高消耗行为识别

```
系统识别的高消耗行为模式（基于信号变化）

情绪性决策
    皮电快速上升 + HRV 骤降 + 心率加快
    同时用户开始大量输入（打字/语音）
    → 可能：情绪化争论、冲动决定
    → 触发：「当前状态是否适合做这个决定？」

过度社交消耗
    持续 2 小时以上的高皮电状态
    HRV 持续下降
    没有运动触发
    → 可能：高强度社交消耗
    → 触发：「你已经高度激活 2 小时，是否需要安静一段时间？」

睡前高激活
    临近用户的惯常睡眠时间
    神经激活度仍然 > 70
    → 可能：影响睡眠质量
    → 触发：「距离你通常的睡眠时间还有 X 分钟，当前激活度偏高」
```

### 4.3 克制建议的原则

```
永远是建议，不是命令
    「基于你当前的状态，这个选择可能代价较高」
    不是「你不应该这样做」

给出具体的代价估算
    「这会消耗你约 15 点 CEI，预计恢复需要 4-6 小时」
    不是模糊的「对你不好」

时机选择
    在用户即将做出选择前提醒，不是在之后批评
    提醒只在用户有信号数据异常时触发，不主动打扰
    每天同类提醒不超过 3 次，防止疲劳
```

## 五、能量补给建议引擎

```
基于当前 CEI 和预测趋势
系统给出具体的补给建议

生理储备低时
    「建议：20 分钟的低强度有氧，而不是高强度训练」
    「建议：增加蛋白质摄入（你上次记录是 X 小时前）」
    不是营养师，不给具体食谱

神经激活度低时
    「建议：短暂的感官刺激（冷水洗脸、5 分钟快走）」
    「当前状态下咖啡因的效果预计比平时降低 30%」

压力负荷高时
    「建议：15 分钟的感受包（平静类）」
    「建议：减少下一个小时的信息输入」

情绪稳定度低时
    「建议：延迟高风险决策 2 小时以上」
    「当前状态下的情绪反应可能比平时更强烈」
```

## 六、和弱周期的边界

```
能量状态引擎的工作范围
    CEI > 35（维持区以上）
    在这个范围内做状态优化和克制提醒

进入弱周期（CEI < 35）
    能量状态引擎停止「优化」建议
    转交给弱周期保护机制（见独立文档）
    保护机制不做「提升」，只做「兜底」

边界的意义
    不是所有时候都适合「努力维持强势」
    弱的时候，最好的做法是停止干预
    等待自然恢复，不是强行推起来
```

---

*强势不是永恒的状态，是可以被识别、保护和延长的窗口。克制不是软弱，是对能量的精确管理。*
