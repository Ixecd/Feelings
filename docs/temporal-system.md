# 时间维度系统设计

> 作者：qc
> 日期：2026-04-05
> 来源：感受有时间结构，单次体验之外还有成长轨迹、季节性、和生命节点

---

## 一、感受有时间结构

所有已有的设计文档讨论的都是单次体验。但感受不是孤立的点，是有时间结构的线：

```
今天的感受基线        和三个月前不同
某类感受的持续缺失    是最近的，还是一直以来的？
感受的季节性          外部环境影响神经系统状态
成长的轨迹            你的感受地图，在过去一年里变了什么？
生命节点              生日、重要纪念日，是感受的天然锚点
```

Feelings 拥有用户完整的历史数据，这些数据不只是安全判断和评分校准的原料，是用户感受人生的一面镜子。

## 二、心动模式：补全感受缺失

### 设计逻辑

心动模式不是推你喜欢的，是推你缺的。

这是和所有推荐系统相反的逻辑——网易云「你可能喜欢」是基于偏好的强化，心动模式是基于缺失的补全。更接近营养配给：不是给你更多你爱吃的，是给你长期缺乏的那类营养。

```
标准推荐逻辑    你经常体验「专注」→ 推更多「专注」类感受包
心动模式逻辑    你经常体验「专注」，但从未体验「被理解」
               → 主动推「被理解」方向，帮你发现感受空白
```

### 触发条件

系统检测到以下情况时，激活心动模式建议：

```
某类感受维度    连续30天未体验
某类强度区间    长期回避（有访问权限但从未选择）
情绪档案空白    音乐平台数据显示长期缺失的感受维度
季节性低谷      个人历史数据显示某时段的感受活跃度下降
```

### 呈现方式

心动模式不是强制的，是一个轻提示：

```
「我们注意到你已经很久没有接触「归属感」这个方向了。
 要不要今天试试看？」
```

用户可以接受，也可以忽略。系统记录选择，但不强推。

### 意外的价值

偶尔的意外感受是可以接受的，甚至是有意设计的。

心动模式推出的感受包，用户可能完全没有预期。这个意外本身有价值——对未知的轻微开放，是自省能力成长的信号，也是感受空白被填补的起点。

## 三、季节性感受系统

### 问题的诚实面对

季节性是真实的神经科学现象：光照时长影响血清素分泌，温度影响外周神经敏感度，季节变化影响整体情绪基线。

但「四季」不是普适的：

```
北方用户    四季分明，春夏秋冬有清晰的感受边界
南方用户    季节模糊，「四季不分明」本身是一种感受体验
热带用户    只有旱季和雨季，完全不同的时间结构
极地用户    极昼极夜，感受的时间维度和大多数人完全不同
```

系统不假设所有用户都有四季。

### 实现逻辑

```
数据输入
    用户地理位置（城市级别，不需要精确坐标）
    当地实时气象数据（温度、光照时长、降水）
    用户个人历史：过去同期的感受基线和活跃度

系统判断
    当前时段对这个用户的「季节性特征」是什么
    不是按日历判断，是按用户历史数据和当地气象判断

感受推荐调整
    在心动模式的基础上，叠加季节性权重
    冬季光照减少 → 适当增加「温暖」「归属」类感受包的推荐权重
    梅雨季节 → 「沉静」类感受包更容易被接受
```

### 南方用户的「季节」

对季节感不明显的用户，系统用其他时间维度替代：

```
学期 vs 假期    对学生群体是真实的感受边界
工作周期        年底 vs 年初，节前 vs 节后
个人纪念日      对个体更有意义的时间锚点
```

「不分明」本身就是一种感受，系统不强行为南方用户制造四季框架。

## 四、成长轨迹：基准变化就是成长地图

### 什么是成长轨迹

个人基准会随时间变化。这个变化本身就是用户的感受成长地图：

```
基准提升    某类感受的耐受上限提高，感受精度提升
基准降低    某段时间的神经系统状态下降，承载上限收窄
基准扩展    新的感受维度被打开，地图变宽
基准稳定    某类感受已经内化，不再需要 Feelings 辅助触发
```

提升和降低都正常，没有高下之分。

### 系统的角色

系统观察基准变化，给出建议，不做评判：

```
基准持续提升
    「你在这个方向走得很稳，可以考虑探索相邻的感受维度了」

基准明显下降
    「最近几周你的状态和平时有些不同，要不要先从轻一点的地方开始？」
    不问原因，不给诊断，只调整推荐，提供支撑

基准长期稳定在同一区域
    「你在这个感受维度已经很稳了。Feelings 在这里的作用越来越小，这是好事」
    反依赖引导的一部分
```

### 年度回顾

每年，系统生成一份用户的感受年度报告：

```
内容
    这一年你探索了哪些感受维度
    你的基准在哪些方向发生了变化
    你的感受词汇丰富了多少（自省能力的代理指标）
    你今年第一次接触的感受类型

呈现方式
    不是数据报表，是叙事
    「这一年，你第一次知道了什么叫做『释然后的平静』……」

隐私
    报告只对用户自己可见，永远不对外
```

## 五、生日：系统记得你

用户生日当天，Feelings 做一件事：

送一个感受包。

不是「快乐」——那太轻了。

是一个和「你走过了这一年」有关的感受：带点重量，带点回望，带点对接下来的期待。

```
感受包构成（示例）
    主旋律    一种沉静的完整感（60%）
              「你在这里，你走过来了」
    点缀A     轻微的感慨（20%）
              时间流过去了，有什么变了
    点缀B     向前的隐约期待（20%）
              还有更多，还可以继续
```

不同年龄、不同个人基准的用户，收到的生日感受包参数会有差异——系统根据这一年的个人数据，给出最适合这个人此刻的版本。

附带一句话，不是营销文案，是系统真的「说」的：

**「你又走过了一年。这一年，你的感受地图变了什么样？」**

## 六、时间维度与其他系统的交叉

```
与闭环系统
    时间维度数据是个人基准的历史版本
    基准的时间序列，构成成长轨迹

与心动模式
    季节性权重叠加在感受缺失检测之上
    时间节点（生日/年度）触发特殊推荐逻辑

与自省系统
    年度回顾是最大规模的自省引导
    成长轨迹可见，帮助用户「看见自己变了」

与安全系统
    基准持续下降是安全信号
    系统在这个信号出现时，保守调整可访问强度上限
```

---

*时间维度系统让 Feelings 从单次体验工具，变成陪伴用户成长的长期系统。*
