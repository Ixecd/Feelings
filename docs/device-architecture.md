# 设备架构设计：一套设备，协作运行

> 作者：qc
> 日期：2026-04-05
> 核心：Feelings 不是一个设备，是一套设备，缺了少那部分功能，不影响其他

---

## 一、基础假设的改变

原来的假设：

```
耳后 + 后颈 = 一个完整设备
缺了 = 无法使用
```

正确的假设：

```
每个设备负责一个感受维度或信号层
有什么用什么
缺了 = 少那部分功能，其他继续工作
```

这个改变有一个根本性的影响——**渐进式接入**。

用户不需要一次买齐整套。从一个设备开始，体验基础功能。根据自己的需要，逐步扩展。每增加一个设备，系统能力扩展一层。门槛低，天花板高。

## 二、设备分工

每个设备负责特定的神经通路和信号维度：

### 耳后设备（核心设备）

```
位置        耳后乳突区域
神经通路    迷走神经耳支（Arnold 神经）
职责
    信号输入    听觉通路（音乐系统第三层信号）
    信号输出    迷走神经刺激（情绪基调调节）
    采集        心率、基础皮肤电导
覆盖感受    情绪基调类（平静/焦虑/愉悦/低落的方向性调节）
```

**这是唯一的必选设备。** 其他设备都是扩展。

---

### 后颈设备

```
位置        颈椎 C3-C5 区域
神经通路    脊髓背根 + 本体感受通路
职责
    信号输入    本体感受注入（身体在空间中的存在方式）
    信号输出    姿态感知信号
    采集        体温变化、运动状态、设备佩戴检测
覆盖感受    本体感受类（身体感、空间感、姿态感）
            「训练10年的运动员的身体感」需要这个设备
```

---

### 腕部设备

```
位置        手腕内侧
神经通路    外周神经 + 皮肤感受器
职责
    信号输入    细粒度触觉反馈
    信号输出    皮肤电导精确采集
    采集        皮肤电导（高精度）、血氧、呼吸频率估算
覆盖感受    细粒度情绪信号（感受的「质地」和「湿度」）
            点缀感受的精确传递依赖这个设备
```

---

### 颞部设备

```
位置        太阳穴区域
神经通路    颞叶皮层 + 额叶通路
职责
    信号输入    专注/冥想类感受的精确注入
    信号输出    初步脑电采集（EEG）
    采集        前额叶激活状态（意志力/认知负荷指标）
覆盖感受    认知状态类（深度专注、冥想、创造力涌动）
            意志力张力状态的识别需要这个设备
```

---

### 未来设备（随神经科学进展定义）

```
当前神经科学无法精确支持的感受维度
等待技术成熟后定义对应设备
设备协议预留扩展位，不需要重新设计整个系统
```

## 三、设备组合与能力覆盖

不同组合对应不同的感受覆盖范围：

```
组合                        能力覆盖
────────────────────────────────────────────────────────
只有耳后                    基础情绪基调 + 简单感受引导
                            音乐系统完整工作
                            安全监测：心率（基础）

耳后 + 后颈                 加入本体感受维度
                            姿态感、身体存在感可传递
                            安全监测：心率 + 体温 + 运动状态

耳后 + 后颈 + 腕部          完整感受闭环
                            点缀感受精度大幅提升
                            安全监测：全指标覆盖，精度最高
                            个人基准建立速度最快

耳后 + 后颈 + 腕部 + 颞部   最完整
                            认知状态类感受完整支持
                            意志力张力状态可识别
                            EEG初步采集开启
```

## 四、感受包的设备依赖标注

每个感受包标注完整体验所需的设备，以及降级体验的能力描述：

```
feeling_package {
    ...
    device_requirements {
        full_experience     [耳后, 后颈, 腕部]    // 完整体验所需
        minimum_required    [耳后]                 // 最低可体验配置
        degradation_map {
            [耳后]              "基础情绪轮廓，本体感受和细节缺失"
            [耳后, 后颈]        "加入本体感受，细节精度有限"
            [耳后, 腕部]        "情绪细节完整，本体感受缺失"
        }
    }
}
```

用户缺少设备时，系统不报错，提示降级：

```
「你现在能体验到这个感受的基础轮廓」
「增加腕部设备可以体验到完整的感受质地」
```

不是「你不够」，是「你还可以更多」。

## 五、设备间协作协议

多个设备同时工作时，需要协调机制：

### 主设备选举

```
耳后设备    永远是主设备（必选）
其他设备    向主设备注册，成为从设备
主设备      负责时钟同步、信号协调、与 App 的主通信
```

### 信号同步

```
目标要求    所有设备的采集时钟同步误差 < 1ms
现实约束    标准BLE最小连接间隔为7.5ms，无法满足此要求
            ⚠️ 这是一个专项研究问题，尚无定论

可能的解法方向
    专有无线协议（放弃标准BLE兼容性）
    超宽带（UWB）时间同步
    放宽同步要求至可接受误差范围（待神经科学确认可接受阈值）
    主设备做信号后处理时间对齐（软件补偿）

当前处理
    标注为研究课题，原型阶段重点验证
    在明确可行方案之前，同步精度要求保持开放
```

信号注入的时序由主设备统一调度，感受曲线的实时变化主设备广播给所有从设备。

### 设备掉线处理

```
从设备掉线    系统检测到，记录，降级到对应组合的能力范围
              不中断体验，不提示用户（除非影响安全监测）
主设备掉线    体验立即终止，所有信号停止
              这是唯一的强制中断场景
```

## 六、设备管理（Layer 3）

设备套件在 Layer 3 的管理方式：

```sql
-- 设备套件（一个用户可以有多个设备）
CREATE TABLE devices (
    id               UUID PRIMARY KEY,
    user_id          UUID NOT NULL,
    hardware_id      TEXT UNIQUE,
    device_type      TEXT NOT NULL,     -- 'ear', 'neck', 'wrist', 'temple'
    firmware_version TEXT,
    is_primary       BOOLEAN DEFAULT FALSE,  -- 是否是主设备
    status           TEXT DEFAULT 'offline',
    capabilities     JSONB,             -- 该设备支持的信号类型
    last_seen        TIMESTAMPTZ
);

-- 用户当前设备组合
CREATE TABLE device_sets (
    id               UUID PRIMARY KEY,
    user_id          UUID NOT NULL,
    active_devices   UUID[],            -- 当前在线设备 ID 列表
    coverage_level   TEXT,              -- 'basic'/'standard'/'full'
    updated_at       TIMESTAMPTZ
);
```

## 七、渐进式接入的产品意义

「一套设备，缺了少那部分功能」不只是技术设计，是产品策略。

```
降低入门门槛    一个耳后设备即可开始
提供成长路径    每增加一个设备，体验明显扩展
避免全有全无    不会因为买不起全套就完全无法使用
符合使命        感受的民主化，从门槛开始
```

感受的民主化不只是内容的民主化，也是硬件接入的民主化。不同经济能力的用户，用不同的设备组合，都能找到属于自己的 Feelings。
