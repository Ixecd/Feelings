# 基线收敛与断裂追踪——不是算稳不稳，是算偏了多少

> 作者：qc
> 日期：2026-07-02
> 性质：设计稿——PBM 基线在人生事件下的偏移追踪
> 核心：基线收敛追踪的真正价值不是"看稳不稳"。是看那一帧——基线被人生事件整条掰断——然后重新长。新基线和旧基线之间偏了多少——偏完之后回弹还是停在了新的位置——这才是"认识自己"最关键的帧。

---

## 零、两个概念——收敛和断裂

**基线收敛**：在没有重大人生事件的平稳期——四维 PBM 的滑动窗口偏移幅度逐渐收窄。收敛本身不说明任何东西——只说明"这段日子没什么事情推动我。"

**基线断裂**：一个封闭活动、一次重大决策、一次失去或获得——四维中起码一维的偏移量在短时间内超过 DampingMatrix 的 freeze 阈值——**不是渐进的收敛——是整条基线被掰断了重长。**

```
基线收敛                              基线断裂
───────                               ──────
连续 10 个 session 偏移在阈值以内。       某一帧——情绪跳了 0.3——内脏掉了 0.2。
→ "这段日子——我的锚点在原地。"              → 30 天后——新基线停在了比旧基线偏了好几个刻度的地方。
→ 不坏。也不特别。                       → 不是"恢复"——是"变了"。
                                        → 这就是需要记录的那一帧。
```

---

## 二、断裂检测——实时

复用 DampingConfig 已有的跨维冻结阈值。不需要新建。

```
情绪阈值: 2.0
内脏阈值: 1.5
触觉阈值: 3.0
听觉阈值: 2.0

每 session 后，逐维计算：
  delta = abs(pbm_snapshot[d] - pbm_baseline_sliding_p50[d])

  if delta > threshold[d]:
    → 标记 break_event[d]

  if 过去 7 个 session 内 >= 2 维同时触发：
    → 触发 BaselineBreak 事件
    → 关联最近的 life_history 决策 entry（如果存在）
    → 关联最近的高压场景标签（工作/家庭/健康/关系）
```

## 三、断裂之后——两个出口

```
回归型断裂（30 天后回到断裂前基线）
  type: "regression_break"
  break_vector: [+0.31, -0.18, -0.05, +0.02]
  recovery_vector: [-0.29, +0.16, +0.03, -0.01]
  recovery_days: 23
  含义: 被推远了——自己弹回来了。

驻留型断裂（30 天后新基线稳定在偏离位置）
  type: "persistent_shift"
  break_vector: [+0.24, -0.12, -0.08, +0.01]
  stable_at_30d: [+0.22, -0.10, -0.09, +0.02]
  含义: 变了。新基线不再是以前那个人。
```

回归型=韧性好。驻留型=这次人生事件把这个人推到了一个新的坐标。两种都是正常反应——没有哪条更好。只记录。

---

## 四、和人生历史日志的咬合

每次断裂——往上一帧找：**他之前在 life_history_log 里签过哪一条决策。**

```
life_history entry (决策那帧)           baseline_break entry (断裂之后)

"选了去字节——别后悔"                    之后 7 个 session——情绪飙了。
                                      25 session 后——停在了比之前偏了 0.28 的位置。
→ 不是"选错了"。                        → 也不是"选对了"。
→ 是这次选择——把锚点推到了一个新的坐标。     两条 entry 合在一起——一个人怎么被自己的决策改变了方向。
```

不是归因。是**让用户自己看见——那一次他签字的决策——之后他的身体偏了多少。**

## 五、数据结构

```
struct BaselineBreakEvent {
    timestamp: DateTime,
    session_id: u64,
    break_dimensions: Vec<Dimension>,
    break_vector: [f64; 4],
    linked_life_log_entry_id: Option<String>,
    linked_context_tags: Vec<String>,      // "work", "family", "health", "relation"
    recovery_type: Option<BreakType>,      // 30天后填入
    recovery_vector: Option<[f64; 4]>,
    recovery_days: Option<u32>,
    pbm_before: [f64; 4],
    pbm_after_30d: Option<[f64; 4]>,
}
```

## 六、用户回看——不是诊断

教练自省面板上——按时间轴列出每一次断裂——旁边放几条可能关联的人生决策。不替用户解释因果。只让用户自己看——"那一帧我做了某个选择。之后我的身体偏了多少。回去没有。还是停在了新的地方。"

```
2025-10  career  →  去字节之后——情绪维度一直高企了三个月。
                     不是焦虑。是新的环境一直在往同一个方向推。
                     没回弹。就是变了。
2026-03  health  →  做完手术——内脏维度掉了一大截。
                     后来慢慢回来了。37 天。完全回到原来那条基线。
```

不是评估对错。是**让用户认识——每一次人生事件——把他的锚点推到了哪个坐标。**

---

*基线不在原地——不是退步。是那次选择、那段经历、那次受伤——把锚点从旧坐标推到了新坐标。回弹了 = 韧性好。没回弹 = 变了。两种都是人该有的样子。认识自己的方式——不是回头看不变的自己在哪。是看自己偏了多少——在每一段人生后面——停在了新的位置。*
