# 强度刻度设计：100档对数分布

> 作者：qc
> 日期：2026-04-05
> 来源：对感受强度量化问题的系统性思考

---

## 一、为什么不是 10 档

10 档是直觉上的整洁，但感受不是线性的。

60 到 61 和 90 到 91 之间的神经冲击密度，不在同一个量级。用同样的粒度覆盖这两个区间，意味着在最关键的高强度区丢失了精度——偏偏那里才是最需要精确控制的地方。

**10 档的粒度在低强度区浪费了，在高强度区不够用。**

100 档解决这个问题，同时为对数分布提供了足够的空间。

---

## 二、上限的锚点

感受强度的上限不能是主观的"感觉很强"，需要有据可查的人类极限体验来校准。

90 的参照系：一个月内 150 次极端心理压制的累计神经冲击当量。

这里需要拆清楚一件事：极端体验的强度来自两件事的叠加——

```
生理机制：触发人体底层生存反射
心理机制：无法预判何时停止，持续的失控感
```

Feelings 注入的是神经信号，不是生理刺激本身。所以 90 的含义是**对神经系统造成等量冲击的感受强度**，不是复现具体的生理刺激场景。

**用极限锚定上限，是给整个刻度体系一个诚实的边界。**

90-100 存在的意义不是让人用，而是承认人类极限在哪里，同时向用户明确：Feelings 知道那条线在哪，并选择不轻易越过它。

---

## 三、对数分布：四个区间

```
1 ─────────────────────────────────────────── 100

│        │              │         │    │     │
1       30             60        80   90   100

探索区    成长区          高强度区   极限区  理论上限
```

### 探索区 1–30

**特征**：细粒度，日常可用，感受差异小但真实
**门槛**：无，新用户默认可访问
**体验描述**：感受的轮廓是清晰的，但强度在日常经历的范围内
**设计意图**：让用户建立对感受的基本语言和敏感度，找到自己的基线坐标

---

### 成长区 30–60

**特征**：每 10 档是一个明显的台阶，感受开始超出用户的日常经历边界
**门槛**：需要一定的使用历史积累，系统对用户的耐受模式有基本了解
**体验描述**：开始接触到自己从未经历过的感受密度，可能出现"原来可以是这样的"的认知更新
**设计意图**：真正的扩展发生在这里，是 Feelings 核心价值的主要兑现区间

---

### 高强度区 60–80

**特征**：需要解锁，设备实时监测生理状态，系统保持主动干预能力
**门槛**：使用历史 + 生理状态双重评估通过
**体验描述**：感受强度进入普通人在极端现实场景下才能触及的区间
**安全机制**：
- 设备持续采集心率、皮肤电导等生理指标
- 触发异常阈值自动降档或切换至平静保底包
- 单次会话时长上限

**设计意图**：这是对比协议（contrast-protocol.md）发挥最大价值的区间——高强度的反差，带来最大的感受密度

---

### 极限区 80–90

**特征**：需要专项评估，类比"拿到驾照才能上高速"
**门槛**：专项评估 + 知情确认 + 推荐有陪同的初次体验
**体验描述**：接近人类日常生活条件下感受体验的上限
**设计意图**：为真正有需要的用户（高耐受、有目的性的探索者）提供诚实的通道，而不是用设计上的模糊来掩盖这个区间的存在

---

### 理论上限 90–100

**特征**：可能永远不对普通用户开放
**定义**：90 对应人类已知极限体验的神经冲击当量，100 是理论边界
**存在意义**：
1. 给整个刻度体系一个诚实的顶点
2. 强迫设计者始终清楚"我们在做什么量级的事情"
3. 向用户透明：这条线存在，Feelings 知道它在哪里

---

## 四、粒度分布的非均匀性

100 档不是等距的 100 个刻度，不同区间的感受密度差异决定了粒度的实际意义：

```
区间      有效分辨率    设计理由
1-30      高            用户在这里建立感受语言，需要细粒度
30-60     中            台阶式跃迁，每级都是明显的边界跨越
60-80     中高          精确控制比细粒度更重要
80-90     极高          每一档的差距在这里都是实质性的
90-100    理论存在      不面向实际使用场景设计
```

## 五、解锁逻辑：TCP拥塞控制模型

强度不是付费解锁的，是**耐受历史解锁**的。解锁机制仿照TCP拥塞控制——慢启动，指数增长，异常退避。详见 `docs/safety-system.md` 第三节。

### 慢启动

```
第一次体验    强度上限极低（5分以内）
此后每次无安全事件    指数增长（5→10→20→40...）
触碰区间边界    暂停增长，等待主动解锁申请
```

### 区间门槛（增长到此自动暂停，需额外条件）

```
60分    需要主动申请 + 生理评估通过
80分    需要专项评估 + 知情确认
90+     不对普通用户开放
```

### 退避机制

```
触发级别二安全事件    退回上一档
触发级别三安全事件    退回慢启动起点
触发级别四安全事件    锁定保底区间，需人工评估
```

四个区间描述的是感受密度特征和安全要求，不是固定的访问范围。用户的实际可访问上限由TCP模型动态决定，不是由区间标签决定。

## 六、与盲选模式的交叉

盲选模式（contrast-protocol.md）和强度刻度是两个独立的维度，但交叉出一个重要的设计约束：

**盲选 + 高强度 = 系统责任最重的组合。**

用户不知道接下来是什么，同时强度在 60 以上——这时系统对感受内容的选择权最大，对应的安全责任也最重。

在这个交叉区间，系统的"判断 B"（能不能给，见 contrast-protocol.md 第五节）的权重要高于"判断 A"（给什么）。宁可降档，不可误判。
