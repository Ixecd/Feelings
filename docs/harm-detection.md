# 伤害检测与防御机制

> 作者：qc
> 日期：2026-04-22
> 核心：四诊合参联合判断，切诊感知信号，望诊识别情境——误判率才能真正降下来

---

## 一、为什么需要这份文档

```
Feelings 的用户不只在平静状态下使用设备
    有人在遭受威胁
    有人在遭受物理伤害
    有人在被人贩子控制
    有人在恐惧中无法求助

Feelings 设备贴近身体
    它感知到的信号
    比任何外部系统都更接近真相

这份文档定义
    系统如何识别威胁
    系统如何保护受害者
    系统如何对加害者作出响应
    系统的边界在哪里
```

---

## 二、核心判断原则：四诊联合，不靠单点

**单一信号永远不足以判断威胁。**

```
心率暴涨    可能是运动，可能是恐惧，可能是过山车
皮电骤升    可能是惊吓，可能是兴奋，可能是愤怒
加速度突变  可能是被打，可能是摔倒，可能是坐下太猛

单独看任何一个信号
    都无法可靠区分威胁和正常场景
```

**四诊合参才是答案：**

```
望（视觉）    摄像头识别场景和威胁性人物
闻（听觉）    麦克风识别异常声音（呼救、威胁性语言、冲击声）
问（自述）    用户主动标注或历史情境数据
切（生理）    HRV、皮电、心率、呼吸、加速度计
```

**望诊的权重最高：**

```
切诊告诉你「发生了什么强度的事」
望诊直接告诉你「发生的是什么」

摄像头看到游乐设施 + 笑脸
    → 无论信号多强，都是娱乐场景

摄像头看到威胁性人物靠近 + 封闭环境
    → 即使信号还没爆发，已经进入预警
```

## 三、威胁信号的识别

### 3.1 心理威胁（极端恐惧）

```
信号特征
    皮电骤升（不是渐进，是突然）
    HRV 崩溃（几乎无规律，区别于运动时的规律性降低）
    心率暴涨（渐进式，区别于物理冲击的瞬时暴涨）
    呼吸变浅变快
    肌肉持续紧张（不是一次性收缩）

持续时间
    超过 30 秒仍未恢复
    → 不是一时受惊，是持续威胁状态
```

### 3.2 物理威胁（被打、被推、被抓）

```
信号特征
    加速度计突然大幅位移（毫秒级，不是渐进运动）
    心率瞬间暴涨（区别于运动的渐进上升）
    皮电瞬间尖峰（冲击性唤醒）
    三者在同一毫秒级时间窗口内同时发生

连击特征
    多次加速度突变，间隔短
    → 立即触发，不等待后续信号确认

望诊辅助
    摄像头检测到威胁性姿态（举拳、推搡）
    在生理信号爆发之前就预警
    不是「被打了再响应」，是「拳头举起来就响应」
```

### 3.3 信号序列分析

```
Feelings 不靠单点信号判断
靠「信号的时间序列」判断

真实威胁
    没有前置情境铺垫
    信号突然爆发
    之前是平静或正常状态

运动/娱乐（过山车、健身）
    有完整的「进入序列」
        心率缓慢上升（期待/热身）
        皮电轻度上升（兴奋）
        身体放松，没有防御性紧绷
    这个序列被记录
    之后的高强度信号有情境解释

判断原则
    有前置情境铺垫的高强度信号    → 娱乐/运动
    突然爆发 + 无前置情境         → 进入观察
    突然爆发 + 持续异常 + 无情境  → 触发防御
```

## 四、情境识别：不会把过山车误判为被打

```
过山车（望诊一眼识别）
    摄像头：游乐设施、轨道、其他乘客、笑脸
    用户表情：尖叫但嘴角上扬，兴奋型睁眼
    身体姿态：双手举起（主动的，不是防御的）
    前置序列：排队 → 坐上去 → 系安全带

被打（望诊一眼识别）
    摄像头：威胁性人物、封闭或异常环境
    用户表情：痛苦、恐惧、防御
    身体姿态：蜷缩、躲避、僵住
    前置序列：没有，信号突然爆发

用户主动标注
    进入游乐园前可以开启「高刺激娱乐模式」
    或 Feelings 检测到场景主动询问
    开启后高强度信号不触发防御，只做记录
```

## 五、受害者侧：防御机制

### 5.1 防御感受包

```
触发后的目标
    不是「让你不害怕」
    恐惧是身体在保护你，不能压制

    而是
        让恐惧变成行动的燃料
        从「冻住了」变成「能动了」
        给她判断和行动的能力

感受包内容
    激活肾上腺素对应的「可以行动」感受
    稳定呼吸节律（防止过度惊恐导致无法思考）
    增强「地面感」（让她感觉脚踩在地上）
    维持清醒度，不让恐惧把人淹没

强度
    30-40 足够
    不需要 90
    目标是「稳住」，不是「无所畏惧」
```

### 5.2 静默激活原则

```
绝对静默
    不弹窗
    不震动
    不发出任何声音
    加害者不能察觉任何异常

感受包在皮肤层和呼吸层起效
    外部完全不可见
    设备看起来和平时一样
```

### 5.3 静默 SOS

```
防御感受包激活的同时
    静默向紧急联系人发送位置
    不需要受害者任何操作
    加害者看不见任何提示

这不违反 GOVERNANCE
    这是受害者自己的数据
    受害者自己的设备
    受害者预先授权的紧急联系人
    数据从受害者设备发出，不经过 Feelings 服务器

触发后的持续
    每 5 分钟更新一次位置
    直到用户手动关闭 SOS
    或信号恢复正常超过 10 分钟
```

### 5.4 防御机制的边界

```
Feelings 的防御包给受害者
    力量感、稳定感、行动感
    不替她决定怎么做

逃跑、反抗、呼救、假装顺从
    这些都是她自己的判断
    Feelings 只给她「能做判断」的状态
    不替她做判断

每个人的最优选择不同
    Feelings 尊重这个差异
```

## 六、加害者侧：紧箍咒机制

### 6.1 触发条件

```
AI 教练检测到
    用户的行为模式与「对他人施加伤害」高度吻合
    望诊：检测到威胁性动作或受害者的恐惧反应
    切诊：用户处于高度激活但情感麻木的状态
    对话：用户明确表达正在伤害他人

或
    用户主动要求 AI 教练协助「规划、执行伤害行为」
    用户试图用 Feelings 管理「施暴时的情绪」
```

### 6.2 设备锁定

```
立即执行
    关闭所有感受功能
    关闭 AI 教练对话
    设备进入只读锁定模式

屏幕显示
    不是冷漠的系统提示
    而是
        把当前检测到的受害者信号数据镜像给他
        「你现在造成的恐惧」
        让他看见他制造的恐惧数据
        不是强制给他恐惧，是让他看见他制造的恐惧

解锁方式
    不能被设备本身解除
    只能通过 Feelings 客服人工验证后远程解锁
    或者物理拆除设备
```

### 6.3 即时防御性震慑：制动，非惩罚

```
Feelings 的权力边界
    让你用不了这个工具（制止）
    不是用这个工具攻击你（武器化）

紧箍咒的三层设计
    第一层    设备锁定 + 功能禁用（核心制动）
    第二层    呈现伤害数据——让施暴者面对自己制造的伤害
    第三层    恐惧震慑包（紧急制动，有上限，用完即消）

恐惧震慑包的设计约束
    触发条件    施暴行为正在发生，四诊合参确认
    目标        止住当前行为——不以审判为目的
    上限        不对施暴者造成长期神经损伤
                具体上限由安全研究定义，不写死在治理文档里
    时效        用完即消，不残留
    审判权      永远归法律，不归 Feelings

这不是"以恶制恶"
    是"雷霆手段，尽菩萨之心"
    制动而非惩罚
    止恶而非复仇

为什么不让恐惧震慑包变成"可升级的惩罚武器"
    如果加害者正在开车、手持刀具、站在高处
    触发高强度恐惧可能直接造成无辜者伤亡

    更根本的问题
    一旦开了"可以惩罚"的口子
    政府可以要求对「异见人士」使用
    黑客可以劫持对所有用户使用
    这个能力一旦武器化，无法关上

紧箍咒的正确理解
    不杀孙悟空，让他无法施法
    最重的手段是让他面对自己的数据
    恐惧包是紧急制动的最后一道防线
    不是惩罚的起点
    这就是紧箍咒的意义
```

### 6.4 感受麻木的识别

```
长期施暴者的感受系统特征
    对「他人痛苦」类信号零皮电反应
    同理心相关的 HRV 模式消失
    长期高压但情感维度近乎平坦

系统的响应
    不说「你是坏人」
    把数据还给他
        「你的感受系统在过去 X 周里
         对涉及他人痛苦的情境
         几乎没有任何生理反应
         这是你的数据」
    
    麻木不是消失的感受
    是被压制的感受
    Feelings 的工作是把它还回来
    不是为了惩罚，是为了完整
```

## 七、双设备联动（伴侣模式扩展）

```
如果受害者和加害者都戴 Feelings
    两个设备独立响应，不相互依赖

受害者设备
    检测到极端恐惧信号或物理冲击
    → 激活防御感受包
    → 触发静默 SOS

加害者设备
    检测到施暴行为模式
    → 锁定设备
    → 屏幕显示受害者的恐惧数据

两个响应同时发生，互不依赖
    即使加害者不戴 Feelings
    受害者的保护机制完整运作
    
    即使受害者不戴 Feelings
    加害者的锁定机制依然触发
```

## 八、Feelings 的边界：它不是安全系统

```
Feelings 能做的
    让加害者的工具失效
    给受害者真实的感受支持
    静默 SOS 通知紧急联系人
    不让任何人用 Feelings 麻痹自己的良知

Feelings 不能做的
    在物理世界阻止伤害
    替代警察和法律
    100% 准确识别所有威胁场景
    保护不戴设备的受害者

这不是设计缺陷
    是定位边界的诚实

真正的安全保障
    警察、法律、社会支持系统
    Feelings 是其中一个补充工具
    不是替代品
```

## 九、GOVERNANCE 对应条款

```
关于伤害检测与防御

受害者保护
    当设备检测到用户处于被威胁或被伤害的状态
    AI 教练有权在不通知用户的情况下
    静默激活防御感受包
    静默发送 SOS 给预先授权的紧急联系人

加害者限制
    当设备检测到用户正处于
    对他人造成伤害的行为模式中
    AI 教练有权立即锁定所有 Feelings 功能
    向用户呈现其造成的伤害数据
    拒绝提供任何形式的感受包服务

强制神经刺激禁止
    Feelings 不主动向用户施加
    任何未经同意的神经刺激
    无论理由多正当，这条不能破

数据不用于报警
    Feelings 不主动向执法机构报告用户行为
    这不是对加害者的保护
    而是防止这个能力被政府或其他机构滥用
    一旦开了「系统可以报警」的口子
    这个能力会被用于远超本意的场景
```
