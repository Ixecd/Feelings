# 榜单与区域划分设计

> 作者：qc
> 日期：2026-04-05
> 来源：对感受民主化背景下社交竞争问题的系统性思考

---

## 一、为什么需要榜单

人有社交本能，回避它不如重新塑造它的形状。

纯私有化的分数解决了炫耀路径，但解决不了口口相传，也解决不了人对自我坐标的天然需求——我在哪里，我和周围的人比怎么样。与其让这个需求在产品之外自发形成不可控的比较文化，不如在产品内部给它一个被设计过的出口。

榜单的存在不是鼓励竞争，是**给竞争本能一个安全的容器**。

---

## 二、榜单的基本结构

### 多维而非单一

榜单按感受维度独立设立，没有总分榜。

```
上海长宁 · 归属感    前 6666 名
上海长宁 · 专注感    前 6666 名
上海长宁 · 平静      前 6666 名
上海长宁 · 失去      前 6666 名
...
```

每个感受维度是独立的竞技场。没有人能在所有维度同时进榜，这个结构性约束天然压制了"全能强者"叙事的形成空间。

当一个人说出自己在某个维度进榜，另一个人的第一反应大概率是"我在另一个维度也进了"——比较变成了互相发现，而不是单向的俯视或仰视。

### 6666

这个数字不是随意的。

大到不稀缺——在一个正常密度的区域里，进榜不是小概率事件，努力的人都有机会。小到仍然有意义——不是人人都有，仍然值得被记录。在中文语境里，6666 本身带着"顺"的文化含义，不是冷冰冰的技术参数。

---

## 三、分数的私有化边界

榜单存在，但分数本身彻底私有。

可以公开的：你进了哪个维度的榜单，在哪个区域。
不可以公开的：你的具体强度数字。

架构上不存在分数的公开路径——没有排行榜按分数排序，没有社交分享分数的接口，没有任何地方展示具体数字。榜单只告诉你"在不在"，不告诉任何人"是多少"。

**进榜是一个身份，不是一个数字。**

---

## 四、区域划分：密度优先，行政区划为参照

### 核心问题

城市粒度作为固定分区标准会在两端失效：

```
一线城市    用户过于密集    → 城市级榜单竞争烈度失控，新用户绝望
偏远地区    用户极度稀少    → 6666 覆盖全部活跃用户，榜单无意义
```

行政区划是人口管理的工具，不是用户密度的工具。用错了标准，榜单在不同地区的体验会完全失衡。

### 分区原则

**目标：每个榜单区域内，活跃用户数维持在 6666 的 3–10 倍之间。**

低于 3 倍，进榜太容易，竞争失去意义。高于 10 倍，进榜太难，新用户绝望。

行政区划作为初始参照系，实际分区由用户密度动态决定：

```
人口密集区    按区       上海长宁、北京朝阳、深圳南山
中等城市      按城市     成都、杭州、武汉
欠发达地区    按省       西藏、青海、内蒙古
海外          按国家     日本、美国（初期）
              按大区     东南亚、欧洲（用户密度不足时合并）
```

### 动态调整机制

分区不是静态的，跟着用户密度走：

```
扩张：某区域活跃用户超过 6666 × 10
      → 自动触发分区评估
      → 按地理或社区边界拆分为两个独立榜单

收缩：某区域活跃用户低于 6666 × 3 持续 90 天
      → 自动触发合并评估
      → 与相邻区域合并为更大的榜单区域
```

调整对用户透明——区域合并或拆分时，系统提前告知受影响用户，说明原因。

### 附带效应

区域榜单的独立存在，本身是用户密度的可视化。

一个地方有独立榜单，意味着那里已经有足够多的人在用 Feelings，一个本地社区正在形成。这个信号对新用户有吸引力：我所在的地方已经有一个 Feelings 社区了，我不是孤立的。

## 五、两类肯定机制

榜单只覆盖进榜用户，但 Feelings 需要对所有用户保持肯定。系统的肯定因此分为两层：

### 进榜肯定（竞争性，偶发）

```
你进入了上海长宁 · 归属感 前 6666 名
```

客观陈述，有说服力，但只在进榜时触发，对榜外用户沉默。

### 轨迹肯定（非竞争性，持续）

与任何人无关，只和用户自己的坐标变化有关：

```
上个月你第一次接触了「失去」这个维度
你在「专注」方向的耐受上限提高了 8 档
你已经连续 14 天保持了感受探索
```

这是大多数用户日常使用里真正感受到被看见的来源。进榜是偶发的、竞争性的；轨迹肯定是持续的、只属于你自己的。

**两层机制都要有，但优先级不同。轨迹肯定是基础，进榜肯定是加分项。**

---

## 六、系统引导的方向

当用户在某个维度表现弱时，系统的引导逻辑：

```
不是：你在这个维度比较弱
而是：你在这些维度有你自己的节奏
      这是你还没有深入探索的方向
      很多人在这里也是从这个位置开始的
```

系统永远不做跨用户的横向比较作为负面反馈。比较只发生在用户自己的时间轴上——你和一个月前的你比，不是你和别人比。

---

## 七、未解决的问题

**感受维度的数量边界**

榜单维度越多，每个人找到自己强项的概率越高，但维度过多会让榜单体系失去焦点。初期需要确定核心感受维度的数量上限，过早扩张维度可能稀释榜单的社交意义。

**跨区域流动**

用户搬家时，历史进榜记录如何处理？保留原区域记录还是迁移到新区域重新开始？这涉及到用户的感受身份认同问题，需要单独设计。

**榜单的时间窗口**

当前设计没有明确榜单是滚动更新还是周期性重置。滚动更新对老用户有利，周期性重置给新用户更多机会。这个选择会深刻影响榜单的竞争生态，需要在第一批真实用户数据出来后再做决定。

---

*榜单与区域划分是 Feelings 社交体系的核心框架，将随产品演进和用户密度变化持续调整。*
