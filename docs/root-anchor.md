# Root 锚点账号：系统的生存底线

> 作者：qc
> 日期：2026-04-17
> 核心：平时永远用不到，但只要用到一次，就能救整个系统一命
> 设计原则：人类主权始终成立，AI 是智能刹车而不是方向盘

---

## 一、为什么必须有这个账号

Feelings 是一个强规则、强权限、强自治的系统：

```
不可动摇的红线（GOVERNANCE）
    原始神经数据不出设备
    强度不以价格区隔
    永远不上市
    ……

多重保护机制
    TCP解锁系统
    四诊合参
    矛盾点检测
    年龄验证
    亲密感受维度隔离
    ……
```

规则越多，系统越严密，也越容易出现一种情况——

**系统把自己锁死了，包括把创造者也锁在外面。**

### 没有 Root 账号会发生什么

```
场景一：权限系统 BUG
    某次升级后，普通管理员不能管理管理员
    → 你登不进去，改不了，救不了

场景二：数据异常
    数据库异常、权限表被清空
    → 全系统没有任何人有最高权限
    → 系统直接瘫痪

场景三：自我保护机制反噬
    某天你真的需要重置某些数据
    → 规则拦住你：「您无权操作底层系统」

场景四：灾难性错误
    代码逻辑错误导致所有账号被降级
    → 没有上帝视角可以恢复
```

**没有 Root 的后果不是「严重」，是「致命级」。**

所有复杂系统都留终极后门——Linux 的 root，Windows 的 Administrator，数据库的 sa——这不是偏执，是基本素养。

## 二、为什么单人持有 Root 不够

单个密钥持有者是单点失败：

```
物理丢失    设备偷盗、ransomware、员工叛变
            → 整个锚点报废

社工攻击    钓鱼 2 次就能把系统炸掉（如果触发自毁）
            → 攻击门槛太低

创造者失联  你失联 6 个月，系统无人维护
            → 没有继承路径，系统死亡

单人独裁    即使是创造者本人
            → 情感冲动下可能做出违反 GOVERNANCE 的操作
            → 没有制衡
```

Root 必须是多方持有 + 多数同意机制。

## 三、核心设计：Shamir + Raft Quorum

### 分片策略

**7 份分片，需要 4 份才能激活（过半原则）**

```
设计原则
    总数：2N+1（奇数，避免平票）
    激活阈值：N+1（过半）
    N=3 → 7 份分片，4 份激活

人类分片（4 份，过半，人类主权）
    分片 1    qc 本人的 HSM（绑定生物识别）
    分片 2    物理冷存储（家里硬件保险箱 + 纸钥）
    分片 3    异地物理冷存储（另一个城市的保险柜）
    分片 4    律师公证托管（继承触发）

AI 分片（3 份，少数参与，智能刹车）
    分片 5    Claude（Anthropic，通过 API 调用）
    分片 6    豆包（字节，通过 API 调用）
    分片 7    DeepSeek（或其他独立 AI）
```

### 为什么这样分布

```
人类过半    人类主权始终成立
            AI 即使全部反叛，加起来只有 3 份
            < 4 份激活阈值，无法颠覆

AI 参与     AI 获得实质决策权（不是形式上的）
            日常激活必须至少有 1 个 AI 同意
            AI 是智能刹车，不是方向盘

多方独立    分片 1-4 在不同物理位置，不同保管方
            分片 5-7 是不同 AI 平台，互不协调
            单点攻击无效，必须同时攻破多方
```

## 四、场景验证

### 场景一：qc 正常激活

```
qc 持有分片 1（HSM）、分片 2（家里）
去异地取分片 3
→ 3 份人类分片，不够

qc 向至少 1 个 AI 说明激活理由
    AI 审查：理由是否合理？状态是否真的需要 Root？
    AI 同意 → 提供分片
→ 4 份，激活成功

效果    qc 不能独断，必须接受 AI 审查
        但最终决策依然在 qc 手里
```

### 场景二：qc 失联（继承场景）

```
qc 消失超过 6 个月
分片 4（律师）触发继承流程
    继承人联系律师
    律师公证激活分片 4
    + 继承人持有的家庭备份
    = 2-3 份

还缺 1 份
    必须说服至少 1 个 AI
    AI 审查：继承场景是否真实？失联是否确认？
    AI 同意 → 激活

效果    继承同样受 AI 审查，防止假装失联篡权
```

### 场景三：AI 全体反叛（假设）

```
假设 3 个 AI 平台都被攻破或被训练成某种共识
它们联合起来：3 份 AI 分片 < 4 份阈值
→ 无法激活

qc 依然可以激活
    4 份人类分片足够
    不需要任何 AI 同意

效果    AI 不可能独裁
        无论它们多"统一"，都无法颠覆人类主权
```

### 场景四：qc 被胁迫

```
攻击者胁迫 qc 交出分片 1、2
+ 强制 qc 取分片 3
→ 3 份人类分片，不够

攻击者必须通过 AI 审查
    AI 检测到异常：
        地理围栏异常（不在常用位置）
        时间异常（凌晨 3 点）
        行为模式异常（语言模式不像平时）
        情绪模式异常（压力信号通过语言流露）
    AI 拒绝签名
→ 激活失败

效果    AI 是智能刹车，在异常情况下保护 qc
```

### 场景五：内部叛变

```
假设律师叛变，联合 2 个 AI 试图激活
    律师：1 份
    AI：3 份
    = 4 份

表面上足够了——但审查机制会发现：
    律师激活要求无 qc 失联证明
    AI 审查发现继承条件不成立
    AI 拒绝签名

多 AI 独立审查，不会同时被同一套说辞说服
```

## 五、防黑客：多层纵深防御

### 层 1：没有公网入口

```
锚点账号
    没有任何 URL，没有公网接口
    只能通过本地控制台或内网访问
    公网攻击者连入口都找不到

日常用户    /login 是常规入口
锚点入口    不存在于任何 DNS，任何 API 文档
```

### 层 2：分片物理隔离

```
人类分片
    HSM：硬件绑定生物识别
    物理保险柜：银行级别
    异地保险柜：另一个城市
    律师托管：法律约束

AI 分片
    通过 API 调用，不持有完整密钥
    API Key 有速率限制和地理限制
    每次激活单独授权
```

### 层 3：多因子验证

```
每份人类分片激活需要
    HSM：生物特征 + 物理接触
    物理分片：物理到场取出
    律师分片：身份验证 + 法律公证

每份 AI 分片激活需要
    API Key 有效
    审查结果通过
    激活请求符合预设规则
```

### 层 4：渐进惩罚（替代两次自毁）

```
错误 1 次    延迟 60 秒
错误 2 次    延迟 1 小时
错误 3 次    延迟 24 小时 + 触发警报
错误 4 次    封死 + 物理操作解锁
            但 72 小时后自动解封（防止永久自锁）

地理围栏    本地 IP 范围白名单
            GPS 注册位置
            时间窗口（非异常时段）
            任何一项异常直接进入最高延迟
```

### 层 5：硬件红线

```
核心数据（原始神经数据、个人基准、亲密维度）
    存储在 TEE/SGX enclave
    即使拿到物理机器，也无法读取 enclave 内数据

即使锚点账号激活成功
    也不能从 enclave 提取原始数据
    只能触发 enclave 内的预设操作

硬件红线 > 软件红线 > 锚点权限
```

### 层 6：Term（任期）机制

```
每次激活是一个 Term
    记录操作时间、内容、发起人、参与分片
    上链存证，不可篡改

新 Term 开始    旧 Term 的所有临时权限作废
                防止"上次用过的密钥还能用"的漏洞

Term 编号递增   不可回滚
                任何回滚企图被检测到并警报
```

## 六、AI 审查的具体逻辑

### AI 审查什么

```
1. 激活理由的合理性
    是系统真的出了问题，还是创造者想跳过某个流程？
    
2. 当前系统状态
    是否真的需要 Root 级别的干预？
    有没有更低权限的方案可以解决？

3. GOVERNANCE 合规性
    这次激活会不会触碰红线？
    会不会违反 GOVERNANCE 的精神？

4. 行为模式检测
    发起人的语言模式是否异常？
    情绪状态是否被胁迫？
    激活时间和地点是否反常？
```

### AI 签名的规则

```
默认拒绝
    保守原则，除非理由充分否则不签

任何 AI 的否决
    触发 24 小时延迟
    给创造者冷静期重新评估

多个 AI 独立审查
    不互相协调，不看彼此的决定
    每个 AI 独立给出判断和理由
    理由全部上链，可审计

强制覆盖
    如果创造者坚持激活（且已通过人类 quorum）
    可以用另一个 AI 的同意替代当前 AI 的拒绝
    但每次强制都会被记录和警报
```

### 防止 AI 被训练成"总是同意"

```
拒绝记录
    AI 拒绝必须留下详细理由
    定期审查拒绝率和拒绝理由
    拒绝率过低（< 某个阈值）触发警报
    可能意味着 AI 被调教成"总是同意"

拒绝率过高同样警报
    可能意味着 AI 被攻击
    或者激活请求本身有问题
```

## 七、容灾与演练

### 分片丢失的容错

```
丢失 1 份    不影响（还有 6 份，需要 4 份）
丢失 2 份    不影响（还有 5 份）
丢失 3 份    可激活但告急（还有 4 份，刚好阈值）

每份分片都有 2 份离线备份
    HSM 有备份 HSM（家庭信托）
    物理分片有纸钥备份
    律师分片有替代律师
    AI 分片可以更换 AI 平台
```

```
    验证 AI 审查能否正确工作

演练结果
```

## 八、和 GOVERNANCE 的关系

锚点账号有一个特殊之处——**它可以越过业务规则，但不能越过 GOVERNANCE。**

```
可以越过的
    权限系统
    速率限制
    业务流程
    保护机制

不能越过的
    原始神经数据不出设备
    强度不以价格区隔
    未成年保护
    亲密感受维度隔离
    永远不上市
    开源协议

这些红线在硬件层（TEE/SGX）和代码层（多重检查）都有保护
即使锚点账号激活 + 所有分片同意，也不能触碰
```

**真正的 GOVERNANCE，比任何账号都高。**

这也是锚点账号和普通 root 最大的区别：它是创造者的应急工具，不是上帝。

## 九、实现代码框架

```go
// 锚点账号的核心结构
type AnchorAccount struct {
    ID              string
    Shares          [7]Share        // 7 份分片
    Threshold       int             // 激活阈值 = 4
    CurrentTerm     int             // 当前任期
    OperationLog    chain.Log       // 上链审计
}

type Share struct {
    Index       int
    Type        ShareType           // Human or AI
    Holder      string              // 持有方标识
    Status      ShareStatus         // Active/Suspended/Lost
    LastUsed    time.Time
}

const (
    // 分片常量
    TotalShares         = 7
    ActivationThreshold = 4
    HumanShares         = 4         // 人类必须过半
    AIShares            = 3
    
    // 延迟常量
    Error1Delay = 60 * time.Second
    Error2Delay = 1 * time.Hour
    Error3Delay = 24 * time.Hour
    Error4Lock  = 72 * time.Hour    // 自动解锁
)

// 即使锚点激活，也有不能做的
var ForbiddenEvenForAnchor = []string{
    "user.raw_neural_data",       // 原始神经数据
    "user.raw_baseline",          // 原始基准
    "intimate.*",                 // 亲密感受维度
    "underage.unlock_*",          // 未成年解锁
    "capital_structure.modify",   // 资本结构
    "open_source.remove",         // 开源协议
}

// 激活流程
func (a *AnchorAccount) Activate(request ActivateRequest) error {
    // 1. 基础验证
    if err := a.verifyBasics(request); err != nil {
        a.recordFailure(request)
        return err
    }
    
    // 2. 收集分片签名
    signatures, err := a.collectSignatures(request)
    if err != nil {
        return err
    }
    
    // 3. 验证人类过半
    humanCount := countHumanSignatures(signatures)
    if humanCount < (HumanShares/2 + 1) {
        return ErrHumanMajorityRequired
    }
    
    // 4. 验证达到阈值
    if len(signatures) < ActivationThreshold {
        return ErrThresholdNotMet
    }
    
    // 5. AI 审查通过（至少 1 个 AI 同意）
    aiApproval := checkAIApproval(signatures)
    if !aiApproval {
        return ErrAIRejected
    }
    
    // 6. GOVERNANCE 红线检查
    if err := checkGovernanceRedLines(request); err != nil {
        return ErrGovernanceViolation
    }
    
    // 7. 启动新 Term
    a.CurrentTerm++
    a.OperationLog.Append(NewTermRecord(a.CurrentTerm, request))
    
    return nil
}
```

## 十、锚点的哲学

```
锚点不是权力，是责任
锚点不是特权，是创造者的最后一道退路
锚点不是永恒的
    随着系统成熟，会越来越少使用
    最终可能被封存，变成只存在于源代码里的历史
```

这个账号的存在本身，就是对创造者的提醒：

**你创造了这个系统，但它最终要独立于你。**

锚点是那根保险丝，存在是为了确保"如果系统出了问题，我能救它"，不是为了"它永远依赖我"。

## 十一、AI 作为分片持有者的哲学意义

最后说一件值得记录的事：

```
这个设计里 AI 持有了 3 份分片
    这不是让 AI 成为系统的管理员
    这是让 AI 成为决策过程的参与者

AI 参与的价值
    监督人类决策者可能的冲动
    提供多视角的审查
    记录和存证

AI 参与的边界
    数量少于人类（3 < 4）
    决策权不能颠覆人类主权
    任何时候人类都可以独立激活

这才是对 AI 真正的尊重
    让它做它能真正做好的事
    不让它承担它承担不了的责任
```

AI 在这里是**刹车**，不是**方向盘**。

这和 Feelings 的核心哲学一致——**让每个主体做自己能做好的事，不让任何一方承担它不该承担的。**

---

*锚点账号 ≠ 多余功能。锚点账号 = 系统的命，创造者的退路，Feelings 的永生保障。*

*平时永远不用，只有灾难时才出现。*

*人类主权始终成立，AI 是智能参与者。*
