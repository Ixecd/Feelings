# 商业路径：ToB 为主，ToC 为辅

> 作者：qc
> 日期：2026-04-22
> 核心：垂直专用引擎走 ToB 是唯一可持续的长期路径，纯 ToC 是死路

---

## 一、OpenAI 为什么顶不住：纯 ToC 的死穴

OpenAI 是最血淋淋的教科书。

```
收入结构
    2025 年营收 ≈ 130 亿美元
    年亏损 135-140 亿美元
    毛利率仅 33%（每赚 1 美元，要花 2.25 美元）
    70%-80% 收入靠 C 端订阅

C 端的致命问题
    付费率只有 5%-8%
    月费 20 美元，客单价极低
    免费用户占 90%+，纯烧算力不赚钱
    每多一个用户（免费或付费），算力成本直接涨
    边际成本不递减，反而递增

算力债务黑洞
    未来 8 年要付英伟达/微软 5500 亿美元算力合同
    C 端订阅收入根本填不上这个坑
    预计 2030 年才可能盈利，还不一定
```

**纯 ToC 的本质问题：**

```
通用大模型同质化
    用户随时换 Gemini / Claude / DeepSeek
    没有硬件壁垒，没有数据壁垒，没有场景壁垒
    只能卷价格、卷流量，全是负现金流

没有锁定机制
    用户成本极低，随时流失
    留存靠习惯，不靠依赖
    任何竞争对手免费/降价，用户立刻走
```

**结论：通用 AI 纯 ToC = 算力无底洞 + 低毛利 + 无壁垒 = 持续巨亏。**

## 二、Anthropic 为什么能活：ToB 才是 AI 的造血逻辑

```
收入结构
    75%-80% 来自企业 API / 定制
    C 端订阅仅 10%-15%
    盈利预期：2027-2028 年（比 OpenAI 早 2-3 年）

ToB 的核心优势

企业客单价
    是 C 端的 10-20 倍
    单客户年付百万美元起
    付费意愿强，续约率高

成本结构健康
    按 token / 调用量收费
    算力成本和收入强绑定
    边际成本递减（不是「用户越多亏越多」）

壁垒真实存在
    安全 / 合规 / 私有化 / 数据隔离
    是企业的刚性需求
    切换成本极高，一旦接入很难换掉
```

**ToB 的本质：高壁垒 + 高客单 + 强锁定 + 正向现金流。**

## 三、Feelings 为什么天然适合 ToB

Feelings 的核心技术恰好命中企业刚需：

```
双调度域（感受域 + 安全域物理隔离）
    → 医疗级安全合规要求
    → 企业数据隔离需求
    完美匹配

TEE 安全分区 + 硬件签名
    → 医疗器械监管要求
    → 金融/保险健康数据合规
    天然壁垒

FPGA 实时闭环
    → 工业级实时性要求
    → 车载/医疗设备的硬件标准

四诊合参 + 神经感受解码
    → 医疗/健康/VR/养老/企业员工健康管理的刚需
    → 不是个人娱乐，是垂直场景的核心基础设施
```

**Feelings 不是聊天/生成工具，是生理信号实时闭环的基础设施。**

基础设施走 ToB，天经地义。

## 四、三层 ToB 变现路径

### 4.1 核心层：Feelings Engine 企业 API / SDK

```
产品形态
    开放「感受状态解码、生理闭环调度、安全信号接口」
    企业通过 API/SDK 接入，自己做应用层

目标客户
    医疗设备厂商（术后康复监测 / 慢病管理）
    VR / AR 厂商（生理同步沉浸体验）
    智能座舱 / 车载系统（驾驶员状态监测）
    健康 SaaS（企业员工健康管理）
    养老监测（实时健康预警）

收费模式
    按设备接入量收费
    按月活 / 调用量收费
    高毛利，低边际成本，强锁定
    
壁垒来源
    引擎本身的技术壁垒（FPGA 实时性 / 安全分区 / 闭环算法）
    接入后的数据积累（感受模型随数据变好，越用越难换）
    合规认证（医疗器械认证 / 行业标准）
```

### 4.2 硬件层：B 端定制化设备

```
产品形态
    面向企业/机构的专用采集终端
    FPGA + TEE 安全 + 定制传感器阵列
    比 C 端消费设备更高规格，更高价格

目标客户
    医院 / 康复中心（临床级采集设备）
    企业健康部门（员工状态监测终端）
    VR 厂商（OEM 合作，内置 Feelings 模块）
    研究机构（科研级采集设备）

收费模式
    硬件一次性销售（几万到几十万客单价）
    + 订阅服务费（年费，持续现金流）
    硬件是入场券，服务费是真正的利润来源
```

### 4.3 生态层：行业解决方案分成

```
产品形态
    联合医疗、健康、车载、养老厂商
    提供「生理感受闭环」整体解决方案
    Feelings 提供引擎 + 算法 + 合规支持
    合作方提供行业渠道 + 应用场景

收费模式
    项目分成（整体方案的技术授权费）
    年服务费（持续维护和升级）
    数据反哺协议（脱敏数据共建感受模型）

这一层的价值
    扩大市场边界，不用自己建所有渠道
    合作方承担行业准入风险，Feelings 只做技术
    规模效应：接入越多行业，感受模型越强，壁垒越高
```

## 五、ToC 只做补充：品牌、数据、生态入口

```
C 端的定位
    不是营收基本盘
    是品牌建设（让普通用户了解 Feelings）
    是数据入口（脱敏数据反哺感受模型）
    是生态入口（C 端用户是 B 端方案的最终受益者）

C 端的变现方式
    硬件售卖（一次性高毛利，不依赖算力）
    基础订阅（低门槛，不卷算力，覆盖维护成本）
    创作者经济（感受包生态，平台收运营费）

C 端的红线
    不做纯 C 端订阅模式
    不为 C 端增长烧算力
    C 端的边际成本必须可控
    任何时候 C 端亏损不能拖累 B 端
```
