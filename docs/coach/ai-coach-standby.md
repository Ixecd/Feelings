# AI 教练待命状态机——没事就睡，有事叫醒

> 作者：qc
> 日期：2026-08-11
> 性质：教练 AI 的运行形态设计——低功耗监听 + 事件触发，响应式而非巡逻式
> 核心：教练 AI 不持续待命。默认低功耗监听态——采集在跑、事件检测器在线、教练本体休眠。事件触发才激活：用户主动询问、身体数据异常、定时低优先级任务。处理完回到监听态。传感器在跑（监听）——触发器在站岗（检测）——教练在睡（休眠）——事件一来，叫醒它。

---

## 一、为什么不持续待命

```
资源      持续待命 = 持续推理 = 持续耗电/算力——
          教练 AI 的推理比采样贵几个量级——可穿戴撑不住
打扰      持续在场 = 持续干预——0 输出设计：专注时不打扰——
          持续待命的教练 = 持续的背景噪声
语义      没有事件发生——教练没有事做——待命无意义——
          "响应式而非巡逻式"——教练是响应者不是巡逻者
```

## 二、状态机

```
低功耗监听态（默认）
    采集持续跑（低成本——阻抗/信号采样——传感器便宜）
    事件检测器在线（阈值/模式检测——轻量触发器——
        不是教练 AI——是一组低成本逻辑）
    教练 AI 本体休眠（不激活——0 推理——省电省算力）
        │
        ▼ 事件触发
激活态
    多 agent 合议 → 处理 → 记录
        │
        ▼ 处理完成
回到低功耗监听态
```

## 三、事件触发源

```
① 用户主动询问    对话请求——用户发起——最直接的触发
② 身体数据异常    自动事件——不需要用户开口——
                  PBM 漂移超阈值、HRV 异常、压力超标、
                  漏桶临界、DefenceLevel 激活、睡眠异常——
                  生理信号自己"报警"——身体一直在说话
③ 定时低优先级    基线更新——后台任务——周期触发
```

关键：身体数据异常是自动触发源——用户可以不说话——但身体一直在说话（PBM 漂移就是身体在喊）——教练不需要持续待命——因为身体本身就是它最好的触发器。

## 四、优先级与安全兜底

```
事件总线优先级（engine-design 咬合）：
    P0    安全告警——身体异常的最高级——FPGA 寄存器直刹——
          不需要教练 AI——物理层兜底
    P1    感受闭环关键路径
    P2    实时感受参数调整
    P3    基线更新
    P4    后台分析 / 日志 / AI 教练非实时响应——
          教练挂在 P4——最低优先级——
          事件触发才激活——激活完回待命

安全兜底：P0 不等教练——物理层直刹——
    教练即使休眠——安全也不休眠——
    安全域独立（Engine 无权访问）——教练管不到安全域
```
