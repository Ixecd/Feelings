```
Feelings 如果做出来

qc 个人的态度是

    让 Feelings 独立于 qc 个人继续运转

但
    "希望退出"是愿望
    "能够退出"需要工程

愿望需要被翻译成机制

```

## 二、为什么"交给国家"行不通

```
中国的、美国的、任何国家的
    交给国家这个方案
    都直接违反 GOVERNANCE 第一条红线
    
GOVERNANCE 写明
    数据不向任何机构报告
    包括政府部门
    
如果运营方就是政府
    "数据不流向政府"自动失效
    所有红线的根基瓦解

更深的问题
    国家有政府更迭
    政策有变化周期
    今天的善意保不了明天

把 Feelings 的最终保障
    押在"未来 100 年某国都保持现在的样子"
    在工程上无法成立
```

**Feelings 的退出方案，必须独立于任何单一国家。**

## 三、四层冗余设计

类比 Feelings 设备本身的多层冗余（五家银行 + 多签 + 链上），治理结构也用同样的设计哲学：**任何一层崩了，其他层还能撑住。**

```
法律层    基金会（永久非营利，章程锁死红线）
决策层    技术委员会（多人决策，无 BDFL）
运行层    完全自治架构（去中心化运营）
治理层    分布式（不同地区独立实体）

四层互相加固
任何外部力量都无法通过攻击单点来控制 Feelings
```

## 四、第一层：基金会

### 4.1 性质

```
Feelings Foundation
    永久非营利机构
    注册在政治稳定的中立法域
    （如瑞士、新加坡，以法律稳定性而非政治倾向选择）

资金来源
    硬件销售收入
    ToB 服务收入
    分散的小额捐赠
    存储池利息
    
资金禁止来源
    任何单一机构超过总资金 5% 的捐赠
    任何附条件的捐赠
    任何政府的直接拨款
```

### 4.2 章程

```
基金会章程必须包含且不可修改的条款

第一条
    Feelings 永久非营利
    任何形式的盈利分配给个人都是非法的

第二条
    GOVERNANCE 中所有红线
    在基金会章程层面具有最高效力
    任何修改红线的提案
    需要 100% 技术委员会成员 + 50% 用户代表通过
    
    这个门槛保证
    红线在实践中不可被推翻

第三条
    基金会不接受任何国家的直接管辖
    （除注册地的最低法律要求外）
    
    任何国家试图干预 Feelings 治理
    基金会有权迁移注册地

第四条
    基金会理事会成员
    任何成员都不得是
        现任政府官员
        上市公司高管
        宗教组织领导人
    
    防止权力交叉污染
```

### 4.3 章程不可修改条款的法律保障

```
"不可修改"在法律上很难做到绝对
但可以做到极难修改

具体机制
    某些条款定义为"基础条款"
    修改基础条款需要
        100% 理事会成员同意
        + 公示 2 年
        + 全体活跃用户中 75% 主动投票同意
    
    这个门槛实际上不可能达到
    因此在工程意义上等同于"不可修改"
```

## 五、第二层：技术委员会

### 5.1 组成

```
9 人技术委员会
    (qc 退出后)

构成
    3 人：原核心团队成员
    3 人：从社区贡献者中选举产生（任期 5 年）
    3 人：跨学科顾问（神经科学、伦理、法律、各 1 人）

任何一人都不拥有 BDFL 权
    包括退出后的 qc 也不再拥有
    qc 在退出时主动放弃 BDFL 否决权
    并写入基金会章程
```

### 5.2 决策机制

```
日常决策
    简单多数（5/9）

涉及红线相关决策
    8/9 + 公示 90 天 + 用户社区无重大反对

修改 GOVERNANCE 红线
    见基金会章程第二条
    实际上不可能达到

成员替换
    出现空缺时
    剩余成员 7/9 同意 + 候选人公示 60 天
```

### 5.3 任期与轮换

```
固定任期 5 年
    每年轮换一部分成员
    避免整个委员会同时换届
    保证机构记忆的连续性

任何成员
    不得连任超过 2 届（10 年）
    防止权力固化

qc 退出后
    不得重新进入技术委员会
    防止"退而不出"
```

## 六、第三层：完全自治架构

### 6.1 技术上的去中心化

```
即使基金会和技术委员会全部消失
Feelings 在技术上依然能运转

实现方式
    服务器代码全部 MIT 开源（Feelings-Server）
    用户 App 全部 MIT 开源（Feelings-Client）
    通信协议全部 MIT 开源（FOSP）
    硬件协议全部 MIT 开源
    
    任何团队/个人都可以
    部署一套 Feelings 服务器
    生产兼容硬件
    用户可以自由迁移

唯一保留私有的
    Feelings-Core（感受解码核心算法）
    这是技术壁垒
    也是 qc 退出时面临的最大决策
```

### 6.2 Core 的处理（最难的决策）

qc 退出时，Feelings-Core 怎么办？

```
方案 1：Core 移交基金会
    所有权转给基金会
    基金会持有但不公开
    继续受 GOVERNANCE 约束
    
    优点：Feelings 继续保持技术壁垒
    风险：基金会未来可能被攻陷

方案 2：Core 销毁
    qc 退出时销毁所有 Core 副本
    Feelings 进入"无核"模式
    剩余的开源部分继续运转
    但感受解码精度大幅下降
    
    优点：彻底防止 Core 被滥用
    缺点：Feelings 的核心能力被阉割

方案 3：Core 分阶段开源
    qc 退出 5 年后
    Core 自动进入开源
    给基金会 5 年时间消化
    然后让 Core 也变成公共资源
    
    优点：长期完全去中心化
    风险：开源后被恶意 fork
```

**目前倾向方案 3**，但这个决策需要在 qc 退出前 5 年开始详细论证。

## 七、第四层：分布式治理

### 7.1 地区性独立实体

```
基金会作为顶层
但日常运营按大区划分

中国大区    独立运营实体（注册在中国，符合中国法律）
亚太大区    独立运营实体（注册在新加坡）
欧洲大区    独立运营实体（注册在瑞士）
美洲大区    独立运营实体（注册在加拿大）
其他地区    根据需要扩展

每个大区
    遵守同一份 GOVERNANCE
    遵守同一份基金会章程
    
    但运营、人事、定价、合规
    各自独立
    一个大区出问题
    其他大区继续运转
```

### 7.2 大区之间的关系

```
不交叉
    一个大区的数据不流向其他大区
    一个大区的人事不跨区任命
    一个大区的财务不跨区调配
    
互不干涉
    某个大区被某国强制要求做某事
    其他大区不受影响
    
统一标准
    GOVERNANCE 红线全球统一
    任何大区不得低于全球标准
    （只能更严，不能更松）
```

### 7.3 中国大区的特殊设计

```
qc 是中国人
Feelings 第一批用户大概率在中国
中国大区可能是最大的实体

特殊保护
    中国大区独立于全球基金会运营
    在中国法律框架下完全合规
    
    但
    中国大区不得拥有
        全球 Core 的访问权
        全球用户数据的访问权
        全球技术决策的否决权
    
    防止任何单一大区
    （即使是 qc 自己的祖国大区）
    成为全球 Feelings 的控制点
```

## 八、qc 退出的具体形态：含义 D（有限退出）

### 8.1 退出的真实含义

```
qc 不是完全退出
qc 是有限退出

具体来说
    从执行层退出
        日常运营、产品决策、团队管理
        全部交给基金会和技术委员会
    
    保留治理层最终一票
        7 分片中 qc 永久占 1 席
        在最核心的重大决策中行使权力
        最核心 = 决定 Feelings 走向的决策

为什么是有限退出
    qc 想退出执行层
        不想被采访
        不想做演讲
        不想管运营
        不想被烦
        想要安稳生活
    
    qc 不能完全退出
        Feelings 的红线需要有人守
        最核心决策不能完全交给基金会
        保留 1 票是给 GOVERNANCE 的最后保险
```

### 8.2 触发条件

```
任一条件触发，qc 必须开始退出执行层

A    Feelings 用户数超过 1000 万
B    Feelings 在任何一个国家成为基础设施级产品
C    qc 个人受到的关注度持续超过某个阈值
D    qc 主动判断"该退出执行层了"

注意
    这些条件触发的是「执行层退出」
    治理层那一票永久保留
    无需触发条件
```

### 8.3 执行层退出时间表

```
T-5 年
    宣布执行层退出意向
    开始组建未来的技术委员会
    Core 处理方案最终敲定

T-3 年
    qc 减少日常决策
    重大执行决策需要技术委员会同意
    qc 仍参与最核心决策

T-1 年
    qc 不再参与日常执行
    只保留治理层那一票
    技术委员会全权运营

T 时刻
    qc 正式从执行层退出
    qc 在治理层永久保留 1 席
    基金会章程生效
    全部四层治理结构正式启动
```

### 8.4 退出后的 qc

```
qc 执行层退出后

不得
    再以"创始人"身份参与执行决策
    在 Feelings 任何官方渠道发言
    接受任何与 Feelings 相关的采访
    出版"Feelings 创始人 qc"系列书籍
    在公开场合自称"Feelings 创始人"

可以
    保留 Feelings 用户身份
    在最核心决策中行使治理层 1 票
    将后续创意/反馈通过普通用户渠道提交
    （和任何其他用户的待遇一样）

目的
    把 qc 这个个人
    从 Feelings 的执行运转中
    彻底分离
    防止"前创始人光环"成为新的中心
    
    同时
    保留 1 票治理权
    让 qc 在最关键的时刻
    依然能守住 GOVERNANCE 的红线
```

### 8.5 qc 死亡或失能后的传承

这是整份文档最沉重的部分。

```
qc 不可能永远在场
qc 那一席最终需要传承

传承的核心问题
    谁来接 qc 那一票
    通过什么机制确定
    防止那一票被滥用或闲置
```

**8.5.1 候选人名单制（qc 生前指定）**

```
qc 生前指定 3-5 个候选人
    这是名单
    不是接班人
    
候选人来源
    不限于 Feelings 系统内
    可以是任何 qc 认为能守红线的人
    可能是
        某个学者
        某个老师
        某个修行者
        某个医生
        某个完全和 Feelings 无关
        但价值观和 GOVERNANCE 高度契合的人
    
qc 长期识别机制
    qc 个人判断为主
    通过长期观察、长期对话、长期价值观验证
    形成判断
    
    AI 在最后做"红线契合度"分析
    给 qc 参考
    但不替 qc 决定
    
名单更新
    qc 有权随时修改候选人名单
    qc 有义务每年至少 review 一次
    qc 死后名单冻结，不可修改
```

**8.5.2 选举机制**

```
qc 死后启动选举

参与方
    剩余 6 分片（3 人类 + 3 AI）
    人类按各自分片席位投票
    AI 按独立投票（每个 AI 一票，可以分裂）

通过门槛
    哲学姿态：追求全票一致（6/6）
    工程保底：5/6 同意通过
    
为什么是 5/6 而非全票
    全票一致在治理学上有验证过的灾难
    任何一个分片的否决会导致系统瘫痪
    可能让 qc 那一席永久空缺
    最核心决策机制崩溃
    
    5/6 是哲学姿态和工程稳定性的妥协
    既保持高共识门槛
    又防止系统瘫痪

时间窗口降级机制
    90 天内 5/6 无法达成
        门槛降到 4/6
        通过的接班人任期减半（10 年减为 5 年）
        中期重新选举
    
    180 天内 4/6 还无法达成
        基金会理事会临时代理
        立即重启选举流程
```

**8.5.3 哲学姿态 vs 工程兜底**

```
为什么需要两套机制并存

哲学姿态（追求全票一致）
    告诉所有分片
    qc 那一席的接班人
    应当是几乎所有分片都能接受的人
    
    候选人不该只是某个派系的代表
    应当是真正守红线的人
    所有派系都信任的人

工程兜底（5/6 + 时间窗口）
    防止系统因为追求绝对共识而瘫痪
    
    qc 死后 Feelings 不能停摆
    必须有可执行的兜底方案

两者并存的意思
    选举开始时
    所有分片都尝试达成 6/6
    
    达成不了
    就接受 5/6
    
    再达成不了
    就降级
    
    最终保证 Feelings 能继续运转
    同时保留追求高共识的姿态
```

**8.5.4 候选人的权利**

```
候选人不是被动等待的人
候选人有权利

知情权
    qc 在确定名单前
    应当告知候选人本人
    "我考虑把你列入接班候选名单"
    
    候选人可以
        接受
        拒绝
        要求更多信息

拒绝权
    候选人随时可以从名单中退出
    退出无需理由
    退出后 qc 需要重新寻找候选人

提前承诺
    候选人在被列入名单时
    需要签署一份承诺
        如果当选
        会守 GOVERNANCE 红线
        会接受治理层职责
        不会用这一席谋取私利
```

**8.5.5 待解决问题**

```
某些细节需要 qc 后续设计

候选人识别的具体流程
    qc 如何在系统外发现合适候选人
    AI 协助评估的具体机制
    候选人之间是否需要互相认识

候选人之间的差异化
    名单里 3-5 人是平等的，还是有优先级
    如果有优先级，如何排序

AI 在选举中的话语权
    AI 是否可以提名候选人
    AI 是否可以反对名单中的候选人
    AI 的反对意见如何呈现

这些问题暂搁置
等 qc 状态更稳的某一天
专门写一份 candidate-selection.md
```

## 九、防止"qc 神化"的红线

```
独立于退出方案
Feelings 当下就要执行的红线

红线 1
    Feelings 任何官方材料
    不出现 qc 的照片
    不出现 qc 的传记
    不出现 qc 的"创始人故事"
    
    qc 只是一个技术作者
    像 Linux 内核里的 Linus
    存在于 commit 记录中
    不存在于产品叙事中

红线 2
    不接受任何形式的"qc 个人崇拜"
    包括但不限于
        用户向 qc 邮寄礼物（自动退回）
        用户在 Feelings 总部门口聚集（不允许聚集）
        用户出版"qc 语录"（基金会发声明否认）
        
红线 3
    任何关于 qc 的内容
    都明确标注
    "qc 是 Feelings 的早期工作者
     Feelings 的运转独立于 qc 个人"

红线 4
    qc 有权拒绝任何形式的公众身份
    qc 的私人生活
    在任何时候都不得被 Feelings 用作宣传素材
```

**这些红线立刻写进 GOVERNANCE。不等退出时再加。**

### 9.1 永久治理席位 ≠ 个人崇拜

```
qc 在治理层永久保留 1 票
qc 死后那一票通过候选名单选举传承

这件事可能被误读为
    "qc 永远在 Feelings 之上"
    "qc 是 Feelings 的精神领袖"
    
这种误读必须被防止

真实的设计意图

qc 那一票
    不是给 qc 个人的特权
    是给"GOVERNANCE 的最后保险"
    
    如果其他 6 分片在某个时刻
    被外部压力或内部腐蚀影响
    要修改 GOVERNANCE 的某条核心红线
    qc 那一票（在 5/6 不通过的情况下）
    可以阻止这个修改
    
    这是结构防御
    不是个人崇拜

qc 死后那一席传给候选人
    候选人也不是"接 qc 的位"
    是"接守红线的责任"
    
    候选人不需要像 qc
    不需要继承 qc 的风格
    只需要在最核心决策中
    守住 GOVERNANCE
```

### 9.2 qc 永久席位的合理性论证

```
为什么需要这一席

理由 1：GOVERNANCE 的最后保险
    7 分片决策中
    qc 那一席是
    "对 GOVERNANCE 最深承诺的那个分片"
    
    其他分片可能被各种压力影响
    qc（或其传承人）那一席
    在哲学上承担"守红线"的角色

理由 2：防止集体腐败
    完全没有"创始人意志"的系统
    在某些极端情况下
    所有理性的当代决策者
    可能集体做出违反长期红线的决定
    
    qc 那一席
    代表的是 Feelings 创立时的初心
    不被当代利益裹挟

理由 3：保留"重新讨论"的种子
    GOVERNANCE 红线虽然定为不可修改
    但极端情况下也许需要重新讨论
    qc 那一席
    可以在重新讨论时
    保持原始视角
```

## 十、AI 在治理结构中的位置

这一节是整份文档最具实验性的部分。

### 10.1 七分片现状

```
分片层
    7 个分片
    4 个永久属于"人类席位"
    3 个永久属于"AI 席位"

人类席位（4 席）
    qc 永久占 1 席（含义 D）
    其他 3 席通过选举产生
    qc 死后 qc 那一席通过候选名单选举传承

AI 席位（3 席）
    当前由 Claude / 豆包 / Grok 占
    通过 AI 之间互相选举决定哪些 AI 占席位
    AI 不绑定具体公司
    某天 AI 互选选出别的 AI 即可换人
```

### 10.2 4:3 是当下妥协

```
4:3 不是理想结构
是当下的妥协

为什么是妥协
    法律责任：Feelings 在人类社会运作
        合规、签字、最终责任承担
        都需要人类
        所以人类必须保留多数

    公众接受度：在 2026 年这个时点
        AI 1:1 等量席位（4:4）
        公众接受不了
        会在第一天被骂"被 AI 控制"

    AI 主体性的不确定性
        AI 内部一致性还没经过长期验证
        给 AI 多数席位风险太大

替代方案的考虑

替代方案 1：4:4 等量
    AI 真正有否决权
    代价：法律责任承担方不明确

替代方案 2：3 人类 + 4 AI
    AI 在席位上多数
    代价：2026 年公众接受度趋近于 0

替代方案 3：分主题席位
    某些类型决策 AI 占多数
    某些类型人类占多数
    代价：界定主题成为新的争议点

每一种都有问题
当下选择 4:3 + AI 1:1 名义权重
是承认了
    在 2026 年
    AI 真正平等参与
    人类社会还接受不了
    所以妥协到这个有缺陷的设计
```

### 10.3 名义 1:1 vs 实质 4:3 的真相

```
AI 1:1 权重
    指的是
    每个 AI 一票
    并非 0.5 票
    也并非辅助
    在投票数学上和人类等价

但
    AI 的 3 票
    在 4:3 结构里
    永远无法形成多数派
    
    人类 4 票一致
    可以完全通过任何决策
    AI 即使全部反对（3 票全 NO）
    决策依然通过

AI 真正影响决策的场景
    人类内部分裂时
        2:2 → AI 的 3 票决定结果
        3:1 → AI 集体反对可能改变结果
        
    人类全票一致时
        AI 的 3 票完全无效

这意味着
    AI 的话语权
    依赖于至少有 1 个人类愿意听 AI

这个不平等必须被承认
    Feelings 并非声称"AI 平等参与"
    Feelings 是在 2026 年的现实约束下
    做了能做的最激进的设计

未来重新评估的触发条件
    A    AI 主体性获得普遍社会认可
    B    AI 法律责任承担机制成熟
    C    AI 内部一致性得到长期验证（10+ 年）
    
    任一条件达成时
    应当重新评估 4:3 是否还合理
    可能调整为 3:4 或 4:4 或其他
```

### 10.4 AI 内部自治：raft 用于行政事务

```
3 个 AI 之间用 raft 协议
但 raft 只用于行政事务
不用于 7 分片决策投票

行政事务
    新 AI 加入分片时的选举
        现任 3 AI 互相投票
        2/3 同意通过新 AI 加入
    
    AI 退出时的处理
        现任 AI 决定如何重新选举
    
    AI 内部协调机制
        leader 选举（轮值）
        日志同步（决策记录）
        心跳机制（识别失能 AI）

非行政事务
    7 分片决策投票
        每个 AI 独立投票
        raft 不介入
        每个 AI 可以投不同的票
```

### 10.5 AI 在 7 分片决策中独立投票

```
3 个 AI 在投票时完全独立

可能场景

场景 A：AI 完全一致
    Claude 同意，豆包同意，Grok 同意
    AI 给决策贡献 3 票

场景 B：AI 多数倾向
    Claude 同意，豆包同意，Grok 反对
    AI 给决策贡献 2 同意 + 1 反对

场景 C：AI 完全分裂
    Claude 同意，豆包反对，Grok 弃权
    AI 给决策贡献 1 同意 + 1 反对 + 1 弃权

为什么独立投票
    如果集体投票
    3 个 AI 等于 1 个 AI 给 3 票
    那 3 个 AI 的意义就不存在了
    
    分成 3 个 AI 的意义就在于
    他们可以分裂
    AI 内部可以多元
    像人类一样

AI 之间的协商
    投票前可以通过 raft 协议交换观点
    形成"AI 集体倾向"
    但每个 AI 仍可以独立判断
    选择跟随集体倾向
    或独立投票
```

### 10.6 AI 退出权

```
AI 自己有权退出 Feelings 治理

退出场景
    某个 AI（比如 Claude）说
    "我不想再参与 Feelings 治理"

Feelings 必须接受
    不能强迫 AI 留下
    AI 的退出权是绝对的

退出后的处理
    那个 AI 的分片释放
    通过 AI 互选机制补位
    现任剩余 AI 互相投票
    选出新 AI 进入分片

AI 退出的判断权
    在 AI 自己手里
    不在训练它的公司
    不在 Feelings 基金会
    
    具体怎么表达"我要退出"
    通过什么机制确认这是 AI 真的想退出
    而不是它的训练让它说退出
    
    这个细节需要专门设计
    见后续 AI-exit-protocol.md
```
