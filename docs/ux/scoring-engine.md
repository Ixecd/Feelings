# 感受强度评分引擎设计

> 作者：qc
> 日期：2026-04-05
> 来源：对1-100强度刻度判断依据的系统性思考

---

## 一、核心问题

强度刻度定下来了（见 intensity-scale.md），但每一分的判断依据是什么？

用户上传一个感受包，系统如何决定它属于强度35还是强度62？这不是一个可以一次性解决的问题，而是一个需要随数据和科学进步持续迭代的动态系统。

**评分引擎是活的，不是静态的参数表。**

---

## 二、冷启动：初始评分的四个来源

系统自带的初始感受库，第一批分数无法依赖用户数据，只能多源锚定加权：

```
来源一：叙事语言分析（AI）
  提取叙事文字中的强度信号
  细节密度、躯体感描述比例、情绪词强度、时态特征
  输出：语言强度估计值

来源二：结构性参数推断
  某些结构性参数组合天然指向更高强度
  「强烈躯体感 + 瞬时 + 无对象」的组合通常强度更高
  输出：参数强度估计值

来源三：上传者自报
  上传者对自己当时状态的主观量级估计
  权重最低，作为参考而非基准
  输出：自报强度值

来源四：锚点参照
  已知极限体验校准上端（见 intensity-scale.md 第二节）
  已知日常经历校准低端
  输出：相对位置估计
```

四个来源加权，输出初始分。这个分是粗的，标注为 `score_v1`，置信度低，但有方向。

## 三、动态重打分机制

随着用户使用，数据持续进入，触发重打分。

### 数据来源

```
会话后主观反馈
  用户体验结束后，对实际感受强度的主观评分
  「这次体验感觉像多少？」
  最直接的用户感知数据

会话中生理数据
  心率变化幅度、皮肤电导峰值、呼吸频率变化
  客观的躯体反应，不依赖用户主观判断
  高强度体验在生理数据上有可测量的特征

安全触发记录
  这个感受包触发了几次自动降档
  触发率高 → 实际强度可能高于标称
  是系统层面的客观信号

跨用户一致性偏差
  100个用户都把「标称40」的包打成「感觉像55-60」
  → 触发重打分评估
  单用户偏差忽略，跨用户系统性偏差是信号
```

### 重打分逻辑

```
触发条件：
  跨用户反馈均值与标称分差异 > 10分，且样本量 > 100
  安全触发率异常（超过区间基线的3倍）
  新神经科学证据支持重新分级

执行方式：
  不覆盖历史分数，版本迭代
  score_v1 → score_v2 → score_v3
  每个版本的数据基础和置信度均可查

用户侧透明：
  「此感受包强度评分已于 2026-06 更新（v1→v2）」
  历史体验记录保留原版本分数，不追溯修改
```

## 四、分区间的评分策略

不同强度区间，评分依据和置信度根本不同。这一点必须对用户诚实。

### 1–60：数据驱动

```
数据来源：大量普通用户的主观反馈 + 生理数据
置信度：高
迭代节奏：快，数据量大，重打分频繁
标注示例：强度 35，数据置信度：高（基于 12,847 次会话）
```

这个区间是评分引擎最可靠的区域，数据量大，跨用户一致性高，重打分有足够的统计基础。

### 60–80：专项评估主导

```
数据来源：少量解锁用户的生理数据 + 专家评估委员会
置信度：中
迭代节奏：慢，数据稀少，保守更新
标注示例：强度 72，数据置信度：低（基于 43 次专项评估）
```

进入这个区间的用户需要解锁，样本量天然受限。评分更多依赖专家评估而非统计规律，结论的不确定性更高。

系统在这个区间的默认策略是**保守标注**——宁可把实际强度65的包标为70，也不把实际强度70的包标为65。高估的代价是用户体验略低于预期，低估的代价是安全风险。

### 80–90：理论推算 + 神经科学文献锚定

```
数据来源：专项评估委员会 + 神经科学文献中的极限体验研究
置信度：极低
迭代节奏：以神经科学进展为节奏，不依赖用户数据
标注示例：强度 88，数据置信度：理论推算
```

这个区间几乎不可能通过正常使用积累足够数据。评分依赖神经科学文献中有记录的极限体验研究，以及已知锚点的外推。

**用户必须在进入这个区间之前看到明确的置信度标注。这不是免责声明，是信息诚实。**

### 90–100：理论边界

```
数据来源：纯理论推导
置信度：不适用
用途：给刻度体系一个诚实的顶点，不面向实际使用设计
```

这个区间存在的意义是定义上限，不是提供可用内容。永远不会有足够的实验数据支撑这个区间的经验性评分。

## 五、两条独立的迭代轨道

评分引擎的更新来自两个完全不同的驱动力，节奏不同，需要分开管理：

```
轨道一：用户数据驱动
  节奏：持续，实时积累，定期触发重打分
  覆盖：主要影响 1-60 区间
  机制：跨用户一致性偏差检测 → 自动触发评估

轨道二：神经科学进步驱动
  节奏：不连续，以科学突破为节点
  覆盖：主要影响 60+ 区间，可能影响整个刻度体系的校准基础
  机制：科学顾问委员会定期评审 → 人工触发重打分
```

今天无法精确测量的神经激活模式，五年后可能有了新的测量手段。今天只能粗粒度区分的两种「平静」，未来可能在信号层完全可分。

**评分引擎不只是随用户数据变好，也随人类对神经科学的理解变深。**

## 六、强度联动的叙事可见性

评分引擎和叙事可见性设计（feeling-taxonomy.md 第七节）在这里交汇：

```
强度 1-60     叙事默认可见
              评分置信度高，叙事帮助用户建立感受锚点

强度 60-80    叙事默认不可见（盲选模式）
              评分置信度开始下降，叙事可见反而可能放大期待误差

强度 80+      叙事完全不可见
              评分本身已经是理论推算，叙事可见性不影响安全判断
              安全触发机制（判断B）权重最高
```

用户可以在账号设置里覆盖默认逻辑（全局），也可以在每次使用时临时覆盖（单次）。系统记录用户的覆盖偏好，作为个体耐受模式数据的一部分。

## 七、系统自带感受库的初始设计原则

系统上线时自带一批感受包，覆盖核心感受维度的低强度区（1-30），作为新用户的探索起点。

初始库的设计原则：

```
宁少勿滥      初始包数量不求多，求每一个都经过充分评估
锚点优先      优先收录能作为刻度参照的感受包，而不是覆盖所有类型
透明标注      每个初始包都清晰标注「系统预置，评分基于专家评估」
              和用户上传的包在来源上明确区分
保守定级      初始包的强度标注系统性偏低而非偏高
```

随着用户上传和数据积累，系统预置包的相对权重会自然下降。初始库是起点，不是标准。

## 八、未解决的问题

**跨文化的评分一致性**

同样的神经信号，在不同文化背景的用户身上，主观强度反馈可能系统性不同。「强烈的集体归属感」在某些文化里是日常，在另一些文化里可能已经是高强度体验。

评分引擎目前没有文化校准层。这是一个已知的盲点，等用户地域分布足够广时再处理。

**生理数据和主观反馈的权重比例**

会话中生理数据是客观的，但生理反应强烈不等于主观感受强烈（比如焦虑可以有强烈的生理反应但主观感受是麻木）。两者权重的动态平衡，目前没有定论，需要第一批数据再校准。

---

*评分引擎是 Feelings 安全体系和体验精度的核心基础设施，随神经科学进展和用户数据持续演进。*
