# 权限管控：角色、设备、内容

> 作者：qc
> 日期：2026-04-13
> 核心：用户始终是主体，没有明确授权，任何角色都无法访问

---

## 一、核心原则

```
用户主权    用户对自己的数据有完全控制权
            没有用户的明确授权，任何人都无法访问
            包括平台方本身

最小权限    每个角色只能访问完成其职责所必需的数据
            不多给，不预留「以后可能有用」的权限

显式授权    没有默认授权
            每一项权限都需要用户主动开启
            关闭是默认状态，开启需要动作

可撤销      所有授权随时可以撤销
            撤销立即生效，不需要等待
```

## 二、角色体系

### 用户本人

```
可以看到    自己的所有数据（全量）
可以做      完全控制：查看/下载/删除/授权/撤销授权
            设置安全参数（强度上限/紧急联系人）
            管理设备（激活/停用/远程销毁）
```

### 监护人（特殊用户）

```
适用场景    未成年用户/智障残障用户/老年用户

可以看到    用户授权范围内的状态摘要
            实时安全状态（是否佩戴/当前强度/异常信号）
            不能看到感受体验的具体内容

可以做      设置安全参数（强度上限）
            设置地理围栏
            接收紧急通知
            远程触发急停

不能做      查看原始神经数据
            访问感受地图的详细内容
            修改用户的感受包偏好
```

### 治疗师

```
适用场景    用户主动关联治疗师，用于辅助心理治疗

可以看到    用户授权的感受状态摘要
            感受地图的整体形状（不含具体体验内容）
            自省报告摘要（用户选择分享的部分）

可以做      查看授权的数据
            向AI教练发送建议（AI教练参考，不强制执行）
            调整守护者模式参数（残障用户）

不能做      直接操控感受体验
            查看原始神经数据
            访问亲密感受维度数据
```

### 感受包创作者

```
可以看到    自己上传的感受包的使用数据
            自己的收益和分成记录
            感受包的评分和反馈

不能看到    哪些具体用户使用了自己的感受包
            用户使用时的生理数据

可以做      上传/修改/下架自己的感受包
            提取或存入存储池
```

### 平台审核员

```
可以看到    待审核感受包的叙述描述（脱敏）
            感受包的技术参数（不含用户数据）
            违规举报内容

不能看到    任何用户的个人数据
            感受包使用时的用户数据

可以做      审核通过/拒绝感受包
            下架违规内容
            标记需要人工复核的内容
```

### 平台运营

```
可以看到    脱敏的统计数据（群体级别）
            系统运行指标
            不包含任何个人信息

不能看到    任何用户的个人数据
            任何用户的感受体验数据

可以做      系统维护
            统计报告生成
```

## 四、设备权限管控

### 设备认证流程

```
设备出厂    烧入唯一硬件标识（不可修改）
            固件签名（Feelings私钥）

用户激活    设备和账号绑定
            绑定关系上链（不可篡改）
            激活后该设备只对该用户有效

其他用户    无法激活已绑定的设备
            即使拿到设备，无法读取数据，无法使用
```

### 设备操作权限

```
用户本人    激活/停用/远程销毁/固件更新
监护人      远程触发急停（需要用户事先授权）
平台方      固件推送（用户确认后执行）
            远程销毁（用户报告丢失后执行）
            不能在用户不知情的情况下访问设备数据
```

### 固件更新

```
更新推送    平台推送固件更新通知
用户确认    用户明确同意后才开始更新
            不强制更新（安全修复除外）
安全修复    关键安全漏洞的补丁，在通知用户后48小时内强制推送
            附完整的变更说明
签名验证    设备验证固件签名
            未签名固件拒绝安装
```

## 五、内容权限管控

### 感受包访问控制

```
默认可访问    所有成年用户可以访问的感受包
年龄限制      特定内容只对18+开放（亲密感受维度）
强度限制      TCP解锁阶段限制，未解锁的强度不可访问
特殊限制      创伤协议用户，部分高刺激感受包不可访问
```

### 创作者内容管控

```
上传审核    所有感受包上传后进入审核队列
            AI初审：内容安全 + 技术参数合规
            人工复核：高风险类别（亲密/高强度/创伤相关）

已上线内容  创作者可以随时下架
            平台可以因违规下架
            用户举报触发复审

版权        感受包的创意版权归创作者
            平台有分发权，无所有权
            创作者离开平台，可以带走自己的作品
```

## 六、审计日志

```
记录内容    所有数据访问行为
            操作者/时间/访问的数据类型/操作结果

用户可见    用户可以查看谁在什么时间访问了自己的数据
            异常访问（非用户本人）触发通知

不可篡改    审计日志写入后不可修改
            关键操作的审计日志链上存证

保留期限    审计日志保留5年
            用户注销后，审计日志额外保留1年
```

## 八、生物识别安全

Feelings 使用面容优先、指纹备用的无密码登录体系。生物识别有特殊的安全考量——

```
普通密码泄露    改密码就好
指纹/面容泄露   你没有备用指纹，没有备用面容
                这是生物识别最根本的挑战
```

### 生物数据永远不离开设备

```
错误做法    上传生物特征到服务器
            服务器被攻击 → 所有用户生物特征泄露 → 永久性损害

正确做法    生物特征永远只在设备的安全芯片里
            iOS：Secure Enclave
            Android：StrongBox

Feelings服务器    只看到「验证通过/失败」的结果
                  看不到任何生物特征数据
```

### 活体检测

```
防止攻击者用照片/橡皮泥复制品绕过

面容活体检测    检测眨眼/微表情/深度信息
                3D结构光（iPhone Face ID级别）
                不只是2D图像匹配

指纹活体检测    检测温度/脉搏/皮肤弹性
                确认是活的手指，不是复制品
```

### 设备被盗的防御

```
攻击场景    设备和身体都在攻击者手里

防御层
    地理位置异常检测    新地点首次登录触发额外验证
    新设备登录          需要已有设备确认（类似Apple的设备信任链）
    远程注销            用户可以远程注销所有设备
                        注销后设备上的本地数据被锁定
```

### SOS 伪登录（强迫解锁防御）

```
场景    用户被迫用面容/指纹解锁

防御    连续快速按电源键五次，激活SOS模式
        生物识别依然通过（不让攻击者察觉）
        但进入的是空的感受地图
        真实数据被隐藏，不是删除
        设备外观和正常使用完全相同
```

### 面容识别和四诊合参的协同

```
面容识别通过的那一刻
    设备确认了「是你」
    同时摄像头（望）开始工作
    面容识别 和 四诊合参的「望」 在同一个动作里完成

这是Feelings特有的安全设计
    身份验证和感受感知无缝连接
    不是先验证再感知，而是同一件事
```

```
用户的数据属于用户，不属于Feelings平台
Feelings是数据的托管方，不是所有者

具体体现
    用户随时可以导出所有数据（机器可读格式）
    用户随时可以删除所有数据，删除彻底，无备份
    Feelings平台倒闭，用户数据必须可以被导出和迁移
    不能以「服务条款」为由扣押用户数据
```
