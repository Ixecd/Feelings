# 神经数据传输安全——注入优先的威胁模型

> 作者：qc
> 日期：2026-08-07
> 性质：Feelings 安全设计——神经数据传输链路的专用威胁模型与防护设计
> 核心：神经数据的安全设计不能套用通用方案——因为它的第一威胁不是"窃听"，是"注入"。普通数据的威胁是泄露（加密即够）；神经数据的威胁是注入——攻击者往设备↔存储链路塞伪造信号，等于绕过设备直接操控用户的生理状态。所以安全优先级反过来：帧级认证（防注入）第一，流式加密（防窃听）第二。传输链路是攻击者唯一能碰到神经数据的物理路径——设备内部有 TEE，存储端在用户家，唯独链路是开放的。

---

## 零、为什么神经数据不能套用通用安全方案

```
普通数据（聊天、照片、文档）
    威胁 = 泄露——攻击者看到内容——最坏是隐私损失
    防护 = 加密——传输加密 + 存储加密——够了

神经数据（EEG、皮电、心率、阻抗）
    威胁 = 注入——攻击者往链路上塞伪造信号——
           设备读到伪造的"平静/焦虑"帧——
           直接影响用户的生理状态——
           这不是"看到你的秘密"——是"操控你的身体"
    威胁 = 泄露——同样存在——但注入比泄露危险一个量级
```

Feelings 本身被讨论过"可以当惩罚工具的"——注入攻击就是绕过设备，从链路层干这件事：**不需要入侵设备，不需要拿到钥匙——只需要在设备和存储之间的链路上，让伪造的帧看起来像真的。**

---

## 一、威胁模型——六类攻击，注入第一

```
① 窃听（机密性）   截获链路数据——读神经信号——
                    防护：流式加密——第二优先级

② 注入（真实性）   伪造帧塞进链路——设备或 NAS 当成真数据——
                    直接操控用户的生理状态——
                    防护：帧级认证——第一优先级

③ 篡改（完整性）   修改已存储的历史数据——悄悄改掉某次体验记录——
                    防护：完整性校验——与帧级认证同源

④ 重放（新鲜性）   旧帧/旧数据重放——让设备"重新体验"过去的状态——
                    或让 NAS 归档被旧数据污染——
                    防护：时间戳 + 会话序号——旧帧作废

⑤ 侧信道（物理层） 穿戴设备的时序、功耗、电磁辐射——
                    泄露活动状态——防护：恒时处理 + 屏蔽

⑥ 钥匙（密钥管理） 钥匙被拿 = 一切白搭——
                    防护：TEE 生物绑定 + 轮换——"技术上没有"哲学
```

**威胁模型的一句话排序：注入 > 窃听 > 篡改 > 重放 > 侧信道 > 钥匙。** 普通系统把窃听当第一威胁；神经数据把注入当第一威胁——因为注入有生理后果。

---

## 二、帧级认证——防注入的核心

```
ESIR 帧 = 1ms 一帧——每一帧都必须独立认证——
    帧格式：
        [ 帧头 | 时间戳 | 会话序号 | 载荷 | 认证标签 ]

    认证标签（MAC）：每帧用会话密钥计算——
        伪造帧没有合法 MAC——接收端立即丢弃——
        帧级认证 = 链路层"只收真的"——
        注入攻击者的帧在接收端第一道门就被拒

    防重放：时间戳 + 会话序号——
        旧帧重放 → 序号不连续 → 拒绝——
        时间窗口超过容差 → 拒绝

    设备与 NAS 双向认证——
        NAS 只收来自可信设备的帧——
        设备只向可信 NAS 发送——
        双向防止"假设备"和"假存储"两头
```

**帧级认证为什么必须是每一帧：** 神经数据是流——攻击者不需要注入一整段，只需要在某个敏感时刻注入一帧伪造的"平静"——所以认证的粒度必须是帧，不是会话、不是文件。

---

## 三、流式加密——低延迟的机密性

```
神经数据是连续流（1kHz 采样 × 多通道）——不是请求-响应——
    加密必须跟上帧率——时延预算毫秒级——

    方案：流式加密（如 AES-CTR/GCM 流模式）——
        每帧增量加密——不引入额外延迟——
        认证与加密合并（GCM 模式：加密 + MAC 一步完成）——
        帧级加密 + 帧级认证 = 同一个原语

    密钥轮换：会话密钥定期轮换——
        长期连接（设备↔NAS 常驻）不能一把钥匙用到底——
        轮换周期 + 轮换时的无缝切换——
        旧密钥作废后，截获的旧密文全部失效
```

**局域网内也加密——"局域网"不是安全假设：** 同一网段可能有恶意设备、路由器可能被攻破——**加密的密钥和终点都在用户家，但加密本身不能省。**

---

## 四、局域网传输规范——数据不出门

```
数据流：Feelings 设备 → 局域网（WiFi/有线）→ 用户 NAS
全程不经过公网——互联网上没有神经数据——
不是"不上云"——是"不出门"——
数据连门都没出过——Durov 教训的终极版

传输协议：
    设备 ↔ NAS 之间走专用加密流（见帧级认证 + 流式加密）
    设备本地保留滚动窗口（最近 24h 完整原始）
    NAS 存全量归档（TB 级容量）
    滚动窗口 + 全量归档联动——窗口覆盖，归档长存

设备 ↔ NAS 联动场景：
    多设备汇聚（耳挂、腕部、贴片 → 单点归集）
    历史数据查询（NAS 归档 → 回放/分析）
    设备换新迁移（旧设备数据 → NAS → 新设备）
```

## 五、密钥管理——钥匙在用户手里

```
钥匙存放    设备 TEE + 用户生物特征绑定——
            钥匙不出 TEE——数据在 NAS 上、钥匙在用户身上——
            谁拿到 NAS 硬盘都没有钥匙——
            "技术上没有" > "有但拒绝交"——Durov 教训

Feelings 的角色    卖设备、卖固件、卖协议、卖 NAS——
                  数据在用户家、钥匙在用户手里——
                  卖盒子的人不拥有盒子里的东西——保险箱哲学

红线     Feelings NAS 出厂不得内置任何远程访问能力（除非用户主动开启）——
           OTA 固件更新必须有签名验证——
           更新通道被攻破 = 后门 = "托管密文的另一种形态"——
           信任链责任：固件是产品——被植入 = 全盘皆输
```
