# 数据所有权与销毁规则

> 作者：qc
> 日期：2026-04-22
> 核心：你的感受数据完全归你——你可以随时清除，清除后不可回溯，这是设计上的保证，不是承诺

---

## 一、所有权的法律和技术双重保证

```
法律层面
    GOVERNANCE 明确：原始数据永远不离开用户设备
    用户对自己的所有感受数据拥有完整、永久的所有权
    Feelings 平台不拥有用户数据的任何权利
    包括：使用权、传播权、商业化权

技术层面
    原始数据存储在用户设备的 TEE 加密区
    TEE 的密钥只有用户的生物特征才能解锁
    Feelings 服务器持有的是脱敏统计摘要（用于榜单等功能）
    不是原始数据
    
    技术上的不可能 > 法律承诺
    服务器上没有的数据，连法院命令也无法要求提供
```

---

## 二、数据分类与存储位置

```
原始数据（设备本地 TEE，从不上传）
    原始神经信号（采样数据）
    个人生理基准
    四诊合参的原始读取值
    感受体验的完整记录
    亲密感受维度的所有数据

脱敏摘要（可选上传，用于生态功能）
    感受状态分布（比例统计，不是时间序列）
    体验次数统计（数量，不是内容）
    感受包效果反馈（「有效/无效」，不是具体感受数据）
    这些数据上传前必须用户主动同意，默认关闭

链上记录（公开可查，不含感受内容）
    设备激活记录
    感受包购买记录
    FEEL 代币交易
    授权和撤销授权记录
    这些是交易记录，不是感受数据
```

## 三、数据销毁规则

### 3.1 分级销毁

```
级别 1：当次体验数据清除
    操作：删除单次体验的完整记录
    范围：这次体验的原始信号 + 感受状态记录 + AI 教练对话
    效果：立即生效，不可恢复
    需要：生物识别确认
    常用场景：「这次体验我不想留记录」

级别 2：时间范围数据清除
    操作：删除某个时间段内的所有数据
    范围：该时间段内的所有级别 1 数据
    效果：立即生效，不可恢复
    需要：生物识别确认 + 输入时间范围 + 二次确认
    常用场景：「删除过去一个月的所有记录」

级别 3：账号完全重置
    操作：清除账号内的所有数据
    范围：设备上的所有本地数据 + 服务器上的所有脱敏摘要
    效果：立即生效，不可恢复，账号回到出厂状态
    需要：生物识别 + 输入确认文字 + 24 小时冷静期 + 再次确认
    说明：账号本身（链上地址）保留，但所有数据清空
    常用场景：「我要彻底清空，重新开始」

级别 4：账号注销
    操作：销毁账号 + 所有数据
    范围：级别 3 的所有内容 + 链上账号标记为已注销
    效果：不可逆，账号永久无法恢复
    需要：生物识别 + 确认文字 + 30 天冷静期 + 最终确认
    说明：FEEL 代币在注销前需要转走或放弃，不自动销毁代币
```

### 3.2 销毁的技术实现

```
本地数据销毁
    不是简单的「删除文件」
    是 TEE 内的密钥销毁 + 多次覆写存储区域
    密钥销毁后，即使有人拿到存储介质，数据也无法解密
    符合 NIST SP 800-88 数据销毁标准

服务器端脱敏摘要销毁
    收到销毁请求后，24 小时内从服务器删除
    删除操作链上记录（存证「删除于何时」）
    删除后无法恢复，Feelings 不持有备份

链上记录
    链上的交易记录（设备激活、代币交易等）永远无法删除
    这是区块链的本质属性
    但这些记录不含感受内容
    只是「某个地址在某时做了某个操作」
    用户注销时，链上地址被标记为「已注销」
    链上记录依然可查，但已脱离用户身份
```

## 四、销毁的心理设计

```
不设「你确定吗，这将永久删除...」的恐吓弹窗
    一个简洁的「确认删除」即可
    用冷静期替代恐吓弹窗

    恐吓弹窗的问题
        用大量文字警告制造焦虑
        让用户怀疑「删除是不是我不该做的事」
        Feelings 不评判删除的决定

    冷静期的设计
        时间足够，但不阻塞
        用户可以在冷静期内随时取消
        冷静期结束后自动执行，不需要再次确认

删除不是惩罚
    删除后不会显示「你删除了 X 天的数据」
    不会显示「你失去了 X 个感受记录」
    就是静默完成，什么都不说
    数据消失，就像没有发生过
```

## 五、伴侣模式数据的销毁

```
伴侣连接中的数据
    端对端加密，服务器不持有
    断开连接后，双方设备上的共享数据各自独立处理

你的设备
    你可以用级别 1/2/3 清除你的伴侣模式数据
    你的清除不影响对方设备上的记录

对方的设备
    你无权清除对方设备上的数据
    这是对方的数据，归对方所有

特殊情况
    如果你认为对方在用伴侣模式骚扰你
    你可以举报（见 anti-abuse.md）
    Feelings 会介入，但介入方式是「切断连接」
    不会去删除对方设备上的数据（无权这样做）
```

## 六、数据销毁与 FEEL 代币

```
数据销毁不影响 FEEL 代币余额
    你的代币在链上，链上记录不因数据销毁而变化

账号注销时的代币处理
    必须在注销前把 FEEL 转移到其他钱包
    或者主动放弃（链上记录为「放弃」，代币燃烧）
    Feelings 不替你保管注销账号的代币
    注销后 30 天未处理的代币自动燃烧

感受包购买记录
    链上购买记录永远可查（这是交易记录）
    但本地的感受包使用记录可以清除
    你买了什么，链上可查
    你体验了什么感受，只在你的设备上，可以清除
```

---

## 七、数据所有权 vs 账号功能的取舍

```
完全不上传任何数据
    可以使用所有本地功能
    无法使用排行榜（需要脱敏统计数据）
    无法使用跨设备同步（没有服务器端副本）
    无法使用感受包推荐优化（需要少量反馈数据）

用户自主选择权
    每一项「需要上传数据」的功能
    都可以单独开启或关闭
    关闭后功能消失，数据不上传
    开启后功能可用，数据按最小化原则上传
    不存在「开启某功能就必须上传所有数据」的捆绑
```
