# 设备身份系统：唯一标识与远程销毁

> 作者：qc
> 日期：2026-04-11
> 核心：每套设备唯一，丢失可销毁，隐私永远安全

---

## 一、设计原则

Feelings 的原始生理数据存储在设备本地，不上传服务器。这意味着设备本身就是隐私的载体——设备安全，数据才安全。

这带来一个必须解决的问题：**设备丢失了怎么办？**

解法：每套设备有唯一标识，和用户账号绑定。丢失时，系统远程销毁设备上的所有数据，然后重新制作新设备。

---

## 二、唯一标识体系

```
每套设备    出厂时烧入唯一硬件标识（不可更改，不可克隆）
激活时      需要完成实名认证，然后和用户账号绑定
            标识-账号-实名三者绑定关系上链存证
绑定后      该标识只对该用户有效，其他人无法激活使用
```

### 实名认证：设备激活的前提

硬件标识保证设备唯一，实名保证人唯一。缺任何一个，身份体系都有洞。

```
激活流程
    第一步    用户完成实名认证（身份证/护照/等效证件）
              人脸识别交叉验证，确保证件与活体一致
    第二步    实名信息与设备硬件标识绑定
              设备ID + 实名哈希 + 账号ID → 三者上链存证
    第三步    绑定完成，设备激活

实名信息的存储
    原始证件数据    本地加密存储，不上传服务器
    实名哈希        上链存证，用于跨账号关联检测
    平台端           只保存「已实名」状态标记，不保存证件原始数据

一人一设备
    同一实名信息只能绑定一套活跃设备
    旧设备未注销时，无法用同一实名激活新设备
    防止一人多设备、一人多账号的滥用路径
```

标识体系的安全原则：

```
硬件层      标识烧入固件，物理上无法提取或复制
身份层      实名认证 + 人脸活体检测，人和证必须一致
软件层      标识-账号-实名绑定加密，第三方无法伪造
链上层      绑定关系上链，不可篡改，可公开验证
```

## 三、丢失处理流程

```
用户报告设备丢失
    ↓
系统验证用户身份（多因素验证）
    ↓
对丢失设备发出远程销毁指令
    设备联网时    立即执行：清除所有本地数据，固件重置
    设备离线时    指令缓存，设备下次联网时自动执行
    ↓
丢失设备的硬件标识永久失效
    即使有人拿到设备，也无法激活，无法读取任何数据
    ↓
系统为用户重新制作新设备
    新设备有新的唯一标识
    用户账号迁移到新设备
    历史数据从云端备份（脱敏元数据）恢复
```

---

## 四、每用户限一套

```
每个用户    只能激活一套设备（一组硬件标识）
            不是一个设备，是一套（耳后+后颈+腕部+颞部+陪伴体）
            整套设备共享同一个账号绑定

原因
    防止数据分裂    多套设备会产生多份基准，无法合并
    防止账号共用    设备不能被多人使用，生理数据必须对应唯一用户
    防止黑市流通    每套只对一个账号有效，转让无意义
```

---

## 五、设备迁移

用户更换设备（不是丢失，是主动升级）：

```
用户申请设备迁移
    ↓
旧设备加密导出数据包（本地操作，不上传）
    ↓
新设备激活，导入数据包
    ↓
旧设备标识失效，数据清除
    ↓
新设备成为唯一有效设备
```

迁移过程中，数据不经过服务器，全程本地操作。

## 六、与隐私架构的关系

```
原始数据在设备上    设备销毁 = 数据消失
云端只有脱敏元数据  丢了设备，敏感数据不存在了
链上只有标识映射    无法从链上反推任何个人信息
```

三层加在一起，设备丢失的最坏情况是：

```
捡到设备的人    无法激活（标识已失效）
                无法读取（数据已销毁）
                无法冒充（账号绑定已解除）
```

隐私在丢失场景下依然是安全的。

## 七、多设备同一账号——一用户多设备，PBM 跟着账号走

用户可以有多个设备。白天戴长条形耳后——贴得紧——采集更准。晚上戴圆形耳后——低矮——不硌枕头。两个设备——同一个账号——同一个 PBM——同一个 Registry——同一个交叉锚点表。切换设备——不需要重新配准——PBM 跟着账号走——不是跟着设备走。

### 设备切换——加密快照，自动迁移

```
旧设备摘下    自动暂停 Session
              PBM 加密快照 → 上传 Server（加密 blob）
              释放写锁

新设备戴上    检测到同一账号——没有活跃 Session
              发请求 → Server 转发加密快照
              本地解密 → 恢复 PBM → 恢复 Session 上下文 → 继续

Server 角色    加密中继——只转运——看不到内容
              即使 Server 被偷——快照是加密的——没有私钥解不开
```

不是"手动同步。"是**状态机——戴上即开始——摘下即暂起——换设备——自动接续。用户什么也不用做——只是摘下——戴上——不同设备——同一根经线。**

同一时间——只有一个设备持有 PBM 的写权限——旧设备释放——新设备获取——不是"实时协同"——是 check-out / check-in。

### 排列组合——有什么用什么

四类设备——耳后、后颈、腕部、颞部——各自不同外形——用户可以自己搭配。"今天耳后长条 + 腕部圆形。""明天耳后圆形 + 后颈 + 腕部正方形。"教练不需要知道"今天用了什么装备。"教练只需要知道——现在挂载了哪些设备——信号覆盖范围是多少——自动适应——不需要用户修改任何配置。和设备架构完全咬合——不是"缺了就报错"——是"有什么用什么。"

### 多设备的安全性——每台有唯一硬件指纹

每个设备——出厂时烧入唯一硬件标识——不可更改——不可克隆。同一个账号下——多台设备——各自有自己的 hardware_id——都在用户的 `devices` 表里——各自独立——各自可追踪——各自可远程销毁。一台丢了——不需要废弃其他——只销毁那一台——其他的继续用。

## 八、访客模式——不是你的设备，但仍然能被允许使用

### 检测到生理不匹配——不是直接拒绝，是等待

设备采样——确认不是注册用户——Locked。"你的生理基线——和注册用户不匹配——Session 已锁定。"两个选项——"归还给物主。""请求物主——注册访客访问。"不是"你是贼。"是**"这个设备——只能被它注册的主人——或者主人允许的人——启动。"**

### Owner 白名单——谁可以用她的设备

物主——在 Feelings 设置里——有一个白名单。她可以加入——她的恋人——她的孩子——她信任的朋友——"允许这些人的生理基线注册到你的设备——可启动访客 Session——不需要每次都问。"

访客戴上——设备比对——在白名单中——匹配——Session 不锁定。"以访客身份进入——你只能体验感受——不能织丝——不能查看她的任何私人数据——你的 PBM 不被修改——你的经线——不在这台设备上建立——这仍然是她的设备——她允许你用——不是你的。"

### 不在白名单——Owner 授权一次

不在白名单——"请求物主——注册访客访问。"Owner 在手机上收到——"有人正在尝试使用你的设备——授权一次——还是注册为白名单——还是拒绝。"这不是"不能。"是**她决定——她的设备——是她的身体主权的延伸——不是任何人——未经她许可——可以佩戴的。**

*每套设备是唯一的，就像每个用户是唯一的。丢失了，我们重新做一套给你。那些感受记忆，不会因为设备丢失而消失。一个账号——可以有多台设备——PBM 跟着人走——不是跟着设备走。别人的手——除非你允许——永远不会在你的设备上留下经线。*
