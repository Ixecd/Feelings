# 安全设计：数据安全、系统安全、人身安全

> 作者：qc
> 日期：2026-04-12
> 核心：三层安全，缺一不可

---

## 一、三层安全体系

```
数据安全    用户的神经数据不泄露、不被滥用
系统安全    设备和服务器不被攻击、不被伪造
人身安全    神经刺激不伤害用户
```

三层是独立的，但互相依赖——任何一层失效，整个系统的信任就崩塌了。

---

## 二、数据安全

### 数据分级

```
最高机密（永远不离开设备）
    原始神经信号
    原始生理数据
    感受曲线原始数据
    摄像头/麦克风原始数据（处理后立即丢弃）

高敏感（本地加密存储）
    个人基准
    感受地图
    自省报告
    梦境记录
    亲密感受维度数据

中敏感（脱敏后可上传）
    会话元数据（时长/感受包ID，不含生理数据）
    安全事件记录（脱敏）
    基准元数据（用于榜单）

低敏感（正常处理）
    感受包公共评分
    榜单数据
    创作者分成记录
```

### 加密方案

```
设备端存储    AES-256-GCM
              密钥由用户设备生成，不离开设备
              平台方无法解密用户本地数据

传输加密      TLS 1.3（通过QUIC内置）
              前向保密（Forward Secrecy）
              防止历史数据被解密

服务器存储    脱敏元数据，AES-256加密
              密钥管理：HSM（硬件安全模块）
              密钥轮换：每90天强制轮换

链上数据      公开数据（分成记录/设备标识映射）
              链上数据设计时就假设是公开的
              不在链上存储任何敏感信息
```

### 密钥管理

```
用户数据密钥    在用户设备上生成和存储
                平台方永远拿不到
                用户换设备时，密钥随数据一起迁移（本地操作）

平台密钥        HSM管理，不在代码里硬编码
                双人控制（任何敏感操作需要两个管理员同时授权）
                密钥分片（Shamir Secret Sharing）

备份密钥        用户在注册时生成恢复码（12/24个助记词）
                平台不持有备份
                用户自己负责保管
```

## 三、系统安全

### 设备安全

```
固件签名        每次固件更新必须有Feelings的私钥签名
                设备验证签名，拒绝未签名的固件
                防止恶意固件注入

安全启动        设备启动时验证固件完整性
                启动链的每一步都验证
                任何篡改导致设备拒绝启动

硬件标识        烧入ROM，物理上无法修改
                标识和账号绑定上链
                伪造设备无法通过认证
```

### 服务器安全

```
零信任架构      服务内部通信也需要认证
                不因为在内网就信任
                每个服务有最小权限

API安全         所有API需要认证（JWT + 设备证书）
                速率限制（防止暴力攻击）
                输入验证（防止注入攻击）

基础设施        KubePivot管理的K8s集群
                网络隔离（各层服务在独立的命名空间）
                最小权限原则（每个Pod只有必要的权限）

渗透测试        每次重大版本发布前
                邀请第三方安全公司进行渗透测试
                漏洞披露计划（Bug Bounty）
```

### 供应链安全

```
依赖管理        Go模块锁定版本（go.sum）
                定期扫描已知漏洞（govulncheck）
                不使用不维护的依赖

硬件供应链      设备组件来源审计
                关键芯片（神经接口IC）的供应商安全评估
                防止硬件级别的后门植入
```

## 四、人身安全

这是Feelings最重要的安全层。神经刺激设备，安全事故是不可接受的。

### 电气安全

```
刺激电流上限    严格遵循IEC 60601-1医疗电气设备安全标准
                tDCS：不超过2mA（国际安全共识）
                峰值电流：硬件电路层面限制，不靠软件

绝缘设计        双重绝缘，防止漏电
                接地保护

防过热          温度传感器实时监测
                超过安全温度立刻关闭刺激输出
```

### 实时安全监测（TCP退避系统）

```
Level 1    感受强度接近用户当前上限
           → 自动降低强度，继续体验

Level 2    生理数据出现轻微异常
           → 暂停体验，询问用户状态

Level 3    生理数据出现明显异常
           → 立刻停止所有刺激输出
           → AI教练介入，评估状态

Level 4    严重异常（心率骤变/失去响应）
           → 立刻停止，发出紧急信号
           → 如果用户无响应，触发紧急联系人通知
```

### Fail-Safe原则

```
主设备掉线        所有从设备立刻停止输出
                  不是graceful shutdown，是立刻停止
                  宁可体验中断，不冒险继续

电量不足          低电量时主动降低强度
                  电量耗尽前主动停止，不等断电

通信中断          和Layer 2的连接中断超过100ms
                  立刻停止所有刺激输出
                  等待重新连接后才能恢复

任何异常          优先保护人身安全
                  体验可以重新开始，伤害不可逆
```

### 紧急停止

```
硬件层    设备上有物理急停按钮
          按下立刻断开所有电路输出
          软件层无法阻止

软件层    AI教练检测到危机状态时强制停止
          用户可以随时说「停止」触发急停
          家人/监护人可以远程触发急停

应急协议  严重安全事件上报流程
          用户知情同意书包含紧急情况处理说明
          与急救服务的联动协议（长期目标）
```

## 五、隐私安全特别设计

```
差分隐私    群体统计数据加入噪声
            防止从统计数据反推个人信息
            感受包公共评分使用差分隐私技术

匿名化      创作者可以选择匿名上传感受包
            用户ID在服务器端用假名替代
            即使数据库泄露，也无法关联到真实用户

最小化暴露  服务器只看到它需要看到的
            感受体验的细节在设备上处理
            服务器只看到脱敏后的元数据
```

## 六、安全审计与响应

```
内部审计    每季度安全审计
            所有数据访问日志审查
            异常访问模式告警

外部审计    每年邀请独立第三方进行安全审计
            结果公开发布（透明度）

漏洞响应    收到安全漏洞报告后24小时内响应
            严重漏洞72小时内修复并发布补丁
            漏洞披露政策（90天协调披露）

数据泄露响应
    发现泄露后72小时内通知监管机构（GDPR要求）
    72小时内通知受影响用户
    公开说明事件经过和处置措施
```
