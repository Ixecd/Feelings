# 存储池治理：资金安全与银行托管

> 作者：qc
> 日期：2026-04-21
> 核心：存储池的钱是用户和员工信任的物质基础，分散托管，链上透明，多签授权

---

## 一、核心角色定义

```
qc              项目创始人 & 最终责任人
财务负责人       负责资金记账与出入审核
项目负责人       负责业务支出合理性确认
```

所有授权规则中提到的角色，均以此定义为准。

---

## 二、存储池是什么

```
Feelings 的收入来源
    硬件销售
    平台运营费
    感受包创作者分成（平台运营费部分）
    存储服务利息收益

所有收入进入存储池
    存储池是 Feelings 运营的资金中枢
    进出全部链上记录，透明可查

存储池的支出
    工资（日结/月结，链上到账）
    硬件采购和供应链付款
    平台运营成本
    创作者分成结算
    基础设施维护
```

**存储池不是老板的钱，是 Feelings 这个体系的公共资金。**

---

## 三、为什么分散到多家银行

```
单一银行的风险
    账户被冻结（法律纠纷/监管问题）
    银行系统故障（概率低但存在）
    单点操作失误
    任何一个风险都可能中断工资发放和运营

分散托管的目标
    没有任何一家银行的问题能让 Feelings 停摆
    工资发放不因单一银行故障而中断
    保持运营的连续性
```

## 四、银行按角色分配——不是按名字分配

### 核心原则

**不是"哪家银行占多少比例"。是"每个角色占多少比例——每家在它的角色里占同样的份。"**

角色固定——比例固定——银行按角色加入——同角色平分。加银行——不重新分——只在同角色里均摊。

### 五个角色与固定比例

```
战略储备    25%    永远不动。极端情况下的备用资金。重大资本支出。
运营资金    25%    硬件采购、供应链、工厂。日常运营的主出口。
外汇储备    20%    跨境结算。外币管理。海外供应商。
区域运营    15%    本地结算。区域供应商。下沉市场的本地账户。
流动资金    15%    工资、分成、高频小额流水。不留隔夜钱。

合计        100%
```

### 角色内的分配规则

- 一个角色可以有一家或多加银行
- 同角色的所有银行——平分该角色的固定比例
- 新银行加入一个角色——同角色的比例被重新均分——不需要调整其他角色
- 某家银行被替换——退出——同角色的剩余银行——自然均分

### 启动阶段（五家银行，五个角色各一家）

```
战略储备    工商银行    25%
运营资金    建设银行    25%
外汇储备    中国银行    20%
区域运营    农业银行    15%
流动资金    招商银行    15%
```

### 扩展阶段（示例）

```
战略储备    工商银行    12.5%
           中国邮政    12.5%
运营资金    建设银行    12.5%
           浦发银行    12.5%
外汇储备    中国银行    10%
           汇丰银行    10%
区域运营    农业银行    15%
流动资金    招商银行    7.5%
           网商银行    7.5%
```

加了一家工行同角色的中国邮政——工行从 25% 变成 12.5%——中国邮政同样 12.5%——角色总占比不变——其他角色不受影响。

### 各行职能说明

**战略储备（25%）**

```
定位    国有大型银行优先。资产规模最大，国家信用最强
用途    长期持有，不轻易动
        极端情况下的备用资金
        重大资本支出（建设工厂/大额设备采购）
特点    最静，动得最少，是 Feelings 的压仓石
        流动资金富余的日/周调拨目标
```

**运营资金（25%）**

```
定位    对公业务成熟，基础设施经验丰富
用途    硬件采购付款
        供应链结算
        中期运营周转（季度级别）
        工厂相关支出
特点    稳定的日常运营出口，和供应链深度绑定
        流动资金富余的日/周调拨目标
```

**外汇储备（20%）**

```
定位    外汇业务最强
用途    国际化后的跨境结算
        外币收入的管理
        海外供应商付款（进口传感器/芯片等）
        未来海外市场的资金储备
现阶段    以人民币存放，待 Feelings 国际化后逐步转换用途
纪律      不进行外汇投机，不做杠杆，不做理财
```

**区域运营（15%）**

```
定位    覆盖最广，下沉市场经验最丰富
用途    工厂所在地的本地结算
        区域供应商付款
        未来在非一线城市建工厂时的本地账户
特点    覆盖广度，未来工厂下沉到二三线城市时发挥作用
```

**流动资金（15%）**

```
定位    API 最成熟，对公服务最灵活
用途    工资日结和月结的主出口
        链上结算的法币出入口
        高频小额流水
        开发者/贡献者的链上分成结算
纪律      仅用于当日/当周高频结算
          不长期沉淀大额资金
          每日/每周自动将富余资金调拨至战略储备或运营资金
          保持账户余额在最低必要限度
特点    最活，流转最快，是 Feelings 链上结算的接口层
```

## 五、资金流动逻辑

```
收入进入
    硬件销售收入    → 运营资金
    平台运营费      → 运营资金
    创作者分成      → 流动资金（快速结算）
    利息收益        → 战略储备（沉淀增值）

自动调拨（日/周）
    流动资金富余   → 战略储备或运营资金
    保持流动资金余额在最低必要限度

定期再平衡（季度）
    每季度强制再平衡一次
    当某角色实际占比与目标比例偏差超过 5%
    触发提前再平衡流程，无需等到季度末
    再平衡需要多签授权（见第六节）
    链上记录再平衡操作和理由

支出出口
    工资日结/月结   → 流动资金
    硬件采购        → 运营资金
    外汇支出        → 外汇储备
    本地工厂支出    → 区域运营
    重大资本支出    → 战略储备
```

## 六、多签授权规则

**银行放在哪里是"托管"，钱怎么动才是"管理"。**

> 所有金额均以人民币计算；外币支出按当日汇率折算后适用同一规则。

```
小额支出（< 5 万元）
    1 人授权：财务负责人
    链上自动记录

中额支出（5 万 - 50 万元）
    2 人授权：财务负责人 + 项目负责人
    24 小时内完成授权
    链上记录

大额支出（50 万 - 500 万元）
    2 人授权：财务负责人 + 项目负责人
    链上记录并同步给 qc 备查
    无需 qc 签字

重大支出（> 500 万元）
    3 人授权：财务负责人 + 项目负责人 + qc
    qc 为最终否决权，而非日常签字
    书面说明用途 + 链上永久记录
    72 小时内完成授权

跨银行调拨（再平衡操作）
    2 人授权：财务负责人 + 项目负责人
    链上记录并抄送 qc
    必须注明调拨理由
```

## 七、存储池严禁行为

```
严禁用于个人借款、个人担保、个人理财
严禁参与高风险投资、虚拟货币合约、杠杆交易
严禁未经链上记录的私下转账
严禁为第三方提供任何形式资金担保
严禁外汇投机、杠杆、理财产品（含中国银行账户）
严禁以任何名义绕过多签规则进行资金操作
```

**违反上述任一条款，视为对 GOVERNANCE 的违反，适用 PROTOCOL 的生存条款。**

## 八、透明度规则

```
对内透明
    所有员工可以查看存储池的总余额和月度收支摘要
    不包含具体的采购合同金额（商业敏感）
    不包含个人薪酬（岗位范围公开，个人不公开）

对外透明
    定期发布存储池透明度报告（季度）
    包含：总收入、总支出分类、各银行余额占比
    不包含：具体合同、个人薪酬、商业敏感信息

链上记录
    每一笔超过一定金额的资金流动
    都在链上有对应记录
    不可篡改，可审计
```

## 九、风险应对与警戒线

```
警戒线（黄色）
    存储池总余额 < 3 个月固定运营成本总和
    触发：暂停非必要支出，核心团队预警通知

紧急线（红色）
    存储池总余额 < 1 个月固定运营成本
    触发：立即暂停所有非工资支出
           优先保障工资发放
           优先保障安全机制运营
           召开紧急决策会议

具体金额
    固定运营成本每季度重新计算
    警戒线和紧急线随成本动态调整
    不是固定数字，是动态的 3 倍和 1 倍

某家银行账户被冻结
    同角色的其他银行自动接管
    工资发放切换到同角色或流动资金账户
    业务不中断

某家银行系统故障
    同上，同角色其他银行接管
    通常 24 小时内恢复

极端情况（Feelings 进入终止流程）
    存储池按 state-machine.md 的终止流程处理
    优先结清所有工资
    优先向用户履行退款承诺
    剩余资金按 GOVERNANCE 规定处置
```
