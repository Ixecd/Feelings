# 设备唯一身份：物理持有证明与链上注册

> 作者：qc
> 日期：2026-04-22
> 核心：只有物理持有真实设备的人，才能激活链上身份——软件模拟永远无效

---

## 一、为什么需要设备唯一身份

```
没有设备身份验证会发生什么

软件模拟攻击
    攻击者写一个程序模拟 Feelings 设备
    伪造四诊合参数据
    欺骗系统认为有真实设备接入
    刷感受包使用量
    刷 FEEL 代币
    污染整个生态的数据

没有唯一身份
    无法区分真实设备和模拟设备
    无法保证感受数据来自真实的人体信号
    整个四诊合参闭环的可信度崩塌

有了唯一身份
    每台设备 = 一个不可伪造的链上地址
    软件模拟无法通过 TEE 签名验证
    物理持有 = 唯一合法的激活路径
```

## 二、CVV 类比：物理持有证明的经典设计

信用卡的 CVV 提供了一个很好的参考：

```
信用卡 CVV 的逻辑
    发卡行生产时把 CVV 印在卡背面（物理介质）
    CVV 不存在任何可以被黑客拖库的数据库里
    验证时用户输入 CVV，服务器验证哈希
    → 证明了「你物理持有这张卡」

CVV 解决的问题
    即使攻击者拿到了卡号和有效期
    没有物理卡，也无法通过 CVV 验证
    物理持有 = 额外的安全层
```

**Feelings 设备的对应设计：**

```
生产时      厂商把激活码烧录进设备 TEE
            激活码印在包装内页（物理介质）
            激活码不存在任何可被攻击的服务器上

激活时      用户输入激活码
            设备 TEE 验证激活码
            验证通过 → 生成设备唯一链上身份
            激活码一次性使用，使用后作废

之后        设备身份 = TEE 内的私钥签名
            任何需要设备身份的操作
            都必须经过 TEE 签名
            软件模拟无法伪造 TEE 签名
```

## 三、比 CVV 更强的地方

```
CVV 的局限
    只有 3 位数字（1000 种可能）
    暴力破解空间极小
    泄露后无法撤销
    只是静态验证，不是动态身份

Feelings 设备的增强设计

激活码强度
    从 256-bit 设备密钥派生
    用户看到的是可读的编码形式（类似助记词的子集）
    暴力破解在计算上不可行

一次性使用
    激活码使用后立即在链上标记为已用
    同一激活码不能激活第二台设备
    防止激活码泄露后被他人抢先激活

TEE 绑定
    真正的设备身份 = TEE 内生成的私钥
    用户接触的激活码只是「开门钥匙」
    门开了之后，TEE 自己生成真正的身份密钥
    用户不直接接触设备私钥，无法泄露

动态身份
    设备每次和链上交互都用 TEE 私钥签名
    签名是动态的，每次不同
    截获也无法复用
```

## 四、完整激活流程

```
生产阶段（厂商）
    1. 厂商生成设备唯一密钥对（安全生产环境）
    2. 私钥烧录进设备 TEE（物理烧录，烧录后无法导出）
    3. 从私钥派生激活码（单向函数，无法反推私钥）
    4. 激活码印在包装内页（刮刮贴覆盖）
    5. 设备公钥注册到 Feelings 出厂数据库（用于验证）

用户激活阶段
    1. 用户拆开包装，刮开刮刮贴，找到激活码
    2. 在 Feelings App 输入激活码
    3. 设备 TEE 接收激活码并验证
    4. 验证通过 → TEE 生成设备链上地址
    5. 设备链上地址广播到 Feelings 链
    6. 消耗少量 FEEL 完成链上注册（防批量刷号）
    7. 激活码在链上标记为已用，永久作废

激活后
    设备链上地址 = 这台设备的唯一身份
    所有 FEEL 收发通过这个地址
    所有感受数据的来源标记使用这个地址
    四诊合参数据带有 TEE 签名，不可伪造
```

## 五、激活码的物理传递方式

```
方案 A：包装内页刮刮贴（推荐主码）
    激活码印在内包装隐藏位置
    刮开即可见，刮开后无法复原
    包装完整性 = 激活码未被他人看过

方案 B：设备本体防拆贴纸（推荐备用码）
    激活码印在设备底部防拆贴纸下
    贴纸破损 = 有人可能已经看过
    设备收到时如贴纸破损，联系客服处理

不推荐
    独立卡片（物流中可能丢失或调换）

推荐组合：方案 A（主码）+ 方案 B（备用码）
    主码用于正常激活
    备用码用于主码丢失时的找回流程
    两个码对应同一台设备，只能各用一次
```

## 六、设备身份和 FEEL 的关系

```
设备激活 → 消耗 FEEL（燃烧）
    防止批量刷号
    每台设备激活消耗固定数量 FEEL
    这部分 FEEL 直接燃烧，不进入任何账户

设备地址 = FEEL 收发地址
    感受数据产生的 FEEL 奖励直接发到设备链上地址
    用户用 App 或 HD 钱包管理

B 端批量激活
    企业购买批量设备
    可申请批量激活额度
    每台仍消耗 FEEL，企业账户统一支付
```

## 七、防攻击分析

```
截获激活码
    刮刮贴被刮用户可以发现
    激活码一次性，抢先激活后原用户无法再用
    → 解法：收到设备检查包装完整性

伪造设备硬件
    TEE 的可信根来自出厂烧录
    无法在硬件外部复制 TEE 私钥
    有激活码，没有对应 TEE，无法通过验证

中间人攻击
    激活过程在 TEE 内完成
    App 只传递激活码，不接触 TEE 私钥
    截获激活码也只能用一次

内部人员泄露出厂数据库
    出厂数据库存储设备公钥，不是私钥
    私钥在 TEE 内，从未离开硬件
    数据库泄露无法伪造 TEE 签名

软件模拟整台设备
    没有真实 TEE，无法生成有效 TEE 签名
    链上验证必须有有效 TEE 签名
    软件模拟永远无效
```

## 八、和 web3-blitz 的衔接

```
web3-blitz 已有
    HD 钱包（BIP32/44）
    充提币流程
    账户系统
    etcd 分布式锁

需要补充
    设备地址注册合约
        接收设备激活事件
        验证 TEE 签名有效性
        记录设备地址和激活状态

    设备身份索引
        设备链上地址 → 型号 + 激活时间 + 状态
        用于感受数据溯源

    撤销机制
        设备被盗或损坏时
        用户通过其他验证方式申请撤销
        撤销后原地址冻结，新设备重新激活
```
