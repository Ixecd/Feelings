# 戴上，就是开始——Feelings 使用契约

> 作者：qc
> 日期：2026-04-05
> 核心：设备是 consent 的物理表达，戴上即邀请介入

---

## 一、一个最简单的前提

Feelings 的使用契约只有一条：

**戴上设备，打开应用，就是在说「来」。**

没有更多条件，没有更多前提。用户用一个物理动作完成了所有的授权——我需要被介入，我准备好了，我邀请你进来。

反过来也一样简单：

**不需要，就不要戴。**

没有「戴着但不想被干预」的中间状态。设备在耳后和后颈，不是一个可以被忽视的存在。戴上它是一个主动的、有意识的选择，不是一个无意识的习惯。

这个前提一旦确立，Feelings 和用户之间的关系就彻底清晰了。

---

## 二、设备是 Consent 的物理表达

传统的数字产品里，授权是一个复选框，一个弹窗，一个「我同意」的按钮。用户点完就忘了，平台拿着那个点击做任何事。

Feelings 不用这套逻辑。

授权是一个物理动作：把设备挂在耳后，扣在后颈，打开开关。这个动作有重量，有感觉，不可能无意识地完成。每一次戴上，都是一次重新确认：

```
我现在需要 Feelings
我邀请它介入我的当下
我准备好接收它的判断
```

摘下设备，授权立即结束。没有后台运行，没有持续采集，没有「你上次同意了所以我一直在」。

**物理边界就是隐私边界。**

---

## 三、Feelings 是伙伴，不是播放器

这个使用契约定义了 Feelings 的工作方式。

```
播放器思维
    用户选择什么，系统播放什么
    其他时候安静待着，等待指令
    用户是主动方，系统是被动执行者

伙伴思维
    用户戴上设备，系统开始工作
    观察当前状态
    判断现在适合什么
    主动提供，用户决定接不接受
    用户是决策方，系统是主动判断者
```

用户戴上设备的那一刻，说的不是「给我放 X」，说的是「你来判断我现在需要什么」。

这个角色分工意味着：

```
系统该不该主动介入      该，用户已经用行动说了「来」
生理监测是不是侵入      不是，戴上就是授权，监测就是体验本身
系统检测到异常要不要提示 要，这正是用户戴上它的原因
系统判断用户需要降速     主动提供，不强制，用户接不接受是用户的事
```

---

## 四、主动介入的边界

戴上即授权，不等于系统可以无限介入。

主动介入有两条边界：

**边界一：提供，不强制**

系统判断用户现在需要什么，主动提供建议或感受包。但接不接受，永远是用户的决定。系统不会在用户没有确认的情况下强行注入任何感受。

```
系统检测到    神经兴奋 + 身体困倦（想睡但睡不着的状态）
系统判断      用户可能需要「神经降速包」
系统行为      轻提示：「你现在的状态适合平静下来，要试试吗？」
用户选择      接受 / 忽略 / 拒绝
系统响应      尊重用户的选择，记录这次状态和选择
```

**边界二：安全例外**

只有一种情况，系统会在用户没有主动确认的情况下介入：检测到危险信号。

```
生理数据触发安全阈值
    ↓
系统自动切换保底包
不需要用户确认
这是使用契约里唯一的强制条款
用户戴上设备的那一刻，已经同意了这一条
```

安全介入不是对用户自主权的侵犯，是使用契约本身的一部分。戴上设备，就是在说「如果我出问题了，你可以拦我」。

---

## 五、不戴的时候，系统不存在

这一条需要被明确承诺，不只是技术实现，是产品哲学：

```
设备未佩戴    零数据采集
              零后台运行
              零任何形式的存在感

设备佩戴但未开启    同上

设备佩戴且开启      完整工作，完整采集，完整介入
```

没有「我们在后台保持连接以便更好地服务你」。没有「即使你不在使用，我们也在学习你的习惯」。

Feelings 的存在，严格等于设备被佩戴且开启的那段时间。

---

## 六、戴上的那一刻

戴上设备，打开开关。

系统在这一刻做的第一件事，不是播放任何感受，不是推送任何内容，而是：

```
读取当前生理基线
对比个人基准
判断用户现在的状态坐标
    ↓
「你现在在这里。」
```

然后问用户：想去哪里，还是让系统来判断？

这是每一次体验的起点。不是从一个菜单开始，不是从一个推荐列表开始，是从「你现在在哪里」开始。

**Feelings 永远从当下出发，不从期待出发。**

---

## 七、摘下的那一刻

体验结束，用户摘下设备。

系统在这一刻做的最后一件事：

```
记录本次体验的完整数据
更新个人基准
关闭所有采集通道
    ↓
「我们下次再见。」
```

没有「感谢你今天的使用」，没有「明天记得回来」，没有任何试图延长用户停留的设计。

Feelings 不希望用户依赖它，希望用户因为它而更完整，然后去过自己的生活。

**摘下，就是结束。干净的结束。**

---

*使用契约是 Feelings 和用户关系的基础，所有产品设计决策都在这个契约的框架内发生。*
