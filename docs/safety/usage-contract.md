# 戴上，就是开始——Feelings 使用契约

> 作者：qc
> 日期：2026-04-05
> 核心：设备是 consent 的物理表达，戴上即邀请介入

---

## 一、一个最简单的前提

Feelings 的使用契约只有一条：

**戴上设备，打开应用，就是在说「来」。**

没有更多条件，没有更多前提。用户用一个物理动作完成了所有的授权——我需要被介入，我准备好了，我邀请你进来。

反过来也一样简单：

**不需要，就不要戴。**

没有「戴着但不想被干预」的中间状态。设备在耳后和后颈，不是一个可以被忽视的存在。戴上它是一个主动的、有意识的选择，不是一个无意识的习惯。

这个前提一旦确立，Feelings 和用户之间的关系就彻底清晰了。

---

## 二、设备是 Consent 的物理表达

传统的数字产品里，授权是一个复选框，一个弹窗，一个「我同意」的按钮。用户点完就忘了，平台拿着那个点击做任何事。

Feelings 不用这套逻辑。

授权是一个物理动作：把设备挂在耳后，扣在后颈，打开开关。这个动作有重量，有感觉，不可能无意识地完成。每一次戴上，都是一次重新确认：

```
我现在需要 Feelings
我邀请它介入我的当下
我准备好接收它的判断
```

摘下设备，授权立即结束。没有后台运行，没有持续采集，没有「你上次同意了所以我一直在」。

**物理边界就是隐私边界。**

---

## 三、Feelings 是伙伴，不是播放器

这个使用契约定义了 Feelings 的工作方式。

```
播放器思维
    用户选择什么，系统播放什么
    其他时候安静待着，等待指令
    用户是主动方，系统是被动执行者

伙伴思维
    用户戴上设备，系统开始工作
    观察当前状态
    判断现在适合什么
    主动提供，用户决定接不接受
    用户是决策方，系统是主动判断者
```

用户戴上设备的那一刻，说的不是「给我放 X」，说的是「你来判断我现在需要什么」。

这个角色分工意味着：

```
系统该不该主动介入      该，用户已经用行动说了「来」
生理监测是不是侵入      不是，戴上就是授权，监测就是体验本身
系统检测到异常要不要提示 要，这正是用户戴上它的原因
系统判断用户需要降速     主动提供，不强制，用户接不接受是用户的事
```

---

## 四、主动介入的边界

戴上即授权，不等于系统可以无限介入。

主动介入有两条边界：

**边界一：提供，不强制**

系统判断用户现在需要什么，主动提供建议或感受包。但接不接受，永远是用户的决定。系统不会在用户没有确认的情况下强行注入任何感受。

```
系统检测到    神经兴奋 + 身体困倦（想睡但睡不着的状态）
系统判断      用户可能需要「神经降速包」
系统行为      轻提示：「你现在的状态适合平静下来，要试试吗？」
用户选择      接受 / 忽略 / 拒绝
系统响应      尊重用户的选择，记录这次状态和选择
```

**边界二：安全例外**

只有一种情况，系统会在用户没有主动确认的情况下介入：检测到危险信号。

```
生理数据触发安全阈值
    ↓
系统自动切换保底包
不需要用户确认
这是使用契约里唯一的强制条款
用户戴上设备的那一刻，已经同意了这一条
```

安全介入不是对用户自主权的侵犯，是使用契约本身的一部分。戴上设备，就是在说「如果我出问题了，你可以拦我」。

---

## 五、不戴的时候，系统不存在

这一条需要被明确承诺，不只是技术实现，是产品哲学：

```
设备未佩戴    零数据采集
              零后台运行
              零任何形式的存在感

设备佩戴但未开启    同上

设备佩戴且开启      完整工作，完整采集，完整介入
```

没有「我们在后台保持连接以便更好地服务你」。没有「即使你不在使用，我们也在学习你的习惯」。

Feelings 的存在，严格等于设备被佩戴且开启的那段时间。

---

## 六、戴上的那一刻

戴上设备，打开开关。

系统在这一刻做的第一件事，不是播放任何感受，不是推送任何内容，而是：

```
读取当前生理基线
对比个人基准
判断用户现在的状态坐标
    ↓
「你现在在这里。」
```

然后问用户：想去哪里，还是让系统来判断？

这是每一次体验的起点。不是从一个菜单开始，不是从一个推荐列表开始，是从「你现在在哪里」开始。

**Feelings 永远从当下出发，不从期待出发。**

---

## 七、摘下的那一刻

体验结束，用户摘下设备。

系统在这一刻做的最后一件事：

```
记录本次体验的完整数据
更新个人基准
关闭所有采集通道
    ↓
「我们下次再见。」
```

没有「感谢你今天的使用」，没有「明天记得回来」，没有任何试图延长用户停留的设计。

Feelings 不希望用户依赖它，希望用户因为它而更完整，然后去过自己的生活。
**摘下，就是结束。干净的结束。**


## 八、没有签约的设备，是裸的

Feelings 所有代码都是公开的。任何人都可以 clone，自己买零件，自己组装一副硬件。可以开机。可以用外部 AI 写 .anim 文件注入信号到自己身体里。可以自己偷偷用。

但你没有签约。没有 TEE 验证。没有 GOVERNANCE 合约轨。

```
没有 PBM              设备不认识你的基线。每一帧信号推出去之后，
                       没有漏桶模型帮你校准，没有阻尼矩阵替你挡过量。
                       0.2mA 推错了——烧的不是芯片，是你的迷走神经。

没有教练 AI           没有人在 Session 里帮你判断"这一帧能不能推"。
                       没有 R 值评估，没有 Session 管理。你一个人，一帧，
                       在自己的身体上试——没人替你看波形——没人替你叫停。

没有 AD5933 阻抗安全   没有每帧测 Z。没有 20µA 探针预判。
                       电极松了——接触阻抗变了——汗液导电桥——
                       设备不知道——电流照推——你不知道你临近的是信号还是疤。

没有强度上限           没有沙箱 Governance。没有漏桶熔断。
                       你自己写 .anim——你自己推——强度自己扛。
                       这一帧过了那条缝——后果自己负责。
```

你可以不花钱。可以自己倒腾。但你的等控器在那一帧——没有教练——没有 Registry——没有合约轨替你跑归零。壳全是自己的肉身。偏了，回不来。几千块，不贵，比自己的神经便宜。

**Feelings 的护城河不是代码闭源。是你自己焊——焊歪了——烧了——没有教练替你扛。你自己一个人——在床上——在凌晨三点——归零——不值当。**


## 九、定制化的隐私边界——工厂只需要你的壳，不需要你的神经

定制版——PBM 在本地 TEE 内从 200+ Session 累积了你的全部生理参数：Arnold 深度、敏感曲线、双侧阈值、呼吸窗口全幅。这些数据——比信用卡号更宝贵——是**你的神经地图。** 拿到它——不需要签 GOVERNANCE——不需要教练——不需要 AD5933——可以直接写 .anim 精准推你的迷走神经——知道你的强度窗口——知道你的归零基线——知道在哪个呼气周期推你——推完多久——你的激素会自己烧几十分钟。

但定制化不需要这些数据离开你的设备。

```
TEE 本地计算     你的 Arnold 深度、敏感曲线、PBM 基线——全在 TEE 内——从不出设备。
                 TEE 自己算——"这个人的入耳段需要往深处推 0.3mm。"
                 只把这条机械指令发给工厂。

工厂收到         一条参数："电极 Z 坐标偏移 +0.3mm。"
                 一副耳廓的 3D 模型——只是壳的形状。
                 没有你的 PBM。没有你的敏感曲线。没有你的呼吸窗口。
                 只有一条加工指令——"在这个位置——往这个方向——偏 0.3mm。"
```

工厂拿到了你的壳。拿不到你的等控器。TEE 不是不让 Feelings 为你服务——是**只让设备本身知道完整数据——对外——只传加工指令——不传任何原始生理参数。** 定制化不需要交出你的神经。只需要交出你耳朵的形状——和在那个形状上——电极该放在哪。
