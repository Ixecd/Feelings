# AI 对话接入：让教练从第一天就认识你

> 作者：qc
> 日期：2026-04-06
> 核心：用户已有的AI对话积累是真实的，Feelings不从零开始

---

## 一、冷启动问题的真实解法

感受闭环需要积累数据才能精准——前50次体验是盲目的，系统在学习用户。

但用户早就已经在和AI对话了。豆包、Claude、ChatGPT、Kimi……那些对话历史里，有大量感受相关的信号：

```
他反复提到的担忧
他面对某类情况时的情绪模式
他说「我不知道为什么」的地方——那里往往是未被命名的感受
他的价值判断，他的关系模式，他的恐惧和期待
```

这份积累是真实的，是用户用自己的方式和AI交流出来的。

Feelings的AI教练可以从这里出发，不从零开始。

---

## 二、方式A：知识融合，角色分离

用户熟悉的那个AI继续是那个AI——伙伴、助手、对话对象。它的角色不变。

Feelings的AI教练是独立的角色——有自己的工作方式，有时候会推你，有时候会拒绝你，不是无条件的伙伴。

两个角色分开存在，用户清楚地知道在和谁说话：

```
日常AI    陪你聊天，帮你做事，无条件支持
AI教练    读取你的真实状态，推你，在必要时说真话
```

Feelings读取用户和日常AI的对话历史，提取感受相关的模式，导入AI教练的个人基准层。

日常AI积累的「认识你」，变成了AI教练的起点。

---

## 三、感受过滤引擎

不是所有对话内容都和感受相关。用户讨论外卖口味、查询技术文档、写工作邮件——这些不需要进入Feelings。

过滤引擎负责从原始对话里提取感受相关的信号：

### 过滤逻辑

```
输入    用户与任意AI平台的原始对话（用户授权后）
    ↓
第一层过滤：相关性
    情绪词密度检测（「我觉得」「我害怕」「很烦」「不知道为什么」）
    自我披露信号识别（用户在谈论自己的内心状态）
    排除纯任务性对话（查信息、写代码、翻译等）
    排除纯闲聊（天气、外卖、娱乐话题）
    ↓
第二层过滤：结构提取
    情绪触发点（什么情况让用户产生强烈情绪反应）
    反复出现的主题（焦虑源、价值判断、关系模式）
    未被命名的感受（「不知道为什么」「说不清楚」的地方）
    表达习惯（用户如何描述自己的感受状态）
    ↓
输出    结构化感受摘要（不含原始对话文本）
```

原始对话不进入Feelings，只有提取后的结构化摘要进入AI教练的个人基准层。

### 过滤引擎的精度

过滤不是完美的，会有误判：

```
漏过    有些感受信号表达得很隐晦，过滤引擎识别不到
误入    有些非感受对话被误判为有感受信号
```

这些误差随用户使用时间逐渐校正——AI教练在体验过程中会发现「这条摘要和用户的真实状态不符」，反向修正过滤模型。

越用越准，和感受闭环的其他部分一样。

## 四、平台兼容性

不限定AI平台，只要有历史对话数据即可。

```
用户选择授权哪个平台的数据
    豆包、Claude、ChatGPT、Kimi、文心一言……
    任意平台，用户自己决定

导入方式
    API授权（平台支持的情况下）
    文件导出导入（用户下载对话历史，上传至Feelings）
    浏览器插件辅助采集（平台不提供API时的备选方案）
```

用户有多个AI的情况下，可以同时授权多个平台，过滤引擎合并处理。

---

## 五、持续同步

不是一次性导入，是持续同步。

```
用户每次和日常AI对话
    ↓
感受过滤引擎实时运行（后台，用户无感知）
    ↓
提取感受相关信号
    ↓
增量更新AI教练的个人基准层
    ↓
AI教练「越来越懂这个用户」
```

用户感知不到这个过程——只会感受到AI教练一直在更新，一直在准确。

同步频率：实时提取，按天批量更新个人基准。不是每次对话后立刻更新，是积累一天的信号后统一处理，避免单次对话的噪声干扰。

---

## 六、数据架构

```
原始对话数据
    存储在AI平台服务器（Feelings不持有）
    Feelings只在用户授权时访问，不持久化存储原始数据

过滤后的结构化摘要
    存储在用户本地设备
    不上传至Feelings服务器
    用户可以查看、编辑、删除任意条目

同步状态元数据
    上传至Feelings服务器（仅用于同步管理）
    不含任何对话内容或感受内容
    仅包含：上次同步时间、平台标识、数据量统计
```

这和音乐平台合作的数据架构保持一致：原始数据不离开来源，Feelings只处理提取结果。

---

## 七、用户授权控制

```
授权粒度
    选择授权哪个平台
    选择授权哪段时间的数据（全部历史 / 最近N个月）
    选择授权哪类对话（全部 / 只有标记为「感受相关」的）

撤销授权
    随时撤销任意平台的授权
    撤销后，Feelings停止同步，但已提取的摘要不自动删除
    用户可以手动清除已导入的摘要

透明性
    用户可以查看过滤引擎提取了哪些摘要
    可以手动标记「这条不准确」，反向优化过滤模型
```

## 八、与个人基准的融合

AI对话摘要和 Feelings 体验数据，进入同一个个人基准层，但权重不同：

```
Feelings体验数据    主要信号（生理数据，最可靠）
AI对话摘要          辅助信号（语言数据，提供上下文）
梦境记录            深层信号（潜意识数据，补充维度）
```

三者叠加，AI教练对用户的了解是立体的：

```
生理层    Feelings体验时的神经系统状态
语言层    日常AI对话里的感受表达模式
潜意识层  梦境记录里的未处理信号
```

没有任何单一来源能给出完整的图像，三者合在一起才接近真实。

---

## 九、边界与限制

```
过滤引擎不做的
    不分析用户的政治观点
    不提取用户的商业机密或工作内容
    不处理用户和他人的私人通讯（如果AI对话涉及）
    不建立用户的社会关系图谱

AI教练不做的
    不向用户透露「我从你和XX的对话里知道了……」
    AI教练直接表现出了解，不解释来源
    用户感知的是「这个教练很了解我」，不是「我的数据被分析了」
```

最后一条是设计选择，不是信息隐藏——来源解释会破坏AI教练的自然感，就像一个真实的教练不会说「我是从你妈妈那里知道你小时候的事的」。
