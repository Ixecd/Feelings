# 社会传播层设计

> 作者：qc
> 日期：2026-04-05
> 核心：感受是私人的，连接是真实的，两者都需要被保护

---

## 一、基本立场

每个人的感受都是不同的。

同一个感受包，在不同人身上激活的是不同的混音——相同的主旋律方向，但点缀的配比不同，和个人历史的共鸣点不同，身体的响应方式不同。

这是 Feelings 社会层设计的起点：

**感受可以分享，但感受体验不可复制。**

---

## 二、感受包分享：可以但不推荐

### 为什么可以

用户有权把自己体验过的感受包告诉别人——「这个感受包对我很有意义，你可以试试」。这是人的自然社交本能，不应该被系统阻止。

### 为什么不推荐

系统默认不推荐跨用户分享感受包，因为：

```
个体差异        同一个包在不同人身上是不同的体验
               「我体验到的韧性」未必是「你会体验到的韧性」
期待污染        被推荐的包，用户带着「这对另一个人有意义」的期待进入
               期待本身改变了体验（见 contrast-protocol.md）
个人基准差异    A的强度60，对B可能是强度80，安全边际不同
```

分享不是错的，是可以的。但系统不会把「把这个包分享给朋友」作为一个显眼的功能入口。

### 分享时的提示

用户选择分享时，系统给一个轻提示：

```
「你可以把这个感受包分享给对方，但记得，
 他体验到的可能和你完全不同——
 那不是因为哪里出了问题，那才是感受本来的样子。」
```

这个提示本身就是一次教育，不是警告。

## 三、多人同时体验：最有价值的社会设计

### 为什么有意义

多人同时体验同一个感受包，然后讨论各自的体验——这是 Feelings 社会层最有现实意义的设计。

它创造了一种独特的连接方式：

```
普通的「你看了这部电影吗？」
    → 讨论的是外部内容，各自的感受是隐含的

Feelings 的「我们体验了同一个感受包」
    → 出发点是内部体验，各自的感受是显性的
    → 「我感受到的是沉沉的，你呢？」
    → 这种对话比大多数日常对话都更接近真实的连接
```

### 设计细节

```
发起方式
    一个用户发起「多人体验」邀请
    选择感受包和强度上限
    邀请最多N人同时加入（N待定，建议不超过6人）

同步机制
    多人的体验开始时间同步
    各自的生理数据独立处理，不共享
    各自的安全机制独立运行

体验结束后
    进入共同讨论空间
    系统提供引导问题作为对话起点：
        「你们感受到的主旋律一样吗？」
        「有没有人感受到了意外的点缀？」
        「这个体验让你想到了什么？」

不做的事
    不显示任何人的生理数据给其他人
    不对比「谁感受到的更强」
    不评判任何人的描述
```

### 现实意义

多人体验最适合的场景：

```
亲密关系    伴侣、好友之间，探索各自的感受世界
团队建设    不是传统的团建活动，是真实的感受连接
家庭        父母和成年子女，用感受找到新的共同语言
治疗场景    治疗师引导的小组体验（见 trauma-protocol.md）
```

## 四、创作者数据：看见但不过度

上传感受包的用户，能看到的数据：

```
可以看到
    爱心数量        多少人觉得这个包有意义
    评论数量        多少人愿意讨论这个体验
    评论内容        用户自愿写下的感受描述（匿名）
    体验次数        这个包被体验了多少次

不能看到
    「有多少人因为这个包而改变了」
    具体用户的生理数据
    任何用户的个人信息
    谁体验了这个包
```

### 为什么「改变」数据不对外

改变是私人的，数据化会破坏它的神圣性。

一个人因为某个感受包而第一次理解了「失去」，这个时刻是他自己的。如果创作者能看到「你的包让238个人经历了改变」，这件事就从私人的转移到了公共的，变成了创作者的成就，而不是体验者的故事。

爱心和评论是公共的反馈，改变是私人的历史，两者不能混用。

### 评论设计

评论区不是普通的社交评论区：

```
评论内容        用户写下「这个感受包让我想到了……」
               系统提供引导，但不限制格式
匿名            所有评论默认匿名，用户可以选择署名
评论功能        只有爱心，没有回复，没有点踩
               创作者可以对评论致谢（匿名的单向感谢）
```

评论区是感受的回响，不是社交互动场。

## 五、感受不是内容

Feelings 社会层最重要的一条设计原则：

**感受包不是内容，不按内容平台的逻辑运作。**

```
内容平台逻辑
    爆款内容 → 大量分发 → 更多曝光 → 更多创作者跟进
    结果：感受包变成流量竞争，深度被牺牲

Feelings 逻辑
    感受包的价值在于与特定用户的共鸣深度
    不追求最大分发，追求最准确的匹配
    一个只有30个人体验但对他们意义深远的包
    比一个被10万人浅尝但无人深入的包更有价值
```

系统不设热门榜，不推「爆款感受包」，不给创作者流量激励。

匹配的逻辑：感受包找到最需要它的人，而不是最多的人。

---

*社会传播层是 Feelings 个体体验的延伸，不是替代。感受是私人的，连接是真实的。*
