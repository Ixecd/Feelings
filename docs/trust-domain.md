# 信任域——全栈掌控的红利是砍掉冗余

> 作者：qc
> 日期：2026-05-21
> 性质：Feelings 工程哲学，不可降级
> 核心：传统架构的多层互不信任导致了大量防御设计。全栈自己掌控 = 信任域收窄到物理边界——边界之内零冗余，边界之上不砍。

---

## 零、传统架构的信任模型

传统软件开发里，每一层都不信任其他层。不是因为偏执——是因为上一层和下一层不是同一批人写的，不是同一家公司维护的，不是同一个时间设计的。

```
App     不信任 OS       → API 每次都带认证 token，每次都要重试超时
OS      不信任驱动      → IOMMU 隔离 + 系统调用校验 + 用户态/内核态切换
驱动    不信任硬件      → 协议握手 + 版本协商 + 错误校正码
硬件    不信任物理      → ECC 内存 + 冗余电源 + 看门狗定时器
```

每层都在防御下层可能出错。但大部分时候下层没有出错——只是在预防它可能出错。这些预防措施加起来：协议协商的往返次数、序列化/反序列化的 CPU 时间、重复认证的网络延迟、防御性拷贝的内存占用。每一项单独看都是必要的。全部加起来——就是传统架构的信任税。

---

## 一、全栈控制的信任域

Feelings 的二十二层全栈——从电子到感受——每一层都是自己设计的。硬件是你指定的。固件是你写的。OS 是你写的。交织器是你写的。AI 教练是你写的。没有外包。没有第三方。没有「我不知道这一层在干什么」。

```
Feelings 的信任域

    层 0-4   电子/晶体管/逻辑门/离散/机器码     FPGA——你选的型号，你写的 bitstream
    层 5     固件与实时系统                     Feelings-OS——六个守护进程，全部你写的
    层 6     设备硬件                           /dev/ear /dev/wrist——设备是你设计的
    层 7-9   信号处理/交织管线/类型系统           animi——八 Pass 全是你写的
    层 10-18 数据/网络/应用/AI/安全/治理          全部 Feelings 自研
    层 19-21 解剖/神经/感受                      物理边界——这一层你没法控制

    信任域 = 层 0-18 = 整个工程栈 = 所有进程、所有驱动、所有硬件。
    物理边界 = 层 19-21 = 神经和感受。不能控制，但可以预埋插桩。
```

信任域不再是层与层之间的间隙——信任域覆盖了整个工程栈。从 FPGA 寄存器到 animi 的输出，中间没有「别人的代码」。

---

## 二、可以砍掉——信任域内部的冗余

**协议协商。** TCP 三次握手、TLS 握手、HTTP 头解析、内容协商。这些存在是因为客户端和服务端互相不信任对方的版本和能力。Feelings-OS 里 busd 直连驱动，设备直连 FPGA，总线的两端都是你写的。接收方知道发送方会发什么格式的数据。不需要协商——你知道对面是什么。

**序列化/反序列化。** JSON/Protobuf/Avro 序列化是因为数据要跨语言、跨平台、跨网络。Feelings 全栈内部——FPGA 寄存器数据 → C 驱动 volatile → Rust 上层 → animi——数据在同一个物理地址空间里流动。帧缓冲页直接 mmap 切换指针。不经过任何序列化/反序列化。

**重复认证。** 传统架构：App → API Gateway（认证）→ Service A（再认证）→ Service B（再认证）→ DB（再认证）。每一层都在验证调用者身份——因为每一层都不确定上游是不是已经被攻破。Feelings 只有一个信任域。设备认证在 FPGA 的 TEE 里做一次。后面全部信任——同一个地址空间，同一个进程树，同一个框架。

**防御性拷贝。** 不确定调用方会不会在你去读的时候修改数据——先拷一份再传。Feelings 里帧缓冲是单写者单读者。写入完成切换指针。读者看到的就是完整的新帧。零防御性拷贝。

**多版本兼容。** REST API 的 `/v1` `/v2` `/v3` 并存——因为不知道客户端升级到哪了。Feelings 的设备固件、animi 版本、Feelings-OS 版本在一个仓库里同步发布。不存在客户端比服务端先升级或者反过来。只有一套版本——就是当前版本。

**日志级别动态调整。** 生产环境把日志级别调到 WARN——因为不信任你自己写的 DEBUG 日志不会拖慢系统。Feelings 的审计日志是 logd 单独进程——追加写入，不分配内存，不经过调度器。DEBUG 日志和 EMERGENCY 日志的开销一样——因为都是顺序写入、哈希链锚定。

---

## 三、不能砍——物理边界上的安全带

**安全域的硬件隔离。** 不是不信任自己写的代码——是不信任物理世界。FPGA 可能被辐射翻转 bit。供电可能抖动。BRAM 可能出现不可恢复错误。安域和感受域必须保持物理隔离——不是因为代码会故意作恶，是因为硬件会偶然出错。这个隔离可以加固（双独立 FPGA 芯片——OS-FUTURE F3），但不能砍。

**神经安全校验的多层防线。** 三层安全防线——StaticSafety / UserStateSafety / RuntimeGuard——不是冗余。是你写了一个感受包。animi 正确交织了。FPGA 正确执行了。设备正确输出了。但神经系统的反应——你永远不能 100% 预测。不是因为你的代码不够好。是因为生物系统是非线性的。安全插桩必须保留。安全校验帧必须在每 N 帧嵌入。保底包必须永远待命。这些不砍——不是因为不信任自己。是因为不能信任生物学。

**审计日志。** 似乎和实时管线无关——可以砍掉。不砍是因为它服务的是另一个层级的信任：不是工程信任，是社会信任。员工要知道自己的工资没有被暗改。创作者要知道分成是按照规定比例发的。审计日志不为运行时服务——为事后验证服务。这一层信任的对象不再是代码，是人。

## 四、信任域的内外分界

```
信任域内（层 0-18）
    省掉的           协议协商、序列化、重复认证、防御性拷贝、多版本兼容、日志分级
    保留的           类型检查、安全规则校验——这些不是信任问题，是正确性问题
                    硬件层的 ECC——单比特翻转不是为了防不信任，是防物理事实

物理边界（层 19-21）
    不可砍的         安全插桩——因为神经是非线性的
                    安全域隔离——因为物理世界的噪声是不可预测的
                    审计日志——因为社会信任需要事后验证
```
