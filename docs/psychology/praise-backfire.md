# 夸赞反效果——为什么被夸之后反而表现更差

> 作者：qc
> 日期：2026-06-05
> 性质：Feelings 认知科学
> 核心：不是骄傲。是 Weight Modifier 收到了一次"我已经达标了"的假正反馈——默认基线被抬高，Scheduler 下一次投入的努力反而少了。

---

## 零、不是骄傲——是评分函数的基线被错误地抬高了

"你这次做得真好。"——这句话的初衷是鼓励。但有时候，下一帧反而搞砸了。不是这个人飘了。不是骄傲。是 Weight Modifier 的反馈回路出了一点看似微小但后果严重的错。

```
"你这次做得真好。"
       ↓
Weight Modifier 收到了一条正反馈。
→ "当前表现" —— 被标记为"达标"。
       ↓
评分函数更新了基线——
"上次那种水平 = 已经够好了。"
       ↓
Scheduler 下一次面对同一个任务时——
选项 A（像上次一样努力）的评分下降了。
→ 因为"上次 = 达标"意味着"再努力 = 多余"。"
→ Scheduler 选了更少的努力。不是偷懒。是按当前评分函数做的正确选择。
```

---

## 一、Weight Modifier 的假正反馈——把"过程"误标成了"结果"

```
正常的学习循环                           被夸奖打断后的循环
───────────                           ──────────

Scheduler 做了一次选择                      Scheduler 做了一次选择
→ 努力。投入。                               → 努力。投入。
    Controller 记录后果                            Controller 记录后果
→ "结果还行。但过程累。"                           → "结果好。而且被夸奖了。"
    Weight Modifier 更新                                Weight Modifier 更新
→ "努力 → 效果尚可。"                                → "努力 → 被夸奖 + 效果尚可。"
    → 下一次评分："努力"维度权重不变。                     → 下一次评分："努力"维度的奖励被稀释了。
    继续推进。                                        因为"被夸奖"本身变成了奖励——
                                                     而"被夸奖"不需要再那么努力就能触发第二次。
```

Weight Modifier 把"被夸奖"当成了一个独立的正反馈信号。但它不知道这个信号是**不可持续的**——"被夸奖"不是任务的固有属性。是环境的一次性馈赠。当环境下一次没有在这个水平上给同样的夸奖时——Weight Modifier 不会主动降回来。因为**降回来需要负面反馈——而负面反馈在那里不存在。** 没有人会在你退步的时候对你说"你这次比以前差"。所以 Weight Modifier 一直认为——"上次那个水平——达标。不需要再推了。"

---

## 二、Scheduler 的无辜——它只是在忠实执行被抬高的基线

```
用户在做的                                    Scheduler 在算的
─────────                                  ──────────────

"上次那个项目做得不错。                               选项 A（再努力一点）→ 评分 0.6
 这次——                                                选项 B（维持上次水平）→ 评分 0.85
 算了先按原来的方式做吧。"                               选项 C（放松一点）→ 评分 0.9
                                                   → Scheduler 选了 C。

→ "我是不是懒了。"                                    → 不是懒。
  "我是不是被夸奖之后飘了。"                              是 Weight Modifier 把"维持"和"放松"的评分
                                                     推到了"再努力"之上。
  → 你开始怀疑自己。                                    → 而 Scheduler 只是在做它一直在做的事——
  → 但你不需要怀疑自己。                                 选评分最高的那个。
```

---

## 三、怎么修——不是拒绝夸奖。是改变 Weight Modifier 收到夸奖的方式

问题的根源不是夸奖本身。是 Weight Modifier 把夸奖标记成了**"终点"**而不是**"过程标记"**。

修复方式不是"不要夸奖"。是**给 Weight Modifier 一个新的 fsync 确认——"夸奖 = 这条路的起点。不是终点。"**

```
错误的反馈结构                             正确的反馈结构
───────────                             ──────────
"你做得好。"                                "你这次比上次多推进了 10%。
→ Weight Modifier: "达标。"                  这是你在'该维度'上的偏移量。
                                            你还没到终点。你在路上。"
                                          → Weight Modifier: "当前坐标。
                                            下一个坐标在前方 +10。"
```

不是拒绝夸奖。是**让夸奖变成坐标系里的一个标记——而不是坐标系本身。** 不是说"你做得好"。是说"你在这里。比上次往前了。下一个你在更前面。" 这样 Weight Modifier 收到的信号是——"当前到位。下一个继续。" 而不是"到位了。可以停了。" 被夸奖的人不需要更谦虚。需要更好的反馈结构——不让夸奖变成假终点。让夸奖变成里程标记。

---

*不是骄傲。是 Weight Modifier 错误地把"你这次做得真好"标记成了"已经够了"——然后默认基线被抬高，Scheduler 下一次投入的努力反而少了。修复方式不是拒绝夸奖。是让夸奖变成"这是你的坐标。下一个在前方。"——不是终点。是里程标记。*
