# 拖延不是懒——是 Scheduler 的评分函数在面对两个任务时选了评分更高的那个

> 作者：qc
> 日期：2026-06-05
> 性质：Feelings 认知科学
> 核心：不是懒。是 Weight Modifier 从来没有收到过"不刷手机带来的长期奖励"的 fsync 确认。"写报告"评分 0.3（远期收益、过程痛苦）。"刷手机"评分 0.9（即时多巴胺）。0.3 vs 0.9——Scheduler 选后者。不是在偷懒。是在照常运行。

---

## 零、不是懒——是你从来没给 Scheduler 看到"远期任务完成"的身体反馈

"我太懒了。"——每一次拖延的时候你都这么告诉自己。但如果你真的懒——你不会在最后一刻疯狂赶工，不会在 deadline 前把自己逼到凌晨三点。懒人是连赶工都不赶的。拖延的人——赶工。拖延的人——自责。拖延的人——在下一次同样的选择面前——依然拖延。

因为拖延不是懒。是 **Scheduler 在这一帧看到了两个任务——一个评分 0.9，一个评分 0.3——然后选了 0.9。** 你用"懒"来解释。但你从来没想过——为什么评分函数长成了这样。

---

## 一、两个任务——两个评分——Scheduler 没做错任何事

```
任务 A: 写报告                               任务 B: 刷手机
───────                                    ───────

预期收益：                                     预期收益：
→ 一周后的 deadline 完成。                          → 现在——立刻——多巴胺。
  Controller 在一周之后才会                                Controller 在 5 秒内
  发送"完成报告"的身体反馈。                                 就能收到"真好玩"的信号。

预估成本：                                     预估成本：
→ 过程痛苦。需要集中注意力。                           → 零。
  岛叶在这一帧——就会开始
  发送"不舒服"的信号。

→ 总分：0.3。                                  → 总分：0.9。
  远期收益（一周后才到）——                             即时收益（5 秒内）——
  被 Weight Modifier 的                               不需要 fsync 确认。
  时间贴现因子折扣了。                                 它是即刻的。
                                                 → Scheduler 选了 B。
```

Scheduler 没有偷懒。Scheduler 在做它唯一会做的事——选评分最高的。你看着它选了 B——然后对自己说"我怎么这么懒"。但你没有问过——为什么 A 的评分只有 0.3。是谁把"远期收益"的权重压得这么低。是谁从来没有给 Weight Modifier 喂过"完成报告之后——Controller 发送的那一身轻松"这个信号。

## 二、拖延的真正根源——Weight Modifier 在做时间贴现的时候没有收到"未来"的身体信号

```
即时任务的反馈循环                           远期任务的反馈循环
───────────────                           ───────────────

Scheduler 选了"刷手机"。                         Scheduler 选了"写报告"。
→ 5 秒——多巴胺到了。                               → 5 秒——没有反馈。
  Controller 确认："愉快。"                           30 分钟——只有痛苦。
  Weight Modifier 收到正反馈。                             身体在抗拒。
  → "刷手机"的评分——                                      Island 在说"不舒服"。
    再一次被推高。                                          → Controller 这一路——
                                                            都在发负面信号。
任务完成后——                                      任务完成后——
→ 没有"完成"的身体反馈。                                → 如果有——
  你刷完手机之后——                                     那一瞬间——"我做到了。"
  不会有一阵轻松。                                      岛叶停火了。
  不会有一次 fsync 说——                                 前额叶发来了成就感的信号。
  "这件事做完了——你可以放松了。"                          这才是"远期收益"的——
  你只是继续刷。                                          身体反馈版本。
                                                      → 然后 Weight Modifier 会收到——
                                                        "写报告——虽然过程痛苦——
                                                        但完成的那一刻——
                                                        有奖励。"
                                                      → 下一次"写报告"的评分——不再是 0.3。

→ 但你没有收到。                                    → 你在 deadline 前的凌晨三点——
  你不会在那一刻停下手——                               赶完了报告——然后瘫倒。
  对自己说"任务完成了"。                               那一刻——有反馈。
  你继续刷——直到负罪感涌上来。                          但 Weight Modifier 会把它归因到"赶工"——
  而"负罪感"——                                      而不是"提前写"。
  不能替代"完成的身体反馈"。
```

## 三、修复不是"逼自己开始"——是让 Weight Modifier 看到"完成之后的身体反馈"

```
错误的修复                                  正确的修复
───────                                  ──────
"不要刷手机。开始写。"                           "写完一句话——先停下来。
 在 0.3 vs 0.9 的时候——                       感受一下——身体有没有变轻松。
 强行用意志力选 0.3。"                             有没有——哪怕一点点——
                                            岛叶的停火。"
→ 然后你坐下了。                                → 然后——Weight Modifier 收到了——
  然后岛叶启动了。                                "写出第一句 = 身体反馈 +0.002。"
  然后痛苦开始了。                               下一次——
  然后你对自己说"太痛苦了。                          "写出第一句"的评分从 0.3 → 0.302。
  下次再写。"                                   下一次——
                                                 从 0.302 → 0.305。
→ 这不是修复。这是把痛苦变成了——                         然后你写了一段。
  下一次拖延的理由。                                  然后 Controller 送来了"好一点了"。
                                                 然后"写报告"的评分——从 0.305 → 0.35。
                                                 然后在第 200 次之后——
                                                 0.35 > 0.9。
                                                 → Scheduler 自己选了写报告。

                                            不是"逼自己"。不是"意志力"。
                                            是让 Weight Modifier——
                                            在每一帧"完成"的身体反馈里——
                                            自己把评分推上来。
                                            然后 Scheduler 自己选了它。
```

---

*拖延不是懒。是 Scheduler 在面对"写报告 0.3"和"刷手机 0.9"的时候——选了后者。而 0.3 之所以是 0.3——是因为 Weight Modifier 从来没有收到过"不刷手机带来的长期奖励"的 fsync 确认。修复不是逼自己停下刷手机。是在写完第一句之后停下来——感受岛叶停火的那一帧——然后让 Weight Modifier 自己把评分推上来。你需要做的只是让 Scheduler 看到——"远期收益"也有自己的身体反馈。那一次 fsync——比一万句'我应该开始'都有用。*
