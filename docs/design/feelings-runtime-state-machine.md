# Feelings 运行时状态机——从冷启动到完整闭环

> 作者：qc
> 日期：2026-08-12
> 性质：系统运行时行为设计——状态转换、事件触发、职能分工、安全兜底
> 核心：一条链路九个阶段——冷启动建基线建档 → 监听等事件 → 合议评估 → 选配方 → 注入 → 微调 → 静默/安全 → 档案进化。用户给方向（声明），教练合议选配方（Session 级），FPGA 帧级执行（设备内），反馈收敛，档案越用越厚。

---

## 一、阶段总览

```
阶段一   冷启动（Session Zero）    采集建基线 + 建档 + 安全验证
阶段二   监听态（默认）            低功耗——采集跑/触发器站岗/教练休眠
阶段三   评估态（教练激活）        多 agent 合议——实时×档案×意图
阶段四   匹配态（选 .animi）       场景约束×状态需求×意图目标×档案边界
阶段五   注入态（FPGA 执行）       按配方+帧级反馈——设备内——零延迟
阶段六   微调态（反馈闭环）        帧级微调/切换配方/异常兜底
阶段七   静默态（成功态）          0 输出——保持监测——专注不打扰
阶段八   安全态（P0 兜底）         FPGA 直刹——物理层——任何阶段可进入
阶段九   档案进化（贯穿）          PBM 漂移/偏好更新/耐受模式/安全阈值
```

## 二、阶段详解

### 阶段一：冷启动（Session Zero——第一天戴上）

```
动作：
    采集——不刺激——建立 PBM 基线（四维——fast/mid/slow）
    UserProfile 建档——基础身份/健康字段（家族遗传病/过敏——
      安全阈值初始化——漏桶参数个体化起点）
    安全验证——cap 校验/病史申报/接触阻抗确认
状态：基线达标 + 档案建档 → 进入监听态

冷启动逻辑：零数据先探索（推荐系统同构）——
    广谱采集（探索）→ 建立基线 → 才有资格闭环校准——
    冷启动不是等待期——是唯一的破局点——
    这轮不刺激是为了将来刺激得准

基线≠永久不变（明确标注）：
    基线是"当时的你"——不是"永远的你"——
    用户选择（生活方式/训练/用药变化）、时间（季节/年龄）、
    重大事件（创伤/疾病/人生阶段）——都会改变基线——
    后期必须区分"正常生理漂移"（基线跟着人生走——
    漏桶参数随之更新）和"异常告警"（短期突发偏离——
    触发安全响应）——
    不区分的话——长期使用后漏桶判定会跑偏：
    把"正常的基线变化"当异常（误告警）——
    或把"异常的偏离"当漂移（漏报）——
    区分依据 = 时间尺度（周内波动=正常漂移——
    持续数月的变化=基线更新——突发剧烈偏离=告警）
```

### 阶段二：监听态（默认——低功耗）

```
运行：
    采集持续跑（阻抗/信号采样——低成本）
    事件检测器在线（阈值/模式检测——轻量触发器——不是教练）
    教练休眠（0 推理——省电省算力）

触发源（任一——事件推入总线 → 激活教练）：
    a. 用户声明——"我在房间看书""我要睡了"——
       最高权限输入——大方向直接给——无需推断
    b. 身体异常——PBM 漂移超阈值/HRV 异常/漏桶临界/
       DefenceLevel 激活——身体自己说话——不开口也触发
    c. 场景变化——运动传感器/环境感知——推断（没声明时）
    d. 定时低优先级——基线更新/档案回填

多事件同时撞线的优先级仲裁（显性固化——避免合议输入冲突）：
    P0    安全告警（生理异常/漏桶临界/DefenceLevel）——
          最高——物理直刹优先——不需要等合议
    P1    用户声明——最高权限输入——
          多事件撞线时用户的话优先于推断（场景变化靠后）
    P2    场景变化（推断）——无声明无异常时生效
    P3    定时低优先级（基线更新/档案回填——可延后）
    冲突消解：安全 > 用户声明 > 场景推断 > 定时——
    合议时输入按此仲裁——不互相打架——
    （HRV 异常 + 用户说"我没事" + 场景变化——
     安全告警先行（P0）——用户声明用于评估——
     场景推断降级为参考）
```

### 阶段三：评估态（教练激活——多 agent 合议）

```
输入：
    实时      PBM 状态（现在怎样）+ 场景（在哪）
    长期      UserProfile（是谁——偏好/边界/健康/阶段）
    意图      用户声明（要干啥——有则用——无则推断）

三个职能 Agent 分工合议（角色是架构——后端是实例）：
    陪伴/称呼 Agent    状态确认、对话基调——
                       档案里的称呼偏好
    深度/背景 Agent    判断 push 深度与方向——
                       career_stage/expertise——该推还是该护
    安全/边界 Agent    健康字段 + afraid_of 边界——
                       权重最高——推的边界别越过——
                       安全 override 阈值

合议输出：目标状态判断（需要什么——调节/维持/切换）
    ├─ 现有配方合适 → 直接注入（阶段五）
    └─ 需要新配方 → 匹配态（阶段四）
```

### 阶段四：匹配态（选 .animi——主旋律匹配）

```
选择逻辑（四重约束）：
    场景约束    物理环境（屋里/大街/聚会——可选范围）
    状态需求    PBM（兴奋/平静/紧张——需要方向）
    意图目标    用户声明/合议判断（调节/维持）
    档案边界    likes/dislikes/afraid_of（方向与红线）
    → 从 .animi 库选出主旋律配方 → 注入

主旋律概念：.animi 是场景配方（有主旋律）——
    调整是旋律内的（微调）——切换是旋律间的（换配方）——
    屋里不一定是平静——场景是约束——状态才是需求——
    房间不会告诉你心情——身体会（PBM）

.animi 主旋律轮换策略（防钝化——写进档案进化）：
    耐受衰减自动调度——同一配方长期使用效果钝化——
    档案追踪每个配方的耐受模式——效果衰减到阈值——
    自动轮换到等效替代配方（换神经纤维亚群——
    对抗耐受——多点轮换的配方版）——
    调度逻辑活在档案进化里（阶段九）——
    不是人工干预——是自动的

用户手动锁定/禁用开关（预留——用户主权）：
    用户可手动锁定某个配方（"这个对我有效——别换"）——
    也可禁用某个配方（"这个我不喜欢/不舒服——别再给我"）——
    自动轮换必须尊重用户锁——锁定的不轮换——
    禁用的不出现——用户主权高于自动调度——
    （和"阶段感知不主动收集"同一原则——用户说了算）
```

### 阶段五：注入态（FPGA 执行）

```
执行：
    按配方 + 实时帧级反馈——注入刺激——
    FPGA 设备端执行（1ms 级——不走手机——零延迟）
    教练不逐帧介入——配方已定——执行是机器的事——
    教练介入"刺激方案"（配方层）——
    不介入"刺激执行"（帧级）
```

### 阶段六：微调态（反馈闭环——旋律内调整）

```
反馈循环：
    帧级反馈 → FPGA 微调（维持/微调——旋律内呼吸）
    ├─ 达到目标 → 静默态（阶段七）
    ├─ 效果差 → 回匹配态（阶段四——换配方）
    └─ 异常（P0）→ 安全态（阶段八——物理直刹）
    会话级反馈 → 教练复盘（Session 结束后——
                 反馈写回——用于下次配方选择/档案更新）

反馈状态完整梯度：
    维持（继续）/ 微调（反复逼近——常态）/
    切换（换配方——教练的活）/
    静默（够了——成功收）/ 停止（坏了——安全刹）
```

### 阶段七：静默态（0 输出——成功态）

```
状态：
    停止刺激——保持监测——0 输出（专注时不打扰）
    ├─ 场景/状态变化 → 回评估态（阶段三）
    └─ 维持 → 保持静默
```

### 阶段八：安全态（P0——兜底——任何阶段可进入）

```
动作：
    FPGA 直刹——物理层——不需要教练——不需要合议
    漏桶临界/生理异常/接触异常——立即停止刺激——记录
    ├─ 异常排除 → 回评估态或监听态
    └─ 记录写回 → 安全阈值微调（个体化防线进化）
```

### 阶段九：档案进化（贯穿所有阶段——后台）

```
持续更新：
    PBM 基线漂移（长期统计——感受地图进化——见下方三尺度）
    行为/偏好更新（Session 复盘——likes/dislikes 调整）
    耐受模式（哪个配方效果衰减——轮换调度依据——
      自动轮换 + 用户锁/禁用开关）
    安全档案（阈值微调——个体化防线越来越准）
    断档处理（历史平均值结算——档案不因离开而废）
    阶段感知（用户愿说的——陪伴长出来的上下文——
      不主动收集——用户接纳信息才流动）

基线更新的三个时间尺度（与信任额度的周/月/年统计同构）：
    一周小统计    短期趋势——近 7 天漂移模式——
                  正常波动 vs 异常告警的短期窗口——
                  周内波动 = 正常生理漂移（漏桶随之微调）
    一月中统计    中期模式——适应/矫正效果——
                  持续数周的漂移 = 基线在变（更新基线——
                  不是告警）
    一年大统计    长期画像——人生阶段变化——
                  用户选择/重大事件的年际影响——
                  基线跟着人生走——年度重新校准

基线变化的来源（三尺度捕捉）：
    用户选择    生活方式/训练/用药——月级-年级影响
    时间        季节/年龄——年级影响
    重大事件    创伤/疾病/人生阶段——可触发即时基线重估
    区分铁律：时间尺度决定定性——
      短波动=漂移（正常——微调）——
      持续变化=基线更新（正常——重估）——
      突发剧烈=告警（异常——安全响应）
```

## 三、角色分工总表

```
用户          声明（大方向）——最高权限输入——
              说了就听（先验）——没说才推断（测量）——
              反馈收敛（修正）
陪伴 Agent    称呼/语气/状态确认（档案）
深度 Agent    推的深度与方向（阶段适配）
安全 Agent    边界/阈值（权重最高——合议里一票否决级）
教练合议      评估/匹配——配方层（Session 级）——
              教练休眠时被事件叫醒（待命状态机）
FPGA         注入/微调/刹车——帧级（设备内——零延迟）
反馈          帧级微调（机器）——会话级复盘（教练）
档案          UserProfile——长期背景（评估输入）+
              持续进化（输出）——字段按职能标注——
              角色是架构——豆包/claude/qc 是实现
```
