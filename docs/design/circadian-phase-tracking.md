# 昼夜相位跟踪——PBM 的时间维度不是太阳时，是相位

> 作者：qc
> 日期：2026-08-15
> 性质：Feelings 设计，PBM 的时间维度
> 核心：spec(t) 里的 t 不是墙上时钟，是用户的节律相位。生物钟是一台 PLL：光照是参考信号，SCN 是约 24.2h 的压控振荡器，时差是相位跳变，倒班是参考信号周期性乱跳，10-10-5 是锁在稳定但错位的相位上。相位跟踪是双轨的：主时钟跟光走，外周时钟跟进食走，两者的相位差 Δφ 才是节律紊乱的健康指标。设备用耳挂和腕表覆盖 24 小时，按逆方差融合各信号源，每天结算一次相位。干预层闭环：光做主力的重同步，刺激做错位托底，分级负反馈从测量噪声推导阈值，不发明魔法数字。所有写死值走四层划分，所有可配置值带默认值和上下限，所有指标带公式。相位是时间问题，振幅是能量问题：节律平坦化是慢性煎熬的生理读数，gap 是身体强制执行的熔断恢复协议。

---

## 零、先定前提

每个人的节律相位不同：全世界飞的有时差，倒班的相位在漂，互联网厂子 10-10-5 锁在错位相位上。如果 PBM 的时间维度按太阳时查表，以上所有人都会得到错误的基线。

```
太阳时 = 参考系
用户相位 = 本体
spec(t) 的 t = 用户相位，不是钟表读数
```

身体的 spec 是时间的函数：体温凌晨 4-6 点最低、下午最高，血压夜间勺型下降、醒来前猛升，皮质醇醒前就爬。但"凌晨""下午"这些词，在生物钟的语言里对应的是相位，不是小时数。身体对地球自转建了前馈模型，Feelings 对用户建模型，两层模型嵌套。

---

## 一、生物钟 = PLL

昼夜节律系统的结构和锁相环完全同构：

```
参考信号      光照
             视网膜黑视蛋白（ipRGC）只报"现在是白天吗"
             蓝光在错误相位打进来 = 噪声输入
压控振荡器    SCN 约 24.2h 的自主节律
             洞穴实验证明它自由运转
锁定过程      时差 = 相位跳变，重新锁定要几天
             锁定期间体温最低点和睡眠窗口一起漂
```

三种错位，三种形态：

```
时差（相位跳变）     一次跳几小时，锁定过程可见
倒班（参考信号乱跳）  光照相位周期性翻转，
                     内脏时钟跟吃饭走、主时钟跟光走，
                     两个时钟持续打架
10-10-5（锁在错相位） 相位稳定，只是偏移
                     伤害来自光照质量差和周末补觉
                     周末补觉 = 每周末来一次时差，
                     周一再来一次，社会时差的元凶
```

## 二、社会节律的共进化

10-10-5 不是某个人拍板定的，是产业节律和劳动力节律互相塑造的稳态：

```
屏幕蓝光（错误相位的授时信号）
→ 全民生物钟系统性后移
→ 大学生晚睡成为常态（宿舍文化，无人强制关灯）
→ 公司顺着劳动力池的节律定作息
→ 下一届学生更晚
```

大学生晚睡是果不是因，公司作息也是果。整个链条的源头是：现代人的主授时信号早就不是太阳，是屏幕和灯。错位的稳态好过混乱的漂移：一个 11-11-6 但规律、白天见光的人，可能比 9-9-5 但周末狂补觉的人节律更健康。设计不能按"哪种作息正确"来，要按"相位是否稳定"来。

## 三、双轨相位——主时钟与外周时钟

相位不是一条，是两条。节律系统是"主时钟 + 外周时钟"的多级结构，拆成双轨跟踪：

```
主时钟轨道 φ_central
    驱动者    光照（SCN，最强的授时输入）
    输出      皮质醇、褪黑素、核心体温节律
    对应      spec(t) 的主体（体温血压基线走这条）

外周时钟轨道 φ_peripheral
    驱动者    进食（肝脏时钟的最强授时因子）、
             运动、温度
    输出      消化、代谢、胰岛素敏感性的节律
    对应      代谢状态的时间窗

相位差 Δφ = φ_central - φ_peripheral
    这才是节律紊乱的核心健康指标
    光相位很稳 + 吃饭时间乱
    = 内脏在"白天"被喂饭 → 内部失同步
    = 倒班工人代谢病的机制入口
```

为什么不融合成单相位：失同步本身就是信号。融合会把 Δφ 抹掉，而 Δφ 恰恰是倒班工人糖尿病、脂肪肝风险的那个物理量。肝的时钟被进食锁在另一个相位上，主时钟还以为世界正常——这个"两个时钟打架"的差值一旦被平均掉，模型就看不见病了。

反向弱耦合 κ（二阶修正项）：

```
限时进食或长期断食下，
肝脏代谢信号可通过迷走或体液途径
反向牵引 SCN
（外周 → 主时钟的弱耦合真实存在）

κ 默认接近零（第三层可配置参数）
激活闸门（滞回）：
|Δφ| > τ 且持续 N 天（默认 7 天）
激活后 κ·Δφ 计入 φ_central 的漂移项
日常微小抖动被闸门挡在外面，
避免低通滤波截不断低频漂移

涌现价值：κ 本身是健康指标
κ 显著大于零 = 失同步有自我纠正倾向
              （代谢反馈通路活着，
              身体尚具自愈代偿能力）
κ ≈ 0        = 节律脱节进入病理固化期
一个控制方程的二阶校正项，
反向转化为临床级的高阶健康读出
```

多授时因子的权重，按双轨分：

```
光照       φ_central 权重最高（lux × 时长积分，
           剂量响应见第四节）
           φ_peripheral 弱
进食       φ_peripheral 权重最高（进食时间点 + 禁食时长）
           φ_central 弱（限时进食能反向拽动 SCN，
           但幅度小）
运动       两轨中等（晨练提前相位，晚间运动推后）
温度       两轨都弱（人是恒温动物，
           体温节律是时钟的输出不是输入）
社会时间   闹钟 = 醒来时刻 → 通过光照起始间接作用
```

测量落点：每个授时因子设备怎么拿到：

```
光照       耳挂设备的环境光传感器直接测
运动       腕部加速度计直接测
进食       没有进食传感器，
           主通道是用户声明（"测得到的靠传感器，
           测不到的靠嘴"）
           辅助：餐后产热微升 + HRV 偏移
           （弱信号，只能做校验不能做主输入）
```

结论：spec(t) 的基线主体用 φ_central 跑（体温血压皮质醇都是主时钟输出），但 PBM 里多存一个 Δφ。单相位给基线，双相位给健康判断。

## 四、光驱动项——黑视蛋白的定量账

"蓝光不对"不能停在定性。黑视蛋白的物理账全部可查，构成设备端相位计算的公式。

光谱账：

```
黑视蛋白峰值    λmax ≈ 480nm（478-484nm 区间）
标准函数        CIE S 026 黑视素光谱函数
设备要求        照度传感器按 melanopic 加权采样
               （m-EDI，等效日光照度），
               或普通 lux 乘光谱修正系数
```

强度账（剂量-响应）：

```
<10  m-lux          可忽略（夜间保护阈值，
                    CIE 建议晚间低于此值）
10-50               弱，褪黑素抑制的起步段
~100 m-lux × 6.5h   半最大相位偏移点
                    （Zeitzer 2000 经典剂量曲线）
1000+               接近饱和，边际收益递减
```

时间尺度注意：上述是 6.5 小时持续暴露的量级，日常屏幕是分段的。分段脉冲可叠加，间歇强光效果接近连续暴露。

光历史适应：连续几天暗环境后，敏感度上调，同一个 lux 偏移量变大。剂量响应不是固定曲线，是带记忆的曲线。

相位账（PRC 相位响应曲线）：光的作用方向取决于它落在核心体温最低点（CBTmin）的哪一侧：

```
光在 CBTmin 之前（晚间）    → 相位延迟
光在 CBTmin 之后（清晨）    → 相位提前
中午附近                    → 死区，几乎无偏移
幅度随接近 CBTmin 增大
```

设计结论：φ_central 的光驱动项写成卷积，而不是定性描述：

```
日相位偏移 Δφ_light = Σ light(t) × PRC(t - CBTmin) × w(m-lux)

light(t)    设备光传感器按 melanopic 加权采样
PRC         标准相位响应曲线（查表）
w           剂量权重（半最大 ~100 m-lux × 6.5h，
            饱和 1000+）
CBTmin      由体温/睡眠窗口估计
```

每天结算一次光驱动的相位偏移，叠加进 φ_central 的估计器。

### 置信度接口

每个相位信号源输出一个元组 (Δφ_i, σ²_i)：估计值 + 不确定度。σ² 是置信度的倒数。

```
光照源的 σ² 由四件事决定
    照度量级     >1000 m-lux 户外：信号主导噪声，σ² 小
                 <50 室内弱光：传感器噪声主导，σ² 大
    遮挡事件     快速下降沿 + 与环境不匹配
                 （头发、帽子、枕头瞬时遮挡）
                 → 该窗口 σ² = ∞，直接丢弃
    佩戴状态     未佩戴 → 丢弃（接触阻抗、温度判据）
    光历史       连续暗环境后敏感度上调，
                 σ² 相应收窄（模型知道自己在高增益区）
```

融合层唯一要遵守的契约：

```
融合器只认 (Δφ_i, σ²_i) 接口
    不关心每个信号的物理来源
    光照、HRV、皮肤温度、活跃窗口、
    第三方导入、手填数字
    进来都是同一个形状
    加权 = 逆方差加权
    公式结构永不改，只换输入源
```

接口先行，公式后行：先写死"光照是主信号、其余是辅助"，等到发现倒班工人光相位没意义时再拆公式，是经典返工。统一接口让加一个数据源只是多一组输入。

## 五、测量网络——双设备 24 小时覆盖

相位决定性的数据在睡眠期生成（CBTmin 定位、夜间 HRV 斜率），而耳机睡觉不戴，手表睡觉戴。两个设备在时间上天然分工：

```
耳挂设备    白天窗口：环境光（φ_central 的光驱动项）
            心率、耳温（靠近颈动脉血，稳定）
腕表设备    夜间窗口：腕温（CBTmin 定位的主数据）
            皮电、运动
24 小时覆盖 = 白天靠耳，夜晚靠腕
```

双点位温差本身就是相位信号：腕温（远端）与耳温（近端）的梯度是经典相位标志。睡前远端血管扩张散热，腕温上升、梯度收窄；醒来时反向。这个远端-近端梯度（DPG）比单点温度信噪比高得多：

```
环境温度同时影响两个点
差分把共模噪声压掉
= 模电的差分放大：
只取差异，丢掉共同
工频是共模，室温也是共模
```

微气候对差分假设的破坏与相位上下文判据：

```
差分假设的前提：环境温度对两个点位是共模
睡眠场景的破坏：手伸进被窝、头部露在外面
（被窝微气候）——腕温单向假性升高，
共模假设失效

判据（相位上下文，而非静态突变）
    生理性远端升温只发生在睡前散热窗口，
    伴随睡眠阶段迁移和 HRV 同步变
    微气候假升温任意相位都可能出现，
    且不伴随睡眠结构变化
    → DPG 上升 + 不在睡前窗口
      + 无睡眠阶段迁移 = 微气候嫌疑
    → 该窗口 σ² → ∞，直接置空
    姿态事件是诱因不是排除项：
    先动了一下，然后温度持续爬
    （把手伸进被窝必有动作，
    动作是因果链的头，不是尾）
```

接口红利：传感器内部逻辑再复杂，对外输出只有 (值, σ²) 两个量。新噪声源的识别是模块内部的事，融合器零修改。

主动控温：腕表能主动控温，测量从被动变主动：

```
定时给皮肤一个标准热脉冲
测血管舒张响应的幅度
响应本身是相位依赖的（夜间强、白天弱）
主动扰动把环境噪声变成可控变量
从"采集"到"探测"的升级
```

CBTmin 定位的信号优先级：

```
主    夜间腕温序列 + 耳温交叉验证
辅    DPG 梯度（睡前收窄、醒来扩大）
HRV   耳挂心率，污染事件门控：
      咖啡因 = 用户声明
      运动 = 加速度计直接测到
      情绪 = 漏桶高水位期间降权
校验  活跃窗口（精度最低，只做校验不做主输入）
```

全部汇总到 (Δφ_i, σ²_i) 接口上做逆方差加权。

## 六、冷启动与数据带入

没有问卷。冷启动的收敛靠被动采集和已有数据带入：

```
路径 A（默认，零负担）
    戴表睡 2-3 晚（前 2 晚剔除首夜效应）
    被动检出：入睡时刻、醒来时刻、时长、质量
    初估：CBTmin ≈ 醒来时刻 - 2h
    φ_central 一阶估计，±1h 量级
    没有问卷，没有等待感，戴了就有

路径 B（加速，手填）
    已有其他厂商手表数据的用户
    直接填数字（入睡、醒来时间）
    当天就有初估

路径 C（持续，平台对接）
    接入健康数据聚合层：
    苹果系 HealthKit、安卓系 Health Connect、
    国内华为/小米/荣耀运动健康
    睡眠、HRV、腕温（Apple Watch S8 起有）
    自动流入，不是一次性的
```

路径 C 的设计原则：

```
单向阀      数据只进不出：
            外部数据进得来，
            Feelings 数据出不去
            数据永不离设备的价值观硬件化
厂商无关    不对接厂商，对接聚合层
            一次集成覆盖绝大多数用户
            与 KubePivot 的 0 client-go 同招：
            对接接口层，不对接实体
```

来源即置信度：导入的数据带着出身进入融合框架，全部压进 σ²：

```
Tier 1  Feelings 自家设备（最高置信度，
        含主动控温探测、双点位差分）
Tier 2  平台导入（中置信度，
        Apple Watch 腕温 > 手环睡眠估计）
Tier 3  手填数字（低置信度，当种子够用）
```

留存逻辑：冷启动最怕的不是不准，是用户在前几天感受不到任何东西。路径 A 让用户"戴着睡觉就有进度"，路径 B 和 C 让老手表用户"第一天就有基准"，三条路都消灭了空窗期。

## 七、相位状态机与判据阈值

判据钉在噪声地板上：健康成年人的日间相位波动 SD 约 ±0.5h（CBTmin 逐日变异性）。所有阈值从它出发：

```
正常日内波动
    |Δφ| 日间 < 0.5h，且无方向性
    = 噪声地板以下，不触发任何状态变化

相位跳变（时差）
    单日位移 > 2h（越过地板 4 倍）
    且伴随环境光相位同步跳变
    （光照起始时刻和相位一起跳 = 跨时区指纹）
    判据不是幅度本身，是"一步到位"

渐进漂移（倒班、作息慢性后移）
    连续 7 天同向累计位移 > 1h
    （每日 ~0.2h 的方向性小步）
    判据是"方向一致性"，不是单日幅度
```

状态机：

```
LOCKED（锁定）     相位稳定，spec(t) 按 φ 正常跑
DRIFTING（漂移）   7 天同向累计 > 1h
JUMP（跳变恢复）   单日 > 2h + 光照同步跳变
UNSTABLE（无锁相） 14 天内无稳定相位

转移
LOCKED → DRIFTING   漂移检测成立
LOCKED → JUMP       跳变检测成立
JUMP → LOCKED       重新锁定完成
DRIFTING → LOCKED   相位稳定 ≥ 7 天
```

重新锁定的速率不对称：

```
西飞（延迟方向）  ~1.5h/天  内源周期 24.2h，
                            延迟比提前好调
东飞（提前方向）  ~0.5-1h/天
恢复天数 ≈ 时区数 × 1~2 天
```

恢复天数是可预测的，这个预测本身可以报给用户。

用户声明是前馈输入："我明天飞纽约"在跳变发生前就进入状态机——设备预先知道要跳，把 JUMP 状态提前开，光照传感器一到新相位立刻开始计恢复天数，而不是等 2h 位移攒够才后知后觉。声明让设备提前进入待跳状态，测量只做确认。

更新节奏：状态按天结算（相位是慢变量，日级分辨率），但跳变检测是事件驱动的（光照起始时刻突变、睡眠时刻突变立即触发）。

## 八、无稳定相位的管理——错位状态而不是审判

天天飞的人、随机排班的轮班工人、严重失眠者，没有稳定锁相点。对他们的管理原则：**不管相位本身（生活方式决定，设备去管就是越权），管错位状态下的三件事**：

```
① 疲劳归因
    "累"有三种，主观上分不清：
    睡眠债（欠觉，补觉有效）
    相位错位（睡够也累，补觉无效，
              正确动作是光暴露）
    单纯疲劳（两者都不是）
    归因决定动作，用户没能力做归因，
    设备有（外置的漂移检测器）
    → "你现在的累是相位错位型，
    睡八小时也没用，明早 7 点见光"

② 褪黑素审计
    用户分不清褪黑素的两种效果：
    真调相位（体温节律确实移动了）
    只是催眠（睡得更早，但相位没动）
    两种效果主观体验几乎一样，
    体温序列看得清清楚楚
    → "你吃的褪黑素这周只在催眠，
    没在调相位"

③ 错位期保护
    Δφ 大的窗口里，认知和情绪都打折
    设备同步降级：刺激强度收窄、
    安全阈值收紧、脆弱帧不注入
    错位期不折腾身体，只托底
```

重同步加速：落地后重锁定的速率主要取决于光照时刻。设备知道相位漂到哪了，就能算出该在哪天哪个小时见光。这是给一台 PLL 的参考信号做时刻优化。

UNSTABLE 的干预降级规则：不输出"建立规律作息"类建议（班表不归用户管，建议的正确性等于废话）。设备对这类用户只做托底三件套（归因、审计、保护），节律健康度只输出稳定度趋势，明确标注"当前节律无稳定相位"。

### 执行层三策略——建议会死，执行不会

信息不稀缺，行动带宽才稀缺。用户说"我本来就知道，但我没时间"——意思是输出在"念"层，卡点在"行"层。设备的输出必须降两层：

```
① 成本压缩——把动作削到借口线以下
    剂量-响应是可压缩的：
    10 分钟万级照度 ≈ 30 分钟三千照度
    不说"晒 30 分钟"，
    说"5 分钟，买咖啡的路上绕东边走"
    当动作成本 < 借口成本，借口自动失效

② 搭便车——寄生在既有习惯上
    不创造新动作，改造旧动作的路径
    用户本来就要下楼买咖啡、抽烟、遛狗
    光照指导挂在这些时刻上：
    "你已经在外面了，脸朝东 3 分钟就行"
    新动作零新增时间成本

③ 设备代执行——把建议变成硬件
    光需要打到视网膜上，
    可做成光疗眼镜形态：
    镜框内侧 480nm LED，边缘视野照射
    用户啥都不用做，戴上就是执行
    建议会死，硬件不会
```

催促是负资产：设备永远不主动推"你该去晒太阳了"——只在检测到用户已经处于自然机会里（在外面、醒着、有窗口）时才给最低成本版本。时机匹配，不催促。

借口的正确定义：借口不是需要被说服的态度问题，是行动成本超过感知收益的市场信号。设计者的工作不是改变用户的态度，是改变行动的价格——要么降价，要么打包，要么自己付。设备不能要求用户有空，只能让正确的动作不需要时间。

## 九、干扰识别与数据置信度

干扰分两类，处理完全不同：相位药物（褪黑素）不是噪声，是外部授时输入；发烧、咖啡因、生理期才是要剔除的。

```
褪黑素    真调相位——它就是外部 zeitgeber
          有自己的 PRC（与光的 PRC 相位约差 12h）
          → 当输入建模：用户声明"吃了"
          → 按 melatonin PRC 计入相位方程，
          跟光照同一待遇
咖啡因    非相位干扰：HRV 变、睡眠变，体温不动
感冒药    抗组胺 → 睡眠时刻变；减充血剂 → 兴奋
酒精      睡眠结构变 + 血管扩张（腕温假升高）
          + HRV 降
发烧      体温升 1-3°C + 心率升 + HRV 降 + 活动降
          振荡整体抬升，CBTmin 定位被毁
生理期    黄体期体温基线 +0.3-0.5°C，约 14 天，
          28 天周期，只有体温动其余正常
```

核心判据是相干性：真相位变化会让全体节律标志一起动——体温、睡眠、HRV 同步移相。干扰只动一两个信号：

```
相位跳变     全体标志同步移相（相干）
发烧         体温猛移，但心率、HRV、活动
             以疾病模式移动，且不同相
生理期       只有体温基线平移，其余纹丝不动
```

三级处理管道：

```
① 相干性检查
    全体节律标志是否同步移动
    → 决定是"相位变了"还是"信号脏了"
    单信号异动 → 该信号 σ² 放大或剔除

② 已知系统分量扣除
    生理期：体温双相 28 天分量跟踪并扣除
            （第二层去节律：日节律之后
            再去月经周期，剩下的才是偏差）
    发烧：体温 + 心率 + HRV + 活动
          组合命中疾病签名
          → 整窗口 σ² = ∞，相位估计冻结

③ 药物通道
    褪黑素 = 外部授时输入（声明 + PRC 计入）
    其余药物 = 噪声源（相应信号 σ² 放大）
```

Core 的既有接缝：DataConfidence 枚举（High / Low / Contaminated）就是为这个设计的，SessionLabel::Abnormal → SafetyOnly 更新策略也是。本节只定义"什么时候翻成 Contaminated"：相干性检查 + 疾病签名 + 药物通道。

褪黑素的剂量饱和与个体化增益：

```
剂量问题    生理分泌量 ~0.3mg，
            市售 3-10mg 是生理剂量的 10-30 倍
            MT1/MT2 受体脱敏 + 持续催眠拖尾，
            实际移相效率反而下降
            （MIT 经典结论：
            部分目的下 0.3mg 优于 3mg）

默认先验（S 型饱和曲线）
    生理区（≤0.5mg）   线性，接近标准 PRC
    超生理区（1-5mg）  平台封顶
    巨量区（>5mg）     拖尾衰减

闭环校准（系统辨识）
    褪黑素审计的实测相位偏移
    vs 标准 PRC 预测值求残差
    离线更新该用户的个体增益系数
    审计从日志记录升级为参数识别

分层收容
    个体增益存入 Layer 2 配置区
    不污染 Layer 1 硬件底线
    不硬编码进 Layer 3 状态机
```

### 化学攻防环——咖啡因与助眠剂的双向拉锯

白领的"白天咖啡 + 晚上助眠剂"不是两个独立习惯，是同一个环的两半：

```
咖啡因    不调相位，只盖住睡眠债
          （腺苷受体阻断，半衰期 5-6h）
          Walker 2013 经典数据：
          睡前 6 小时摄入 400mg，
          客观睡眠仍被砍掉 1 小时以上，
          受试者大多自己察觉不到
          → 入睡困难的原因
          藏在下午 4 点那杯咖啡里
助眠剂    治标：只买"入睡更快"
          （褪黑素缩短入睡潜伏期约 7-10 分钟）
          不治本：相位没动，债没还
环的动力学   咖啡因 → 睡得更晚 → 睡眠更差
          → 早上更累 → 咖啡因更多
          → 晚上更睡不着 → 助眠剂
          → 第二天重复
          两药互相稳定对方的副作用，
          这个环可以稳定跑很多年
```

环的每一环设备都看得见：咖啡因声明 + HRV 签名、褪黑素审计、睡眠债累积、相位漂移。归因是现成的："你的入睡困难，40% 在下午 4 点的咖啡，30% 在相位漂移，褪黑素只帮你治了 7 分钟的表。"

顺带一个旁证：健康大学生群体的醉茄双盲 RCT 主要分析不显著，失眠/应激人群才有适度收益——补剂的收益和系统的损坏程度成正比，桶模型对健康控制器依然无效。

### 教练问答接口

用户不需要理解内部机制，只需要问一句。教练把管道翻译成人话：

```
用户："看看我是不是发烧了"
教练（查询模式）：
    "体温基线 +1.2°C，心率 +15，HRV 下降，
    活动量降——疾病签名命中。
    但注意：昨晚喝酒也会产生类似模式。
    你昨晚喝酒了吗？"
```

三个设计要点：

```
鉴别诊断而不是下结论
    体温升高有五六个来源
    （发烧、酒精、运动后、生理期、室温）
    教练列出候选并附数据支持度
    不是拍板"你就是发烧了"
    解释权永远在用户

交互式消歧
    教练可以反问（"喝酒了吗"）
    用户声明就是最高置信度的鉴别信息

边界内置
    答完收一句：
    "数据支持发热样状态，但我不下医学诊断，
    建议体温计复测"
    描述数据，不做诊断
```

查询模式与推送模式的分工：系统自己发现异常是推送（谨慎，容易打扰），用户主动问是查询（零打扰，怎么详细都行）。查询模式没有催促风险，可以放开说。

## 十、刺激的相位修正——三层结构

刺激参数按相位调，但不是查表。相位是协变量，不是开关。三层：

```
① 基线层：刺激靶点是偏差，不是绝对值
    spec(t) 本身在动
    刺激量 = f(实际值 - spec(φ))
    不按绝对值调，按偏差调
    电子学同构：工作点随节律移动，
    刺激是骑在工作点上的增量信号
    节律是偏置，纠偏才是刺激

② 窗孔层：相位窗口门控
    醒后皮质醇峰    不注入高唤醒刺激
    睡前窗口        不注入兴奋性刺激
    深睡相位        静默（0 输出哲学的相位版）
    错位期（Δφ 大） 强度收窄（第八节的保护）

③ 效果层：评估要除相位
    HRV 对刺激的响应，
    和相位预测的 HRV 比，
    不是和原始 HRV 比
    否则下午的正常 HRV 低谷
    会被读成"刺激无效"
    去节律不只用于检测，也用于评估
```

事实依据：自主神经张力昼夜变化（白天交感主导、夜间副交感主导，tVNS 走副交感通路，同一刺激打在两种基线张力上效果不同）；皮肤阻抗有日节律（皮电下午高，同样参数实际到达的电流不同）；皮层兴奋性下午更高（感知阈值和副作用阈值都随相位漂）。

诚实边界：tVNS 对节律相位本身的影响证据很弱（动物有 VNS 移相报道，人类 tVNS 相位效应未确立）。设计立场保守：刺激不宣称会移相，相位校正的主力是光（证据强两个量级）。

### 三区曲线与迟滞

刺激量的函数形态，工程上带迟滞的三区特性：

```
死区    |偏差| < δ      输出 0
        δ 的推导：去节律后残差的日间 SD
        （逐用户估，随 PBM 收敛）
        下限写死：防止被配成 0 去追噪声
线性    δ < |偏差| < L  输出 = k × 偏差
        k 相位相关（本节三层修正）
        带宽约束：k 低于生理滞后倒数
        慢修、稳修（让子弹飞：
        纠偏带宽必须低于生理滞后的倒数，
        k 大了就是把子弹当机枪扫）
饱和    |偏差| > L      输出 = cap
        cap 物理上限写死（第十二节 Layer 1），
        个体值只能向下配
迟滞    区边界双向阈值不重合
        防止在边界上抖
        （LDO 自激振荡的老教训：
        环路增益和相位裕度错了就会抖，
        迟滞就是给纠偏环留相位裕度）
```

### 硬件内环——探测脉冲 + 恒流输出

电极-皮肤接触阻抗随相位变（皮电日节律），同样的设备参数实际到达的有效电流不同。解法是硬件级闭环：

```
探测脉冲    每次刺激脉冲前，先出微幅探测
            幅度在感知阈以下，时长 μs-ms 级
            在刺激频率上测复阻抗（不是直流电阻）
恒流调整    VCCS 按实测阻抗调输出电压
            保证实际注入电流 = 设定值
            （I = V/Z，Z 变则 V 跟）
安全暂停    阻抗超阈值 → 自动暂停
            高阻抗 = 接触面积收缩 =
            电流密度尖峰 = 灼伤风险
            硬件级执行：比较器直接拉断，
            无 FPGA 参与（硬件熔断的阻抗版）
时序分离    先探测、后注入，测的归测的，
            打的归打
            探测突发占空比受限，
            探测量不能累积成生理剂量
```

"硬件级去节律"：这个内环在源头吃掉了阻抗的相位节律，软件层不用知道皮电节律的存在。分层哲学：硬件管"给得准"，软件管"该给多少"。

三层环总装：

```
硬件内环（每脉冲）   探测 → 阻抗 → 调压 → 注入
                     μs-ms 级，保证给得准
软件中环（每帧/天）   spec(t) 相位修正、状态机
                     保证该给多少
用户外环（天/周）     声明、带入、教练问答
                     测不到的靠嘴
```

内环管准确，中环管意图，外环管上下文，互不越权。探测脉冲顺带是电极-皮肤界面磨合的监测仪：阻抗的日趋势就是浴盆曲线"界面磨合期"的实时读数，界面何时从磨合期跨进稳定期，设备自己知道。

## 十一、写死与可配置——四层划分

总原则：三条边界焊死，其余全部参数化。

```
安全红线绝对写死     硬件级安全阈值、人体安全极限，
                    不接受任何软件/用户修改，
                    系统跑飞也不能突破
物理本质骨架写死     人类共有的生理机制、物理规律，
                    核心形态不动，只留个体修正系数
核心逻辑规则写死     判断框架、状态机转移逻辑不动，
                    只调具体阈值和权重
个性化场景化可配置   个体差异、场景适配、参数调优，
                    可读写参数，自动学习或 OTA 更新
```

### 第一层：硬件安全级——100% 写死

最后一道物理保险丝，烧进只读寄存器、硬件比较器、模拟电路。软件总线碰不到，固件升级改不了。

```
刺激绝对安全上限    最大输出电流、单脉冲最大能量、
                    单日最大累积剂量、最高刺激频率
                    依据 IEC 60601-1、皮肤电刺激安全标准
硬件熔断阈值        皮肤阻抗上限、电极温度上限、
                    热脉冲最高温度
                    硬件比较器直接切断，不经 FPGA
探测脉冲安全边界    最大幅度、最高占空比、
                    单脉冲能量上限
                    探测永远不累积成有效刺激
主动热脉冲上限      最高温度、最长持续时间、
                    单位时间最大次数
```

写死的可证性：上电自检（POST）回读熔断值——开机时安全 MCU 读出 OTP 和比较器配置，与出厂记录比对，不符则拒绝启动刺激链路。写死是承诺，POST 是证明。

### 第二层：生理常数层——骨架写死，系数可配

```
骨架写死（形态与方向不变）
    黑视蛋白响应光谱形状（480nm 峰、CIE S 026）
    PRC 方向与形状（CBTmin 前延迟、后提前、中午死区）
    双轨驱动逻辑（主时钟跟光、外周跟进食、Δφ 是指标）
    内源周期基准（24.2h、西飞恢复快于东飞）
系数可配（个体差异与自适应）
    光敏感度系数（默认 1.0，随光历史迭代）
    褪黑素敏感度系数（默认 1.0，随服用后实测偏移学习）
    CBTmin 与睡眠偏移（默认醒前 2h，
    随作息类型校准）
    主-外周耦合系数（默认经验值，随长期数据迭代）
```

骨架的修订路径：科学会进步，PRC 形状是几十年来逐步修正的，24.2h 也是人群均值。骨架写死不等于永不更新——更新走宪章修订流程（独裁者终审、防滑坡机制），OTA 无权触碰。写死不等于僵死，等于重流程。

### 第三层：算法逻辑层——规则写死，阈值可配

```
规则写死（判断逻辑不动）
    相位状态分类逻辑（跳变看单日幅度，
    漂移看方向一致性）
    相干性表决规则（同步移相 = 真相位变化）
    三区特性结构 + 迟滞机制 + 偏差驱动
    去节律预处理流程
参数可配（调优与适配）
    所有状态阈值（噪声地板倍数、跳变幅度、
    漂移累计时长、锁定判定天数）
    数据源置信度权重（Tier 1/2/3 的 σ²）
    刺激增益 k、死区 δ、迟滞宽度
    异常检测组合判据
```

规则写死的最高形态是编译期强制：状态机转移逻辑用 Typestate 实现（Feelings-OS ADR 007 同款），非法转移编译不过。规则写死不是"大家别改"，是"改了编译不过"。

### 第四层：用户体验层——全可配置，边界写死

```
用户可配置
    干预强度偏好（柔和/标准/强效 = k 的缩放）
    干预方式偏好（优先光/优先刺激/仅监测）
    通知权限（哪些场景可提示）
    个人上下文声明（作息、飞行、进食、药物）
边界写死
    所有配置不能突破硬件安全上限
    不能改变核心算法逻辑
    不能修改相位基线（基线是模型的财产）
    声明是策略层的输入，不是基线本身
```

三条落地规则：

```
① 默认值与上下限
    每个可配置数值自带冷启动默认值和合法上下限
    默认值锚定人群平均，上下限锚定安全与物理边界
    配置出错也不会崩
② 权限分层
    硬件安全级：工厂烧录，无人可改
    生理常数层：仅研发可修系数，用户不可见
    算法逻辑层：工程师配置 + OTA
    用户体验层：用户界面自主调整
③ 自适应优先于手动配置
    噪声地板、光敏感度、相位偏移系数
    全部随用户数据自动迭代
    用户感知是"越用越准"
    手动配置只留给极端场景和专业用户
```

## 十二、干预闭环总装

通道优先级：

```
光（主力重同步）
    证据最强：有 PRC、有剂量曲线、有公式
    设备代执行：光疗眼镜（480nm LED）
    行为指导：时机匹配 + 成本压缩 + 搭便车
刺激（错位托底）
    三区曲线 + 相位修正三层
    错位期降级保护、脆弱帧不注入
睡眠侧（辅助）
    睡前窗口保护、暖音、预热（前馈）
铁律
    用户声明最高优先级
    不催促
    解释权永远在用户
```

### 效果验证——干预是前馈，验证是负反馈

干预发出后必须验证，否则干预只是撒药：

```
干预发出（前馈）
    光照时刻指导 / 光疗眼镜 / 刺激托底
期望值（模型预测）
    重锁定速率基准：西飞 1.5h/天，东飞 0.5-1h/天
实际测量（负反馈）
    相位是否按期望速率移动
```

### 分级负反馈——阈值从测量噪声推导

偏差分级修正，但阈值不发明数字，从噪声推导：

```
σ_m = 相位测量的噪声标准差（逐用户估计）

|偏差| < 2σ_m     正常波动档
                 只记录数据，不调整参数
                 2σ = 95% 置信带，落在这里
                 就是噪声的日常散步
2σ_m ~ 5σ_m      剂量级修正档
                 上调当前通道强度或时长
                 同时排查干扰源（未声明的
                 咖啡因、熬夜、进食紊乱）
                 同步修正相位估计置信度
> 5σ_m           通道级切换档
                 当前通道判失效，
                 切到下一优先级通道
                 触发全信号相干性检查
                 （第九节管道复查：
                 是否发生了未察觉的相位变化）
```

每一轮修正记录四元组：干预参数 → 预期效果 → 实际偏差 → 修正动作。形成用户个人的干预效果日志，长期迭代个性化敏感度参数。这就是用户自己的实验记录，闭环每转一圈，模型就准一分。

### 多通道协同与互斥

```
光剂量统一台账
    光疗眼镜主动光照 + 环境光 + 建议光照
    合并计入日剂量积分
    行为建议的光照剂量自动扣除硬件已补足的部分
    防止重复计算导致相位过冲
时间互斥
    晚间镇静刺激 vs 夜间蓝光暴露，互斥
    晨间唤醒刺激 vs 褪黑素服用窗口，互斥
    冲突时自动降级低优先级通道
单日总干预封顶
    所有干预的总相位偏移预估量设安全上限
    多通道叠加不得导致相位过冲
```

### 反依赖阶梯——带迟滞的退出机制

干预环的终点是用户不再需要它。阶梯结构 + 迟滞防横跳：

```
轻度内化
    连续 N1 周（默认 4），行为重合度达标
    → 提示频率下调一半，仅留关键窗口建议
中度内化
    连续 N2 周（默认 8），相位稳定性维持个人优秀区间
    且 Δφ 持续低于阈值
    → 提示频率下调 80%，仅保留异常预警
陪伴模式（完全内化）
    连续 N3 周（默认 12）
    → 静默监测态：不主动推送，
    仅用户主动查询时输出分析
回退迟滞
    连续 2 周相位稳定性明显下降才逐级恢复
    迟滞宽度可配，防状态反复横跳
```

N1/N2/N3 与迟滞宽度全部是第三层可配置参数，默认值只是起点。

行为重合度的定义必须设备可测，不靠自报：

```
重合度 = 设备建议窗口内的实际光暴露剂量
       / 建议剂量
环境光传感器天然能测到用户是否真的见了光
（执行了 = 光传感器读数上升，
没执行 = 读数不动）
重合度是测量值，不是问卷值
```

### UNSTABLE 的干预降级

无稳定相位的用户（随机轮班、严重失眠），干预环降级：

```
不输出"相位校准"类干预
    不给"建立规律作息"建议
    （班表不归用户管，建议的正确性等于废话）
核心目标切换
    降低震荡幅度、减少内部失同步
    可执行的部分只有托底三件套：
    疲劳归因、褪黑素审计、错位期保护
    睡眠窗口保护照常（睡前暖音、预热）
节律健康度降级
    只输出稳定度趋势
    不做同步性、恢复力评分
    标注"当前节律无稳定相位"
```

## 十三、节律健康度

四个分量，每个都有公式。相位是时间问题，振幅是能量问题——两者缺一不可：

```
稳定性 S1
    输入：相位日间方差
    归一：对个人历史方差分布取分位数
    S1 = 1 - 当前方差在个人分布中的分位
同步性 S2
    输入：Δφ 的幅度与持续时间
    归一：同 S1，对个人历史分布
恢复力 S3
    输入：重锁定速率 vs 期望速率
    （西飞 1.5h/天、东飞 0.5-1h/天）
    S3 = min(实际/期望, 1)
振幅 A
    输入：节律峰谷差（体温、HRV 的昼夜摆幅）
    归一：对个人历史分布取分位数
    相位正常但摆幅塌陷 = 煎熬的生理读数
```

振幅是"还活着多少"的读数：慢性压力的生物标志不是相位错，是节律平坦化——burnout 研究里最一致的标志之一是皮质醇觉醒反应（CAR）钝化，健康人的晨峰是陡的，长期高压的白领是平的；HRV 昼夜摆幅同理。节律还在 24 小时跑，但峰谷差越来越小，像一张被拉平的图。

```
gap = 身体的强制不应期
    慢性压力 → HPA 轴持续高负荷
    → 身体反复申请维护窗口
    （疲惫、失眠、烦躁）
    → 被咖啡因和助眠剂按下去
    → 身体强制执行：熔断（辞职/被优化）
    → gap 是恢复期，振幅应在其中可观测回升
熔断-恢复同构（Feelings-OS ADR 003）
    熔断 → 脱离环境 → 保底帧
    → 慢启动爬坡 → 决定是否重新入局
    身体自己有一套熔断恢复协议，
    咖啡因和助眠剂的作用是无限期推迟执行，
    gap 是协议最终强制执行的样子
```

合成：

```
H = w1·S1 + w2·S2 + w3·S3 + w4·A
权重默认 30/30/20/20，属第三层可配置参数
冷启动：个人分布未建立时用人群参考分布，
标注"基线建立中"
```

归一化的本质是 k8s 的 Prometheus 思路：个人历史基线 = 自定义 metric，冷启动人群基线 = 默认 metric，随数据收敛切换到自定义。**用户的 80 分和别人的 80 分不是同一个含义，因为分母是各自的分布。**

输出范式：

```
默认只输出变化量
    "本周节律稳定度较上周 +14%，
    内部同步度 +8%"
    对比才是感知（jnd-and-contrast 的原则）
分项可追溯
    点进去看到四个分项的趋势曲线
    和行为归因挂钩：
    "周末作息波动导致稳定性 -9%"
```

### 境界评分——分数是当前阶段内的掌握度

绝对分不隐藏，先消解它的语义。分数的本质是修仙式的分层归一化：

```
境界 = 用户自己选的 spec 层级
    每层有自己的分数空间（归一化分母不同）
    用户的 80 分和别人的 80 分不是同一个含义，
    因为分母是各自的境界分布
圆满 = 本层高分 = 对当前阶段的掌握度
    不代表"更好"，只代表"在这一层走得稳"
突破 = 用户声明的阶段切换
    分数从漂亮变不漂亮 = 新层的新手期
    不是退步，是爬下一座山的正常读数
安于现状 = 合法的
    不进阶不判负（PASS 原则：只有深浅没有高下）
```

三个设计推论：

```
阶段切换是声明驱动的前馈
    "我要突破"和"我明天飞纽约"同构
    设备提前知道分数要降，
    不会把突破期的新手读数误报成"状态在恶化"
    分数下降有两种语义：
    突破期的新手读数 vs 同层内真实退化
    阶段上下文来自用户声明，
    声明消歧，测量确认

心魔防御 = reward hacking 的天然免疫
    分数漂亮是诱惑不是成就
    设备偶尔说：
    "你在这层已经圆满了，继续待着分数会很漂亮"
    把"漂亮分数"揭示成诱惑本身
    选择权永远在用户：待着也好，突破也好
    设备不替人选

飞升 = 反依赖的终点
    最终阶段的分母不是"设备陪伴下的表现"
    是"没有设备时的表现"
    飞升 = 脱下设备还稳
    反依赖追踪的天庭出口
```

语义变了，审判就没了：低分不再意味着"你这个人不行"，只意味着"你在这座山刚起步，很正常"。工程实现只是阶段切换时的归一化分母切换 + 预期重置（每个阶段一个 metric namespace，Prometheus 思路原样复用）。绝对分在境界框架下不再是判决，管理模式可选可见——诚实是入口，不是默认。

## 十四、定位——日常保养，不是 gap 劝退

Gap 终究是有门槛的：需要积蓄、需要机会成本、需要能再回来的底气，不是所有人都付得起这个代价。

```
Feelings 不做的
    不劝人辞职
    不喊"逃离大厂"
    不说"你应该规律作息"
    （班表不归用户管，
    正确的废话还是废话）

Feelings 做的
    在现有的生存结构里，
    把日常的节律损伤降到最低：
    零成本的搭便车
    低成本的剂量优化
    硬件的代执行
```

不用等到熬垮了再 gap 保养。能在日常里把 Δφ 稳住、把节律振幅守住、把自主神经的弹性留住——就是对绝大多数人更有用的"日常保养"。gap 是身体的止损线，日常保养是止损线之前的减损。两条路都成立，Feelings 只做后者，因为后者人人付得起。
