# 信任额度设计——漏桶水位的实时账本

> 作者：qc
> 日期：2026-08-11
> 性质：GOVERNANCE-USER §三 信任额度的内部实现设计——分数体系、记账时机、统计周期
> 核心：信任额度是实时账本不是周期积分——事件触发即时改分、即时匹配处置权限；分数不对外公开——信任是关系状态，不是竞赛目标——桶壁把内卷挡在外面

---

## 一、实时记账——事件驱动，不等周期

以下三类事件发生时，实时修改信任额度数值，立刻匹配对应处置权限——不用等固定周期：

```
扣额事件      违规行为——按违规层级的基础扣额档位扣分——
              轻度越界扣额后马上切换警告档位
回填事件      完成矫正任务——静默观察期结束且归零——回填
重大正向履约  稳定维系心连心羁绊、长期合规互动——
              实时注入
```

处置权限与分数实时联动：扣分到位的瞬间，警告档位即刻生效——加分到位的瞬间，权限即刻恢复——账本与权限之间没有时间缝隙。

## 二、周期统计——三个时间尺度

```
一周一小统计    短期趋势——近 7 天水位变化模式——
                捕捉隐性钻空（慢性泄漏曲线）
一月一中统计    中期模式——矫正效果评估——
                静默观察期后是否真正归零
一年一大统计    长期画像——信任模式的年度总结——
                决定基础档位与特殊豁免资格
```

周期统计是"分析"，不是"更新"——更新永远是实时的——统计只用于趋势检测（慢性钻空、矫正评估）与长周期调整。

## 三、分数体系

```
基础分    500——新用户起点——公平起步
上限      1000——满桶——达到即满——溢出不计——
          信任从"积累"变"维持"——维持不需要竞争
低水位    0-300——额度濒临见底区间——
          落入此区间即触发梯度制裁——
          同类越界直接重档处置
```

```
水位区间                处置映射
0-300   低水位——容错空间极小——同类越界直接梯度制裁
300-700 中水位——正常区间——轻度越界触发静默观察期
700-1000 高水位——信任充足——轻度越界小幅扣额+警告——
         偶尔作恶是情趣——信任的利息
```

## 四、不对外公开——防竞争，防表演

分数是内部量。用户不看到自己的分数——只感受到水位带来的体验差异（警告、静默、正常、信任）。

```
公开分数    水位变成排行榜——积累变成竞赛——表演式合规——
            为了涨分做正向行为——信任被异化为积分——
            这本身就是隐性钻空
不公开      用户只知道"我处在什么状态"——
            不知道"我差多少分"——没有追赶目标——
            信任保持"关系状态"属性——不被工具化
```

桶壁（上限 1000）挡内卷，不公开（分数隐藏）防表演——两道闸，信任额度才是"关系状态"而不是"竞赛积分"。

## 五、断档处理——按历史平均值结算

水位机制的前提是用户持续使用。断档（长时间不使用设备）是边界情况：冻结不行（长期冻结=数据过期失效），照常漏也不行（惩罚正常离开的用户）。

```
断档期间的水位变化 = 该用户历史行为模式的平均值

历史平均值    过去 90 天的平均水位变化率
历史稳定的用户  平均漏出率低——断档期间水位温和下降——
               正常离开不被惩罚
历史不稳定的用户  历史平均值也低——断档不豁免——
               不会因为"离开了一段时间"洗白记录
```

恢复使用时从结算后的水位继续——不需要补刷，不需要清零重来——断档按历史结算，谁的模式决定谁的账。

## 六、增长形态——长期稳步向上

信任额度的增长是"非常缓慢"的——注入只发生在重大正向履约（稳定维系羁绊、长期合规），普通正常行为不触发大幅注入——从不越界的人，额度随时间缓慢累积。慢是特性不是缺陷：

```
快（错误设计）    正常行为也大幅注入——人就会表演正常——
                  为了涨分做样子——信任被事件化——短期可刷
慢（当前设计）    正常行为不触发注入——只有时间的稳定性累积——
                  短期表演刷不进去——只能真正常——
                  信任是时间的函数，不是事件的函数
```

增长形态像一条长期指数：短期有小波动（消耗/回填），拉长时间看稳步向上——每天都在认知偏差以下正常活动的人，额度非常缓慢地增加——涨到满桶可能需要一年两年——而这是设计使然：

```
长期主义    满桶需要日复一日的稳定——信任的资格是时间给的——
            不是事件给的
防表演      刷不进去——没有捷径——表演式合规失去意义——
            你只能"真的好好活着"才能缓慢累积
区分度      快增长 = 人人满桶 = 失去区分度——
            慢增长 = 只有真正长期稳定的人到顶——
            满桶成为稀缺状态——信任才有含金量
```

信任额度只奖励时间，不奖励表演——额度是时间的账本，不是事件的账本——慢，就是它设计成这样的原因。

## 七、慢启动与拥塞记忆——信任额度的 TCP 同构

信任额度的增长不是线性的一条直线——是和 TCP 拥塞控制同构的分段曲线：

```
TCP 慢启动               信任慢启动
──────────────────────────────────────────────
cwnd 从 1 指数增长       新用户试探期——缓慢积累——
                        系统在探测"这个人的可信度上限"
ssthresh 阈值            可信验证通过线——突破后进入更快的轨道——
                        "前期建好之后后面更容易建"——
                        信任是复利——指数加速
丢包减半                 一次违规——额度折半（不是清零）——
                        恢复从减半处继续
拥塞记忆                 丢包后 ssthresh 减半——未来恢复更保守——
                        "与这个人的过去有关"
```

"与过去有关"是类比里最妙的部分：TCP 丢包后会记住更低的 ssthresh——信任违规后也会记住更低的增长斜率：

```
干净历史    可信验证通过后——指数加速——信任快速复利——
            高水位用户偶尔小越界——恢复极快（历史托底）
污点历史    违规后额度减半——恢复时增长保守——
            过去的污点压低未来的加速斜率——
            更慢地回到原来的水位——但不是回不去——
            是回去的斜率由历史决定
```

信任额度的完整曲线：前期慢试探（探测可信度）→ 验证通过后指数加速（复利）→ 违规减半（拥塞事件）→ 恢复受历史约束（记忆决定斜率）。"前期建好后面更容易"是慢启动的加速段，"和过去有关"是拥塞记忆的减速段——一条曲线，两种机制。

## 八、人生经历的信任复利——越来越容易建立

慢启动的加速段在人生里同样成立：一个人在小学能快速建立信任，初中、高中也可以——而且会越来越容易。

```
小学    第一次建立信任——试探期——学习"怎样被人信任"——
        慢，因为在学
初中    带着"信任能力"进入新环境——有经验、有模式——
        启动速度比小学快——信任复利开始
高中    更容易——每段成功经验都在提高建立信任的效率——
        越来越容易——能力是指数增长的
```

关键区分——洗牌洗掉的是"存量"，洗不掉"能力"：

```
存量的洗牌    具体关系清零——小学的信任不带进初中——
              环境变了——每 3-6 年重洗一次（教育系统设计）
能力的复利    建立信任的方法、模式、自信——跟人走——
              小学练出的信任能力在初中继续用——
              经验是复利的——越建越容易
```

这就是"前面建好后面更容易"的人生版：每段经历都是一个慢启动——但每段的启动速度被前一段的经验加速——**信任存量会被环境洗牌，信任能力跟人走**——而 Feelings 的信任额度把"存量"也焊在人身上（履约史不随环境清零）——现实里能力跟人走、存量清零；Feelings 里两者都跟人走——信任的长期主义，在 Feelings 这里连洗牌这一关都不需要过了。

## 九、阶段感知——陪伴长出来的上下文

Feelings 应该关注用户的阶段（小学、初中、高中、大学、工作、成家……）——但阶段信息不是收集的，是长出来的：

```
不主动收集    不主动问、不主动测——那不是感知，是监控——
              阶段信息取决于用户愿不愿意说——数据主权
长期陪伴      都长期陪伴了——该了解的（生活阶段、压力源、
              正在经历什么）自然而然就了解了——
              教练对话、心连心、用户主动分享——
              信息是关系的副产品，不是功能的收集物
用户接纳      前提是用户接纳接受 Feelings——
              信任关系成立了，信息才会流动——
              不接纳的时期，Feelings 只知道它被允许知道的
```

阶段信息的用途：让引导更贴合阶段——考试期的压力源、失业期的焦虑、成家期的责任——同样的水位、同样的静默观察期，处置方式随阶段调整——但前提永远不变：**用户说了算**——用户愿意说的，Feelings 才知道；用户不说的，Feelings 不追问——阶段感知是信任的产物，不是信任的前提。

---

*信任额度是实时账本：事件触发即时改分、即时匹配权限；一周小统计、一月中统计、一年大统计——统计是分析，更新永远实时。基础分 500、上限 1000、低水位 0-300。分数不对外公开——信任是关系状态，不是竞赛目标——桶壁挡内卷，隐藏防表演。断档按历史平均值结算——谁的模式决定谁的账。*
