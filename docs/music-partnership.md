# 音乐平台合作设计

> 作者：qc
> 日期：2026-04-05
> 来源：音乐听歌数据作为感受档案的输入层，与音乐平台建立上下游关系

---

## 一、核心洞察：听歌数据是最诚实的情绪地图

用户在网易云/Spotify听了几年歌，那份数据里藏着他最真实的情绪地图。

什么时候听什么，单曲循环了什么，跳过了什么，凌晨三点听的是哪首——这些行为比任何问卷调查都诚实。没有人会在凌晨三点单曲循环一首歌是为了给别人看的。

**音乐偏好是感受偏好的投影，只是用户自己可能从来没有意识到。**

Feelings要做的，是把这份投影翻译回感受本身。

---

## 二、经典音乐：系统默认层

经典音乐之所以被称为经典，是因为它的普适性。

贝多芬第七交响曲第二乐章，不管你是哪国人，什么背景，听到都会慢下来。这种普适性是神经科学现象——某些音乐结构对人类神经系统有接近通用的激活模式，跨越个体差异。

这对Feelings意味着：经典音乐可以作为感受包的**基准校准层**。

```
经典音乐库
    ↓
系统默认层，所有用户共享
不依赖个体偏好，直接使用普适激活模式
用于校准感受强度的音乐参照基准
AI生成音乐时，经典结构作为骨架参考
```

用户不需要主动选择经典音乐，系统默认使用。如果用户想指定，明确选择自己偏好的流派：

```
巴洛克        结构清晰，对位复杂，适合专注类感受
浪漫主义      情绪浓烈，叙事性强，适合高强度情感类感受
现代简约      重复与变化，冥想感，适合平静/沉浸类感受
爵士          即兴与张力，适合带有不确定性的感受
其他流派      用户自定义优先级
```

系统在用户指定的流派范围内做匹配，不强制。

## 三、音乐平台合作框架

### 合作本质

Feelings和音乐平台是上下游关系，不是竞争关系。

```
音乐平台    让用户找到共鸣
Feelings    让用户真正经历那个共鸣背后的感受
```

用户在网易云单曲循环一首歌，是在反复寻找某种感受但没有完全得到。Feelings把那个感受真正给他。音乐平台的数据在Feelings里有了新的意义，Feelings的分析结果也能反哺音乐平台的推荐优化。

三方都有增量，不是零和。

### 数据流向

```
用户授权
    ↓
音乐平台提供    脱敏后的用户听歌行为数据
                （播放记录、单曲循环、跳过行为、收藏、时间分布）
    ↓
Feelings AI分析
    ↓
个人感受档案    （仅存储在用户设备，不上传至Feelings服务器）
    ↓
感受包推荐      反哺给Feelings体验层
感受分析报告    可选择性分享给音乐平台，用于推荐优化
```

关键原则：**原始听歌数据不离开用户设备，Feelings只处理分析结果，不持有原始数据。**

### 合作伙伴优先级

```
第一批    网易云音乐（中国市场覆盖最广，情绪标签体系完整）
          Spotify（国际市场，数据维度最丰富）

第二批    Apple Music、QQ音乐、YouTube Music

长期      独立音乐平台、古典音乐专项平台（如IDAGIO）
```

## 四、AI分析：从听歌行为到感受档案

AI分析运行在服务器端。用户授权后，音乐平台将脱敏听歌数据传输至Feelings服务器，AI在服务器上完成分析，将结果（感受档案元数据）下发至用户设备本地存储。

**原始听歌数据的流向**：音乐平台 → Feelings服务器（分析用，不持久化） → 分析结果下发本地 → 原始数据不在服务器留存。

这和神经数据的隐私原则不同：神经数据连服务器都不经过，听歌数据经过服务器分析但不持久化存储。这个差异需要在隐私政策里明确说明。

### 情绪偏好图谱

```
亲近感受类型    用户反复选择的音乐对应哪类感受
               「他总在听带有淡淡忧愁底色的快乐」
               「他偏好有紧张感但最终释放的结构」

感受空白区域    他从不听的情绪类型
               可能是感受空白，可能是主动回避
               系统标注但不强推，等待用户自己探索

高密度时刻      单曲循环的歌背后，是什么感受在被反复寻找
               这是需求最强烈、但可能一直没有被满足的感受

时间维度        凌晨听什么，工作时听什么，运动时听什么
               同一个人在不同状态下的感受需求是不同的
```

### 个人感受档案结构

```
user_feeling_profile {
    dominant_feelings      []FeelingType    // 主导感受类型
    feeling_gaps           []FeelingType    // 感受空白区域
    intensity_comfort      IntRange         // 舒适强度区间估算
    temporal_patterns      map[TimeSlot][]FeelingType  // 时间段偏好
    music_structure_prefs  MusicStructure   // 偏好音乐结构参数
    last_updated           TIMESTAMPTZ
    data_source            []Platform       // 数据来源平台
}
```

这份档案存储在用户本地设备，不上传服务器。用户可以查看、编辑、删除任意条目，也可以完全清除后重新建立。

## 五、档案的三个用途

### 用途一：感受包推荐

不是基于「你听了什么」的音乐推荐，而是基于「你在寻找什么感受」的感受推荐。

```
用户档案显示：反复寻找「被理解的安静」但从未完整得到
    ↓
系统推荐：感受库中「被接住之后的平静」类感受包
          强度从用户舒适区间下沿开始
```

这可能是用户第一次意识到自己一直在寻找的东西叫什么。

### 用途二：强度解锁建议

听歌数据里有强度耐受的隐性信号。

```
用户长期偏好高张力、强烈情绪起伏的音乐
    ↓
系统判断：该用户可能对更高强度的感受有天然耐受
          建议适当提前开放30-60区间的探索
```

这不是自动解锁，是系统给出建议，用户自己决定要不要接受。

### 用途三：AI生成音乐的个人化参数

用户偏好的音色、节奏密度、和声复杂度，直接进入AI音乐生成的参数层。

```
用户偏好    钢琴主导、弦乐辅助、中等节奏密度、偏大调
    ↓
AI生成音乐时，在感受曲线约束下，优先选用这类音色和结构
```

两个用户体验同一个感受包，AI生成的音乐结构相似，但音色质感是个人化的。

**重要约束**：AI音乐和本地音乐是互斥的，不是并行的。

```
用户选择本地音乐    → AI不介入音乐层，系统只做感受时长适配
用户选择AI音乐      → 完整的感受曲线实时驱动，个人化参数生效
用户关闭所有音乐    → 神经接口单通道工作
```

用本地音乐意味着主动放弃AI音乐的实时感受曲线同步能力，系统会在切换时告知这个代价。

## 六、隐私边界

神经数据和听歌数据，是Feelings处理的两类最敏感的个人数据。

```
神经数据        永远不离开设备（见 tech-architecture.md）
原始听歌数据    由音乐平台持有，Feelings不存储，仅在设备本地处理
感受档案        存储在用户设备，用户完全控制
分析结果        用户可选择是否分享给音乐平台用于推荐优化
```

用户对数据流向有完整的控制权：

```
选项A    完全不授权    Feelings不使用任何外部数据，体验依然完整
选项B    单向授权      音乐平台数据进入Feelings，不反向分享
选项C    双向授权      感受分析结果也反哺给音乐平台推荐系统
```

默认选项A，用户主动升级。

## 七、与音乐平台的商业结构

```
Feelings获得    用户听歌行为数据的使用授权
音乐平台获得    感受维度的用户洞察（选项C用户）
               Feelings平台内的音乐播放数据（版权收益）
               合作标注：「此感受由XX音乐数据支持」

用户获得       更精准的感受推荐
              更个性化的AI生成音乐
              第一次看见自己的感受地图
```

音乐版权收益是合作的基础商业逻辑——用户在Feelings里触发的经典音乐播放，版权费正常结算给音乐平台。Feelings不绕开版权，通过合作解决。

## 八、未解决的问题

**听歌数据的代际差异**

一个用Netflix长大的用户和一个听磁带长大的用户，听歌行为数据的结构完全不同。AI模型如何在不同代际的数据格式和行为模式之间保持一致性，是冷启动阶段的主要挑战。

**感受档案的冷启动**

新用户没有历史听歌数据，或者不愿意授权，感受档案为空。这部分用户的推荐逻辑需要完全依赖使用行为数据从零建立，节奏更慢，体验需要单独设计。

**跨平台数据的一致性**

同一个用户在网易云和Spotify上的行为可能截然不同——工作时用一个，私人情绪时用另一个。如何合并两份数据而不是简单叠加，需要专门的融合算法。

---

*音乐平台合作是Feelings个人化体系的数据基础，将随合作伙伴覆盖范围扩大持续演进。*
